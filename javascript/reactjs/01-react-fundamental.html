1. Introduction

L1

L1 Fundamental

1.1. Overview

  • React is a JavaScript library for building user interfaces. You describe what the UI should look like for a given state; React updates the DOM when state changes.
  • React apps are built from components — reusable pieces of UI. Modern React uses function components and hooks (Files 03, 05, 07 go deeper).
  • Default rule today: use function components, create projects with Vite, keep components small and focused, and pass data down with props (one-way data flow).

1.2. Default rules and how to study this file

  • Default rule today: prefer function components and hooks; keep components small; colocate state with the UI that needs it.
  • After reading sections 2–6, complete P. Practical Assignment in 01-practice.jsx before File 02. Review C. Common questions.

2. What is React & setup

L1

L1 Fundamental

2.1. What React does

  • React handles:
  • UI as a function of state — when data changes, UI re-renders.
  • Efficient DOM updates — compares virtual tree and patches only what changed (reconciliation).
  • Component composition — nest small components into larger screens.
  • React is only the view layer — routing, global state, and API calls are added with libraries (Files 09–11).

L1 Fundamental

2.2. Create a project (Vite)

  • Recommended starter for new apps:
npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev

my-app/

// main.jsx
import { StrictMode } from "react";

    <App />
  </StrictMode>
);
  • StrictMode runs extra checks in development (double-invokes some effects — File 05).

2.3. First component

  • A component is a function that returns JSX:
function Welcome() {
  return <h1>Hello, React!</h1>;
}

export default Welcome;
  • Use it like a custom HTML tag:
function App() {
  return (
    <div>
      <Welcome />
      <Welcome />
    </div>
  );
}
  • Rules:
  • Component names PascalCase (Welcome, not welcome).
  • Return one root element (or use a Fragment — File 04).

2.4. React 18+ Root API (createRoot) vs Legacy ReactDOM.render

  • Legacy API (React 17 and earlier):
// React <=17 (Legacy synchronous rendering)
import ReactDOM from "react-dom";
import App from "./App";

ReactDOM.render(<App />, document.getElementById("root"));
// Unmount:
// ReactDOM.unmountComponentAtNode(document.getElementById("root"));
  • Modern API (React 18 & 19):
// React 18+ (Concurrent-enabled root)
import { createRoot } from "react-dom/client";
import App from "./App";

const container = document.getElementById("root");
const root = createRoot(container);
root.render(<App />);

// Clean unmount:
// root.unmount();
  • Why the root API changed:
    1. Concurrent Features: createRoot enables Concurrent React capabilities such as transitions (useTransition), Suspense streaming, and selective hydration. Legacy ReactDOM.render ran strictly synchronously.
    2. Automatic Batching: State updates inside promises, timeouts, and native event handlers are batched automatically under createRoot (see File 03).
    3. Clean lifecycle: Encapsulates container binding inside the root object instead of mutating the container DOM node repeatedly.

2.5. Virtual DOM & Fiber Tree Architecture Overview

  • Virtual DOM (VDOM): A lightweight, in-memory JavaScript representation of the actual DOM tree. Each JSX element creates a plain JS object descriptor (e.g. { type: "div", props: { className: "card", children: ... } }).
  • Reconciliation vs Rendering:
    • Reconciliation (Diffing): React compares the new Virtual DOM tree with the previous one to calculate the minimal set of mutations.
    • Renderer: The platform-specific module that applies changes to the target environment (react-dom for web browsers, react-native for mobile).
  • The Fiber Reconciler:
    • In React 16+, React rebuilt its core reconciler from the ground up using Fibers.
    • A Fiber is a JavaScript object representing an incremental unit of work.
    • Instead of traversing a recursive call stack synchronously (which could freeze the browser tab during heavy renders), the Fiber tree is a singly linked list using three primary pointers: 
      fiberNode = {
  type: ComponentOrTag,
  key: keyIdentifier,
  child: firstChildFiber,       // Pointer to first child
  sibling: nextSiblingFiber,    // Pointer to next sibling
  return: parentFiber,          // Pointer back to parent
  memoizedState: hookLinkedList // Component state & hooks
};
    • This pointer structure enables React to pause, resume, prioritize, or abort rendering tasks without locking the browser main thread — providing the engine foundation for React 18 Concurrency.

3. JSX

L1

L1 Fundamental

3.1. What is JSX

  • JSX looks like HTML inside JavaScript. It compiles to React.createElement(...) calls:
const element = <h1 className="title">Hello</h1>;

// roughly compiles to:
// React.createElement("h1", { className: "title" }, "Hello");
  • JSX is expressions — wrap in {} for JavaScript:
const name = "Bharat";
const element = <p>Hello, {name}!</p>;

const sum = <p>{1 + 2}</p>;  // 3

3.3. JavaScript in JSX

  • Conditionals (full detail in File 04):
function Greeting({ isLoggedIn }) {
  return (
    <div>
      {isLoggedIn ? <p>Welcome back</p> : <p>Please sign in</p>}
    </div>
  );
}
  • Attributes — use {} for dynamic values:
<img src={user.avatarUrl} alt={user.name} />
<button disabled={!isValid}>Submit</button>
  • Style — object, camelCase properties:
<div style={{ color: "navy", fontSize: "1.2rem" }}>Styled</div>

3.4. Modern JSX Runtime (react/jsx-runtime vs React.createElement)

  • Legacy JSX Transform (React ≤16):

    Every JSX tag was transformed by Babel into a call to React.createElement(...):

    // Source JSX:
const heading = <h1 className="title">Hello World</h1>;

// Legacy compiled output:
import React from 'react'; // MANDATORY even if not referenced directly!
const heading = React.createElement("h1", { className: "title" }, "Hello World");
  • Modern JSX Transform (React 17, 18, 19):

    Modern compilers (Vite, Next.js, Babel) automatically import specialized functions from react/jsx-runtime:

    // Source JSX:
const heading = <h1 className="title">Hello World</h1>;

// Modern compiled output (injected automatically by compiler):
import { jsx as _jsx } from 'react/jsx-runtime';
const heading = _jsx("h1", { className: "title", children: "Hello World" });
  • Key Technical Advantages:
    1. No scope import required: You no longer need to write import React from 'react' just to use JSX syntax in your files.
    2. Flat props representation: Children are passed as a regular property on the props object instead of variable rest arguments, reducing heap allocation overhead during object creation.
    3. Tree-shaking: Unused functions on the global React namespace are not bundled if you only consume JSX and specific hooks.

4. Components

L1

L1 Fundamental

4.1. Function components

  • Standard way to define UI (class components are legacy):
function UserCard({ name, role }) {
  return (
    <article>
      <h2>{name}</h2>
      <p>{role}</p>
    </article>
  );
}
  • Export for use in other files:
// UserCard.jsx
export function UserCard({ name, role }) { /* ... */ }

// App.jsx
import { UserCard } from "./UserCard.jsx";
  • Default export (one main component per file is common):
export default function App() {
  return <UserCard name="Bharat" role="Developer" />;
}

4.2. Component tree

  • React apps form a tree — parent components render children:
function App() {
  return (
    <Layout>
      <Header title="My App" />
      <Main>
        <UserCard name="Bharat" role="Dev" />
      </Main>
      <Footer />
    </Layout>
  );
}
  • Each component encapsulates its own markup and logic. Split when a section is reused or gets too large (File 02 — composition).

L1 Fundamental

4.3. Pure components (concept)

  • Given the same props, a component should return the same UI. Avoid side effects in the render body (File 12 — memo):
// Good — render is a pure function of props
function Badge({ label, color }) {
  return <span style={{ background: color }}>{label}</span>;
}

// Avoid during render — use useEffect (File 05)
// fetch("/api/user");  // side effect in render

5. Props

L1

L1 Fundamental

  • Props (properties) pass data from parent to child. Props are read-only — children must not mutate them.

5.1. One-way data flow

  • Data flows down the tree via props. Siblings do not share props directly — lift shared state to a common parent (File 03).
function Parent() {
  const name = "Bharat";
  return (
    <>
      <ChildA name={name} />
      <ChildB name={name} />
    </>
  );
}

L1 Fundamental

5.2. Passing and reading props

function UserCard({ name, age, isActive }) {
  return (
    <div>
      <h2>{name}</h2>
      <p>Age: {age}</p>
      {isActive && <span>Active</span>}
    </div>
  );
}

function App() {
  return (
    <UserCard name="Bharat" age={30} isActive={true} />
  );
}
  • Props destructuring in the parameter list is idiomatic. Alternative:
function UserCard(props) {
  return <h2>{props.name}</h2>;
}

5.3. Default props

function Button({ label = "Click me", variant = "primary" }) {
  return <button className={variant}>{label}</button>;
}

<Button />                    // "Click me"
<Button label="Save" />       // "Save"

5.4. Children prop

  • Content between opening and closing tags becomes props.children:
function Card({ title, children }) {
  return (
    <section>
      <h3>{title}</h3>
      <div>{children}</div>
    </section>
  );
}

function App() {
  return (
    <Card title="Notes">
      <p>First paragraph</p>
      <p>Second paragraph</p>
    </Card>
  );
}
  • children can be text, elements, or multiple nodes (File 02 — composition patterns).

6. State intro

L1

L1 Fundamental

  • State is data that changes over time and affects what the UI shows. When state updates, React re-renders the component.

6.1. Why not plain variables?

// This does NOT work — changing message does not re-render
function Broken() {
  let message = "Hello";
  return (
    <button onClick={() => { message = "Hi"; }}>
      {message}
    </button>
  );
}
  • React needs useState (or similar) to schedule a re-render (File 03).

6.2. State vs props

PropsState
SourceParentInside component
Mutable by child?NoYes (via setter)

function UserPanel({ userId }) {        // prop — from parent
  const [name, setName] = useState(""); // state — local

  return <p>{userId}: {name}</p>;
}

L1 Fundamental

6.3. useState basics

import { useState } from "react";

function Counter() {
  const [count, setCount] = useState(0);

  return (
    <div>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>+1</button>
    </div>
  );
}
  • useState(initial) returns [value, setter].
  • Call setCount(newValue) to update — React re-renders.
  • State is local to the component instance — two <Counter /> on screen have independent state.
  • Functional update when next state depends on previous:
setCount((prev) => prev + 1);

6.4. Minimal interactive example

import { useState } from "react";

function LikeButton() {
  const [liked, setLiked] = useState(false);

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? "❤️ Liked" : "🤍 Like"}
    </button>
  );
}
  • Event handlers use camelCase (onClick, onChange). Details in File 03.

C. Common questions

L1 L2

L1 Fundamental

C.1. What is React? ▾ Answer

A JavaScript UI library for building interfaces with components. It updates the DOM efficiently when application state changes.

C.2. What is JSX? ▾ Answer

Syntax extension that lets you write HTML-like markup in JavaScript. It compiles to React.createElement and must follow JSX rules (className, one root, closed tags).

C.3. What are props? ▾ Answer

Inputs passed from parent to child. They are read-only and enable one-way data flow down the tree.

C.4. What is state? ▾ Answer

Internal data owned by a component that can change over time. Updating state triggers a re-render. Use useState in function components.

C.5. What is children in props? ▾ Answer

Special prop for nested content between a component's JSX tags. Used for wrappers, layouts, and composition.

L1 Fundamental

C.6. Why must component names be capitalized? ▾ Answer

React treats lowercase tags as built-in HTML (<div>) and PascalCase as custom components (<UserCard>).

C.7. Do I need to learn class components? ▾ Answer

For new code, no — use function components and hooks. You may see classes in older codebases.

C.8. What should I learn next after this file? ▾ Answer

File 02 (components & props depth), File 03 (state & events), then File 04 (lists & conditional rendering).

L2 Intermediate

C.9. What is the difference between a component and an element? ▾ Answer

An element is a plain object describing UI (e.g. <div />). A component is a function or class that returns elements (or other components).

C.10. What is the difference between props and state? ▾ Answer

Props come from outside and are immutable in the child. State is managed inside the component and updated with a setter function.

P.3. Challenge

  1. Explain in comments: library vs framework, and what “declarative UI” means for your Hello app. ▾ Solution 
    /*
Library vs Framework & Declarative UI:
- Library (React): You control the flow. React provides UI rendering primitives and hooks; you choose routing, data-fetching, and build tools.
- Framework (Angular / Next.js): Inverts control ("Hollywood Principle"). The framework calls your code according to strict conventions.
- Declarative UI: You describe WHAT the UI should look like given current state (UI = f(state)), instead of imperatively manipulating DOM nodes step-by-step (e.g. document.createElement, appendChild).
*/
