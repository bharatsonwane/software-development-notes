05. useEffect & Side Effects

File 05 — useEffect, deps, cleanup, sync with external systems.

NotesExamplesPracticeInterview

1. Introduction

L1

L1 Fundamental

1.1. Overview

  • React components should be pure during render: given the same props and state, they return the same UI. Anything that touches the outside world — fetching data, subscribing to events, updating document.title, starting timers — is a side effect. useEffect runs that work after React paints the screen, and lets you sync component state with external systems.
  • Builds on state and events (File 03) and rendering patterns (File 04). File 10 goes deeper on data fetching; File 07 covers custom hooks that wrap effects.
  • Default rule today: put side effects in useEffect, not in the render body; list every value from the component that the effect reads in the dependency array; return a cleanup function when you subscribe, listen, or create resources that must be torn down.

1.2. Default rules and how to study this file

  • Default rule today: prefer function components and hooks; keep components small; colocate state with the UI that needs it.
  • After reading sections 2–10, complete P. Practical Assignment in 05-practice.jsx before File 06. Review C. Common questions.

2. Side effects vs render

L1 L2

L1 Fundamental

2.1. What belongs outside render

  • Render should compute UI from props and state only:
function Greeting({ name }) {
  // Good — pure calculation during render
  const label = name.trim() || "Guest";
  return <h1>Hello, {label}</h1>;
}
  • Side effects change something outside this render pass:
Side effectExample
Networkfetch("/api/user")
DOM APIdocument.title = "Home"
Subscriptionssocket.on("message", handler)
TimerssetInterval(tick, 1000)
Third-party widgetsnew Chart(canvas, options)
Local storagelocalStorage.setItem("theme", theme)
  • Running these during render causes bugs: they may run on every render, race with each other, and break React's predictable model (File 01 — pure components).

L2 Intermediate

2.2. Where useEffect runs

import { useState, useEffect } from "react";

function Page({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    // Runs AFTER React commits UI to the screen
    document.title = user ? `${user.name} — App` : "App";
  }, [user]);

  return user ? <Profile user={user} /> : <p>Loading...</p>;
}
  • Order on mount/update:
  1. Component function runs (render).
  2. React updates the DOM.
  3. Browser paints.
  4. useEffect callbacks run.

2.3. Execution Timing: useEffect vs useLayoutEffect

  • Detailed Browser Paint Timeline:
[React Render] → [DOM Mutations] → [useLayoutEffect (Sync)] → [Browser Paint] → [useEffect (Async)]
  • useEffect (Asynchronous & Non-Blocking):
    • Fires after the browser has computed layout and painted changes to the screen.
    • Default choice for 99% of side effects (data fetching, subscriptions, timers, analytics) so UI rendering is never blocked.
  • useLayoutEffect (Synchronous & Pre-Paint):
    • Fires synchronously immediately after DOM mutations, but before the browser paints pixels to the screen.
    • Use case: Measuring DOM elements (e.g. getBoundingClientRect()) or positioning tooltips/popovers where calculating dynamic dimensions in useEffect would cause an ugly visual "flicker" or jump before repositioning.
import { useLayoutEffect, useRef, useState } from "react";

function Tooltip({ targetRect }) {
  const ref = useRef(null);
  const [coords, setCoords] = useState({ top: 0, left: 0 });

  useLayoutEffect(() => {
    // Synchronously measure before browser paints — prevents visual glitch
    const { height } = ref.current.getBoundingClientRect();
    setCoords({
      top: targetRect.top - height - 8,
      left: targetRect.left
    });
  }, [targetRect]);

  return <div ref={ref} style={{ top: coords.top, left: coords.left }} className="tooltip">Hint</div>;
}

3. Basic useEffect syntax

L1

L1 Fundamental

3.1. Effect function

useEffect(() => {
  // effect body — side effect code here
});
  • The function you pass to useEffect is the effect. React calls it after render.

L1 Fundamental

3.2. Optional cleanup return

useEffect(() => {
  const id = setInterval(() => console.log("tick"), 1000);

  return () => {
    clearInterval(id);  // cleanup — runs before next effect and on unmount
  };
}, []);
  • Return a cleanup function when you need to undo what the effect set up.

3.3. Dependency array (third argument)

useEffect(() => {
  // ...
}, [dep1, dep2]);  // re-run when dep1 or dep2 change
Dependency arrayWhen effect runs
OmittedAfter every render (almost never what you want)
[]Once after mount (plus Strict Mode extra run in dev — see 5.7)
[a, b]After mount and whenever a or b changes

4. Dependency array in depth

L1 L2

L1 Fundamental

4.1. Include what you read

  • If the effect uses a value from the component, include it in deps:
function ChatRoom({ roomId }) {
  useEffect(() => {
    const connection = createConnection(roomId);
    connection.connect();
    return () => connection.disconnect();
  }, [roomId]);  // roomId is read inside — must be listed
}
  • When roomId changes, React runs cleanup for the old room, then runs the effect for the new room.

4.2. ESLint react-hooks/exhaustive-deps

  • The eslint-plugin-react-hooks rule warns when deps are missing or unnecessary. Treat warnings seriously — they catch stale closure bugs. Suppress only with a comment and a clear reason.

L2 Intermediate

4.3. Stale closures

  • Missing deps causes stale values inside the effect:
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const id = setInterval(() => {
      console.log(count);  // always logs initial count if [count] missing
    }, 1000);
    return () => clearInterval(id);
  }, []);  // Bug — count is stale

  return <button onClick={() => setCount((c) => c + 1)}>{count}</button>;
}
  • Fix options:
// Option A — add count to deps (effect re-subscribes when count changes)
useEffect(() => {
  const id = setInterval(() => console.log(count), 1000);
  return () => clearInterval(id);
}, [count]);

// Option B — functional update in event handler, not in interval (often better design)
// Option C — useRef for latest value without re-running effect (File 07)

4.4. Stable functions and deps

  • Functions defined in the component are new references every render:
function Search({ query }) {
  function fetchResults() {
    return fetch(`/api?q=${query}`);
  }

  useEffect(() => {
    fetchResults();
  }, [fetchResults]);  // runs every render — fetchResults identity changes
}
  • Fixes:
// Move fetch inline in effect — only list query
useEffect(() => {
  fetch(`/api?q=${query}`);
}, [query]);

// Or wrap fetchResults in useCallback when shared (File 12)
  • Setters from useState and dispatch from useReducer are stable — safe to omit from deps (React guarantees identity).

4.5. Objects and arrays as deps

useEffect(() => {
  saveSettings(settings);
}, [settings]);  // new object reference every render → effect runs every time
  • If settings is recreated each render, the effect fires too often. Derive stable deps (primitives) or memoize the object (File 12).

5. Cleanup

L1 L2

L1 Fundamental

5.1. Subscriptions and listeners

useEffect(() => {
  function onResize() {
    setWidth(window.innerWidth);
  }

  window.addEventListener("resize", onResize);
  return () => window.removeEventListener("resize", onResize);
}, []);
  • Always remove listeners, close connections, and abort fetches in cleanup.

5.2. Aborting fetch

useEffect(() => {
  const controller = new AbortController();

  async function load() {
    try {
      const res = await fetch(`/api/users/${id}`, {
        signal: controller.signal,
      });
      const data = await res.json();
      setUser(data);
    } catch (err) {
      if (err.name !== "AbortError") setError(err);
    }
  }

  load();
  return () => controller.abort();
}, [id]);
  • Without abort, a slow response for old id can overwrite state after new id loaded (race condition). File 10 expands on loading/error UI.

5.3. Timers

useEffect(() => {
  const id = setTimeout(() => setVisible(true), 300);
  return () => clearTimeout(id);
}, []);

L2 Intermediate

5.4. When cleanup runs

  • Cleanup runs:
  1. Before the effect runs again (when deps change).
  2. When the component unmounts.
useEffect(() => {
  console.log("subscribe", roomId);
  return () => console.log("unsubscribe", roomId);
}, [roomId]);

// Mount room A:  subscribe A
// Change to B:   unsubscribe A → subscribe B
// Unmount:       unsubscribe B

6. Common effect patterns

L1

L1 Fundamental

6.1. Syncing document title

function ProductPage({ product }) {
  useEffect(() => {
    document.title = product ? product.name : "Shop";
  }, [product]);

  return <ProductDetails product={product} />;
}
  • Small, self-contained — good first useEffect.

6.2. Fetch on mount / when id changes

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;

    async function load() {
      setLoading(true);
      setError(null);
      try {
        const res = await fetch(`/api/users/${userId}`);
        if (!res.ok) throw new Error("Failed to load");
        const data = await res.json();
        if (!cancelled) setUser(data);
      } catch (e) {
        if (!cancelled) setError(e);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }

    load();
    return () => { cancelled = true; };
  }, [userId]);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error.message}</p>;
  if (!user) return null;

  return <Profile user={user} />;
}
  • For production apps, prefer TanStack Query or similar (File 10) instead of hand-rolled fetch effects.

6.3. Syncing to localStorage

function usePersistedState(key, initial) {
  const [value, setValue] = useState(() => {
    const stored = localStorage.getItem(key);
    return stored ? JSON.parse(stored) : initial;
  });

  useEffect(() => {
    localStorage.setItem(key, JSON.stringify(value));
  }, [key, value]);

  return [value, setValue];
}
  • Note: reading localStorage in lazy useState initializer is fine; writing on every value change belongs in an effect (or event handler if you only save on explicit save).

6.4. External non-React library

useEffect(() => {
  const chart = new Chart(canvasRef.current, { /* options */ });
  return () => chart.destroy();
}, [data]);
  • Create / destroy imperatively in effect + cleanup when the library is not React-aware.

7. When not to use useEffect

L1 L2

L1 Fundamental

7.1. Initial data that could be server-provided

  • In frameworks with server components or loaders (File 09), fetch on the server or in the route loader instead of useEffect on mount when possible.

L2 Intermediate

7.2. Deriving state during render

  • Don't sync state with props via effect when you can compute during render:
// Avoid
function FullName({ first, last }) {
  const [full, setFull] = useState("");
  useEffect(() => {
    setFull(`${first} ${last}`);
  }, [first, last]);
}

// Prefer
function FullName({ first, last }) {
  const full = `${first} ${last}`;
  return <span>{full}</span>;
}
  • Use useMemo only when the computation is expensive (File 12).

7.3. User events belong in handlers

// Avoid — effect on every query change to POST analytics
useEffect(() => {
  trackSearch(query);
}, [query]);

// Prefer — track when user submits
function onSubmit(e) {
  e.preventDefault();
  trackSearch(query);
  runSearch(query);
}
  • Effects are for syncing with external systems, not for chaining event → state → event.

7.4. Resetting state when a prop changes

// Avoid extra effect + flash
useEffect(() => {
  setSelectedItem(null);
}, [userId]);

// Prefer — key on child resets state when userId changes
<UserItems key={userId} userId={userId} />
  • Or pass userId and derive selection during render.

8. Strict Mode and development behavior

L2

L2 Intermediate

  • In React Strict Mode (dev only), React mounts → unmounts → remounts components immediately upon first load:
useEffect(() => {
  console.log("effect setup");
  return () => console.log("cleanup teardown");
}, []);

// In Development (Strict Mode):
// 1. "effect setup"     (Initial mount)
// 2. "cleanup teardown" (Immediate simulated unmount)
// 3. "effect setup"     (Remount with preserved state)

// In Production:
// 1. "effect setup"     (Runs exactly once)
  • Why React does this:

    React is preparing codebases for concurrent features where React unmounts and remounts views to preserve state (such as tab switching with Offscreen component caching, or instant back/forward navigation). If an effect breaks when unmounted and remounted, it is guaranteed to leak memory or cause duplicate data bugs in production.

  • ❌ The Ref Anti-Pattern (Don't Do This): 
    // Anti-pattern: trying to force the effect to run only once in dev
const didRun = useRef(false);
useEffect(() => {
  if (didRun.current) return;
  didRun.current = true;
  connectSocket(); // Leaks! Cleanup will never disconnect the second instance!
}, []);
  • ✅ The Correct Solution (Symmetrical Cleanup):

    Every effect setup must have a corresponding teardown. If your setup creates a connection, cleanup must close it. If your setup adds a listener, cleanup must remove it.

9. Multiple effects

L1

L1 Fundamental

  • Split unrelated side effects into separate useEffect calls:
function Dashboard({ userId }) {
  useEffect(() => {
    document.title = "Dashboard";
  }, []);

  useEffect(() => {
    const conn = connectAnalytics(userId);
    return () => conn.disconnect();
  }, [userId]);

  useEffect(() => {
    // fetch widgets...
  }, [userId]);

  return <div>...</div>;
}
  • Each effect has its own deps and cleanup — easier to reason about than one large effect.

10. Putting it together

L1

L1 Fundamental

10.1. Online status hook (preview of File 07)

function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(
    typeof navigator !== "undefined" ? navigator.onLine : true
  );

  useEffect(() => {
    function goOnline() { setIsOnline(true); }
    function goOffline() { setIsOnline(false); }

    window.addEventListener("online", goOnline);
    window.addEventListener("offline", goOffline);

    return () => {
      window.removeEventListener("online", goOnline);
      window.removeEventListener("offline", goOffline);
    };
  }, []);

  return isOnline;
}

function StatusBar() {
  const online = useOnlineStatus();
  return <span>{online ? "Online" : "Offline"}</span>;
}
  • Custom hooks are just functions that call useEffect — File 07 formalizes the pattern.

10.2. Debounced search (effect + cleanup)

function SearchUsers({ onResults }) {
  const [query, setQuery] = useState("");

  useEffect(() => {
    if (!query.trim()) {
      onResults([]);
      return;
    }

    const id = setTimeout(async () => {
      const res = await fetch(`/api/users?q=${encodeURIComponent(query)}`);
      const data = await res.json();
      onResults(data);
    }, 300);

    return () => clearTimeout(id);
  }, [query, onResults]);

  return (
    <input
      value={query}
      onChange={(e) => setQuery(e.target.value)}
      placeholder="Search users"
    />
  );
}
  • Debounce cleanup cancels the pending fetch when query changes before 300ms.

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a side effect in React? ▾ Answer

Anything that touches outside the render result — network, DOM APIs, timers, subscriptions, storage. Run these in useEffect, not during render.

L1 Fundamental

C.2. What does an empty dependency array [] mean? ▾ Answer

Run the effect once after mount (and run cleanup on unmount). In Strict Mode dev, mount/cleanup/mount runs once extra to test cleanup.

C.3. Can I fetch data in useEffect? ▾ Answer

Yes for client-only loading. Use abort/cancel on cleanup to avoid races. For real apps, prefer TanStack Query or route loaders (Files 09–10).

C.4. What should I read next? ▾ Answer

File 06 (forms — controlled inputs and submit), File 07 (custom hooks, useRef), File 10 (data fetching patterns).

L2 Intermediate

C.5. When does useEffect run? ▾ Answer

After React commits the update to the DOM and the browser paints. On mount and after re-renders where dependencies changed (if you pass a dependency array).

C.6. What happens if I omit the dependency array? ▾ Answer

The effect runs after every render. Rarely correct — almost always specify [] or [deps].

C.7. Why do I need a cleanup function? ▾ Answer

To undo subscriptions, listeners, timers, and in-flight requests when deps change or the component unmounts. Prevents leaks and stale updates.

C.8. How do I fix stale closure bugs in effects? ▾ Answer

Add missing values to the dependency array, use functional state updates, or store latest values in useRef (File 07). Follow exhaustive-deps lint warnings.

C.9. Should I use useEffect to update state when props change? ▾ Answer

Usually no — compute derived values during render, reset with key, or adjust design. Effects that only mirror props into state often cause extra renders.

C.10. Why does my effect run twice in development? ▾ Answer

Strict Mode intentionally double-invokes effects in dev to verify cleanup. Production runs once per dependency change.

P.1. Warm-up

  1. useEffect that logs mount once ([]). ▾ Solution 
    import { useEffect } from "react";

function MountLogger() {
  useEffect(() => {
    console.log("Component mounted into the DOM!");
    // Empty dependency array [] means run once after initial mount
  }, []);

  return <div>Mount Logger Active</div>;
}

export default MountLogger;
  2. Effect that runs when a query string state changes. ▾ Solution 
    import { useEffect, useState } from "react";

function SearchWatcher({ query }) {
  useEffect(() => {
    console.log(`Query changed to: "${query}". Initiating search debounce...`);
  }, [query]); // Runs on mount and whenever 'query' changes

  return <div>Searching for: {query}</div>;
}

export default SearchWatcher;
  3. setInterval in effect with clearInterval cleanup. ▾ Solution 
    import { useState, useEffect } from "react";

function TickingTimer() {
  const [seconds, setSeconds] = useState(0);

  useEffect(() => {
    const timerId = setInterval(() => {
      setSeconds((prev) => prev + 1);
    }, 1000);

    // Cleanup function runs when component unmounts or before re-running effect
    return () => {
      clearInterval(timerId);
      console.log("Timer interval cleaned up!");
    };
  }, []);

  return <p>Elapsed seconds: {seconds}</p>;
}

export default TickingTimer;

P.2. Core tasks

  1. fetch on id change — AbortController or ignore stale responses. ▾ Solution 
    import { useState, useEffect } from "react";

function UserViewer({ userId }) {
  const [user, setUser] = useState(null);

  useEffect(() => {
    const controller = new AbortController();

    async function loadUser() {
      try {
        const res = await fetch(`https://jsonplaceholder.typicode.com/users/${userId}`, {
          signal: controller.signal
        });
        const data = await res.json();
        setUser(data);
      } catch (err) {
        if (err.name !== "AbortError") {
          console.error("Fetch failed:", err);
        }
      }
    }

    loadUser();

    return () => {
      controller.abort(); // Cancel in-flight request when userId changes or unmounts
    };
  }, [userId]);

  return <div>{user ? user.name : "Loading..."}</div>;
}

export default UserViewer;
  2. sync document.title — from state. ▾ Solution 
    import { useEffect } from "react";

function DocumentTitleSync({ title }) {
  useEffect(() => {
    const previousTitle = document.title;
    document.title = `${title} | My React App`;

    return () => {
      document.title = previousTitle; // Restore title on unmount
    };
  }, [title]);

  return null;
}

export default DocumentTitleSync;
  3. event listener — window resize with remove on cleanup. ▾ Solution 
    import { useState, useEffect } from "react";

function WindowDimensions() {
  const [width, setWidth] = useState(window.innerWidth);

  useEffect(() => {
    const handleResize = () => setWidth(window.innerWidth);
    window.addEventListener("resize", handleResize);

    return () => {
      window.removeEventListener("resize", handleResize);
    };
  }, []);

  return <p>Window width: {width}px</p>;
}

export default WindowDimensions;

Strict Mode Double Invocation:

P.3. Challenge

  1. Identify an effect that should be an event handler instead; refactor. ▾ Solution 
    // Anti-pattern: Using useEffect for user event reactions
// WRONG:
// const [clicked, setClicked] = useState(false);
// useEffect(() => { if (clicked) buyItem(); }, [clicked]);

// CORRECT: Handle directly in the event handler!
function BuyButton({ productId }) {
  const handleBuy = async () => {
    console.log("Submitting purchase for product:", productId);
    await api.checkout(productId);
  };

  return <button onClick={handleBuy}>Buy Now</button>;
}

export default BuyButton;
  2. Multi-effect component: one for title, one for fetch — keep them separate. ▾ Solution 
    import { useState, useEffect } from "react";

function MultiEffectDemo({ count, category }) {
  // Separate Concern 1: Document title synchronization
  useEffect(() => {
    document.title = `Count: ${count}`;
  }, [count]);

  // Separate Concern 2: Analytics logging on category switch
  useEffect(() => {
    analytics.logPageView(category);
  }, [category]);

  return <div>Multi-effect Component Active</div>;
}

export default MultiEffectDemo;
