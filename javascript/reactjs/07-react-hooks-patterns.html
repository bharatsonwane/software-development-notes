1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Hooks are functions that let function components use state, effects, refs, and more. This chapter covers rules you must follow, custom hooks for reusable logic, useRef for values and DOM access, and useId for stable ids.
  • Builds on useState (File 03), useEffect (File 05), and forms (File 06). File 08 adds Context and useReducer.
  • Default rule today: only call hooks at the top level of React functions; prefix reusable hook logic with use; use useRef for mutable values that should not trigger re-renders; use useId for accessibility ids in SSR-safe apps.

1.2. Default rules and how to study this file

  • Default rule today: prefer function components and hooks; keep components small; colocate state with the UI that needs it.
  • After reading sections 2–8, complete P. Practical Assignment in 07-practice.jsx before File 08. Review C. Common questions.

2. Rules of Hooks

L1

L1 Fundamental

2.1. Only call hooks at the top level

  • Do not call hooks inside loops, conditions, or nested functions:
// Wrong
function Bad({ show }) {
  if (show) {
    const [x, setX] = useState(0);  // breaks rules
  }
}

// Right
function Good({ show }) {
  const [x, setX] = useState(0);
  if (!show) return null;
  return <div>{x}</div>;
}
  • React relies on call order being identical every render to match state to the right hook.

2.2. Only call hooks from React functions

  • Call hooks from:
  • Function components
  • Custom hooks (functions whose names start with use)
  • Do not call hooks from regular JS functions, class components, or event handlers.

L1 Fundamental

2.3. ESLint enforcement

  • eslint-plugin-react-hooks with rules rules-of-hooks and exhaustive-deps catches most mistakes. Enable them in every React project.

2.4. Hook Internals & The Fiber memoizedState Linked List

  • How React Tracks Hooks Without Names:

    React hooks do not accept key names. Instead, React attaches a singly linked list of hook objects to the currently rendering component's Fiber node at fiber.memoizedState:

    fiberNode.memoizedState = {
  memoizedState: 0,            // First hook: useState(0)
  queue: { pending: null },
  next: {
    memoizedState: "dark",     // Second hook: useState("dark")
    queue: { pending: null },
    next: {
      memoizedState: { ... },  // Third hook: useEffect(...)
      next: null
    }
  }
};
  • Why Calling Hooks Conditionally Destroys State:
    1. On mount: Hook 1 = useState(0), Hook 2 = useState("dark"), Hook 3 = useEffect.
    2. On update: If Hook 1 is skipped inside an if (condition), Hook 2 executes first. React looks at the first node in the linked list and gives Hook 2 the value 0 instead of "dark"!
    3. Every subsequent hook is shifted by one position, corrupting variables and crashing the application.

3. Custom hooks

L1 L2

L1 Fundamental

3.1. What is a custom hook?

  • A function that calls other hooks and returns state, handlers, or refs for components to use:
function useCounter(initial = 0) {
  const [count, setCount] = useState(initial);
  const increment = () => setCount((c) => c + 1);
  const decrement = () => setCount((c) => c - 1);
  const reset = () => setCount(initial);
  return { count, increment, decrement, reset };
}

function App() {
  const { count, increment } = useCounter(0);
  return <button onClick={increment}>{count}</button>;
}
  • Each component calling useCounter gets its own independent state.

L1 Fundamental

3.2. Naming convention

  • Name must start with use so React (and linters) know it may call hooks:
function useLocalStorage(key, initial) { ... }
function useMediaQuery(query) { ... }

3.3. Extract when logic repeats

  • Extract a custom hook when:
  • Same state + effect + handlers appear in multiple components
  • A component grows too large and one concern can be isolated
  • You want to test logic separately from UI
  • Keep hooks focused — one responsibility per hook when possible.

3.4. Custom hook wrapping useEffect

  • From File 05 — online status:
function useOnlineStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    const on = () => setIsOnline(true);
    const off = () => setIsOnline(false);
    window.addEventListener("online", on);
    window.addEventListener("offline", off);
    return () => {
      window.removeEventListener("online", on);
      window.removeEventListener("offline", off);
    };
  }, []);

  return isOnline;
}

L2 Intermediate

3.5. Returning stable APIs

  • Return an object or tuple — document whether functions are stable. For callbacks passed to effects, wrap in useCallback when needed (File 12).

4. useRef

L1 L2

L1 Fundamental

4.1. Ref object persists across renders

const ref = useRef(initialValue);
// ref.current — read/write without re-render
  • Updating ref.current does not trigger a re-render (unlike setState).

L1 Fundamental

4.2. DOM refs

  • Attach to JSX to access the underlying DOM node:
function FocusInput() {
  const inputRef = useRef(null);

  function focus() {
    inputRef.current?.focus();
  }

  return (
    <>
      <input ref={inputRef} />
      <button type="button" onClick={focus}>Focus</button>
    </>
  );
}
  • Use for: focus, scroll, measuring size, integrating non-React libraries.

4.3. Mutable instance values

  • Store timers, previous props, or any value that should survive renders without causing them:
function Timer() {
  const intervalRef = useRef(null);

  useEffect(() => {
    intervalRef.current = setInterval(tick, 1000);
    return () => clearInterval(intervalRef.current);
  }, []);
}

4.4. Storing previous value

function usePrevious(value) {
  const ref = useRef();
  useEffect(() => {
    ref.current = value;
  }, [value]);
  return ref.current;
}

L2 Intermediate

4.5. Latest callback without re-subscribing

function Chat({ onMessage }) {
  const onMessageRef = useRef(onMessage);
  onMessageRef.current = onMessage;

  useEffect(() => {
    const sub = subscribe((msg) => onMessageRef.current(msg));
    return () => sub.unsubscribe();
  }, []);  // empty deps — always calls latest onMessage
}
  • Pattern: keep ref synced each render; effect reads ref.current.

4.6. ref callback (advanced)

<div ref={(node) => { /* node mounted or unmounted */ }} />
  • Use when you need setup/teardown per DOM node. Less common than object ref.

4.7. useImperativeHandle & React 19 Ref as a Prop

  • Custom Imperative Handle: Instead of exposing the entire raw DOM element to a parent, useImperativeHandle restricts and customizes the exposed methods:
import { useImperativeHandle, useRef } from "react";

// In React 19: ref is a standard prop (no forwardRef needed!)
// In React 18: wrap component in forwardRef((props, ref) => ...)
function CustomInput({ ref, placeholder }) {
  const realInputRef = useRef(null);

  useImperativeHandle(ref, () => ({
    focusInput() {
      realInputRef.current?.focus();
    },
    resetInput() {
      if (realInputRef.current) realInputRef.current.value = "";
    }
  }), []);

  return <input ref={realInputRef} placeholder={placeholder} />;
}

// Parent usage:
function Parent() {
  const inputRef = useRef(null);
  return (
    <>
      <CustomInput ref={inputRef} placeholder="Search..." />
      <button onClick={() => inputRef.current.focusInput()}>Focus</button>
      <button onClick={() => inputRef.current.resetInput()}>Clear</button>
    </>
  );
}

5. useId

L1 L2

L1 Fundamental

5.1. Stable unique ids for accessibility

  • Link labels, inputs, and error messages with matching id / htmlFor:
function EmailField({ label, error }) {
  const id = useId();
  const errorId = `${id}-error`;

  return (
    <div>
      <label htmlFor={id}>{label}</label>
      <input
        id={id}
        aria-describedby={error ? errorId : undefined}
        aria-invalid={!!error}
      />
      {error && <p id={errorId} role="alert">{error}</p>}
    </div>
  );
}

L2 Intermediate

5.2. SSR, Hydration, and the useId Tree Path Algorithm

  • Why Global Incremental Counters Fail in SSR:

    If you use a simple module variable let id = 0; id++, multiple incoming server requests interleave counter increments. When the client hydrates the page, components receive mismatched IDs, throwing severe hydration errors and breaking input accessibility associations.

  • The useId Tree Path Algorithm:

    Instead of a global integer counter, React generates a base-32 string representation of the component's exact position in the component tree hierarchy (e.g. :r0:, :r1:, :r2:). Because both the server HTML generator and the client hydrator traverse the Fiber tree in the exact same depth-first order, the generated IDs are guaranteed to match identically with zero network coordination.

5.3. Do not use useId for list keys

  • Keys in lists need stable data ids (item.id), not useId() — useId is per component instance, not per list item logic.

6. Composing hooks

L1

L1 Fundamental

6.1. Hooks can call hooks

function useUser(userId) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    let cancelled = false;
    fetch(`/api/users/${userId}`)
      .then((r) => r.json())
      .then((data) => { if (!cancelled) setUser(data); })
      .finally(() => { if (!cancelled) setLoading(false); });
    return () => { cancelled = true; };
  }, [userId]);

  return { user, loading };
}
  • File 10 covers server-state libraries that replace hand-rolled fetch hooks.

6.2. Split hooks by concern

function ProfilePage({ userId }) {
  const { user, loading } = useUser(userId);
  const isOnline = useOnlineStatus();
  // render...
}
  • Smaller hooks compose into readable components.

8. Putting it together

L1

L1 Fundamental

8.1. useDebouncedValue

function useDebouncedValue(value, delayMs) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const id = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(id);
  }, [value, delayMs]);

  return debounced;
}

function Search() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebouncedValue(query, 300);

  useEffect(() => {
    if (debouncedQuery) search(debouncedQuery);
  }, [debouncedQuery]);

  return <input value={query} onChange={(e) => setQuery(e.target.value)} />;
}

C. Common questions

L1 L2

L1 Fundamental

C.1. What are the Rules of Hooks? ▾ Answer

Call hooks only at the top level of React functions, and only from components or custom hooks — never inside conditions, loops, or plain functions.

C.2. What is a custom hook? ▾ Answer

A reusable function named useSomething that calls hooks and returns state, effects, or handlers for components.

L1 Fundamental

C.3. What is useId for? ▾ Answer

Generate stable unique ids for label/input/aria-* links, especially with SSR.

C.4. Can custom hooks return JSX? ▾ Answer

They can, but usually return data and functions — keep UI in components. Exception: small shared layout hooks are rare.

C.5. How do I test custom hooks? ▾ Answer

@testing-library/react renderHook (File 13) — render hook in isolation and assert return values.

C.6. What should I read next? ▾ Answer

File 08 (Context, useReducer), File 12 (useCallback/useMemo with hooks), File 13 (testing hooks).

L2 Intermediate

C.7. Does each component share custom hook state? ▾ Answer

No. Each call site gets independent state, like useState.

C.8. When do I use useRef vs useState? ▾ Answer

useState when UI should update. useRef for DOM access or mutable values that should not re-render on change.

C.9. Can I use useId as a list key? ▾ Answer

No. Use stable ids from data (item.id).

C.10. Why store callbacks in refs? ▾ Answer

So effects with empty deps can call the latest callback without re-subscribing every render.

P.2. Core tasks

  1. useLocalStorage — sync state with localStorage. ▾ Solution 
    import { useState, useEffect } from "react";

function useLocalStorage(key, initialValue) {
  const [storedValue, setStoredValue] = useState(() => {
    try {
      const item = localStorage.getItem(key);
      return item ? JSON.parse(item) : initialValue;
    } catch {
      return initialValue;
    }
  });

  useEffect(() => {
    try {
      localStorage.setItem(key, JSON.stringify(storedValue));
    } catch (err) {
      console.error("localStorage error:", err);
    }
  }, [key, storedValue]);

  return [storedValue, setStoredValue];
}

export default useLocalStorage;
  2. usePrevious — ref pattern for previous value. ▾ Solution 
    import { useEffect, useRef } from "react";

function usePrevious(value) {
  const ref = useRef();

  useEffect(() => {
    ref.current = value;
  }, [value]); // Updates after render finishes

  return ref.current; // Returns value from previous render
}

export default usePrevious;
  3. compose — hook that uses two other hooks. ▾ Solution 
    import { useState } from "react";

function useCounterWithLimit(initial = 0, max = 10) {
  const [count, setCount] = useState(initial);

  const increment = () => {
    if (count < max) setCount((c) => c + 1);
  };

  const decrement = () => {
    if (count > 0) setCount((c) => c - 1);
  };

  return { count, increment, decrement, isAtMax: count === max };
}

export default useCounterWithLimit;

  1. useDebouncedValue hook; use it on a search input. ▾ Solution 
    import { useState, useEffect } from "react";

function useDebouncedValue(value, delayMs = 300) {
  const [debounced, setDebounced] = useState(value);

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(value), delayMs);
    return () => clearTimeout(timer);

// Search input integration:
function SearchBox() {
  const [query, setQuery] = useState("");
  const debouncedQuery = useDebouncedValue(query, 400);

  useEffect(() => {
    if (debouncedQuery) {
      console.log("Fetching API for:", debouncedQuery);
    }
  }, [debouncedQuery]);

  return <input value={query} onChange={(e) => setQuery(e.target.value)} placeholder="Type to search..." />;
}
  2. Document when useRef should not hold values that need re-render. ▾ Solution 
    /*
When NOT to use useRef:
- Do NOT use useRef for values that should trigger a component re-render when changed (e.g. counter display, form error messages, list items).
- Modifying ref.current is a silent mutation that React does not track.
- Use useState / useReducer for UI-affecting values; use useRef only for DOM references, timer IDs, or values outside the render cycle.
*/
