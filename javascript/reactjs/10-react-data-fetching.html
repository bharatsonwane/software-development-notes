1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Most apps load remote data. You need predictable loading, error, and success UI, plus rules for when to fetch, caching, and refetching. This chapter covers hand-rolled fetch with React state, then TanStack Query (React Query) as the modern default for server state.
  • Builds on useEffect (File 05), lists and conditionals (File 04), and routing loaders (File 09).
  • Default rule today: treat server state separately from UI state; use TanStack Query (or similar) for API data in production apps; hand-roll fetch + useState only for small cases or learning.

1.2. Default rules and how to study this file

  • Default rule today: prefer function components and hooks; keep components small; colocate state with the UI that needs it.
  • After reading sections 2–10, complete P. Practical Assignment in 10-practice.jsx before File 11. Review C. Common questions.

3. Fetch with useState and useEffect

L1 L2

L1 Fundamental

3.1. Basic pattern

function UserProfile({ userId }) {
  const [user, setUser] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    let cancelled = false;

    async function load() {
      setLoading(true);
      setError(null);
      try {
        const res = await fetch(`/api/users/${userId}`);
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        const data = await res.json();
        if (!cancelled) setUser(data);
      } catch (e) {
        if (!cancelled) setError(e);
      } finally {
        if (!cancelled) setLoading(false);
      }
    }

    load();
    return () => { cancelled = true; };
  }, [userId]);

  if (loading) return <p>Loading...</p>;
  if (error) return <p>Error: {error.message}</p>;
  return <div>{user.name}</div>;
}

3.2. Extract to custom hook

function useUser(userId) {
  const [state, setState] = useState({ data: null, loading: true, error: null });

  useEffect(() => {
    let cancelled = false;
    (async () => {
      try {
        const res = await fetch(`/api/users/${userId}`);
        if (!res.ok) throw new Error("Failed");
        const data = await res.json();
        if (!cancelled) setState({ data, loading: false, error: null });
      } catch (error) {
        if (!cancelled) setState({ data: null, loading: false, error });
      }
    })();
    return () => { cancelled = true; };
  }, [userId]);

  return state;
}
  • Good for learning; production apps benefit from a query library.

L2 Intermediate

3.3. Race conditions

  • When userId changes quickly, an older request may finish last. Fixes:
  • AbortController abort on cleanup (File 05)
  • cancelled flag (above)
  • Query library handles this automatically

5.2. useQuery

import { useQuery } from "@tanstack/react-query";

function UserProfile({ userId }) {
  const { data, isLoading, isError, error } = useQuery({
    queryKey: ["user", userId],
    queryFn: () =>
      fetch(`/api/users/${userId}`).then((r) => {
        if (!r.ok) throw new Error("Failed");
        return r.json();
      }),
  });

  if (isLoading) return <p>Loading...</p>;
  if (isError) return <p>Error: {error.message}</p>;
  return <div>{data.name}</div>;
}
  • queryKey — unique cache identity. queryFn — returns a Promise of data.

5.3. What TanStack Query gives you

5.4. useMutation

import { useMutation, useQueryClient } from "@tanstack/react-query";

function CreatePostForm() {
  const queryClient = useQueryClient();

  const mutation = useMutation({
    mutationFn: (newPost) =>
      fetch("/api/posts", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(newPost),
      }).then((r) => r.json()),
    onSuccess: () => {
      queryClient.invalidateQueries({ queryKey: ["posts"] });
    },
  });

  return (
    <button
      onClick={() => mutation.mutate({ title: "Hello" })}
      disabled={mutation.isPending}
    >
      {mutation.isPending ? "Saving..." : "Create"}
    </button>
  );
}
  • invalidateQueries — refetch lists after create/update.

5.5. React 19 use() Hook for Reading Promises

  • Reading Promises in Render: In React 19, the new use() API lets components read the value of a Promise directly during render without useEffect or local loading state:
import { use, Suspense } from "react";

// Fetch function returns a Promise
function fetchUserData(userId) {
  return fetch(`/api/users/${userId}`).then(res => res.json());
}

function UserCard({ userPromise }) {
  // Unwraps the promise directly during render!
  // Suspends execution until promise resolves:
  const user = use(userPromise);
  return <div><h3>{user.name}</h3><p>{user.email}</p></div>;
}

// Parent component provides Suspense boundary fallback:
function UserPage({ userId }) {
  const userPromise = fetchUserData(userId);

  return (
    <Suspense fallback={<p>Loading user profile...</p>}>
      <UserCard userPromise={userPromise} />
    </Suspense>
  );
}
  • Key Difference from Standard Hooks: Unlike other hooks, use() can be called conditionally inside if statements and loops!

6. Query keys and cache rules

L1 L2

L1 Fundamental

6.1. Key structure

["users"]                    // all users list
["users", userId]            // one user
["users", userId, "posts"]   // nested resource
  • Keys should include every variable the queryFn uses.

6.2. enabled option

  • Skip fetch until ready:
useQuery({
  queryKey: ["user", userId],
  queryFn: () => fetchUser(userId),
  enabled: !!userId,
});

L2 Intermediate

6.3. staleTime and gcTime

  • staleTime — how long data is "fresh" before background refetch
  • gcTime (formerly cacheTime) — how long unused cache stays in memory
  • Tune per resource — static config vs live dashboard differ.

6.4. Stale-While-Revalidate (SWR) Cache Lifecycle & Invalidation

  • The 3-Step SWR Lifecycle:
    1. Serve Stale Cache: If cached data exists for the query key, TanStack Query returns it synchronously from memory. The component renders instantly with zero loading spinner (isPending: false, isFetching: true).
    2. Background Revalidation: An asynchronous fetch is dispatched in the background to verify the data against the server.
    3. Silent Reconciliation: When the response arrives, if the data has changed, the cache is updated and the component quietly re-renders with the fresh data.
  • Invalidation Strategies:
    • Active query invalidation: queryClient.invalidateQueries({ queryKey: ['todos'] }) marks queries as stale and immediately refetches any queries currently rendered on the screen.
    • Exact key matching: Pass { exact: true } to prevent broad prefix matching (e.g. invalidating only ['todos'] without invalidating ['todos', 'detail', id]).

10. Putting it together

L1

L1 Fundamental

10.1. Products list + detail

function ProductList() {
  const { data: products, isLoading, error } = useQuery({
    queryKey: ["products"],
    queryFn: fetchProducts,
  });

  if (isLoading) return <p>Loading products...</p>;
  if (error) return <p>Failed to load products.</p>;

  return (
    <ul>
      {products.map((p) => (
        <li key={p.id}>
          <Link to={`/products/${p.id}`}>{p.name}</Link>
        </li>
      ))}
    </ul>
  );
}

function ProductDetail({ id }) {
  const { data: product, isLoading, error } = useQuery({
    queryKey: ["products", id],
    queryFn: () => fetchProduct(id),
  });

  if (isLoading) return <p>Loading...</p>;
  if (error) return <p>Not found.</p>;
  return <h1>{product.name}</h1>;
}

C. Common questions

L1 L2

L1 Fundamental

C.1. Where should I fetch — useEffect or event handler? ▾ Answer

Load data — useEffect, route loader, or useQuery. Mutations — event handlers / useMutation, not effect on mount.

C.2. What is server state? ▾ Answer

Data that lives on the server and you cache on the client — users, lists, permissions. Different from UI toggles and form drafts.

C.3. Why TanStack Query over raw fetch? ▾ Answer

Caching, deduping, retries, background refresh, and less boilerplate for loading/error.

C.4. What is a query key? ▾ Answer

A serializable array identifying a query in the cache — must include all variables (userId, filters).

C.5. How do I refetch after a mutation? ▾ Answer

queryClient.invalidateQueries({ queryKey: [...] }) or update cache directly with setQueryData.

C.6. What should I read next? ▾ Answer

File 11 (global client state), File 12 (Suspense + queries), File 09 (loaders).

L2 Intermediate

C.7. How do I avoid fetch races? ▾ Answer

AbortController, cancelled flag, or use a library that cancels outdated queries by key.

C.8. isLoading vs isFetching? ▾ Answer

isLoading — no cached data yet and fetching. isFetching — any in-flight request (including background).

C.9. Should I store API data in useContext? ▾ Answer

Usually no — use TanStack Query. Context fits auth session, theme, not full API cache.

C.10. Loader vs useQuery? ▾ Answer

Loader prefetches before route render. useQuery fetches when component mounts. Combine with shared queryKey.

P.1. Warm-up

  1. Fetch a public JSON API in useEffect; show loading/error/data. ▾ Solution 
    import { useState, useEffect } from "react";

function PublicDataFetcher() {
  const [data, setData] = useState(null);
  const [loading, setLoading] = useState(true);
  const [error, setError] = useState(null);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/posts/1")
      .then((res) => {
        if (!res.ok) throw new Error("HTTP error " + res.status);
        return res.json();
      })
      .then((json) => setData(json))
      .catch((err) => setError(err.message))
      .finally(() => setLoading(false));
  }, []);

  if (loading) return <p>Loading data...</p>;
  if (error) return <p className="error">Error: {error}</p>;
  return <div><h3>{data.title}</h3><p>{data.body}</p></div>;
}

export default PublicDataFetcher;
  2. Button that refetches. ▾ Solution 
    import { useState, useEffect } from "react";

function RefetchableComponent() {
  const [count, setCount] = useState(0);
  const [data, setData] = useState(null);

  useEffect(() => {
    fetch("https://jsonplaceholder.typicode.com/todos/1")
      .then((r) => r.json())
      .then((d) => setData(d));
  }, [count]); // Refetches when count changes

  return (
    <div>
      <p>Data: {data ? data.title : "Loading..."}</p>
      <button onClick={() => setCount((c) => c + 1)}>Refetch Data</button>
    </div>
  );
}

export default RefetchableComponent;

P.2. Core tasks

  1. stale response — ignore outdated fetch when id changes. ▾ Solution 
    import { useState, useEffect } from "react";

function PostViewer({ postId }) {
  const [post, setPost] = useState(null);

  useEffect(() => {
    let isCurrent = true; // Prevents race condition / stale response

    fetch(`https://jsonplaceholder.typicode.com/posts/${postId}`)
      .then((r) => r.json())
      .then((data) => {
        if (isCurrent) setPost(data);
      });

    return () => {
      isCurrent = false; // Discards response if postId changed before request returned
    };
  }, [postId]);

  return <div>{post ? post.title : "Loading..."}</div>;
}

export default PostViewer;
