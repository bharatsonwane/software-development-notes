1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Forms are where users enter data. In React, the usual pattern is controlled components: input value comes from state, and onChange updates that state. On submit, you validate, then send data to an API or parent handler.
  • Builds on state and events (File 03). File 05 covers side effects if you sync form data externally; File 10 covers submitting to a server.
  • Default rule today: control inputs with value + onChange (or checked for checkboxes); handle onSubmit on <form> and call preventDefault(); validate before submit and show inline errors near fields.

1.2. Default rules and how to study this file

  • Default rule today: prefer function components and hooks; keep components small; colocate state with the UI that needs it.
  • After reading sections 2–9, complete P. Practical Assignment in 06-practice.jsx before File 07. Review C. Common questions.

2. Controlled vs uncontrolled inputs

L1

L1 Fundamental

2.1. Controlled input

  • React state is the single source of truth:
function NameField() {
  const [name, setName] = useState("");

  return (
    <input
      value={name}
      onChange={(e) => setName(e.target.value)}
    />
  );
}
  • Every keystroke updates state → React re-renders → input shows new value.

2.2. Uncontrolled input

  • The DOM holds the value; read it with a ref when needed (File 07):
function NameField() {
  const inputRef = useRef(null);

  function handleSubmit(e) {
    e.preventDefault();
    console.log(inputRef.current.value);
  }

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="" />
      <button type="submit">Save</button>
    </form>
  );
}
  • Use uncontrolled inputs sparingly — file uploads, integrating non-React widgets, or simple one-off reads.

L1 Fundamental

2.3. Why controlled is default

ControlledUncontrolled
Instant validationValidate on submit only
Reset/clear via stateReset via DOM APIs
Same data in UI and JSMust read ref to get value
Works with React one-way flow (File 03)Escapes React model

3. Text inputs and textareas

L1

L1 Fundamental

3.1. Single-line text

function SignUpForm() {
  const [email, setEmail] = useState("");

  return (
    <label>
      Email
      <input
        type="email"
        name="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
        autoComplete="email"
      />
    </label>
  );
}
  • Always pair value with onChange. A value without onChange makes the input read-only.

3.2. Textarea

  • Same pattern — use value / onChange, not children for the current value:
<textarea
  value={bio}
  onChange={(e) => setBio(e.target.value)}
  rows={4}
/>

3.3. Multiple fields — object state or separate state

  • Separate state — clear for small forms:
const [firstName, setFirstName] = useState("");
const [lastName, setLastName] = useState("");
  • Object state — scales to many fields:
const [form, setForm] = useState({ firstName: "", lastName: "", email: "" });

function updateField(field) {
  return (e) => {
    setForm((prev) => ({ ...prev, [field]: e.target.value }));
  };
}

<input value={form.firstName} onChange={updateField("firstName")} />
<input value={form.lastName} onChange={updateField("lastName")} />
  • Immutable update — spread prev, change one key (File 03).

  • Use checked, not value:
const [agreed, setAgreed] = useState(false);

4.2. Checkbox group (array)

const [selected, setSelected] = useState([]);

function toggle(id) {
  setSelected((prev) =>
    prev.includes(id) ? prev.filter((x) => x !== id) : [...prev, id]
  );
}

{options.map((opt) => (
  <label key={opt.id}>
    <input
      type="checkbox"
      checked={selected.includes(opt.id)}
      onChange={() => toggle(opt.id)}
    />
    {opt.label}
  </label>
))}

4.3. Radio buttons

  • Group by name; state holds the selected value:
const [size, setSize] = useState("medium");

<label>

    type="radio"

    value="small"
    checked={size === "small"}
    onChange={(e) => setSize(e.target.value)}

5. Form submit

L1

L1 Fundamental

5.1. onSubmit on the form

  • Prefer form onSubmit over button onClick — handles Enter key and accessibility:
function LoginForm() {
  const [email, setEmail] = useState("");
  const [password, setPassword] = useState("");

  function handleSubmit(e) {
    e.preventDefault();  // stop full page reload
    console.log({ email, password });
    // call API, lift to parent, etc.
  }

  return (
    <form onSubmit={handleSubmit}>
      <input
        type="email"
        value={email}
        onChange={(e) => setEmail(e.target.value)}
      />
      <input
        type="password"
        value={password}
        onChange={(e) => setPassword(e.target.value)}
      />
      <button type="submit">Log in</button>
    </form>
  );
}

5.2. Button types

typeBehavior
submitSubmits nearest form (default inside <form>)
buttonNo submit — use for custom actions
resetResets form fields to initial values
  • Use type="button" on buttons that should not submit (e.g. "Cancel", "Add row").

5.3. Disabled submit while invalid or loading

const canSubmit = email.includes("@") && password.length >= 8 && !loading;

<button type="submit" disabled={!canSubmit}>
  {loading ? "Saving..." : "Save"}
</button>

5.4. React 19 Form Actions (<form action={action}>)

  • Native Action Functions: In React 19, the HTML <form action> prop accepts a JavaScript function directly (either synchronous or asynchronous):
async function updateProfile(formData) {
  'use server'; // If using Next.js / React Server Actions
  const name = formData.get("name");
  const email = formData.get("email");
  await saveUserToDatabase({ name, email });
}

function ProfileForm() {
  return (
    <form action={updateProfile}>
      <input name="name" defaultValue="Bharat" />
      <input name="email" defaultValue="bharat@example.com" />
      <button type="submit">Update</button>
    </form>
  );
}
  • Key Advantages:
    1. No manual e.preventDefault() needed.
    2. Receives native browser FormData directly.
    3. Automatically resets uncontrolled inputs upon successful submission.

5.5. React 19 Form Hooks: useActionState & useFormStatus

  • useActionState: Manages state based on the result of a form action (replaces manual isLoading, error state management):
import { useActionState } from "react";

async function loginAction(previousState, formData) {
  const username = formData.get("username");
  const res = await apiLogin(username);
  if (!res.ok) return { error: "Invalid credentials" };
  return { error: null, user: res.user };
}

function LoginForm() {
  const [state, formAction, isPending] = useActionState(loginAction, { error: null });

  return (
    <form action={formAction}>
      <input name="username" />
      <SubmitButton />
      {isPending && <p>Logging in...</p>}
      {state?.error && <p className="error">{state.error}</p>}
    </form>
  );
}
  • useFormStatus: Reads parent form status from within child components without prop drilling:
import { useFormStatus } from "react-dom";

function SubmitButton() {
  const { pending } = useFormStatus();
  return (
    <button type="submit" disabled={pending}>
      {pending ? "Submitting..." : "Submit"}
    </button>
  );
}

5.6. Optimistic UI Updates with useOptimistic

  • Instant Feedback: Shows the expected result immediately before the server response finishes:
import { useOptimistic, useState } from "react";

function TodoList({ initialTodos }) {
  const [todos, setTodos] = useState(initialTodos);
  const [optimisticTodos, setOptimisticTodos] = useOptimistic(
    todos,
    (state, newTodo) => [...state, { text: newTodo, sending: true }]
  );

  async function handleAdd(formData) {
    const text = formData.get("todo");
    setOptimisticTodos(text); // UI updates instantly!
    const saved = await apiAddTodo(text);
    setTodos(prev => [...prev, saved]); // Server state updates
  }

  return (
    <form action={handleAdd}>
      <ul>
        {optimisticTodos.map((t, i) => (
          <li key={i} style={{ opacity: t.sending ? 0.5 : 1 }}>
            {t.text} {t.sending && "(Sending...)"}
          </li>
        ))}
      </ul>
      <input name="todo" />
      <button type="submit">Add</button>
    </form>
  );
}

6. Validation basics

L1 L2

L1 Fundamental

6.1. When to validate

TimingUse for
On submitSimple forms, fewer distractions
On blurField-level feedback after user leaves input
On changeLive hints (debounce expensive checks — File 05)
  • Start with validate on submit; add blur/change when UX needs it.

6.2. Client-side validation example

function SignUpForm() {
  const [form, setForm] = useState({ email: "", password: "" });
  const [errors, setErrors] = useState({});

  function validate(values) {
    const next = {};
    if (!values.email.includes("@")) next.email = "Enter a valid email.";
    if (values.password.length < 8) next.password = "At least 8 characters.";
    return next;
  }

  function handleSubmit(e) {
    e.preventDefault();
    const nextErrors = validate(form);
    setErrors(nextErrors);
    if (Object.keys(nextErrors).length > 0) return;

    submitSignUp(form);
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <div>
        <input
          value={form.email}
          onChange={(e) => setForm({ ...form, email: e.target.value })}
          aria-invalid={!!errors.email}
          aria-describedby={errors.email ? "email-error" : undefined}
        />
        {errors.email && <p id="email-error" role="alert">{errors.email}</p>}
      </div>
      {/* password field similarly */}
      <button type="submit">Sign up</button>
    </form>
  );
}
  • noValidate — disable browser popup validation when you show custom errors (still use semantic type="email" etc.).

6.3. Libraries

  • For large forms: React Hook Form, Formik, or Zod + resolver. Same ideas — register fields, validate schema, handle submit.

L2 Intermediate

6.4. Server errors

  • After failed API response, map server messages to fields or a form-level banner:
try {
  await signUp(form);
} catch (err) {
  if (err.fieldErrors) setErrors(err.fieldErrors);
  else setErrors({ form: err.message });
}

9. Putting it together

L1

L1 Fundamental

9.1. Contact form

function ContactForm({ onSend }) {
  const [form, setForm] = useState({ name: "", message: "" });
  const [errors, setErrors] = useState({});
  const [status, setStatus] = useState("idle"); // idle | sending | sent | error

  function validate(v) {
    const e = {};
    if (!v.name.trim()) e.name = "Name is required.";
    if (!v.message.trim()) e.message = "Message is required.";
    return e;
  }

  async function handleSubmit(e) {
    e.preventDefault();
    const e2 = validate(form);
    setErrors(e2);
    if (Object.keys(e2).length) return;

    setStatus("sending");
    try {
      await onSend(form);
      setForm({ name: "", message: "" });
      setStatus("sent");
    } catch {
      setStatus("error");
    }
  }

  return (
    <form onSubmit={handleSubmit} noValidate>
      <label>
        Name
        <input
          value={form.name}
          onChange={(ev) => setForm({ ...form, name: ev.target.value })}
        />
      </label>
      {errors.name && <p role="alert">{errors.name}</p>}

      <label>
        Message
        <textarea
          value={form.message}
          onChange={(ev) => setForm({ ...form, message: ev.target.value })}
        />
      </label>
      {errors.message && <p role="alert">{errors.message}</p>}

      <button type="submit" disabled={status === "sending"}>
        {status === "sending" ? "Sending..." : "Send"}
      </button>
      {status === "sent" && <p>Message sent!</p>}
      {status === "error" && <p role="alert">Something went wrong.</p>}
    </form>
  );
}

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a controlled input? ▾ Answer

An input whose value (or checked) is driven by React state, updated via onChange. React owns the displayed value.

L1 Fundamental

C.2. Why must I call preventDefault on submit? ▾ Answer

Without it, the browser reloads the page on form submit — you lose SPA state and React's handler may not run as expected.

C.3. Checkbox: value or checked? ▾ Answer

Use checked={bool} and onChange with e.target.checked. value on checkboxes is the value submitted in native forms, not visibility state.

C.4. How do I handle many form fields? ▾ Answer

One object in state + helper like updateField("email"), or a form library. Keep updates immutable.

C.5. When should I validate? ▾ Answer

Start on submit. Add on blur or on change when users need earlier feedback. Always re-validate on submit.

C.6. Controlled vs uncontrolled — which default? ▾ Answer

Controlled for most React forms. Uncontrolled + ref for file inputs, some third-party widgets, or rare performance cases.

C.7. How do I disable browser validation popups? ▾ Answer

Add noValidate on <form> and implement your own error UI.

C.8. How do I reset a controlled form? ▾ Answer

Set state back to initial values, or remount with key.

C.9. What should I read next? ▾ Answer

File 07 (useRef, custom hooks), File 10 (submitting to APIs), File 06 patterns apply inside File 09 route forms.

L2 Intermediate

C.10. Can I use defaultValue with controlled inputs? ▾ Answer

No — pick one model. defaultValue is for uncontrolled; value is for controlled. Mixing causes confusion.

  2. multi-field — one state object; onChange by name. ▾ Solution 
    import { useState } from "react";

function MultiFieldForm() {
  const [form, setForm] = useState({ firstName: "", lastName: "", role: "user" });

  const handleChange = (e) => {
    const { name, value } = e.target;
    setForm((prev) => ({ ...prev, [name]: value }));
  };

  return (
    <div>
      <input name="firstName" value={form.firstName} onChange={handleChange} placeholder="First Name" />
      <input name="lastName" value={form.lastName} onChange={handleChange} placeholder="Last Name" />
      <pre>{JSON.stringify(form, null, 2)}</pre>
    </div>
  );
}

export default MultiFieldForm;
  3. validation — disable submit until email looks valid. ▾ Solution 
    import { useState } from "react";

function ValidatedRegistration() {
  const [email, setEmail] = useState("");

  return (
    <div>
      <input

        value={email}
        onChange={(e) => setEmail(e.target.value)}
        placeholder="Enter email"
      />
      <button disabled={!isValidEmail}>
        {isValidEmail ? "Register" : "Enter Valid Email"}
      </button>
    </div>
  );
}

export default ValidatedRegistration;

  1. Reset form to initials after successful submit. ▾ Solution 
    import { useState } from "react";

const INITIAL_STATE = { name: "", email: "" };

function FeedbackForm() {
  const [form, setForm] = useState(INITIAL_STATE);

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log("Sending data to API:", form);
    // Reset to initial clean state
    setForm(INITIAL_STATE);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input value={form.name} onChange={(e) => setForm({ ...form, name: e.target.value })} placeholder="Name" />
      <input value={form.email} onChange={(e) => setForm({ ...form, email: e.target.value })} placeholder="Email" />
      <button type="submit">Send</button>
    </form>
  );
}

export default FeedbackForm;
  2. Uncontrolled input with useRef + defaultValue; compare to controlled. ▾ Solution 
    import { useRef } from "react";

// Uncontrolled form using useRef & defaultValue
function UncontrolledForm() {
  const inputRef = useRef(null);

  const handleSubmit = (e) => {
    e.preventDefault();
    console.log("Read directly from DOM node:", inputRef.current.value);
  };

  return (
    <form onSubmit={handleSubmit}>
      <input ref={inputRef} defaultValue="Initial Text" />
      <button type="submit">Submit Uncontrolled</button>
    </form>
  );
}

// Comparison:
// Controlled: React state is the single source of truth; rerenders on keystroke; allows instant validation.
// Uncontrolled: DOM keeps internal state; read only when submitted via ref; fewer re-renders.
