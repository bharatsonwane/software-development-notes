1. Introduction

L1 Fundamental

1.1. Overview

  • Streams process data in chunks (download, upload, transform) without loading everything into memory. WebSocket is a full-duplex socket for low-latency messaging.

1.2. Default rules and how to study this file

  • Default rule today: use fetch + streaming body for large HTTP payloads; use WebSocket (or SSE) for live bidirectional updates. Async iteration: File 21.

L1 Fundamental

2.1. for await on bodies

const res = await fetch("/large.txt");
for await (const chunk of res.body) {
  // chunk is Uint8Array in browsers
}

2.2. TransformStream (pipe)

const upper = new TransformStream({
  transform(chunk, controller) {
    controller.enqueue(chunk.toUpperCase());
  },
});

const readable = new ReadableStream({
  start(controller) {
    controller.enqueue("hi");
    controller.close();
  },
});

const out = readable.pipeThrough(upper);
const reader = out.getReader();
console.log((await reader.read()).value); // "HI"

L2 Intermediate

2.3. Backpressure (idea)

  • If the consumer is slow, the stream signals the producer to slow down (via promise-based write / pull). Avoid buffering unbounded chunks in memory.
  • Node has its own stream API (stream.Readable); modern Node also supports Web Streams.

3. WebSocket

L1 L2

L1 Fundamental

  • Persistent connection after HTTP upgrade. Both sides can send anytime.
const ws = new WebSocket("wss://example.com/socket");

ws.addEventListener("open", () => {
  ws.send(JSON.stringify({ type: "hello" }));
});

ws.addEventListener("message", (e) => {
  console.log(e.data); // string or Blob/ArrayBuffer if binaryType set
});

ws.addEventListener("error", console.error);
ws.addEventListener("close", (e) => {
  console.log(e.code, e.reason);
});

L1 Fundamental

3.1. Ready states and binary

ws.readyState; // 0 CONNECTING, 1 OPEN, 2 CLOSING, 3 CLOSED
ws.binaryType = "arraybuffer";
ws.send(new Uint8Array([1, 2, 3]));
ws.close(1000, "done");

L2 Intermediate

3.2. Practical notes

  • Reconnection, heartbeats, and auth tokens are application-level — not built into the API.
  • Prefer wss:// in production. For one-way server push, SSE (EventSource) is simpler.
  • Compare with HTTP polling / long-poll — WebSocket wins for chat, collaborative edits, live feeds.

C. Common questions

L1 L2

L1 Fundamental

C.1. When streams vs reading full body?

  • A: Stream when the payload is large or you want progressive UI. Use res.json() / res.text() for small complete responses (File 24).

L2 Intermediate

C.2. WebSocket vs fetch?

  • A: fetch is request/response. WebSocket stays open for many messages both ways with lower overhead after connect.
