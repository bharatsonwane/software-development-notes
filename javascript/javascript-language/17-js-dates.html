L1 Fundamental

2.1. Date object

const now = new Date();
const specific = new Date("2026-06-25T10:00:00Z");
const fromParts = new Date(2026, 5, 25);  // month 0-indexed

now.getTime();           // timestamp ms since epoch
Date.now();              // same, static
now.toISOString();       // "2026-06-25T..."
now.toLocaleDateString();

L1 Fundamental

2.2. Timestamp and UTC

const d = new Date();
d.getUTCHours();
d.getUTCMinutes();
Date.UTC(2026, 5, 25);   // ms at UTC midnight
  • Store dates as ISO strings or epoch ms in JSON/APIs.

2.3. Intl API

new Intl.DateTimeFormat("en-IN", {
  dateStyle: "medium",
  timeStyle: "short",
}).format(new Date());

new Intl.NumberFormat("en-IN", {
  style: "currency",
  currency: "INR",
}).format(1234.5);  // "₹1,234.50"

2.3.1. More Intl formatters

  • Intl.Collator — locale-aware string compare (better than raw < for UI sort):
const collator = new Intl.Collator("de", { sensitivity: "base" });
["ä", "z", "a"].sort(collator.compare);
  • Intl.RelativeTimeFormat — “3 days ago”, “in 2 hours”:
new Intl.RelativeTimeFormat("en", { numeric: "auto" })
  .format(-1, "day");  // "yesterday"
  • Intl.Segmenter — split by grapheme / word / sentence (locale-aware):
const seg = new Intl.Segmenter("en", { granularity: "word" });
[...seg.segment("Hello, world!")].filter((s) => s.isWordLike).map((s) => s.segment);
// ["Hello", "world"]
  • Also useful: Intl.ListFormat, Intl.PluralRules, Intl.DisplayNames.

L2 Intermediate

2.4. Timezones

  • Date internally is UTC; display methods use local timezone. For robust timezone logic use Temporal (stage 4+) or libraries (date-fns, Luxon, Day.js).

C. Common questions

L1 L2

L1 Fundamental

C.1. How should I store dates in APIs?

  • A: ISO 8601 strings (toISOString()) or epoch milliseconds — avoid locale-specific strings.

C.2. What is Intl beyond DateTimeFormat?

  • A: Also NumberFormat, Collator (sort), RelativeTimeFormat, Segmenter, ListFormat, and more — prefer these over hand-rolled locale logic.
