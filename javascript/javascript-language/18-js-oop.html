1. Object-oriented concepts

L1 L2

L1 Fundamental

1.1. Encapsulation

  • Hide internal state — closures (File 17), # private fields (this file), or module scope (File 21).

1.2. Inheritance

  • Share behavior via extends (this file) or the prototype chain (File 19).

L2 Practical

1.3. Polymorphism

  • Same interface, different implementations — method override in subclasses:
class Shape { area() { throw new Error("implement"); } }
class Circle extends Shape {
  constructor(r) { super(); this.r = r; }
  area() { return Math.PI * this.r ** 2; }
}

1.4. Abstraction

  • Expose simple API, hide complexity — e.g. fetch wrapper, repository class over raw HTTP.

2. Classes

L2 L3 L4

L2 Practical

  • ES6 class syntax is clearer but compiles to prototype + constructor mechanics.

2.1. Class basics

class User {
  constructor(name, age) {
    this.name = name;
    this.age = age;
  }

  greet() {
    return `Hi, ${this.name}`;
  }

  isAdult() {
    return this.age >= 18;
  }
}

const u = new User("Bharat", 30);
u.greet();  // "Hi, Bharat!"
  • Methods are on User.prototype (non-enumerable).
  • constructor is the initialization function called by new.
  • No hoisting like function declarations — TDZ until class line (File 08).
typeof User;  // "function" — classes are functions
User.prototype.greet === u.greet;  // false — bound method, but same prototype fn

2.2. Static methods and fields

  • Static — on the constructor, not instances:
class User {
  static fromJSON(json) {
    const data = JSON.parse(json);
    return new User(data.name, data.age);
  }

  constructor(name, age) {
    this.name = name;
    this.age = age;
  }
}

const u = User.fromJSON('{"name":"Bharat","age":30}');
  • Static fields (ES2022+):
class Config {
  static apiUrl = "https://api.example.com";
  static version = 1;
}

Config.apiUrl;
  • Instance fields (ES2022+):
class Counter {
  count = 0;

  increment() {
    this.count++;
  }
}

2.3. Getters and setters

class Rectangle {
  constructor(width, height) {
    this.width = width;
    this.height = height;
  }

  get area() {
    return this.width * this.height;
  }

  set area(value) {
    // example: set square from area
    const side = Math.sqrt(value);
    this.width = side;
    this.height = side;
  }
}

const rect = new Rectangle(4, 5);
rect.area;       // 20 — accessed like property
rect.area = 25;  // uses setter
  • Also valid in object literals (File 12):
const user = {
  _name: "",
  get name() { return this._name; },
  set name(v) { this._name = v.trim(); },
};

L3 Intermediate

2.4. extends and super

class Animal {
  constructor(name) {
    this.name = name;
  }

  speak() {
    return `${this.name} makes a sound`;
  }
}

class Dog extends Animal {
  constructor(name, breed) {
    super(name);  // must call before using `this` in subclass constructor
    this.breed = breed;
  }

  speak() {
    return `${this.name} barks`;
  }
}

const d = new Dog("Rex", "Lab");
d.speak();  // "Rex barks"
  • Rules:
  • super(...) in subclass constructor must run before this is used.
  • super.method() calls parent prototype method.
class Dog extends Animal {
  speak() {
    return super.speak() + " (loudly)";
  }
}

L4 Advanced

2.6. Private fields and methods (ES2022+)

  • True instance privacy with #:
class BankAccount {
  #balance = 0;

  deposit(amount) {
    this.#balance += amount;
  }

  getBalance() {
    return this.#balance;
  }
}

const acct = new BankAccount();
acct.deposit(100);
// acct.#balance;  // SyntaxError — private outside class
  • Private is hard privacy — not accessible via closure trick from outside. Different from convention _prefix.

3. Common questions

L1 L2 L3

L1 Fundamental

3.1. What are the OOP pillars in JavaScript?

  • A: Encapsulation (hide state), inheritance (extends / prototypes), polymorphism (override methods), abstraction (simple API over complexity).

L2 Practical

3.2. When do I use class vs a plain object?

  • A: Use class when you need many instances with shared methods, inheritance, or instanceof. Use a plain object (File 12) for one-off records / DTOs.

L3 Intermediate

3.3. Is class different from prototypes?

  • A: At runtime, no — class is sugar over constructor + prototype. File 19 shows the compiled shape.

3.4. Why must super() run before this in a subclass?

  • A: The parent constructor sets up the instance. Until super() returns, this is not initialized.
