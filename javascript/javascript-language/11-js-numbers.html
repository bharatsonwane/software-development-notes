L2 Practical

1.2. Number object and methods

Number.isNaN(NaN);        // true
Number.isFinite(42);      // true
Number.isInteger(3.0);    // true
Number.parseInt("42px");  // 42
Number.parseFloat("3.14");
(3.14159).toFixed(2);     // "3.14"
(3.14159).toPrecision(3); // "3.14"
  • Prefer Number.isNaN over global isNaN (coerces first).
  • Math helpers (round, random, trig) are File 12.

L3 Intermediate

1.3. NaN and Infinity

0 / 0;           // NaN
Number("abc");   // NaN
1 / 0;           // Infinity
-1 / 0;          // -Infinity

1.4. Floating point precision

  • All JS numbers are IEEE 754 doubles:
0.1 + 0.2;                    // 0.30000000000000004
0.1 + 0.2 === 0.3;            // false
(0.1 + 0.2).toFixed(1);       // "0.3"
Number((0.1 + 0.2).toFixed(2)); // 0.3
  • For money, store cents as integers or use a decimal library.

1.5. Safe integers, EPSILON, parseInt radix

Number.MAX_SAFE_INTEGER;     // 9007199254740991  (2**53 - 1)
Number.isSafeInteger(2**53); // false — use BigInt past this

Number.EPSILON;              // ~2.22e-16 — smallest gap around 1
Math.abs((0.1 + 0.2) - 0.3) < Number.EPSILON;  // true

Number.parseInt("10", 10);   // 10 — always pass radix
Number.parseInt("10", 2);    // 2
Number.parseInt("08");       // 8 in modern JS; still pass 10

(255).toString(16);          // "ff"
  • Compare with Object.is when you care about NaN and -0 (File 03).

2. Common questions

L1 L2 L3

L1 Fundamental

2.1. How do you check for NaN?

  • A: Number.isNaN(value) — not value === NaN or global isNaN.

L3 Intermediate

2.2. Why is 0.1 + 0.2 !== 0.3?

  • A: Binary floating point cannot represent some decimals exactly. Use rounding, integer cents, or compare with a tolerance (Number.EPSILON).

2.3. Why pass a radix to parseInt?

  • A: So "08" / "0x10" are not misread. Prefer Number.parseInt(s, 10) or Number(s) for decimal.
