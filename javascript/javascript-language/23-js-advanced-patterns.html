1. Introduction

L1

L1 Fundamental

1.1. Overview

  • This chapter covers how JS runs code in memory, advanced object APIs, functional utilities, and practical performance habits. It builds on scope (File 08), closures (File 18), and modern syntax (File 22).

1.2. Default rules and how to study this file

  • You do not need to micro-optimize every line — but understanding execution context, GC, and patterns like debounce helps you write reliable production code and debug hard issues.
  • Default rule today: modules and strict mode by default; prefer immutability for predictable state; use Proxy sparingly (frameworks/libraries); measure before optimizing hot paths.
  • Interactive visualizer: open 23-js-advanced-patterns-animation.html in a browser — debounce/throttle timelines, currying, memoization, revealing module, compose/pipe (Run / Step).
  • After reading sections 2–8, complete P. Practical Assignment in 23-practice.js before File 24. Review C. Common questions.

2. Execution context

L2 L3

L2 Intermediate

  • An execution context is the environment in which JS code runs. Each function call and global/module script gets a context.

2.1. Types of execution context

TypeWhen created
GlobalProgram / module start
FunctionEach function invocation
Evaleval() (avoid)
ModuleES module top level
  • Each context has:
  • Variable environment — var, function declarations, let/const bindings (in modern spec: lexical environment).
  • this binding — depends on call type (File 18).
  • Outer reference — link to parent lexical environment (scope chain).

2.2. Call stack

  • Contexts are managed on the call stack (File 21):
function first() {
  second();
}

function second() {
  third();
}

function third() {
  console.log("deep");
}

first();
// Stack: first → second → third → pop...
  • Each push is a new function execution context. Stack overflow = too much synchronous recursion.

L3 Advanced

2.3. Creation vs execution phase

  • When a context is created, JS runs two phases:
  • 1. Creation (compile) phase
  • Create variable bindings (hoisting — File 08).
  • Set up scope chain.
  • Determine this.
  • 2. Execution phase
  • Run code line by line.
  • Assign values.
  • Execute function bodies on call.
console.log(a);  // undefined — var hoisted
var a = 10;

// let b; — TDZ
console.log(b);  // ReferenceError
let b = 5;

2.4. Lexical environment

  • Lexical environment = record of identifiers + reference to outer environment. Closures keep outer environments alive (File 18):
function outer() {
  const x = 10;

  return function inner() {
    console.log(x);  // inner's environment references outer's
  };
}
  • Module scope and block scope (let/const) each get their own lexical environment.

3. Memory & garbage collection

L2 L3

L2 Intermediate

3.1. Stack vs heap

StackHeap
Fixed-size, fastLarger, dynamic
Stores execution context frames, primitives (often)Stores objects, functions, closures
LIFO — call stackGC-managed
 
let n = 42;              // primitive — often stack-like
const user = { name: "Bharat" };  // object — heap; user holds reference
  • Variables hold references to heap values (File 02).

3.2. Memory leaks (common causes)

  • Accidental globals:
function leak() {
  accidental = { data: [] };  // no var/let/const — global in sloppy mode
}
  • Forgotten timers / listeners:
setInterval(() => { /* holds closure over bigData */ }, 1000);
// clearInterval(id) when done

element.addEventListener("click", handler);
// removeEventListener when component unmounts
  • Closures holding large objects longer than needed:
function setup() {
  const huge = loadHugeCache();

  return function onClick() {
    // only needs huge.id but closes over entire huge
    console.log(huge.id);
  };
}
  • Detached DOM nodes — JS still references removed DOM elements.
  • WeakMap / WeakSet (File 22) — attach metadata without preventing GC.

L3 Advanced

3.3. Garbage collection (GC)

  • JS engines automatically reclaim memory when values are no longer reachable from roots (global, call stack, registers).
  • Mark-and-sweep (simplified):
  1. Start from roots — mark reachable objects.
  2. Unmarked objects are collected.
function makeUser() {
  const temp = { huge: new Array(1_000_000) };
  return { name: "Bharat" };
  // temp becomes unreachable after return — eligible for GC
}
  • You cannot manually free memory in JS (delete only removes object properties, not GC).

L3 Advanced

3.4. Weak references (brief)

  • WeakRef and FinalizationRegistry — advanced, rare in app code — allow observing when objects are collected. Use when building caches with size limits in libraries.

4. Proxy & Reflect

L2 L3

L2 Intermediate

  • Proxy wraps an object and intercepts operations (get, set, delete, etc.). Reflect provides methods matching proxy traps — default forwarding behavior.

4.1. Basic Proxy

const target = { name: "Bharat", age: 30 };

const proxy = new Proxy(target, {
  get(obj, prop, receiver) {
    console.log(`GET ${String(prop)}`);
    return Reflect.get(obj, prop, receiver);
  },
  set(obj, prop, value, receiver) {
    console.log(`SET ${String(prop)} = ${value}`);
    return Reflect.set(obj, prop, value, receiver);
  },
});

proxy.name;       // logs GET name → "Bharat"
proxy.age = 31;   // logs SET age = 31

4.2. Common traps

TrapIntercepts
getProperty read
setProperty write
hasin operator
deletePropertydelete
applyFunction call
constructnew
  • Validation example:
const user = new Proxy({}, {
  set(obj, prop, value) {
    if (prop === "age" && typeof value !== "number") {
      throw new TypeError("age must be number");
    }
    obj[prop] = value;
    return true;
  },
});

user.age = 30;   // OK
// user.age = "30";  // TypeError

L3 Advanced

4.3. Reflect

  • Reflect methods mirror proxy traps and return sensible results:
Reflect.get(user, "name");
Reflect.set(user, "name", "Dev");
Reflect.has(user, "name");
Reflect.deleteProperty(user, "temp");
  • Use Reflect inside traps instead of direct obj[prop] to avoid recursion and handle receiver/this correctly.

4.4. When to use Proxy

Good useAvoid
Library/framework internals (Vue 3 reactivity)Everyday app objects
Validation / logging layersHot loops without profiling
Immutable-style wrappersReplacing simple classes
  • Proxies add overhead — powerful but not free.

5. Functional patterns

L1 L2 L3

L1 Fundamental

5.1. Pure functions & immutability

  • Pure function — same inputs → same output, no side effects (File 05):
function add(a, b) {
  return a + b;
}

// Impure — mutates external state
let total = 0;
function addToTotal(n) {
  total += n;
}
  • Immutability — return new data instead of mutating:
function addItem(cart, item) {
  return [...cart, item];  // new array
}

function updateUser(user, name) {
  return { ...user, name };  // new object
}
  • React and Redux-style state rely on immutability for change detection.

L2 Intermediate

5.2. Currying

  • Transform f(a, b, c) into f(a)(b)(c) — partial application one arg at a time:
function curry(fn) {
  return function curried(...args) {
    if (args.length >= fn.length) {
      return fn.apply(this, args);
    }
    return (...next) => curried(...args, ...next);
  };
}

function multiply(a, b, c) {
  return a * b * c;
}

const curriedMultiply = curry(multiply);
curriedMultiply(2)(3)(4);  // 24
curriedMultiply(2, 3)(4);  // 24
  • Useful for config presets and reusable handlers.

5.3. Function composition

  • Pipe output of one function into the next:
const compose = (f, g) => (x) => f(g(x));
const pipe = (...fns) => (x) => fns.reduce((v, fn) => fn(v), x);

const double = (n) => n * 2;
const increment = (n) => n + 1;

const doubleThenInc = compose(increment, double);
doubleThenInc(5);  // 11

pipe(double, increment)(5);  // 11
  • Libraries: Ramda, lodash/fp.

6. Utility patterns

L1 L2

L1 Fundamental

6.1. Debounce

  • Run function only after calls stop for a delay — search input, resize:
function debounce(fn, delayMs) {
  let timerId;

  return function (...args) {
    clearTimeout(timerId);
    timerId = setTimeout(() => {
      fn.apply(this, args);
    }, delayMs);
  };
}

const onSearch = debounce((query) => {
  fetchResults(query);
}, 300);

input.addEventListener("input", (e) => onSearch(e.target.value));
  • User types → wait 300ms idle → one API call.

6.2. Throttle

  • Run at most once per interval — scroll, mousemove:
function throttle(fn, intervalMs) {
  let last = 0;

  return function (...args) {
    const now = Date.now();
    if (now - last >= intervalMs) {
      last = now;
      fn.apply(this, args);
    }
  };
}

const onScroll = throttle(() => {
  updateScrollIndicator();
}, 100);

window.addEventListener("scroll", onScroll);
DebounceThrottle
Wait for pauseCap frequency
Search typingScroll / resize firehose

6.3. once

  • Run function only one time:
function once(fn) {
  let called = false;
  let result;

  return function (...args) {
    if (!called) {
      called = true;
      result = fn.apply(this, args);
    }
    return result;
  };
}

const init = once(() => {
  console.log("init");
  return { ready: true };
});

init();  // logs
init();  // silent — returns same result

L2 Intermediate

6.4. Memoization

  • Cache function results by arguments (File 18):
function memoize(fn) {
  const cache = new Map();

  return function (...args) {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);

    const result = fn.apply(this, args);
    cache.set(key, result);
    return result;
  };
}

const slowSquare = memoize((n) => {
  // imagine expensive work
  return n * n;
});

slowSquare(5);  // computes
slowSquare(5);  // cached
  • Use Map when args are objects; consider cache size limits for production.

7. Performance

L3

L3 Advanced

7.1. When to optimize

  1. Make it work — correct, readable code.
  2. Measure — DevTools Performance, console.time, benchmarks.
  3. Optimize hot paths — loops over huge arrays, render-critical UI.
  4. Avoid premature optimization.

7.2. Common pitfalls

PitfallBetter approach
DOM thrashing — read/write layout in loopBatch reads, then writes
Creating functions in hot loopsDefine outside or reuse
+= on strings in tight loopArray + join for many parts
Deep clone everywhereShallow copy + targeted updates
Sync JSON parse of huge payloadStream, chunk, or Web Worker
Blocking main threadasync, Workers, requestIdleCallback
 
// String building
let s = "";
for (let i = 0; i < 10000; i++) s += i;  // slow — many allocations

const parts = [];
for (let i = 0; i < 10000; i++) parts.push(i);
const fast = parts.join("");

7.3. Micro-optimizations that rarely matter

  • for vs forEach vs for...of on small arrays — readability first.
  • Manual loop unrolling — engine often does it.
  • Avoiding try/catch in inner loops — optimize only if profiler shows cost.
  • Focus on algorithm choice (O(n²) → O(n)), network, and bundle size before micro-tuning.

L3 Advanced

7.4. How engines optimize (V8 basics)

  • Modern engines (V8 in Chrome/Node) use:
  • Parsing → AST → bytecode (Ignition) → optimized machine code (TurboFan) for hot functions.
  • Inline caching — speed up repeated property access shapes.
  • Hidden classes — objects with same property order/layout optimize better.
// Good — consistent shape
function Point(x, y) {
  this.x = x;
  this.y = y;
}

// Bad for IC — adding properties in random order on different objects
const a = { x: 1 };
const b = { y: 2, x: 1 };
  • Details are engine-specific — measure, don't guess.

8. Strict mode

L1 L2

L1 Fundamental

  • "use strict" enables stricter parsing and runtime errors — catches silent bugs.

8.1. How to enable

"use strict";

function strictFn() {
  // whole function strict
}

// ES modules are strict by default

8.2. Why use strict

  • Safer refactoring — typos throw instead of creating globals.
  • Required baseline for classes and modules.
  • Matches modern tooling defaults (bundlers, TypeScript emit).
  • Always write new code in strict contexts (modules or "use strict").

C. Common questions

L1 L2 L3

L1 Fundamental

C.1. What is the difference between debounce and throttle? ▾ Answer

Debounce waits for a pause in events then runs once. Throttle runs at most once per time window during continuous events.

C.2. What does strict mode do? ▾ Answer

Turns silent errors into exceptions, disables some unsafe features (with, implicit globals), and makes this undefined in plain function calls.

C.3. What is memoization? ▾ Answer

Caching a function's return values by input arguments to avoid recomputing expensive work. Trade memory for speed.

L2 Intermediate

C.4. What is an execution context? ▾ Answer

The environment for running a piece of JS — includes variable bindings, this, and the outer scope link. Created for global/module code and each function call.

C.5. What is the difference between the call stack and the heap? ▾ Answer

The call stack tracks active function contexts (LIFO). The heap stores objects and other dynamic data referenced from the stack.

C.6. What causes memory leaks in JS? ▾ Answer

Common causes: accidental globals, uncleared timers/listeners, closures holding large unused data, and detached DOM nodes still referenced from JS.

C.7. What is a Proxy? ▾ Answer

A wrapper that intercepts operations on an object (get, set, etc.) via traps. Used in frameworks for reactivity and validation.

C.8. What is currying? ▾ Answer

Transforming a multi-argument function into a chain of functions each taking one (or fewer) arguments — enables partial application.

L3 Advanced

C.9. How does garbage collection work in JavaScript? ▾ Answer

Engines trace reachable objects from roots and reclaim unreachable memory. You do not manually free memory.

C.10. When should you optimize JavaScript performance? ▾ Answer

After measuring a real bottleneck — hot loops, large data, UI jank, or slow API paths. Prefer better algorithms and architecture before micro-optimizations.

  3. Memoize a slow fib(n) with a Map cache. ▾ Solution 
    const memo = new Map();

function fib(n) {
  if (n <= 1) return n;
  if (memo.has(n)) return memo.get(n);

  const result = fib(n - 1) + fib(n - 2);
  memo.set(n, result);
  return result;
}

console.log("fib(10):", fib(10)); // 55
console.log("fib(40):", fib(40)); // 102334155 (instant thanks to memoization)

      inThrottle = true;
