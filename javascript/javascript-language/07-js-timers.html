07. Timers

File 07 — run a function once or repeatedly after a delay.

setTimeout setInterval clearTimeout clearInterval

1. Introduction

L1

L1 Fundamental

1.1. What are timers?

  • Timers schedule a function (File 05) to run later. They do not pause the rest of the program — other code keeps running until the delay finishes.
APIWhat it does
setTimeout()Runs a function once after a delay.
setInterval()Runs a function repeatedly.
clearTimeout()Cancels a timeout.
clearInterval()Stops an interval.

1.2. Default rules and how to study this file

Default rule today: save the id that setTimeout/setInterval returns, and always clearTimeout/clearInterval when you no longer need the callback.

2. setTimeout and clearTimeout

L1 L2

L1 Fundamental

2.1. Run once after a delay

const id = setTimeout(() => {
  console.log("After 1 second");
}, 1000);

clearTimeout(id);  // cancel before it runs
  • Delay is in milliseconds: 1000 is 1 second.
  • setTimeout returns an id. Pass that id to clearTimeout to cancel.

L1 Fundamental

2.2. Extra arguments

setTimeout((name) => {
  console.log(`Hello, ${name}`);
}, 500, "Bharat");

L2 Intermediate

2.3. Delay 0 is not immediate

  • setTimeout(fn, 0) still runs after the current call stack. File 21 (event loop) explains why.

3. setInterval and clearInterval

L1 L2

L1 Fundamental

3.1. Run repeatedly

let count = 0;
const id = setInterval(() => {
  count++;
  console.log(count);
  if (count >= 5) clearInterval(id);
}, 500);
  • setInterval keeps calling the function until you clearInterval.

L1 Fundamental

  • Always clearInterval when done — leftover intervals keep running and can leak memory (File 23).

L2 Intermediate

3.2. requestAnimationFrame

  • For smooth animation synced to display refresh (~60fps), prefer rAF over setInterval:
function animate() {
  // update positions
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

// cancel: cancelAnimationFrame(id);

3.3. Recursive setTimeout vs setInterval

  • setInterval schedules the next tick on a fixed clock — if the callback is slow, calls can overlap or pile up.
  • Recursive setTimeout schedules the next run only after the current callback finishes — better when work length varies:
function tick() {
  // do work (may take longer than the delay)
  setTimeout(tick, 1000);  // next run after this call completes + 1000ms
}
setTimeout(tick, 1000);
  • Timers are macrotasks on the event loop — File 21. setTimeout(fn, 0) still runs after the current stack and pending microtasks.

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between setTimeout and setInterval?

  • A: setTimeout runs once after a delay. setInterval repeats until cleared.

L1 Fundamental

C.2. What do clearTimeout and clearInterval do?

  • A: clearTimeout cancels a pending timeout so it never runs. clearInterval stops a repeating interval. Both need the id returned by setTimeout/setInterval.

C.3. Why use requestAnimationFrame?

  • A: It batches visual updates with the browser repaint cycle — smoother than a fixed setInterval.

C.4. When prefer recursive setTimeout over setInterval?

  • A: When each tick's work can take longer than the interval — recursive setTimeout waits for the previous run to finish before scheduling the next, avoiding overlap. Details: File 21 (event loop).

P. Practical Assignment

L1 L2
Run these in a browser console or Node. Always store timer ids and clear them so scripts do not leak callbacks.

L1 Fundamental

P.1. Warm-up

  1. Use setTimeout to log "hello" after 1 second.
  2. Schedule a timeout, then clearTimeout it immediately so nothing prints.
  3. Pass an extra argument: setTimeout((name) => console.log(name), 500, "Ada").

P.2. Core tasks

  1. Countdown — Log 3, 2, 1, then "go" using chained or nested setTimeout (1s between steps).
  2. Interval counter — Use setInterval to log a number every 500ms; stop at 5 with clearInterval.
  3. Cancel on condition — Start an interval; clear it when a variable stopped becomes true (set stopped = true after 2 seconds with setTimeout).
  4. Delay 0 demo — Log "A", schedule setTimeout(() => console.log("B"), 0), then log "C". Explain the order in a comment.

L2 Intermediate

P.3. Challenge

  1. Recursive setTimeout poll — Simulate work that takes random time: after each tick finishes, schedule the next with setTimeout. Stop after 5 ticks. Comment why this avoids overlap vs setInterval.
  2. Browser only: use requestAnimationFrame to log frame count for ~1 second, then cancel with cancelAnimationFrame.

P.4. Self-check

  • I always save and clear timer ids.
  • I know setTimeout(..., 0) is not instantaneous.
  • I can explain when recursive setTimeout beats setInterval.
