07. Timers

File 07 — run a function once or repeatedly after a delay.

setTimeout setInterval clearTimeout clearInterval

1. Introduction

L1

L1 Fundamental

1.1. What are timers?

  • Timers schedule a function (File 05) to run later. They do not pause the rest of the program — other code keeps running until the delay finishes.
APIWhat it does
setTimeout()Runs a function once after a delay.
setInterval()Runs a function repeatedly.
clearTimeout()Cancels a timeout.
clearInterval()Stops an interval.

1.2. Default rules and how to study this file

Default rule today: save the id that setTimeout/setInterval returns, and always clearTimeout/clearInterval when you no longer need the callback.

  • After reading sections 2–3, complete P. Practical Assignment in 07-practice.js (browser console or Node) before File 08. Review C. Common questions.

2. setTimeout and clearTimeout

L1 L2

L1 Fundamental

2.1. Run once after a delay

const id = setTimeout(() => {
  console.log("After 1 second");
}, 1000);

clearTimeout(id);  // cancel before it runs
  • Delay is in milliseconds: 1000 is 1 second.
  • setTimeout returns an id. Pass that id to clearTimeout to cancel.

L1 Fundamental

2.2. Extra arguments

setTimeout((name) => {
  console.log(`Hello, ${name}`);
}, 500, "Bharat");

L2 Intermediate

2.3. Delay 0 is not immediate

  • setTimeout(fn, 0) still runs after the current call stack and microtask queue drain. File 21 (event loop) explains why.

L3 Advanced

2.4. HTML5 Timer Clamping (4ms) & Background Tab Throttling

  • 4ms Minimum Clamping: Under the WHATWG / HTML5 specification, once timer nesting levels reach 5 or greater, browsers enforce a minimum delay floor of 4ms, even if 0ms was passed.
  • Background Tab Throttling: To preserve laptop battery and mobile CPU cycles, browsers throttle background/unfocused tabs to a minimum timer interval of 1,000ms (1 second) or coarser. Never rely on setInterval for game loops or audio timing—use requestAnimationFrame or Web Workers for precision.
  • Browser vs Node.js Return Types: In browsers, setTimeout returns a numeric integer ID (number). In Node.js, it returns a Timeout object with timer.unref() (which lets the Node.js event loop exit cleanly even if the timer is pending) and timer.ref().
// Node.js only: keep timer without blocking graceful process exit
const timer = setTimeout(() => {
  console.log("Heartbeat check");
}, 60000);
timer.unref(); // Node process will exit if this is the only remaining scheduled task!

3. setInterval and clearInterval

L1 L2

L1 Fundamental

3.1. Run repeatedly

let count = 0;
const id = setInterval(() => {
  count++;
  console.log(count);
  if (count >= 5) clearInterval(id);
}, 500);
  • setInterval keeps calling the function until you clearInterval.

L1 Fundamental

  • Always clearInterval when done — leftover intervals keep running and can leak memory (File 23).

L2 Intermediate

3.2. requestAnimationFrame

  • For smooth animation synced to display refresh (~60fps), prefer rAF over setInterval:
function animate() {
  // update positions
  requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

// cancel: cancelAnimationFrame(id);

3.3. Recursive setTimeout vs setInterval

  • setInterval schedules the next tick on a fixed clock — if the callback is slow, calls can overlap or pile up.
  • Recursive setTimeout schedules the next run only after the current callback finishes — better when work length varies:
function tick() {
  // do work (may take longer than the delay)
  setTimeout(tick, 1000);  // next run after this call completes + 1000ms
}
setTimeout(tick, 1000);
  • Timers are macrotasks on the event loop — File 21. setTimeout(fn, 0) still runs after the current stack and pending microtasks.

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between setTimeout and setInterval? ▾ Answer

setTimeout runs once after a delay. setInterval repeats until cleared.

L1 Fundamental

C.2. What do clearTimeout and clearInterval do? ▾ Answer

clearTimeout cancels a pending timeout so it never runs. clearInterval stops a repeating interval. Both need the id returned by setTimeout/setInterval.

C.3. Why use requestAnimationFrame? ▾ Answer

It batches visual updates with the browser repaint cycle — smoother than a fixed setInterval.

C.4. When prefer recursive setTimeout over setInterval? ▾ Answer

When each tick's work can take longer than the interval — recursive setTimeout waits for the previous run to finish before scheduling the next, avoiding overlap. Details: File 21 (event loop).

  console.log("This will never print!");

clearTimeout(timerId); // Immediately cancelled

  console.log("Hello,", name);

P.2. Core tasks

  1. Countdown — Log 3, 2, 1, then "go" using chained or nested setTimeout (1s between steps). ▾ Solution 
    let count = 3;
const countdownInterval = setInterval(() => {
  if (count > 0) {
    console.log(count);
    count--;
  } else {
    console.log("go!");
    clearInterval(countdownInterval);
  }
}, 1000);
  2. Interval counter — Use setInterval to log a number every 500ms; stop at 5 with clearInterval. ▾ Solution 
    let current = 1;
const counterId = setInterval(() => {
  console.log("Number:", current);
  if (current === 5) {
    clearInterval(counterId);
    console.log("Stopped at 5");
  }
  current++;
}, 100);
  3. Cancel on condition — Start an interval; clear it when a variable stopped becomes true (set stopped = true after 2 seconds with setTimeout). ▾ Solution 
    let score = 0;
const intervalId = setInterval(() => {
  score += 25;
  console.log("Current score:", score);
  if (score >= 100) {
    console.log("Score limit reached! Clearing interval.");
    clearInterval(intervalId);
  }
}, 150);
  4. Delay 0 demo — Log "A", schedule setTimeout(() => console.log("B"), 0), then log "C". Explain the order in a comment. ▾ Solution 
    console.log("A");

setTimeout(() => {
  console.log("B (timer callback from macrotask queue)");
}, 0);

console.log("C");

// Execution order:
// 1. "A" (synchronous)
// 2. "C" (synchronous)
// 3. "B" (asynchronous, runs when call stack is empty)

L2 Intermediate

P.3. Challenge

  1. Recursive setTimeout poll — Simulate work that takes random time: after each tick finishes, schedule the next with setTimeout. Stop after 5 ticks. Comment why this avoids overlap vs setInterval. ▾ Solution 
    function pollServer(attempt = 1) {
  const maxAttempts = 3;
  const delay = attempt * 500; // Progressive backoff

  setTimeout(() => {
    console.log(`Poll attempt #${attempt}`);
    if (attempt < maxAttempts) {
      pollServer(attempt + 1); // Schedule next poll only after previous completes
    } else {
      console.log("Polling completed.");
    }
  }, delay);
}

pollServer();
  2. Browser only: use requestAnimationFrame to log frame count for ~1 second, then cancel with cancelAnimationFrame. ▾ Solution 
    let frameCount = 0;

function onFrame(timestamp) {
  frameCount++;
  console.log(`Frame ${frameCount} rendered at ${Math.round(timestamp)}ms`);

  if (frameCount < 3) {
    // In browser environments: request next screen refresh
    if (typeof requestAnimationFrame !== "undefined") {
      requestAnimationFrame(onFrame);
    }
  }
}

if (typeof requestAnimationFrame !== "undefined") {
  requestAnimationFrame(onFrame);
} else {
  // Node.js fallback demonstration
  console.log("requestAnimationFrame is browser-specific. Use setImmediate in Node.js.");
}
