1. Introduction

1.1. What are variables in JavaScript?

  • JavaScript gives you three keywords to declare variables: const, let, and var. They differ in scope, redeclaration rules, and hoisting behavior.
  • This file covers how to declare and assign variables. Scope and hoisting are File 08 — after Functions — because function scope and function-declaration hoisting make more sense once you know how functions work.

1.2. Default rules and how to study this file

Default rule today: use const by default, let when you need to reassign, and avoid var in new code.
  • How to practice: create a file 01-practice.js, run with node 01-practice.js, or paste into the browser console. After reading section 2, complete P. Practical Assignment before File 02. Review C. Common questions for interview-style checks.

L2 Intermediate

2.4. Reassignment vs rebinding

  • Reassignment — change the value a variable points to (x = newValue).
  • Rebinding — attach the name to a different binding (declaring again in the same scope).
let count = 0;
count = 1;        // reassignment — OK

let count = 2;    // SyntaxError — cannot redeclare let in same scope

var total = 0;
var total = 1;    // OK with var (usually a mistake)

2.5. const — constant binding, not constant value

  • const means the variable binding cannot change. The value can still be mutated if it is an object or array:
const user = { name: "Bharat" };
user.name = "Dev";     // OK — mutating the object
user = { name: "X" };  // TypeError — cannot reassign the variable

const nums = [1, 2];
nums.push(3);          // OK
nums = [4, 5];         // TypeError
  • You must assign const at declaration time:
const x;   // SyntaxError — missing initializer

2.6. Temporal Dead Zone (TDZ)

  • const and let exist from the start of their block, but you cannot access them until the declaration line runs. That gap is the Temporal Dead Zone.
console.log(x);  // undefined — var is hoisted and initialized
var x = 5;

console.log(y);  // ReferenceError — y is in TDZ
let y = 5;
{
  // TDZ for `message` starts here
  // console.log(message);  // ReferenceError

  let message = "hello";   // TDZ ends
  console.log(message);    // "hello"
}
  • Even typeof is unsafe on an undeclared const/let in the same scope:
typeof undeclaredVar;     // "undefined" — no binding exists
let local;
typeof local;             // "undefined" — declared but not assigned

// typeof notYetDeclared; // ReferenceError — binding exists but is in TDZ
let notYetDeclared = 1;

2.7. Global Object Attachment vs Declarative Environment

  • In browser global scope (non-module scripts), variables declared with var create configurable or non-configurable properties directly on the global object (window / globalThis):
  • Variables declared with let and const are stored in the script's Declarative Environment Record. They are top-level and globally accessible in the script, but they never pollute or attach to window:
// In a browser script tag:
var globalVar = "I attach to window";
let globalLet = "I stay in Declarative Environment";
const globalConst = "Me too";

console.log(window.globalVar);   // "I attach to window"
console.log(window.globalLet);   // undefined (Not on window!)
console.log(window.globalConst); // undefined (Not on window!)
console.log(globalLet);          // "I stay in Declarative Environment" (Directly accessible)

2.8. Loop Closure Binding Mechanics: var vs let

A classic JavaScript interview puzzle demonstrates how loop scoping interacts with asynchronous closures:

// Problematic: var shares ONE single variable slot across all iterations
for (var i = 0; i < 3; i++) {
  setTimeout(() => {
    console.log("var i:", i);
  }, 100);
}
// Prints: 3, 3, 3 (All 3 callbacks reference the same mutated variable!)

// Fixed with let: creates a fresh lexical binding per iteration step
for (let j = 0; j < 3; j++) {
  setTimeout(() => {
    console.log("let j:", j);
  }, 100);
}
// Prints: 0, 1, 2 (Each callback captures its own immutable iteration binding!)

// Historical ES5 solution using an IIFE (Immediately Invoked Function Expression):
for (var k = 0; k < 3; k++) {
  (function(capturedK) {
    setTimeout(() => {
      console.log("IIFE k:", capturedK);
    }, 100);
  })(k);
}
// Prints: 0, 1, 2

2.9. Default Parameter TDZ Traps

Function parameters have their own intermediate parameter scope evaluated strictly from left to right. Accessing a right-hand parameter from a left-hand parameter triggers a TDZ ReferenceError:

// ERROR: 'b' is in TDZ when default argument 'a = b' is evaluated!
function invalid(a = b, b = 2) {
  return a + b;
}
// invalid(); // Uncaught ReferenceError: Cannot access 'b' before initialization

// VALID: 'a' has already finished initialization when 'b = a' is evaluated:
function valid(a = 2, b = a) {
  return a + b;
}
console.log(valid()); // 4

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between const, let, and var? ▾ Answer
  • const: Block-scoped. Cannot be reassigned or redeclared. Resides in the TDZ until declared. Preferred by default.
  • let: Block-scoped. Can be reassigned, but cannot be redeclared in the same scope. Resides in the TDZ until declared.
  • var: Function-scoped (ignores { } blocks). Can be redeclared and reassigned. Hoisted and initialized to undefined.
C.2. Can I use a variable before declaring it with var? ▾ Answer

You can read it without throwing a ReferenceError because var declarations are hoisted and initialized to undefined. However, reading undefined before the assignment runs is a common bug source. Prefer const / let so the TDZ catches premature access early.

C.3. Should I ever use var? ▾ Answer

In modern JavaScript, almost never. Use const by default, and let when reassignment is needed. You may still see var in legacy codebases, older tutorials, or interview questions testing scope and hoisting.

L2 Intermediate

C.4. What is the Temporal Dead Zone? ▾ Answer

The Temporal Dead Zone (TDZ) is the state between entering a block scope and executing the line where the let or const variable is declared. Accessing the variable during this window throws an immediate ReferenceError: Cannot access variable before initialization.

C.5. What happens if I assign without var, let, or const? ▾ Answer

In non-strict mode, assigning x = 1 without a declaration keyword creates an accidental global property on window (browser) or global (Node.js). In strict mode ("use strict";) or inside ES modules, it throws a ReferenceError. Always declare with const or let.

C.6. Why does for (var i = 0; ...) print 3, 3, 3 in setTimeout, and how does let fix it? ▾ Answer

Because var is function-scoped, every loop iteration shares the exact same variable binding in memory. By the time the asynchronous timer callbacks run from the task queue, the loop has finished and mutated i to 3.

let is block-scoped: the ECMAScript engine explicitly creates a brand new lexical binding for each loop iteration, so each closure captures an immutable snapshot of that specific iteration's index (0, 1, 2).

C.7. Do let and const attach to the global window object in browsers? ▾ Answer

No. Variables declared with var in global non-module script scope become properties on window / globalThis. In contrast, let and const are stored in the script's Declarative Environment Record; they are globally accessible to code in the page, but they never pollute the global object (window.letVar === undefined).

P.2. Core tasks (write full programs)

  1. Profile card — Declare const for fullName, city, and isStudent. Use let for score. Log a sentence like: Bharat from Pune, score: 85. ▾ Solution 
    const fullName = "Bharat";
const city = "Pune";
const isStudent = true;

console.log(`${fullName} from ${city}, score: ${score}`);
// Output: Bharat from Pune, score: 85
  2. Swap with a temp — Given let a = 10; let b = 20;, swap values using a temporary variable. Log before and after. ▾ Solution 
    let a = 10;
let b = 20;
console.log(`Before swap: a = ${a}, b = ${b}`);

const temp = a;
a = b;
b = temp;

console.log(`After swap:  a = ${a}, b = ${b}`);
  3. const object gotcha — Create const user = { name: "Ada" };. Change user.name to another string (allowed). Then try user = {} and confirm it fails. Write one comment explaining why. ▾ Solution 
    const user = { name: "Ada" };

// 1. Mutating properties inside a const object is ALLOWED:
user.name = "Grace";
console.log("Updated property:", user.name);

// 2. Reassigning the variable itself FAILS:
// user = {}; // TypeError: Assignment to constant variable.

// Reason: const prevents changing the variable's memory binding/reference,
// but does not freeze the properties of the object itself.
