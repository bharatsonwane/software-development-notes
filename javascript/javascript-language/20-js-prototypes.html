20. Prototypes

File 20 — prototype chain, new, and how classes compile. Class syntax is File 19.

NotesExamplesPracticeInterview

1. Introduction

L1

L1 Fundamental

1.1. Overview

  • JavaScript uses prototypal inheritance: objects can delegate property lookups to another object called their prototype. class syntax (File 19) is syntactic sugar over this prototype system — this file is how new, extends, and instanceof actually work.

1.2. Default rules and how to study this file

  • Every object (except Object.create(null)) has an internal link to a prototype. Functions have an extra prototype property used when the function is called with new.
  • Default rule today: write class in application code (File 19); use this file to debug the prototype chain, new, and instanceof.
  • Interactive visualizer: open 20-js-prototypes-animation.html in a browser — chain lookup, new, instanceof, manual inheritance, class extends (Run / Step).
  • After reading sections 2–5, complete P. Practical Assignment in 20-practice.js before File 21. Review C. Common questions.

2. Prototype chain

L1 L2 L3

L1 Fundamental

2.1. What is a prototype?

  • When you read obj.key, JavaScript:
  1. Looks for key on obj itself (own property).
  2. If missing, follows the prototype link to the parent object.
  3. Repeats until found or the chain ends at null.
const animal = {
  eats: true,
  walk() {
    console.log("walking");
  },
};

const rabbit = {
  jumps: true,
};

// Link rabbit's prototype to animal
Object.setPrototypeOf(rabbit, animal);

rabbit.jumps;   // true — own property
rabbit.eats;    // true — from animal
rabbit.walk();  // "walking" — method on animal
  • This linked list is the prototype chain.

L2 Intermediate

2.2. The prototype property on functions

  • Functions (except arrows) have a prototype object. When you call the function with new, the new object's [[Prototype]] is set to that prototype:
function User(name) {
  this.name = name;
}

User.prototype.greet = function () {
  return `Hi, ${this.name}`;
};

const u = new User("Bharat");

Object.getPrototypeOf(u) === User.prototype;  // true
u.greet();  // "Hi, Bharat"
TermWhat it is
obj.[[Prototype]]Link to parent object for lookup
Fn.prototypeObject used as [[Prototype]] for new Fn() instances
obj.__proto__Legacy accessor to [[Prototype]]
  • Arrow functions have no prototype property — they cannot be constructors.

2.3. Own properties vs inherited

const parent = { shared: 1, unique: "parent" };
const child = Object.create(parent);
child.unique = "child";

child.shared;   // 1 — inherited
child.unique;   // "child" — own, shadows parent.unique

Object.hasOwn(child, "shared");  // false
Object.hasOwn(child, "unique");  // true
  • Shadowing — own property hides inherited same-named property:
User.prototype.name = "default";
const u = new User("Bharat");
u.name;  // "Bharat" — own property wins

2.4. instanceof and the prototype chain

  • instanceof checks if Constructor.prototype appears anywhere in the object's prototype chain:
u instanceof User;     // true
u instanceof Object;   // true — Object.prototype in chain

[] instanceof Array;   // true
[] instanceof Object;  // true
function checkInstance(obj, Constructor) {
  return Constructor.prototype.isPrototypeOf(obj);
}

checkInstance(u, User);  // true
  • instanceof is unreliable across realms (iframes) — use Object.prototype.toString or feature checks for libraries.

L3 Advanced

2.5. [[Prototype]], __proto__, and Object.getPrototypeOf

  • The spec uses internal slot [[Prototype]]. In practice:
// Modern — preferred
Object.getPrototypeOf(rabbit);   // animal
Object.setPrototypeOf(rabbit, animal);

// Legacy — avoid in new code
rabbit.__proto__;  // animal (deprecated accessor)
  • Object literal {} inherits from Object.prototype:
const obj = {};
Object.getPrototypeOf(obj) === Object.prototype;  // true

obj.toString();  // "[object Object]" — from Object.prototype
  • Object.create(null) — object with no prototype (useful for pure dictionaries):
const dict = Object.create(null);
dict.name = "Bharat";
dict.toString;  // undefined — no inherited methods

3. Object creation

L1 L2

L1 Fundamental

3.1. Object literals

const user = { name: "Bharat", age: 30 };
  • Prototype is Object.prototype automatically. Methods on the literal are own properties unless added to a shared prototype (unusual for literals).

L1 Fundamental

3.2. Object.create

  • Create an object with an explicit prototype:
const proto = {
  greet() {
    return `Hello, ${this.name}`;
  },
};

const user = Object.create(proto);
user.name = "Bharat";

user.greet();  // "Hello, Bharat"
  • Second argument — property descriptors (like Object.defineProperties):
const user = Object.create(proto, {
  name: { value: "Bharat", writable: true, enumerable: true },
});
  • Pure prototypal pattern — no constructor function required.

3.3. Constructor functions

  • Before class, constructors were the standard pattern:
function User(name, age) {
  this.name = name;
  this.age = age;
}

User.prototype.greet = function () {
  return `Hi, ${this.name}`;
};

User.prototype.isAdult = function () {
  return this.age >= 18;
};
  • Shared methods live on User.prototype — one copy shared by all instances (memory efficient).
  • Do not redefine methods inside the constructor for each instance:
// Avoid — new function object per instance
function Bad(name) {
  this.name = name;
  this.greet = function () { return this.name; };
}

L2 Intermediate

3.4. The new keyword

  • What new User("Bharat") roughly does (File 18 — new binding):
  1. Create empty object {}.
  2. Set object's [[Prototype]] to User.prototype.
  3. Call User with this bound to that object.
  4. If constructor returns a non-object, return the new object; else return constructor's return value.
function User(name) {
  this.name = name;
  // implicit return of `this` when not returning object
}

const u = new User("Bharat");
// u.[[Prototype]] → User.prototype
// u.name → "Bharat"
  • Calling without new on a constructor — this may be global or undefined (bug):
const broken = User("Bharat");  // avoid — pollutes global or fails strict

4. Inheritance

L2 L3

L2 Intermediate

4.1. Prototypal inheritance

  • Inheritance in JS means one object's prototype chain includes another object's methods/properties.
function Animal(name) {
  this.name = name;
}

Animal.prototype.speak = function () {
  return `${this.name} makes a sound`;
};

function Dog(name, breed) {
  Animal.call(this, name);  // "super" constructor — own props on this
  this.breed = breed;
}

// Link prototypes — Dog.prototype inherits from Animal.prototype
Dog.prototype = Object.create(Animal.prototype);
Dog.prototype.constructor = Dog;  // fix constructor pointer

Dog.prototype.speak = function () {
  return `${this.name} barks`;
};

const d = new Dog("Rex", "Lab");
d.speak();           // "Rex barks"
d instanceof Dog;    // true
d instanceof Animal; // true

4.2. Animal.call(this, ...) pattern

  • Constructor stealing — parent constructor runs with child's this to set up own properties:
function Parent(a) {
  this.a = a;
}

function Child(a, b) {
  Parent.call(this, a);  // super(...args) in classes
  this.b = b;
}
  • Methods still need prototype linking (Object.create or class extends).

L3 Advanced

4.3. Classes vs manual prototype setup

  • class Dog extends Animal does the prototype wiring for you (section 4). Manual pattern above is what happens under the hood — useful for debugging and interviews.
  • Composition over inheritance — often prefer containing objects or mixins over deep chains:
const canWalk = {
  walk() { console.log("walking"); },
};

const user = Object.assign(Object.create(null), canWalk, { name: "Bharat" });

5. How classes compile

L1 L2

L1 Fundamental

  • class syntax (constructor, extends, super, # fields) is File 19. This section is what that syntax becomes at runtime.

5.1. class is a constructor plus prototype methods

class User {
  constructor(name) { this.name = name; }
  greet() { return `Hi, ${this.name}`; }
}

// Roughly the same as:
function User(name) { this.name = name; }
User.prototype.greet = function () {
  return `Hi, ${this.name}`;
};
  • Methods live on User.prototype. Instances share one copy.

L2 Intermediate

5.2. extends wires the prototype chain

  • class Dog extends Animal does the same prototype linking as section 3 (Object.create + Parent.call(this, ...)). super(...) is that parent-constructor call.

C. Common questions

L1 L2 L3

L1 Fundamental

C.1. What is the prototype chain? ▾ Answer

The linked list of objects JavaScript walks when a property is not found on the object itself. Lookup goes own properties → prototype → prototype's prototype → … → null.

C.2. Is JavaScript class-based or prototype-based? ▾ Answer

Prototype-based at runtime. class is syntactic sugar over constructor functions and prototype delegation.

C.3. What is the difference between own and inherited properties? ▾ Answer

Own properties exist directly on the object. Inherited properties come from the prototype chain. Use Object.hasOwn(obj, key) to test own properties only.

L1 Fundamental

C.4. Can arrow functions be used as constructors? ▾ Answer

No. They have no prototype and cannot be used with new.

L2 Intermediate

C.5. What does new do? ▾ Answer

Creates an object, sets its prototype to Constructor.prototype, runs the constructor with this bound to that object, and returns the object (unless the constructor returns another object).

C.6. What does instanceof check? ▾ Answer

Whether Constructor.prototype exists anywhere in the object's prototype chain. Not a check of own properties or "type" in the OOP class sense alone.

L3 Advanced

C.7. What is the difference between __proto__ and prototype? ▾ Answer

__proto__ (legacy) is an object's link to its parent prototype. prototype is a property on constructor functions — the object assigned as [[Prototype]] to instances created with new.

C.8. Why call Animal.call(this, name) in subclass constructors? ▾ Answer

To run the parent constructor with the child instance as this, initializing inherited own properties. In classes, super(...) does this.

C.9. What is prototype pollution? ▾ Answer

Attacker-controlled keys like __proto__ or constructor.prototype written onto Object.prototype, so every object inherits malicious properties. Do not merge untrusted JSON onto objects with for...in assignment. Use Object.create(null) maps, or block those keys.

const payload = JSON.parse('{"__proto__":{"isAdmin":true}}');
const user = {};
Object.assign(user, payload);  // dangerous if assign copies prototype
user.isAdmin;  // may be true on some merge helpers — never merge untrusted keys blindly

P. Practical Assignment

L1 L2
Inspect __proto__ / Object.getPrototypeOf. Prefer Object.create experiments over mutating built-in prototypes.

L1 Fundamental

P.1. Warm-up

  1. Log the prototype chain of a plain object and of an array. ▾ Solution 
    const obj = {};
console.log("Object prototype:", Object.getPrototypeOf(obj) === Object.prototype); // true

const arr = [];
console.log("Array prototype: ", Object.getPrototypeOf(arr) === Array.prototype);  // true
console.log("Array -> Object: ", Object.getPrototypeOf(Array.prototype) === Object.prototype); // true
  2. Create an object with Object.create(proto) and inherit a method. ▾ Solution 
    const proto = {
  greet() {
    return `Hello from prototype, ${this.name}!`;
  }
};

const child = Object.create(proto);
child.name = "Bharat";

console.log(child.greet()); // "Hello from prototype, Bharat!"
  3. Show obj.hasOwnProperty vs inherited property. ▾ Solution 
    const parent = { inheritedProp: "from parent" };
const obj = Object.create(parent);
obj.ownProp = "mine";

console.log("Object.hasOwn(ownProp):      ", Object.hasOwn(obj, "ownProp"));       // true
console.log("Object.hasOwn(inheritedProp):", Object.hasOwn(obj, "inheritedProp")); // false
console.log("'inheritedProp' in obj:      ", "inheritedProp" in obj);              // true

P.2. Core tasks

  1. animal proto — dog proto → animal proto with shared speak. ▾ Solution 
    const animal = {
  speak() {
    return `${this.name} makes a sound.`;
  }
};

const dog = Object.create(animal);
dog.name = "Rex";
dog.bark = function() {
  return `${this.name} barks loudly!`;
};

console.log(dog.speak()); // Inherited from animal: "Rex makes a sound."
console.log(dog.bark());  // Own method: "Rex barks loudly!"
  2. constructor link — Set up constructor.prototype and new instances; check .constructor. ▾ Solution 
    function Person(name) {
  this.name = name;
}

Person.prototype.sayHi = function() {
  return `Hi, I am ${this.name}`;
};

const p1 = new Person("Bharat");
console.log(p1.sayHi()); // "Hi, I am Bharat"
console.log(p1.constructor === Person); // true
console.log(Object.getPrototypeOf(p1) === Person.prototype); // true
  3. class desugar — Rewrite a tiny class as constructor + prototype assignments. ▾ Solution 
    // ES6 class:
// class Counter { constructor(start) { this.val = start; } inc() { return ++this.val; } }

// Desugared to constructor + prototype:
function Counter(start) {
  this.val = start;
}

Counter.prototype.inc = function() {
  return ++this.val;
};

const c = new Counter(5);
console.log("Desugared inc():", c.inc()); // 6
console.log("Desugared inc():", c.inc()); // 7
  4. own keys — List own vs inherited keys with Object.keys / for...in caution. ▾ Solution 
    const protoObj = { inheritedA: 1 };
const instance = Object.create(protoObj);
instance.ownB = 2;
instance.ownC = 3;

console.log("Own keys (Object.keys):", Object.keys(instance)); // ["ownB", "ownC"]

const allKeys = [];
for (const key in instance) {
  allKeys.push(key);
}
console.log("All enumerable keys (for...in):", allKeys); // ["ownB", "ownC", "inheritedA"]

L2 Intermediate

P.3. Challenge

  1. null prototype dict — Object.create(null) map; show no inherited toString. ▾ Solution 
    // Object without prototype (clean dictionary with no inherited properties)
const cleanDict = Object.create(null);
cleanDict["data"] = 100;

console.log("cleanDict.data:        ", cleanDict.data);        // 100
console.log("cleanDict.toString:    ", cleanDict.toString);    // undefined
console.log("cleanDict.__proto__:   ", cleanDict.__proto__);   // undefined
console.log("Object.getPrototypeOf: ", Object.getPrototypeOf(cleanDict)); // null
  2. do not extend Array.prototype — Write a comment why mutating built-ins is risky; implement a standalone helper instead. ▾ Solution 
    /*
Why modifying built-in prototypes (e.g. Array.prototype) is dangerous:
1. Namespace collisions: Another library or future ECMAScript version may define the same method with different semantics.
2. Incompatible behavior: Third-party code iterating with for...in may break if methods are added without being non-enumerable.
3. Unintended side-effects: Hard to trace bugs across large teams and dependency trees.
*/

// Instead of monkey-patching Array.prototype.last(), use a standalone helper:
function getLastElement(arr) {
  return arr[arr.length - 1];
}

console.log("Last element:", getLastElement([10, 20, 30])); // 30
