1. Introduction

L1 Fundamental

1.1. What are regular expressions?

  • A regular expression describes a pattern in text. In JavaScript it is a RegExp object (File 02). You use it to test, search, extract, or replace in strings (File 09).

1.2. Default rules and how to study this file

  • Default rule today: prefer a literal /pattern/flags when the pattern is fixed. Use new RegExp(string, flags) only when the pattern is built at runtime. Always think about the g flag and lastIndex.
  • After reading section 2, complete P. Practical Assignment in 10-practice.js before File 11. Review C. Common questions.

2. Regular expressions

L1 L2

L1 Fundamental

2.1. Literal vs constructor

const lit = /hello/i;
const dyn = new RegExp("hello", "i");

lit.test("Hello");  // true
  • Escape \\ in constructor strings: new RegExp("\\\\d+") equals /\d+/.

2.2. Common pattern pieces

PieceMeans
.Any char except newline (unless s)
\d \w \sDigit, word char, whitespace
^ $Start / end of string (or line with m)
* + ? {n,m}Quantifiers
[abc] [^0-9]Character class / negated
(x) (?:x)Capture / non-capturing group
a|bAlternation

L1 Fundamental

2.3. Flags

FlagMeaning
gGlobal — all matches; advances lastIndex
iIgnore case
mMultiline — ^/$ per line
sDotall — . matches newline
uUnicode (code points, \p{...})
ySticky — match only at lastIndex
dGenerate match indices — adds indices array with start/end slice offsets (ES2022)
vUnicode sets — set operations like intersection in character classes (ES2024)

2.4. RegExp methods

/\d+/.test("id-42");     // true
const re = /(\d+)/;
re.exec("id-42");        // ["42", "42", index, input, groups]

const g = /\d+/g;
g.exec("a1 b22");        // ["1"]
g.lastIndex;             // 2
g.exec("a1 b22");        // ["22"]
  • With g, reuse of the same RegExp object is stateful. Prefer matchAll or a fresh literal in a loop.

2.5. String methods

const s = "Price: $12 and $3";

s.match(/\d+/);          // ["12"] — first only
[...s.matchAll(/\d+/g)]; // full match objects for every match
s.search(/\d+/);         // 8 — index, or -1
s.replace(/\d+/, "N");   // first only
s.replaceAll(/\d+/g, "N"); // all — replacement regex must be global
s.split(/\s+/);          // ["Price:", "$12", "and", "$3"]

L2 Intermediate

2.6. Groups, Lookarounds & Match Indices

const re = /(?<year>\d{4})-(?<month>\d{2})/;
const m = re.exec("2026-08");
m[1];              // "2026"
m.groups.year;     // "2026"

"a1b2".replace(/(\d)/g, "[$1]");  // "a[1]b[2]"

// Lookaround Assertions (zero-width matches — do not consume text):
// Positive Lookahead (?=...): matches digits only if followed by "px"
"24px 10em 16px".match(/\d+(?=px)/g); // ["24", "16"]

// Negative Lookahead (?!...): matches digits NOT followed by "px"
"24px 10em 16px".match(/\d+(?!px)/g); // ["10"]

// Positive Lookbehind (?<=...): matches digits preceded by "$"
"$49 €89".match(/(?<=\$)\d+/);         // ["49"]

// Negative Lookbehind (?<!...): matches digits NOT preceded by "$"
"$49 €89".match(/(?<!\$)\b\d+/);       // ["89"]

// ES2022 'd' Flag (Match Indices):
const indexRe = /hello\s+(world)/d;
const res = indexRe.exec("Say hello world!");
console.log(res.indices[0]);           // [4, 15] (start & end of full match)
console.log(res.indices[1]);           // [10, 15] (start & end of group 1)
  • (?:...) groups without capturing. Lookarounds assert without consuming characters.

2.7. lastIndex pitfall

const re = /a/g;
re.test("a");   // true, lastIndex now 1
re.test("a");   // false — starts at index 1
re.lastIndex = 0;

2.8. Catastrophic backtracking

  • Nested or overlapping quantifiers can make the engine try an exponential number of paths on long input — the match may hang (ReDoS risk).
// Dangerous shape: (a+)+ on a long string of a's then a non-match
// /(a+)+$/.test("aaaaaaaaaaaaaaaaaaaaX");  // can be very slow

// Prefer simpler patterns, possessive-style thinking, or non-backtracking alternatives
/^[a-z]+$/.test(input);  // clearer bounds
  • Do not run untrusted user-built regex on large strings. Keep patterns simple; prefer string methods when a regex is unnecessary.

C. Common questions

L1 L2

L1 Fundamental

C.1. Literal or new RegExp? ▾ Answer

Literal when the pattern is known at write time. Constructor when the pattern string is built at runtime.

L1 Fundamental

C.2. Why does the same regex fail the second test? ▾ Answer

The g (or y) flag stores lastIndex on the object. Reset it, or do not reuse a global regex across calls.

C.3. match vs matchAll? ▾ Answer

match with g returns only the matched strings. matchAll needs g and yields match objects including groups.

L2 Intermediate

C.4. How do I escape user input in a pattern? ▾ Answer

Replace regex special characters before new RegExp (or use a well-tested escape helper). Never interpolate raw user text into a regex.

C.5. What is catastrophic backtracking? ▾ Answer

When quantifiers nest or compete, matching can explode in time on certain inputs. Avoid ambiguous nested +/*, bound the input length, and do not evaluate untrusted patterns on large data.

P.1. Warm-up

  1. Write a regex that tests whether a string contains digits. ▾ Solution 
    const hasDigits = /\d/;

console.log(hasDigits.test("user123")); // true

const result = text.replace(/a/g, "A");

console.log(result); // "bAnAnA pAncAke"
  3. Use str.match(/\w+/g) to list words in a short sentence. ▾ Solution 
    const sentence = "JavaScript makes the web interactive!";
const words = sentence.match(/\w+/g);

console.log("Extracted words:", words);
// ["JavaScript", "makes", "the", "web", "interactive"]

P.2. Core tasks

  1. isEmailLite — Simple pattern: local@domain with at least one dot in the domain (not production-grade). Return boolean. ▾ Solution 
    function isEmailLite(email) {
  // Checks non-empty local part, @, domain name, dot, and TLD
  const emailRegex = /^[^\s@]+@[^\s@]+\.[^\s@]+$/;
  return emailRegex.test(email);
}

console.log(isEmailLite("user@example.com")); // true
console.log(isEmailLite("invalid-email@"));   // false
console.log(isEmailLite("plainaddress"));     // false
  2. extractHashtags — From a tweet-like string, return an array of #tags with match or matchAll. ▾ Solution 
    function extractHashtags(tweet) {
  const matches = tweet.match(/#\w+/g);
  return matches || [];
}

const tweet = "Loving #javascript and #webdevelopment! #2026";
console.log(extractHashtags(tweet)); // ["#javascript", "#webdevelopment", "#2026"]
  3. redactDigits — Replace every digit with * using replace. ▾ Solution 
    function redactDigits(card) {
  return card.replace(/\d/g, "*");
}

console.log(redactDigits("Card: 1234-5678-9012-3456"));
// "Card: ****-****-****-****"
  4. escapeUser — Write escapeRegExp(s) that escapes special characters, then build new RegExp(escapeRegExp(user), "i") and search a haystack. ▾ Solution 
    function escapeRegExp(string) {
  // Escapes regex special characters: . * + ? ^ $ { } ( ) | [ ] \
  return string.replace(/[.*+?^${}()|[\]\\]/g, "\\$&");
}

const userQuery = "item (v1.0)? [new]";
const safeRegex = new RegExp(escapeRegExp(userQuery), "g");
console.log("Escaped pattern:", safeRegex.source);
console.log(safeRegex.test("item (v1.0)? [new]")); // true

L2 Intermediate

P.3. Challenge

  1. lastIndex trap — Create const re = /a/g; call re.test("ab") twice; log results and re.lastIndex. Fix it two ways (reset lastIndex; or drop g for test). ▾ Solution 
    const re = /a/g;
const str = "banana";

// /g regex instances maintain state via .lastIndex
console.log(re.test(str), "lastIndex:", re.lastIndex); // true, lastIndex: 2
console.log(re.test(str), "lastIndex:", re.lastIndex); // true, lastIndex: 4
console.log(re.test(str), "lastIndex:", re.lastIndex); // true, lastIndex: 6
console.log(re.test(str), "lastIndex:", re.lastIndex); // false (resets to 0)
console.log("After reset, lastIndex:", re.lastIndex);  // 0
  2. Named or numbered groups — Parse "2026-09-08" into year/month/day with a capturing group pattern; log the parts. ▾ Solution 
    const dateStr = "2026-09-08";

// Using named capture groups:
const dateRegex = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const match = dateStr.match(dateRegex);

if (match) {
  const { year, month, day } = match.groups;
  console.log(`Year: ${year}, Month: ${month}, Day: ${day}`);
  // Year: 2026, Month: 09, Day: 08
}

P.4. Self-check

  • I prefer literals for fixed patterns and constructors for dynamic ones.
  • I watch lastIndex when using the g flag.
  • I escape user input before putting it in a RegExp.
