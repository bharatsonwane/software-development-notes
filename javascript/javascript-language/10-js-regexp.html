1. Introduction

1.1. What are regular expressions?

  • A regular expression describes a pattern in text. In JavaScript it is a RegExp object (File 02). You use it to test, search, extract, or replace in strings (File 09).

1.2. Default rules and how to study this file

  • Default rule today: prefer a literal /pattern/flags when the pattern is fixed. Use new RegExp(string, flags) only when the pattern is built at runtime. Always think about the g flag and lastIndex.

2. Regular expressions

L1 L2

L1 Fundamental

2.1. Literal vs constructor

const lit = /hello/i;
const dyn = new RegExp("hello", "i");

lit.test("Hello");  // true
  • Escape \\ in constructor strings: new RegExp("\\\\d+") equals /\d+/.

2.2. Common pattern pieces

2.3. Flags

FlagMeaning
gGlobal — all matches; advances lastIndex
iIgnore case
mMultiline — ^/$ per line
sDotall — . matches newline
uUnicode (code points, \p{...})
ySticky — match only at lastIndex
vUnicode sets (newer class syntax)

2.4. RegExp methods

/\d+/.test("id-42");     // true
const re = /(\d+)/;
re.exec("id-42");        // ["42", "42", index, input, groups]

const g = /\d+/g;
g.exec("a1 b22");        // ["1"]
g.lastIndex;             // 2
g.exec("a1 b22");        // ["22"]
  • With g, reuse of the same RegExp object is stateful. Prefer matchAll or a fresh literal in a loop.

2.5. String methods

const s = "Price: $12 and $3";

s.match(/\d+/);          // ["12"] — first only
[...s.matchAll(/\d+/g)]; // full match objects for every match
s.search(/\d+/);         // 8 — index, or -1
s.replace(/\d+/, "N");   // first only
s.replaceAll(/\d+/g, "N"); // all — replacement regex must be global
s.split(/\s+/);          // ["Price:", "$12", "and", "$3"]

L2 Intermediate

2.6. Groups

const re = /(?<year>\d{4})-(?<month>\d{2})/;
const m = re.exec("2026-08");
m[1];              // "2026"
m.groups.year;     // "2026"

"a1b2".replace(/(\d)/g, "[$1]");  // "a[1]b[2]"
  • (?:...) groups without capturing. Lookahead (?=...) / lookbehind (?<=...) assert without consuming.

2.7. lastIndex pitfall

const re = /a/g;
re.test("a");   // true, lastIndex now 1
re.test("a");   // false — starts at index 1
re.lastIndex = 0;

2.8. Catastrophic backtracking

  • Nested or overlapping quantifiers can make the engine try an exponential number of paths on long input — the match may hang (ReDoS risk).
// Dangerous shape: (a+)+ on a long string of a's then a non-match
// /(a+)+$/.test("aaaaaaaaaaaaaaaaaaaaX");  // can be very slow

// Prefer simpler patterns, possessive-style thinking, or non-backtracking alternatives
/^[a-z]+$/.test(input);  // clearer bounds
  • Do not run untrusted user-built regex on large strings. Keep patterns simple; prefer string methods when a regex is unnecessary.

C. Common questions

L1 L2

L1 Fundamental

C.1. Literal or new RegExp?

  • A: Literal when the pattern is known at write time. Constructor when the pattern string is built at runtime.

L1 Fundamental

C.2. Why does the same regex fail the second test?

  • A: The g (or y) flag stores lastIndex on the object. Reset it, or do not reuse a global regex across calls.

C.3. match vs matchAll?

  • A: match with g returns only the matched strings. matchAll needs g and yields match objects including groups.

L2 Intermediate

C.4. How do I escape user input in a pattern?

  • A: Replace regex special characters before new RegExp (or use a well-tested escape helper). Never interpolate raw user text into a regex.

C.5. What is catastrophic backtracking?

  • A: When quantifiers nest or compete, matching can explode in time on certain inputs. Avoid ambiguous nested +/*, bound the input length, and do not evaluate untrusted patterns on large data.

P. Practical Assignment

L1 L2
Write patterns yourself. Test with several strings. Reset lastIndex (or avoid reusing global regexes) when using the g flag.

L1 Fundamental

P.1. Warm-up

  1. Write a regex that tests whether a string contains digits.
  2. Use str.replace(/a/g, "A") on a sample sentence.
  3. Use str.match(/\w+/g) to list words in a short sentence.

P.2. Core tasks

  1. isEmailLite — Simple pattern: local@domain with at least one dot in the domain (not production-grade). Return boolean.
  2. extractHashtags — From a tweet-like string, return an array of #tags with match or matchAll.
  3. redactDigits — Replace every digit with * using replace.
  4. escapeUser — Write escapeRegExp(s) that escapes special characters, then build new RegExp(escapeRegExp(user), "i") and search a haystack.

L2 Intermediate

P.3. Challenge

  1. lastIndex trap — Create const re = /a/g; call re.test("ab") twice; log results and re.lastIndex. Fix it two ways (reset lastIndex; or drop g for test).
  2. Named or numbered groups — Parse "2026-09-08" into year/month/day with a capturing group pattern; log the parts.

P.4. Self-check

  • I prefer literals for fixed patterns and constructors for dynamic ones.
  • I watch lastIndex when using the g flag.
  • I escape user input before putting it in a RegExp.
