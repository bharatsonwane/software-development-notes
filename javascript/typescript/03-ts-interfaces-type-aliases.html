2. interface syntax

L1 L2

L1 Fundamental

  • An interface names the shape of an object:
interface User {
  id: number;
  name: string;
  email?: string; // optional
}

const user: User = {
  id: 1,
  name: "Bharat",
};

L1 Fundamental

2.1. Readonly and index signatures

interface Config {
  readonly apiUrl: string;
  timeout: number;
}

interface StringDictionary {
  [key: string]: string;
}

interface NumberDictionary {
  [index: number]: string; // array-like
}

L2 Intermediate

2.2. Call and construct signatures

interface SearchFn {
  (query: string, limit?: number): string[];
}

interface Timestamped {
  createdAt: Date;
}

interface UserConstructor {
  new (name: string): User;
}

3. type aliases

L1 L2

L1 Fundamental

  • type creates an alias for any type — objects, unions, primitives, tuples:
type UserId = number;
type Point = { x: number; y: number };

type Result =
  | { success: true; data: string }
  | { success: false; error: string };

L1 Fundamental

  • Object shapes with type:
type User = {
  id: number;
  name: string;
  email?: string;
};

L2 Intermediate

  • For a plain object shape, interface User and type User = { ... } are often interchangeable.

4. Extending interfaces

L1

L1 Fundamental

  • Interfaces support declaration merging and extends:
interface Person {
  name: string;
}

interface Employee extends Person {
  employeeId: number;
  department: string;
}

const emp: Employee = {
  name: "Bharat",
  employeeId: 101,
  department: "Engineering",
};
  • Multiple inheritance:
interface Named {
  name: string;
}

interface Aged {
  age: number;
}

interface Person extends Named, Aged {}

L1 Fundamental

4.1. Extending with type (intersection)

  • Types use & (intersection), not extends:
type Person = Named & Aged;

type Employee = Person & {
  employeeId: number;
};

5. Interface vs type — when to use which

L1 L2

L1 Fundamental

Prefer interfacePrefer type
Object / class contractsUnions, intersections, tuples
Public API shapes you may extendMapped / conditional types
Declaration merging (e.g. augmenting modules)Aliasing primitives (type ID = string)
React component props (team convention)Utility type compositions

L1 Fundamental

5.1. Practical team guidelines

// Object shape for a domain model
interface Product {
  id: string;
  title: string;
  price: number;
}

// Discriminated union of API outcomes
type ApiResponse<T> =
  | { status: "ok"; data: T }
  | { status: "error"; message: string };

// Reusable primitive alias
type ProductId = string;
  • Many codebases use interface for objects and type for everything else. Consistency within a project matters more than the rule itself.

5.2. Implementing in classes

  • Both work with implements:
interface Serializable {
  serialize(): string;
}

class User implements Serializable {
  constructor(public name: string) {}
  serialize() {
    return JSON.stringify({ name: this.name });
  }
}

L2 Intermediate

5.3. Declaration merging (interfaces only)

interface Window {
  myAppVersion: string;
}

// Later in another file — merges into Window
interface Window {
  theme: "light" | "dark";
}
  • Types cannot be merged — duplicate type Window is an error.

C. Common questions

L1 L2

L1 Fundamental

C.1. What does ? mean on a property? ▾ Answer

Optional — the property may be missing or explicitly undefined (with strictNullChecks).

C.2. Can interfaces describe functions? ▾ Answer

Yes — via call signatures (interface Fn { (x: number): number }) or as a property type.

C.3. What is an index signature? ▾ Answer

Allows arbitrary keys of a given type — [key: string]: number for a string-keyed map.

C.4. Do interfaces exist at runtime? ▾ Answer

No. They are erased during compilation — zero runtime footprint.

L1 Fundamental

C.5. Can I use interface and type together? ▾ Answer

Yes. An interface can extend a type alias, and a type can use an interface in an intersection.

C.6. Which is better for React props? ▾ Answer

Both work. interface Props is common; type Props is equally valid, especially with unions.

L2 Intermediate

C.7. When would I augment an interface? ▾ Answer

Extending third-party types (e.g. adding fields to Express.Request) via declaration merging in a .d.ts file.

C.8. Interface vs type performance? ▾ Answer

No runtime difference. Compile-time performance is similar; pick based on expressiveness and team style.

P.1. Warm-up

  1. Define interface User and create a value. ▾ Solution 
    interface User {
  id: number;
  name: string;
  isActive: boolean;
}

const user1: User = {
  id: 101,
  name: "Bharat",
  isActive: true
};

console.log(user1);
  2. Add optional email?. ▾ Solution 
    interface UserProfile {
  id: number;
  name: string;
  email?: string; // Optional property
}

const withEmail: UserProfile = { id: 1, name: "Alice", email: "alice@example.com" };
const withoutEmail: UserProfile = { id: 2, name: "Bob" };

console.log(withEmail, withoutEmail);
  3. Create type ID = string | number. ▾ Solution 
    type ID = string | number;

function printId(id: ID) {
  console.log("Identifier:", id);
}

printId(101);
printId("usr_abc123");

P.2. Core tasks

  1. extend — Admin extends User. ▾ Solution 
    interface User {
  id: number;
  name: string;
}

interface Admin extends User {
  permissions: string[];
}

const superAdmin: Admin = {
  id: 1,
  name: "Bharat",
  permissions: ["read", "write", "delete"]
};

console.log(superAdmin);
  2. index signature — string-keyed numbers. ▾ Solution 
    interface StringNumberMap {
  [key: string]: number;
}

const inventory: StringNumberMap = {
  apples: 10,
  bananas: 25,
  oranges: 14
};

console.log("Apples in stock:", inventory["apples"]);
  3. readonly — readonly id. ▾ Solution 
    interface Config {
  readonly apiKey: string;
  endpoint: string;
}

const config: Config = {
  apiKey: "secret_key_123",
  endpoint: "https://api.example.com"
};

// config.apiKey = "new_key"; // Error: Cannot assign to 'apiKey' because it is a read-only property
config.endpoint = "https://staging.example.com"; // OK
  4. interface vs type — same shape both ways; comment pick. ▾ Solution 
    // Defining same shape via Interface vs Type:
interface PointInterface {
  x: number;
  y: number;
}

type PointType = {
  x: number;
  y: number;
};

/*
Guideline:
- Use interface for object shapes and class contracts (supports declaration merging and extends).
- Use type for unions, primitives, tuples, and mapped types.
*/

P.3. Challenge

  1. Declaration merging demo. ▾ Solution 
    // Declaration Merging (Interfaces only):
interface WindowSettings {
  title: string;
}

interface WindowSettings {
  width: number;
  height: number;
}

const myWindow: WindowSettings = {
  title: "App",
  width: 1200,
  height: 800
};

console.log(myWindow);
  2. Function type alias. ▾ Solution 
    type MathOperation = (a: number, b: number) => number;

const add: MathOperation = (a, b) => a + b;
const multiply: MathOperation = (a, b) => a * b;

console.log("Add:", add(5, 3));           // 8
console.log("Multiply:", multiply(5, 3)); // 15
