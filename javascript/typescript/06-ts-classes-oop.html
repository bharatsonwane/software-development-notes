3. public, private, protected

L1 L2

L1 Fundamental

ModifierClassSubclassOutside
public (default)YesYesYes
protectedYesYesNo
privateYesNoNo
 
class Animal {
  public name: string;
  protected age: number;
  private secret: string;

  constructor(name: string, age: number) {
    this.name = name;
    this.age = age;
    this.secret = "hidden";
  }
}

class Dog extends Animal {
  bark() {
    console.log(this.name);  // OK — public
    console.log(this.age);   // OK — protected
    // console.log(this.secret); // Error — private
  }
}

L2 Intermediate

3.1. ECMAScript #private fields

  • JS native private fields work alongside TS modifiers:
class Account {
  #balance = 0;

  deposit(amount: number) {
    this.#balance += amount;
  }
}
  • #balance is true runtime private; TS private is compile-time only.

4. implements and extends

L1 L2

L1 Fundamental

4.1. Implementing interfaces

interface Serializable {
  serialize(): string;
}

interface Timestamped {
  createdAt: Date;
}

class Note implements Serializable, Timestamped {
  createdAt = new Date();

  constructor(public body: string) {}

  serialize(): string {
    return JSON.stringify({ body: this.body, createdAt: this.createdAt });
  }
}
  • implements checks that the class satisfies the shape — no code is inherited.

L2 Intermediate

4.2. Extending classes

class Employee extends User {
  constructor(
    id: number,
    name: string,
    public department: string
  ) {
    super(id, name);
  }

  override greet(): string {
    return `${super.greet()} from ${this.department}`;
  }
}
  • Use override (with noImplicitOverride) when replacing a base method.

L3 Advanced

4.3. Structural Class Compatibility & Private Member Isolation

  • Classes are Structurally Typed: If two different classes have identical public shapes, TypeScript treats their instances as mutually interchangeable:
class Customer {
  constructor(public name: string) {}
}
class Supplier {
  constructor(public name: string) {}
}

let c: Customer = new Supplier("Acme Corp"); // OK! Structurally identical!
  • How Private / Protected Members Enforce Nominal Identity: When a class has a private or protected member, TypeScript requires that the private member originates from the exact same declaration. Two distinct classes with identical private fields are incompatible:
class SecureUser {
  private token: string = "secret";
  constructor(public name: string) {}
}
class Imposter {
  private token: string = "secret";
  constructor(public name: string) {}
}

let user: SecureUser;
// user = new Imposter("Eve"); // Error: Types have separate declarations of a private property 'token'!

5. Abstract classes

L1 L2

L1 Fundamental

  • Abstract classes cannot be instantiated directly — they define a partial implementation for subclasses:
abstract class Shape {
  abstract area(): number;

  describe(): string {
    return `Area: ${this.area()}`;
  }
}

class Circle extends Shape {
  constructor(public radius: number) {
    super();
  }

  area(): number {
    return Math.PI * this.radius ** 2;
  }
}

// new Shape(); // Error — abstract
const c = new Circle(5);

5.1. Static members

class MathUtil {
  static PI = 3.14159;

  static clamp(value: number, min: number, max: number): number {
    return Math.min(max, Math.max(min, value));
  }
}

MathUtil.clamp(10, 0, 5); // 5

L2 Intermediate

5.2. Abstract class vs interface

Can have implemented methodsMethods only as signatures (unless default in TS 5+)

L3 Advanced

5.3. Constructor Type Signatures & Factory Patterns

  • Typing Class Constructors: When passing a class as an argument to a factory or dependency injection container, type its construct signature using new:
// Generic Constructor Type (instantiable via new):
type Constructor<T = {}> = new (...args: any[]) => T;

// Abstract Constructor Type (accepts both concrete and abstract classes):
type AbstractConstructor<T = {}> = abstract new (...args: any[]) => T;

function createInstance<T>(cls: Constructor<T>, ...args: any[]): T {
  return new cls(...args);
}

const user = createInstance(User, 1, "Bharat");

C. Common questions

L1 L2

L1 Fundamental

C.1. Does TypeScript support multiple class inheritance? ▾ Answer

No — one extends only. Use implements for multiple interfaces.

C.2. When use abstract class over interface? ▾ Answer

When subclasses share concrete helper methods or fields; interfaces for pure shapes.

C.3. Are classes the preferred pattern in TS? ▾ Answer

Many TS/React codebases favor functions + interfaces over classes. Use classes when modeling stateful entities or extending frameworks (Angular, some ORMs).

C.4. How do generics work with classes? ▾ Answer

class Box<T> { constructor(public value: T) {} } — same as generic functions (File 04).

L2 Intermediate

C.5. Is private enforced at runtime? ▾ Answer

TS private/protected are compile-time only. Use #field for runtime privacy.

C.6. Can classes implement type aliases? ▾ Answer

Yes, if the alias resolves to an object type with members to satisfy.

C.7. What is override for? ▾ Answer

Ensures you intentionally replace a base method — catches typos in method names.

C.8. Class fields vs constructor assignment — any difference? ▾ Answer

Parameter properties are syntactic sugar. Both compile to similar JS depending on target.

P.3. Challenge

  1. Generic Box<T>. ▾ Solution 
    class Box<T> {
  private content: T;

  constructor(value: T) {
    this.content = value;
  }

  get(): T {
    return this.content;
  }

  set(value: T): void {
    this.content = value;
  }
}

const numBox = new Box<number>(100);
console.log("Boxed number:", numBox.get());

const strBox = new Box<string>("Hello");
console.log("Boxed string:", strBox.get());
  2. Structural typing comment. ▾ Solution 
    /*
TypeScript Structural Typing ("Duck Typing") with Classes:
Two classes with identical public shapes are interchangeable in TypeScript, regardless of inheritance hierarchy.
Example:
class Point2D { x: number = 0; y: number = 0; }
class Vector2D { x: number = 0; y: number = 0; }

let p: Point2D = new Vector2D(); // Valid in TypeScript!
Because both share the exact same structural contract { x: number, y: number }.
*/
