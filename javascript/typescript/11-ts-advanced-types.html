2. infer keyword

L2 L3

L2 Intermediate

  • Inside a conditional type, infer declares a type variable to capture part of a matched type:
type ElementType<T> = T extends (infer U)[] ? U : T;

type A = ElementType<string[]>;  // string
type B = ElementType<number>;    // number

L3 Advanced

2.1. Extract function return type (how ReturnType works)

type MyReturnType<T> = T extends (...args: never[]) => infer R ? R : never;

type R = MyReturnType<() => string>; // string

2.2. Extract promise inner type

type Awaited<T> = T extends Promise<infer U> ? U : T;

type Data = Awaited<Promise<{ id: number }>>; // { id: number }
  • Built-in Awaited<T> (TS 4.5+) handles nested promises.

2.3. Tuple element inference

type Head<T> = T extends [infer H, ...unknown[]] ? H : never;
type Tail<T> = T extends [unknown, ...infer Rest] ? Rest : never;

type H = Head<[string, number, boolean]>; // string

3. Template literal types

L2 L3

L2 Intermediate

  • Combine string literal types like template strings:
type EventName = "click" | "focus" | "blur";
type HandlerName = `on${Capitalize<EventName>}`;
// "onClick" | "onFocus" | "onBlur"

3.1. Intrinsic string manipulation types

UtilityExample
Uppercase<S>"hello" → "HELLO"
Lowercase<S>"HELLO" → "hello"
Capitalize<S>"hello" → "Hello"
Uncapitalize<S>"Hello" → "hello"
 
type HttpMethod = "get" | "post";
type Route = `/api/${string}`;
type GetRoute = `/api/${Lowercase<HttpMethod>}`;

3.2. CSS / API route safety

type Color = "red" | "green" | "blue";
type BgClass = `bg-${Color}`;
// "bg-red" | "bg-green" | "bg-blue"

function setBg(className: BgClass) {
  document.body.className = className;
}

L3 Advanced

3.3. Mapped + template combo

type PropEvents<T> = {
  [K in keyof T as `on${Capitalize<string & K>}Change`]: (value: T[K]) => void;
};

type UserEvents = PropEvents<{ name: string; age: number }>;
// { onNameChange: (value: string) => void; onAgeChange: (value: number) => void }

4. Branded types

L2 L3

L2 Intermediate

  • Branded (nominal) types prevent accidentally mixing structurally identical types:
type UserId = string & { readonly __brand: "UserId" };
type OrderId = string & { readonly __brand: "OrderId" };

function createUserId(id: string): UserId {
  return id as UserId;
}

function getUser(id: UserId) {
  return { id, name: "Bharat" };
}

const userId = createUserId("u-123");
const orderId = "o-456" as OrderId;

getUser(userId);   // OK
// getUser(orderId); // Error — OrderId not assignable to UserId

L3 Advanced

4.1. Opaque aliases with helper

declare const __brand: unique symbol;

type Brand<T, B extends string> = T & { readonly [__brand]: B };

type Email = Brand<string, "Email">;
type Password = Brand<string, "Password">;

function register(email: Email, password: Password) {}
  • Forces explicit creation functions — raw strings cannot slip through.

4.2. Units of measure (pattern)

type Meters = number & { readonly unit: "m" };
type Feet = number & { readonly unit: "ft" };

function toMeters(feet: Feet): Meters {
  return (feet * 0.3048) as Meters;
}

5. Type-safe API patterns

L2 L3

L2 Intermediate

5.1. Zod / schema validation at boundaries

  • Types are compile-time only — validate external data at runtime:
import { z } from "zod";

const UserSchema = z.object({
  id: z.number(),
  name: z.string(),
});

type User = z.infer<typeof UserSchema>;

function parseUser(raw: unknown): User {
  return UserSchema.parse(raw);
}
  • Single source of truth: schema → runtime check + inferred TS type.

5.2. Const assertions for API contracts

const ROUTES = {
  home: "/",
  profile: "/profile",
} as const;

type Route = typeof ROUTES[keyof typeof ROUTES];
// "/" | "/profile"

5.3. Checklist for type-safe boundaries

  • Advanced types shine at system boundaries — HTTP, env vars, config keys — where mistakes are costly:
  1. Parse external input (unknown → validated type)
  2. Brand IDs and domain primitives
  3. Discriminate responses with tagged unions (File 05)
  4. Derive types from schemas or const objects — avoid duplicating shapes

L3 Advanced

5.4. End-to-end typed fetch

type ApiRoutes = {
  "/users": { GET: { response: User[] } };
  "/users/:id": { GET: { response: User } };
};

async function apiGet<Path extends keyof ApiRoutes>(
  path: Path
): Promise<ApiRoutes[Path]["GET"]["response"]> {
  const res = await fetch(path as string);
  return res.json();
}

const users = await apiGet("/users"); // User[]
  • Libraries like tRPC, Hono RPC, and OpenAPI generators automate this pattern.

5.5. Builder pattern with chained generics

class QueryBuilder<T extends Record<string, unknown>> {
  where<K extends keyof T>(key: K, value: T[K]): this {
    return this;
  }
}

const q = new QueryBuilder<{ name: string; age: number }>();
q.where("name", "Bharat"); // OK
// q.where("age", "thirty"); // Error

C. Common questions

L2 L3

L2 Intermediate

C.1. What does infer do? ▾ Answer

Captures a type inside a conditional match — "if T looks like X, name this part U".

C.2. Are template literal types only for strings? ▾ Answer

Yes — they operate on string literal types and string manipulation utilities.

C.3. Do branded types exist at runtime? ▾ Answer

No — brands are compile-time only. Runtime validation still needed for untrusted input.

C.4. When are advanced types worth it? ▾ Answer

Libraries, design systems, API clients, large teams. Overkill for small scripts.

C.5. How does Zod relate to TypeScript? ▾ Answer

Zod validates at runtime; z.infer gives static types — bridges the compile/runtime gap.

C.6. What is satisfies (TS 4.9+)? ▾ Answer

Checks value matches type while preserving narrow literal inference — great for config objects:

const palette = {
  red: "#f00",
  green: "#0f0",
} as const satisfies Record<string, string>;

L3 Advanced

C.7. What is the difference between infer and generics? ▾ Answer

Generics declare parameters on types/functions. infer extracts types inside conditional type logic.

C.8. Can template literals be too slow to compile? ▾ Answer

Very large cartesian products of unions can slow tsc. Split types or simplify unions if builds lag.

P.2. Core tasks

  1. infer param type. ▾ Solution 
    // Extracting function parameter types with infer:
type FirstParameter<T> = T extends (arg1: infer P, ...rest: any[]) => any ? P : never;

function authenticate(apiKey: string, strict: boolean) {
  return apiKey.length > 0;
}

type AuthKeyType = FirstParameter<typeof authenticate>; // string
const key: AuthKeyType = "secret_key";
console.log(key);
  2. event name map. ▾ Solution

  login: { username: string };
  logout: { timestamp: number };

type EventHandlers = {
  [K in keyof Events as `on${Capitalize<K>}`]: (data: Events[K]) => void;

/*
Inferred shape:
{
  onLogin: (data: { username: string }) => void;

}

  3. parseUserId brand. ▾ Solution 
    function parseUserId(input: string): UserId {
  const num = parseInt(input, 10);
  if (Number.isNaN(num) || num <= 0) {
    throw new Error("Invalid User ID");
  }
  return num as UserId;
}

const validUserId = parseUserId("105");
console.log("Parsed valid user ID:", validUserId);
  4. fetch Result<T> wrapper. ▾ Solution 
    type Result<T, E = Error> =
  | { success: true; value: T }
  | { success: false; error: E };

async function safeFetch<T>(url: string): Promise<Result<T>> {
  try {
    const res = await fetch(url);
    if (!res.ok) return { success: false, error: new Error(`HTTP ${res.status}`) };
    const data = await res.json();
    return { success: true, value: data };
  } catch (err) {
    return { success: false, error: err instanceof Error ? err : new Error(String(err)) };
  }
}

P.3. Challenge

  1. NonNullable conditional. ▾ Solution 
    // Implementation of NonNullable<T>:
type MyNonNullable<T> = T extends null | undefined ? never : T;

type RawType = string | number | null | undefined;
type CleanType = MyNonNullable<RawType>; // string | number

const val: CleanType = "Hello";
console.log("Clean type value:", val);
  2. type-safe route params. ▾ Solution 
    // Type-Safe Route Parameter Extraction from Route Strings:
type ExtractRouteParams<T extends string> =
  T extends `${string}/:${infer Param}/${infer Rest}`
    ? Param | ExtractRouteParams<`/${Rest}`>
    : T extends `${string}/:${infer Param}`
    ? Param
    : never;

type Params = ExtractRouteParams<"/users/:userId/posts/:postId">;
// "userId" | "postId"

const params: Record<Params, string> = {
  userId: "u123",
  postId: "p456"
};
console.log("Parsed route params:", params);
