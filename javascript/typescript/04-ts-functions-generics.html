2. Typed parameters and return types

L1

L1 Fundamental

function add(a: number, b: number): number {
  return a + b;
}

// Arrow function
const multiply = (a: number, b: number): number => a * b;

// Function type alias
type BinaryOp = (a: number, b: number) => number;
const divide: BinaryOp = (a, b) => a / b;

L1 Fundamental

  • Return type inference usually works; explicit return types help on public APIs and catch accidental changes:
function getUser(id: number) {
  // inferred return type from return statements
  return { id, name: "Bharat" };
}

3. Optional and default parameters

L1

L1 Fundamental

function greet(name: string, greeting?: string): string {
  return `${greeting ?? "Hello"}, ${name}!`;
}

function createUser(name: string, role: string = "member"): User {
  return { id: 1, name, role };
}
  • Optional parameters must come after required ones. Default parameters make the argument optional at the call site.
greet("Bharat");           // "Hello, Bharat!"
greet("Bharat", "Hi");     // "Hi, Bharat!"
createUser("Alex");        // role = "member"

L1 Fundamental

3.1. Rest parameters

function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}

sum(1, 2, 3); // 6

4. Function overloads

L1 L2

L1 Fundamental

  • When one function behaves differently based on argument types, overloads document the contract:
function format(value: string): string;
function format(value: number): string;
function format(value: string | number): string {
  if (typeof value === "number") {
    return value.toFixed(2);
  }
  return value.trim();
}

format("  hi  "); // string
format(3.14159);  // "3.14"

L1 Fundamental

  • Rules:
  • Overload signatures have no body — they declare allowed call shapes.
  • One implementation signature must accept all overload cases (often wider types).

L2 Intermediate

  • Use sparingly — unions and generics often replace overloads:
function identity<T>(value: T): T {
  return value;
}

5. Generic functions and constraints

L1 L2

L1 Fundamental

  • Generics let you write reusable code while preserving type relationships.

5.1. Basic generic function

function first<T>(items: T[]): T | undefined {
  return items[0];
}

first([1, 2, 3]);     // number | undefined
first(["a", "b"]);    // string | undefined

L1 Fundamental

5.2. Multiple type parameters

function pair<A, B>(a: A, b: B): [A, B] {
  return [a, b];
}

pair("id", 42); // [string, number]

5.3. Generic interfaces and classes

interface ApiResult<T> {
  data: T;
  status: number;
}

class Stack<T> {
  private items: T[] = [];
  push(item: T) {
    this.items.push(item);
  }
  pop(): T | undefined {
    return this.items.pop();
  }
}

5.4. Defaults on generics

function createState<T = string>(initial: T): { value: T } {
  return { value: initial };
}

L2 Intermediate

5.5. Constraints with extends

  • Limit what T can be:
function getProperty<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { name: "Bharat", age: 30 };
getProperty(user, "name"); // string
// getProperty(user, "email"); // Error — "email" not in user

5.6. const type parameters (TS 5.0+)

  • Preserve literal types through generic calls:
function asConst<T extends readonly unknown[]>(items: T): T {
  return items;
}

const colors = asConst(["red", "green"] as const);
// type readonly ["red", "green"]

C. Common questions

L1 L2

L1 Fundamental

C.1. What is void vs omitting return type? ▾ Answer

void means the caller should ignore the return value. Functions with no return implicitly return undefined.

C.2. Are generics erased at runtime? ▾ Answer

Yes — like all types, generics do not exist in emitted JavaScript.

L1 Fundamental

C.3. Should I always annotate return types? ▾ Answer

Not for simple internal functions — inference is fine. Annotate exported functions and when you want to lock the contract.

C.4. Can arrow functions be generic? ▾ Answer

Yes: const fn = <T>(x: T): T => x; (in .tsx, use <T,>(x: T) => x to avoid JSX ambiguity).

C.5. What is the difference between (x: number) => void and (x: number): void =>? ▾ Answer

First is a type; second is invalid syntax. Arrow function: (x: number): void => { ... }.

C.6. How do generics relate to any? ▾ Answer

Generics preserve type information through the call. any throws it away.

L2 Intermediate

C.7. When are overloads better than unions? ▾ Answer

When return type depends on input type in a way callers should see clearly (document.getElementById style). Prefer generics when one pattern fits all.

C.8. What does extends keyof T mean? ▾ Answer

K must be one of the keys of T — safe property access.

P.2. Core tasks

  1. Typed rest sum. ▾ Solution 
    function sum(...numbers: number[]): number {
  return numbers.reduce((acc, curr) => acc + curr, 0);
}

console.log("Sum of 4 numbers:", sum(1, 2, 3, 4)); // 10
  2. Overload format for number|string. ▾ Solution 
    // Function Overloads:
function format(val: string): string;
function format(val: number): string;
function format(val: string | number): string {
  if (typeof val === "string") return val.trim().toUpperCase();
  return `$${val.toFixed(2)}`;
}

console.log(format("  typescript  ")); // "TYPESCRIPT"
console.log(format(19.99));            // "$19.99"
  3. Constraint with extends. ▾ Solution 
    interface HasLength {
  length: number;
}

function logLength<T extends HasLength>(item: T): number {
  console.log("Length:", item.length);
  return item.length;
}

logLength("Hello World"); // string has .length
logLength([1, 2, 3, 4]);   // array has .length
  4. void callback example. ▾ Solution 
    function performTask(callback: (status: string) => void) {
  console.log("Performing task...");
  callback("DONE");
}

performTask((status) => {
  console.log("Callback received status:", status);
});

L2 Intermediate

P.3. Challenge

  1. mapArray generic without Array.map. ▾ Solution 
    function mapArray<T, U>(arr: T[], fn: (item: T, index: number) => U): U[] {
  const result: U[] = [];
  for (let i = 0; i < arr.length; i++) {
    result.push(fn(arr[i], i));
  }
  return result;
}

const squared = mapArray([1, 2, 3], (x) => x * x);
console.log("Squared:", squared); // [1, 4, 9]
  2. findById with T extends { id: number }. ▾ Solution 
    function findById<T extends { id: number }>(items: T[], id: number): T | undefined {
  return items.find((item) => item.id === id);
}

const users = [{ id: 1, name: "Bharat" }, { id: 2, name: "Alice" }];
console.log("Found user:", findById(users, 1)); // { id: 1, name: "Bharat" }
