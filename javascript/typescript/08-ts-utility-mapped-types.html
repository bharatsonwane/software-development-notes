1.1. Overview

  • TypeScript ships built-in utility types and lets you build your own with mapped and conditional types.

  • Default rule today: enable strict when you can; prefer precise types over any.

2. Partial, Required, Pick, Omit

L1 L2

L1 Fundamental

2.1. Partial<T>

  • Makes all properties optional — useful for update payloads:
interface User {
  id: number;
  name: string;
  email: string;
}

function updateUser(id: number, changes: Partial<User>) {
  // apply changes
}

updateUser(1, { name: "Alex" }); // OK — only name required

2.2. Pick<T, K> and Omit<T, K>

  • Select or remove properties:
type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string }

type UserWithoutEmail = Omit<User, "email">;
// { id: number; name: string }
  • Common for DTOs and form state:
type CreateUserInput = Omit<User, "id">;
type UserListItem = Pick<User, "id" | "name">;

L2 Intermediate

2.3. Required<T>

  • Opposite of Partial — all properties required:
type RequiredUser = Required<Partial<User>>; // same as User if all keys were optional first

3. Record and ReturnType

L1 L2

L1 Fundamental

3.1. Record<K, V>

  • Object type with keys K and values V:
type Role = "admin" | "member" | "guest";
type Permissions = Record<Role, string[]>;

const perms: Permissions = {
  admin: ["read", "write", "delete"],
  member: ["read", "write"],
  guest: ["read"],
};
  • String-keyed dictionaries:
type StringMap = Record<string, number>;

L2 Intermediate

3.2. ReturnType<T>

  • Extract function return type:
function createUser() {
  return { id: 1, name: "Bharat" };
}

type User = ReturnType<typeof createUser>;
// { id: number; name: string }
  • Related utilities:
type Params = Parameters<typeof createUser>; // tuple of arg types
type Constructor = ConstructorParameters<typeof Date>;

L3 Advanced

3.3. Deconstructing Standard Utility Types (How They Work Internally)

  • Understanding how TypeScript defines utility types in its standard library (lib.es5.d.ts) demystifies the type system:
// Exclude: Drops types in U from union T
type MyExclude<T, U> = T extends U ? never : T;
type T1 = MyExclude<"a" | "b" | "c", "a">; // "b" | "c"

// Extract: Keeps only types assignable to U
type MyExtract<T, U> = T extends U ? T : never;
type T2 = MyExtract<string | number | (() => void), Function>; // () => void

// NonNullable: Strips null and undefined
type MyNonNullable<T> = T extends null | undefined ? never : T;
type T3 = MyNonNullable<string | null | undefined>; // string

// Omit: Built by combining Pick with Exclude!
type MyOmit<T, K extends keyof any> = Pick<T, Exclude<keyof T, K>>;

// Awaited: Recursively unwraps Promise return types
type P = Awaited<Promise<Promise<number>>>; // number

4. Mapped types

L1 L2 L3

L1 Fundamental

4.1. as const and keyof patterns

const CONFIG = {
  apiUrl: "https://api.example.com",
  timeout: 5000,
} as const;

type ConfigKey = keyof typeof CONFIG; // "apiUrl" | "timeout"
type ConfigValues = typeof CONFIG[ConfigKey];

L2 Intermediate

  • A mapped type transforms each property of an existing type:
type Readonly<T> = {
  readonly [K in keyof T]: T[K];
};

type Optional<T> = {
  [K in keyof T]?: T[K];
};

L3 Advanced

4.2. Key remapping (as)

type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K];
};

type UserGetters = Getters<{ name: string; age: number }>;
// { getName: () => string; getAge: () => number }

4.3. Filtering keys

type RemoveId<T> = {
  [K in keyof T as K extends "id" ? never : K]: T[K];
};

L3 Advanced

4.4. Mapped Type Modifiers (-readonly and -?)

  • You can add modifiers using + (default) or strip them using -:
// Strip readonly modifier (make all properties mutable):
type Mutable<T> = {
  -readonly [K in keyof T]: T[K];
};

// Strip optional modifier (make all properties strictly required):
type Concrete<T> = {
  [K in keyof T]-?: T[K];
};

interface LockedUser {
  readonly id: number;
  name?: string;
}

type EditableUser = Mutable<LockedUser>;  // id is now mutable
type CompleteUser = Concrete<LockedUser>; // name is now required (not optional)

5. Conditional types (intro)

L2 L3

L2 Intermediate

  • Conditional types pick types based on a condition: T extends U ? X : Y.
type IsString<T> = T extends string ? true : false;

type A = IsString<string>;  // true
type B = IsString<number>;  // false

5.1. Practical example — nullable unwrap

type NonNullable<T> = T extends null | undefined ? never : T;

type Safe = NonNullable<string | null>; // string

L3 Advanced

5.2. Distributive conditionals

  • When T is a union, conditionals distribute:
type ToArray<T> = T extends unknown ? T[] : never;

type R = ToArray<string | number>;
// string[] | number[]

5.3. infer preview (File 11)

  • Extract types inside conditionals:
type ElementType<T> = T extends (infer U)[] ? U : T;

type Item = ElementType<string[]>; // string
  • Conditional + mapped types power most advanced TS libraries (File 11).

C. Common questions

L1 L2 L3

L1 Fundamental

C.1. When use Pick vs Omit? ▾ Answer

Pick when you need few fields; Omit when you need almost everything except a few.

C.2. Can I combine utilities? ▾ Answer

Yes — Partial<Pick<User, "name" | "email">> is common.

C.3. How does ReturnType help with refactoring? ▾ Answer

Derive types from implementation — change the function, derived types update automatically.

L2 Intermediate

C.4. What does keyof T return? ▾ Answer

Union of property names of T — "id" | "name" | "email" for User.

C.5. What is the difference between mapped types and interfaces? ▾ Answer

Mapped types transform existing types programmatically; interfaces declare shapes directly.

C.6. What does readonly [K in keyof T] do? ▾ Answer

Same keys as T, all marked readonly — like the built-in Readonly<T>.

L3 Advanced

C.7. Are utility types built into the compiler? ▾ Answer

Yes — defined in lib.es5.d.ts and friends; no import needed.

C.8. When do conditional types run? ▾ Answer

At compile time only — they emit no JavaScript.

L1 Fundamental

P.1. Warm-up

  1. Partial and Required. ▾ Solution 
    interface Article {
  title: string;
  body: string;
  tags: string[];
}

// Partial: all fields become optional (useful for update patches)
type ArticleUpdate = Partial<Article>;

// Required: all fields become mandatory
type CompleteArticle = Required<ArticleUpdate>;

const patch: ArticleUpdate = { title: "Updated Title" };
console.log(patch);
  2. Pick and Omit. ▾ Solution 
    interface FullUser {
  id: number;
  name: string;
  email: string;
  passwordHash: string;
}

// Pick specific fields:
type UserSummary = Pick<FullUser, "id" | "name">;

// Omit sensitive fields:
type PublicProfile = Omit<FullUser, "passwordHash">;

const summary: UserSummary = { id: 1, name: "Bharat" };
console.log(summary);
  3. Record scores map. ▾ Solution 
    type UserScores = Record<string, number>;

const leaderboard: UserScores = {
  alice: 98,
  bob: 85,
  charlie: 91
};

console.log("Leaderboard:", leaderboard);

P.2. Core tasks

  1. ReturnType/Parameters. ▾ Solution 
    function createUser(name: string, role: string) {
  return { id: Math.random(), name, role, createdAt: new Date() };
}

type UserParams = Parameters<typeof createUser>; // [name: string, role: string]
type CreatedUser = ReturnType<typeof createUser>; // { id: number, name: string, role: string, createdAt: Date }

const newUser: CreatedUser = createUser("Bharat", "Architect");
console.log(newUser);
  2. Soft<T> mapped optional. ▾ Solution 
    // Custom Mapped Type making all properties optional:
type Soft<T> = {
  [K in keyof T]?: T[K];
};

interface Device {
  brand: string;
  model: string;
}

const partialDevice: Soft<Device> = { brand: "Apple" };
console.log(partialDevice);
  3. readonly mapped type. ▾ Solution 
    // Custom Readonly Mapped Type:
type Immutable<T> = {
  readonly [K in keyof T]: T[K];
};

interface Point {
  x: number;
  y: number;
}

const fixedPoint: Immutable<Point> = { x: 10, y: 20 };
// fixedPoint.x = 15; // Error: Cannot assign to 'x' because it is a read-only property
  4. conditional toy. ▾ Solution 
    // Conditional Type:
type IsString<T> = T extends string ? "yes" : "no";

type A = IsString<string>; // "yes"
type B = IsString<number>; // "no"

console.log("Conditional types evaluated at compile time.");

L2 Intermediate

P.3. Challenge

  1. MyPick implementation. ▾ Solution 
    // Implementation of built-in Pick<T, K>:
type MyPick<T, K extends keyof T> = {
  [P in K]: T[P];
};

interface Car {
  make: string;
  model: string;
  year: number;
}

type SimpleCar = MyPick<Car, "make" | "model">;
const c: SimpleCar = { make: "Honda", model: "Civic" };
console.log(c);
  2. Exclude/Extract on literals. ▾ Solution 
    type Color = "red" | "green" | "blue" | "yellow";

// Exclude: removes types from a union
type PrimaryColors = Exclude<Color, "green" | "yellow">; // "red" | "blue"

// Extract: selects types present in both unions
type Extracted = Extract<Color, "blue" | "purple">; // "blue"

console.log("Exclude & Extract computed.");
