1. Introduction

L1

L1 Fundamental

1.1. Overview

  • TypeScript is JavaScript with an optional static type system. Your .ts files compile to plain .js that runs anywhere JavaScript runs.
  • TypeScript catches many bugs before runtime — wrong property names, missing arguments, incorrect return types.
// app.ts
const name: string = "Bharat";
const age: number = 30;

function greet(person: string): string {
  return `Hello, ${person}!`;
}

1.2. Default rules and how to study this file

  • Default rule today: enable strict when you can; prefer precise types over any.

2. What TypeScript adds to JavaScript

L1

L1 Fundamental

  • JavaScript is dynamically typed — types are checked at runtime (or not at all):
function add(a, b) {
  return a + b;
}
add("1", 2); // "12" — probably not what you wanted
  • TypeScript is statically typed — types are checked at compile time:
function add(a: number, b: number): number {
  return a + b;
}
add("1", 2); // Error at compile time: Argument of type 'string' is not assignable to parameter of type 'number'

2.1. Key benefits

BenefitWhat it means
Early error detectionTypos and wrong types fail in the editor / tsc, not in production
Better toolingAutocomplete, go-to-definition, safe refactors
Self-documenting codeTypes describe the shape of data and APIs
Gradual adoptionAdd types file-by-file; .js can coexist with .ts

2.2. What TypeScript is not

  • Not a new runtime — browsers and Node still execute JavaScript.
  • Not a guarantee of zero bugs — logic errors still slip through.
  • Not required everywhere — you can use any or plain .js when migrating.

L1 Fundamental

2.3. TypeScript vs JavaScript relationship & Compiler Pipeline

TypeScript Source Code (.ts / .tsx)
        │
        ▼  1. Scanner (Lexer creates token stream)
        ▼  2. Parser (Builds Abstract Syntax Tree / AST)
        ▼  3. Binder (Maps identifier symbols to declarative scopes)
        ▼  4. Checker (Resolves types, enforces assignability, computes errors)
        ▼  5. Emitter (Emits clean JavaScript, .d.ts declarations, & source maps)
        │
        ▼
Pure JavaScript (.js) — Types Completely Erased
        │
        ▼
Browser / Node.js / V8 Engine
  • Type Erasure (Zero Runtime Cost): All TypeScript types, interfaces, type aliases, and generic parameters are completely erased during emit. Types exist solely for development and build verification. At runtime, JavaScript has zero memory or execution overhead from TypeScript, but also means types cannot be inspected via runtime reflection.
  • Every valid JavaScript program is syntactically valid TypeScript (with allowJs). TypeScript adds type syntax; it does not alter JavaScript runtime semantics.

3. Installing and compiling (tsc)

L1

L1 Fundamental

3.1. Install locally in a project

npm init -y
npm install typescript --save-dev
npx tsc --version
  • Global install is optional; project-local TypeScript keeps teams on the same version:
npm install -g typescript   # optional
tsc --version

3.2. First compile

  • Create hello.ts:
const message: string = "Hello, TypeScript!";
console.log(message);
  • Compile:
npx tsc hello.ts          # produces hello.js
node hello.js

L1 Fundamental

3.3. Watch mode

  • Recompile on every save:
npx tsc --watch
# or
npx tsc -w

3.4. Where output goes

Flag / configEffect
tsc file.tsEmits file.js next to source
"outDir": "./dist"All compiled files go to dist/
"noEmit": trueType-check only (common with Vite/Next — bundler emits JS)
  • Modern apps often use Vite, Next.js, or esbuild to transpile TS; tsc is still used for type-checking (tsc --noEmit).

L2 Intermediate

3.5. Modern Execution Runners (tsx, ts-node & Node 22+)

  • Direct execution without manual compile: Tools like tsx (powered by esbuild) execute TypeScript files instantly in memory during development:
# Run directly with zero build config:
npx tsx src/index.ts

# Watch mode development:
npx tsx watch src/index.ts
  • Native Node.js 22.6+ Type Stripping: Modern Node.js can execute TypeScript files directly without any third-party compiler via built-in type stripping:
# Native Node 22.6+ / 23+ (No tsc or tsx required!):
node --experimental-strip-types src/index.ts
  • Node strips all type syntax in memory and passes pure JavaScript directly to the V8 engine!

4. tsconfig.json basics

L1

L1 Fundamental

  • Initialize a config file:
npx tsc --init
  • Minimal example:
{
  "compilerOptions": {
    "target": "ES2020",
    "module": "ESNext",
    "strict": true,
    "esModuleInterop": true,
    "skipLibCheck": true,
    "outDir": "./dist",
    "rootDir": "./src"
  },
  "include": ["src/**/*"],
  "exclude": ["node_modules", "dist"]
}

L1 Fundamental

4.1. Important compiler options

OptionPurpose
targetJS version emitted (ES2020, ESNext, …)
moduleModule system for output (CommonJS, ESNext, …)
strictEnables strict type-checking (recommended)
noEmitCheck types without writing .js files
jsxHow to handle .tsx (react-jsx, preserve, …)
moduleResolutionHow TS resolves imports (node, bundler)
baseUrl / pathsPath aliases (File 09)

4.2. include and exclude

{
  "include": ["src"],
  "exclude": ["**/*.test.ts", "node_modules"]
}
  • Only files matched by include (and not exclude) are part of the project.

4.3. Strict mode

  • "strict": true turns on a bundle of checks. The most important:
  • strictNullChecks — null / undefined must be handled explicitly
  • noImplicitAny — variables need types or inferrable values
  • strictFunctionTypes — safer function parameter checking
  • Start with strict enabled on new projects.

L2 Intermediate

4.4. Essential Production Flags

FlagWhy It Matters in Production
"isolatedModules": trueEnsures code can be safely transpiled by single-file tools (Babel, SWC, esbuild, Vite). Disallows ambient const enums and ambiguous type re-exports.
"verbatimModuleSyntax": true(TS 5.0+) Enforces clear separation: value imports are always emitted as JS imports, while import type is completely elided. Prevents circular bundling bugs.
"noEmitOnError": truePrevents tsc from emitting output JS files when compilation errors exist. Ensures broken builds never slip into production.
"skipLibCheck": trueSkips type checking of all .d.ts files inside node_modules. Drastically speeds up compilation times without sacrificing your app's type safety.

5. Type annotations on variables

L1 L2

L1 Fundamental

  • A type annotation tells TypeScript what shape a value must have.

5.1. Basic annotations

let count: number = 0;
let title: string = "Notes";
let active: boolean = true;

L1 Fundamental

5.2. Type inference

  • When you initialize a variable, TypeScript often infers the type — no annotation needed:
let count = 0;        // inferred as number
const title = "Notes"; // inferred as string (literal type "Notes" — widened to string on `let` reassignment context)
  • Prefer inference when the type is obvious; add annotations when it helps readability or when inference is too wide.
// Explicit when empty — TS cannot infer usefully
let items: string[] = [];

// Explicit for function boundaries (File 04)
function parseId(raw: string): number {
  return Number(raw);
}

5.3. Annotating arrays and objects (preview)

const tags: string[] = ["ts", "js"];
const scores: number[] = [90, 85];

const point: { x: number; y: number } = { x: 10, y: 20 };
  • Interfaces and type aliases (File 03) replace inline object shapes in larger codebases.

5.4. Comments that strip types (@ts-check in JS)

  • In plain .js files you can opt into checking:
// @ts-check
/** @type {string} */
let name = "Bharat";
  • For new code, prefer .ts files.

L2 Intermediate

5.5. const vs let

const PI = 3.14;           // number
let status = "pending";    // string

const user = { name: "Bharat" }; // { name: string }
user.name = "Alex";        // OK — object is mutable
// user = {}              // Error — cannot reassign const

C. Common questions

L1 L2

L1 Fundamental

C.1. Does TypeScript slow down my app? ▾ Answer

No. Types are erased at compile time. Zero runtime cost from typing.

C.2. What file extensions does TypeScript use? ▾ Answer

.ts for TypeScript; .tsx when JSX is included (React).

C.3. Is TypeScript a superset of JavaScript? ▾ Answer

Practically yes — valid JS (with minor config caveats) is valid TS. TS adds types and a few extra syntax features (enum, interface, etc.).

L1 Fundamental

C.4. Do I need to annotate every variable? ▾ Answer

No. Use inference for locals; annotate function parameters, return types, and public APIs when it clarifies intent.

C.5. Can I use TypeScript without tsconfig.json? ▾ Answer

Yes for single files (tsc file.ts). Real projects should use tsconfig.json for consistent options.

C.6. What does strict: true do? ▾ Answer

Enables the strictest family of checks. Recommended for new projects; migrating old code may require fixing many errors first.

C.7. How do I run TypeScript directly without compiling manually? ▾ Answer

Use tsx or ts-node for scripts; use a bundler/dev server (Vite, Next) for apps. Production still runs compiled JS.

L2 Intermediate

C.8. What is the difference between tsc and Babel/esbuild? ▾ Answer

tsc type-checks and can emit JS. Babel/esbuild/Vite transpile TS fast but often ignore type errors unless you run tsc --noEmit separately.
