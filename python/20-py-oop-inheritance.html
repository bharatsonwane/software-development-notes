1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Real-world systems are built from complex networks of interconnected entities. Object-Oriented Programming establishes relationships between classes through two fundamental architectures:
    1. HAS-A Relationship (Composition & Aggregation): An object contains or holds references to other objects.
    2. IS-A Relationship (Inheritance): A specialized child class inherits state and behavior from a generic parent class.
  • Python provides native support for Multiple Inheritance, resolved gracefully using the C3 Linearization Algorithm (Method Resolution Order / MRO) and cooperative super().

2. HAS-A relationship (composition / aggregation)

L1 L2

L1 Fundamental

2.1. Composition vs Aggregation

RelationshipCouplingLifecycle DependencyExample
Composition (Strong HAS-A) Tightly coupled Child lifecycle depends on Parent. If Parent is destroyed, Child is also destroyed. Car HAS-A Engine. If the car is crushed, its engine is destroyed.
Aggregation (Weak HAS-A) Loosely coupled Child exists independently of Parent. If Parent is destroyed, Child survives. Department HAS-A Professor. If department closes, professor continues to exist.

L2 Intermediate

# Composition Example (Car owns Engine lifecycle):
class Engine:
    def __init__(self, hp):
        self.hp = hp

    def ignite(self):
        return f"{self.hp} HP engine running."

class Car:
    def __init__(self, brand, hp):
        self.brand = brand
        self.engine = Engine(hp)  # Engine created internally inside Car

    def start(self):
        print(f"{self.brand}: {self.engine.ignite()}")

my_car = Car("Porsche", 450)
my_car.start()  # Porsche: 450 HP engine running.
Design Principle: "Favor object composition over class inheritance." Composition gives flexibility to swap components at runtime (dependency injection) without brittle deep inheritance trees.

3. IS-A relationship (inheritance)

L1 L2

L1 Fundamental

3.1. Basic Inheritance Syntax

A child class inherits all accessible attributes and methods of its parent class:

class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        return "Some generic sound"

# Dog IS-A Animal:
class Dog(Animal):
    def speak(self):
        return f"{self.name} says Woof!"

d = Dog("Buddy")
print(d.speak())  # Buddy says Woof!

L2 Intermediate

3.2. Type Inspection: isinstance() vs issubclass()

print(isinstance(d, Dog))       # True
print(isinstance(d, Animal))    # True (Dog IS-A Animal)
print(isinstance(d, object))    # True (Everything is an object)

print(issubclass(Dog, Animal))  # True
print(issubclass(Animal, Dog))  # False

4. Types of inheritance

L1 L2

L1 Fundamental

4.1. The 5 Inheritance Architectures in Python

  1. Single Inheritance: One child class inherits from one parent class (B(A)).
  2. Multilevel Inheritance: A chain of inheritance (C(B) where B(A)).
  3. Hierarchical Inheritance: Multiple children inherit from a single parent (B(A), C(A)).
  4. Multiple Inheritance: One child class inherits directly from two or more parent classes (C(A, B)).
  5. Hybrid Inheritance: Combination of two or more inheritance models above.

L2 Intermediate

# Multiple Inheritance Example:
class Flyer:
    def fly(self):
        return "Soaring in the sky"

class Swimmer:
    def swim(self):
        return "Swimming in the water"

# Duck inherits from BOTH Flyer and Swimmer:
class Duck(Flyer, Swimmer):
    def quack(self):
        return "Quack quack!"

d = Duck()
print(d.fly())    # Soaring in the sky
print(d.swim())   # Swimming in the water
print(d.quack())  # Quack quack!

5. Method Resolution Order (MRO)

L1 L2

L1 Fundamental

5.1. The Diamond Problem & C3 Linearization

The Diamond Problem: If Class D inherits from B and C, and both B and C inherit from A, which method executes when calling D.action()? Python resolves this deterministically using the C3 Linearization Algorithm:
  • Subclasses are checked before their parents.
  • Multiple parents are searched in the exact order listed in the class header.
  • Monotonicity is preserved (a class will never be visited twice).

L2 Intermediate

5.2. Inspecting MRO

class A:
    def greet(self):
        return "A"

class B(A):
    def greet(self):
        return "B"

class C(A):
    def greet(self):
        return "C"

class D(B, C):
    pass

d = D()
print("Greets as:", d.greet())  # B (Because B appears before C in class D(B, C))

# Inspecting MRO tuple:
print("MRO for Class D:")
for cls in D.__mro__:
    print(" ", cls.__name__)
# Order: D -> B -> C -> A -> object

6. super() function

L1 L2

L1 Fundamental

6.1. Constructor Chaining with super()

super() returns a proxy object delegating method calls to parent classes in the MRO:

class Person:
    def __init__(self, name, age):
        self.name = name
        self.age = age

class Employee(Person):
    def __init__(self, name, age, emp_id, salary):
        # Delegate name and age initialization to Person:
        super().__init__(name, age)
        self.emp_id = emp_id
        self.salary = salary

emp = Employee("Bharat", 29, 1001, 95000.0)
print(f"{emp.name} (ID: {emp.emp_id}) is {emp.age} years old.")

L2 Intermediate

6.2. Cooperative Multiple Inheritance

In multiple inheritance, super() does not simply call the parent class; it calls the next class in the MRO chain:

class Base:
    def __init__(self):
        print("Base __init__")

class MixinA(Base):
    def __init__(self):
        super().__init__()
        print("MixinA __init__")

class MixinB(Base):
    def __init__(self):
        super().__init__()
        print("MixinB __init__")

class Combined(MixinA, MixinB):
    def __init__(self):
        super().__init__()
        print("Combined __init__")

# MRO: Combined -> MixinA -> MixinB -> Base -> object
c = Combined()
# Output order:
# Base __init__
# MixinB __init__
# MixinA __init__
# Combined __init__

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between Composition and Inheritance? ▾ Answer
  • Inheritance (IS-A): A Dog IS-A Animal. Extends behavior from a base class. Creates tight compile-time coupling. Use when true substitutability (Liskov Substitution Principle) applies.
  • Composition (HAS-A): A Car HAS-A Engine. Assembles complex behavior by containing references to other components. Allows swapping implementations dynamically at runtime.
C.2. How does Python solve the Diamond Problem in Multiple Inheritance? ▾ Answer

Python resolves it using the C3 Linearization Algorithm to construct a linear Method Resolution Order (MRO). If both parent classes inherit from a common ancestor, C3 ensures the common ancestor is visited only after both parent branches have been traversed.

C.3. Why does super() not always call the immediate parent class? ▾ Answer

In multiple inheritance, super() does not mean "call my parent." It means "call the next class in the active instance's MRO".

In cooperative multiple inheritance, calling super() in one sibling mixin will actually invoke the other sibling mixin if it follows it in the MRO list.

C.4. What is the root base class of all classes in Python 3? ▾ Answer

The built-in object class. In Python 3, writing class MyClass: implicitly inherits from class MyClass(object):. It provides default implementations for __str__, __repr__, __eq__, and __hash__.

L2 Intermediate

C.5. What causes a TypeError: Cannot create a consistent method resolution order (MRO)? ▾ Answer

This error occurs when the inheritance graph creates an impossible cyclic or contradictory hierarchy that violates C3 linearization rules (e.g. attempting class A(B, C): pass when C is already a subclass of B). Python rejects such class definitions at definition time.

C.6. What are Mixins in Python? ▾ Answer

A Mixin is a lightweight class that provides a specific set of reusable helper methods to other classes via multiple inheritance. Mixins are not intended to be instantiated on their own and typically do not define an __init__ constructor (e.g. JSONSerializableMixin, LoggableMixin).

C.7. How does issubclass(bool, int) evaluate and why? ▾ Answer

issubclass(bool, int) returns True. In Python, the bool type was implemented as a direct subclass of int for historical backwards compatibility. True has value 1 and False has value 0.

C.8. Why should you always call super().__init__() in subclasses? ▾ Answer

If a subclass defines its own __init__ method, Python does not automatically invoke the parent class's __init__. Failing to explicitly call super().__init__(...) leaves parent attributes uninitialized, resulting in unexpected AttributeError failures when calling inherited methods.

    class TimestampMixin:
    def __init__(self, *args, **kwargs):
        import time
        self.created_at = time.time()
        super().__init__(*args, **kwargs)

class AuditableMixin:
    def audit_log(self):

class UserAccount(TimestampMixin, AuditableMixin):

        self.username = username
        self.email = email
        super().__init__()

        super().__init_subclass__(**kwargs)

class CSVExporter(BaseExporter, format_name="csv"):

class JSONExporter(BaseExporter, format_name="json"):
    pass

print("Auto-registered Exporters:", BaseExporter.registry)
