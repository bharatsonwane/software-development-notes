  1. Skim the section map; write a 3-bullet comment summarizing Importance of generators and demos. ▾ Solution 
    # Summary of Importance of Generators:
# 1. Generators use 'yield' to produce values on-demand (lazy evaluation), maintaining internal state.
# 2. Massive memory savings: they do not hold entire sequences in memory like lists.
# 3. Generators implement the iterator protocol (__iter__ and __next__) automatically.
  2. Create a tiny example related to Advantages and limitations and print the result. ▾ Solution 
    # Advantages and limitations:
# Advantage: Infinite streams and large datasets handled with O(1) memory.
# Limitation: Generator items can only be consumed once; cannot index or slice directly.

def count_up(start=0):
    n = start
    while True:
        yield n
        n += 1

gen = count_up(1)
print(next(gen))  # 1
print(next(gen))  # 2
print(next(gen))  # 3

P.2. Core tasks

  1. Task 1: Importance of generators and demos — Write a small working demo (10–20 lines) covering the idea; print outputs. ▾ Solution 
    # Task 1: Importance of generators and demos
def fibonacci_generator(limit):
    """Generate Fibonacci numbers up to limit count."""
    a, b = 0, 1
    count = 0
    while count < limit:
        yield a
        a, b = b, a + b
        count += 1

print("First 8 Fibonacci via generator:")
for num in fibonacci_generator(8):
    print(num, end=" ")
print()
  2. Task 2: Advantages and limitations — Write a small working demo (10–20 lines) covering the idea; print outputs. ▾ Solution 
    # Task 2: Advantages and limitations (Memory comparison demo)
import sys

# List comprehension: builds all 1,000,000 items in memory immediately
list_data = [x * 2 for x in range(1000000)]
print("List size in RAM:", sys.getsizeof(list_data), "bytes")

# Generator expression: computes items lazily on the fly
gen_data = (x * 2 for x in range(1000000))
print("Generator size in RAM:", sys.getsizeof(gen_data), "bytes (O(1) memory!)")
  3. Cheat sheet — Comment 5 key facts about Generators. ▾ Solution 
    # Cheat sheet — 5 Key Facts about Generators:
# 1. Any function containing the 'yield' keyword returns a generator object when called.
# 2. State, local variables, and instruction pointer are suspended between yield invocations.
# 3. Generators raise StopIteration when execution completes or reaches a return statement.
# 4. Generator expressions use parentheses: (x for x in seq) vs [x for x in seq] for lists.
# 5. Generators are single-pass: once exhausted, iterating over them again yields nothing.

  1. Mini project — Combine two topics from this file into one short script related to Generators. ▾ Solution 
    # Mini Project: Streaming CSV Pipeline with Generator Functions
def stream_log_lines():
    logs = [
        "2026-09-13 12:00:01 INFO Server startup",
        "2026-09-13 12:01:15 ERROR Database connection pool exhausted",
        "2026-09-13 12:02:00 WARN Disk space below 15%",
        "2026-09-13 12:03:22 ERROR Payment gateway timeout",
        "2026-09-13 12:04:10 INFO Healthcheck OK"
    ]
    for line in logs:
        yield line

def filter_errors(lines):
    for line in lines:
        if "ERROR" in line:
            yield line

def extract_message(error_lines):
    for line in error_lines:
        yield line.split("ERROR", 1)[1].strip()

# Chain generator pipeline:
pipeline = extract_message(filter_errors(stream_log_lines()))

print("Filtered Error Messages:")
for msg in pipeline:
    print("  ->", msg)
  2. Edge cases — List 3 edge cases or mistakes beginners make; demonstrate at least one safely. ▾ Solution 
    # Generator Pitfalls & Edge Cases:
# 1. Re-using exhausted generator:
gen = (x for x in [1, 2, 3])
list(gen) # [1, 2, 3]
list(gen) # [] (Empty! Already exhausted)

# 2. Catching StopIteration manually:
g = (x for x in [10])
print(next(g)) # 10
# next(g) # Raises StopIteration!
print(next(g, "DEFAULT")) # Safe fallback using default argument
