1. Introduction

L1

L1 Fundamental

1.1. Overview

  • A Dictionary (dict) is Python's built-in associative mapping type that associates unique keys with arbitrary values ({key: value}).
  • Unlike sequences (strings, lists, tuples) which are indexed by sequential numeric positions, dictionary items are accessed via their keys.
  • Since Python 3.7 (language specification guarantee), dictionaries maintain insertion order: iterating through a dictionary yields items in the exact order they were inserted.

1.2. CPython Internals: The Compact Hash Table

Under the Hood (PEP 468 & Python 3.6+): CPython uses an ingenious compact hash table design:
  • The Old Design (pre-3.6): Stored [hash, key, value] directly in a sparse hash table with empty entries, wasting 30–40% memory and having random iteration order.
  • The Modern Compact Design: Uses two arrays:
    1. A dense entries array that stores [hash, key, value] in chronological insertion order.
    2. A sparse indices array of small integer indices mapping the hash code to the index in the entries array.
  • This saves 20% to 25% RAM and provides guaranteed insertion-ordered iteration for free.

L2 Intermediate

2.3. Safe vs Unsafe Key Access: d[key] vs d.get()

Key Access Best Practice:
  • d[key]: Fast lookup. If key is not found, it raises a KeyError. Use this when the key is expected to exist.
  • d.get(key, default=None): Returns the value if found; returns None (or specified default) if missing. Never raises a KeyError.
profile = {"username": "sonwanebr", "tier": "gold"}

# Unsafe access:
print(profile["username"])  # 'sonwanebr'
# print(profile["email"])   # Raises KeyError: 'email'

# Safe access with get():
print(profile.get("email"))                 # None (No error)
print(profile.get("email", "not_provided")) # 'not_provided'

# Membership testing: O(1) constant time on keys
if "tier" in profile:
    print(f"User tier is {profile['tier']}")

3.1. Mutating & Adding Key-Value Pairs

inventory = {"apples": 50, "bananas": 100}

# 1. Direct assignment (Updates existing key or inserts new key):
inventory["apples"] = 75     # Updates 'apples'
inventory["oranges"] = 60    # Inserts 'oranges'

# 2. update() method (merges another dict or iterable of pairs):
inventory.update({"grapes": 40, "bananas": 120})

3.2. Dynamic Default Initialization: setdefault()

d.setdefault(key, default) checks if key exists. If present, it returns its current value. If missing, it inserts key with value default and returns that default:

# Grouping words by their first letter using setdefault:
words = ["apple", "apricot", "banana", "blueberry", "cherry"]
grouped = {}

for w in words:
    grouped.setdefault(w[0], []).append(w)

print("Grouped words:", grouped)
# {'a': ['apple', 'apricot'], 'b': ['banana', 'blueberry'], 'c': ['cherry']}

L2 Intermediate

3.3. Deleting Elements: pop(), popitem(), del, clear()

MethodBehaviorMissing Key Handling
d.pop(k[, default]) Removes key k and returns its value. Returns default if given; otherwise raises KeyError.
d.popitem() Removes and returns last inserted (key, value) pair (LIFO order). Raises KeyError if dictionary is empty.
del d[k] Deletes key k statement-style. Raises KeyError if missing.
d.clear() Empties dictionary in-place. Always safe. 
cache = {"req_1": "OK", "req_2": "FAIL", "req_3": "TIMEOUT"}

# pop():
val = cache.pop("req_2")
print(f"Popped: {val}, Remaining: {cache}")

# pop() with default prevents KeyError:
missing = cache.pop("req_99", "NOT_FOUND")
print("Missing key pop:", missing)  # 'NOT_FOUND'

# popitem() removes last item (LIFO):
last_pair = cache.popitem()
print("Popped item:", last_pair)   # ('req_3', 'TIMEOUT')

3.4. Dictionary View Objects: keys(), values(), items()

These methods return dynamic view objects that reflect changes in the underlying dictionary in real time:

prices = {"pen": 10, "notebook": 50, "marker": 25}

k_view = prices.keys()
v_view = prices.values()
i_view = prices.items()

print("Keys:  ", list(k_view))
print("Values:", list(v_view))

# Views dynamically reflect changes:
prices["eraser"] = 5
print("Keys after update:", list(k_view))  # Automatically includes 'eraser'

# Iterating key-value pairs:
for item, price in prices.items():
    print(f"{item:<10} -> ${price}")

4.1. Dict Comprehension Syntax

Constructs a new dictionary concisely from any iterable:

# Syntax: { key_expr: value_expr for item in iterable if condition }

# Numbers mapped to their squares:
squares = {x: x**2 for x in range(1, 6)}

high_earners = {k: v for k, v in salaries.items() if v >= 80000}
print("High earners:", high_earners)  # {'Alice': 85000, 'Charlie': 95000}

5. Merging and nested collections

L1 L2

L1 Fundamental

5.1. Dictionary Merging in Python 3.9+ (PEP 584)

Python 3.9 introduced the union operator (|) and in-place update operator (|=) for dictionaries. The right-hand operand takes precedence on duplicate keys:

default_cfg = {"host": "localhost", "port": 8080, "timeout": 30}
user_cfg = {"port": 9000, "debug": True}

# 1. Merge operator (|) returns a brand new dictionary:
merged = default_cfg | user_cfg
print("Merged (user overrides default):", merged)
# {'host': 'localhost', 'port': 9000, 'timeout': 30, 'debug': True}

# 2. In-place merge (|=):
default_cfg |= user_cfg
print("In-place updated default_cfg:", default_cfg)

# 3. Older pre-3.9 unpacking method:
unpacked = {**default_cfg, **user_cfg}

L2 Intermediate

5.2. Deep Merging & Nested Dictionaries

# Nested JSON-like record:
company = {
    "org": "TechCorp",
    "departments": {
        "engineering": {"head": "Rahul", "members": 45},
        "marketing": {"head": "Sneha", "members": 15}
    }
}

# Safe nested navigation:
eng_head = company.get("departments", {}).get("engineering", {}).get("head")
print("Engineering Head:", eng_head)  # Rahul

# Merging dictionary configurations with Python 3.9+ '|' merge operator:
base_config = {"ui": {"theme": "light", "fontSize": 14}, "api": "v1"}
user_overrides = {"ui": {"theme": "dark", "fontSize": 14}, "debug": True}

merged_config = base_config | user_overrides
print("Merged Configuration:", merged_config)
# {'ui': {'theme': 'dark', 'fontSize': 14}, 'api': 'v1', 'debug': True}

6.1. Supermarket Inventory & Invoice Generation System

A complete, modular Python application using nested dictionaries for catalog lookup, stock tracking, and invoice generation:

# Supermarket catalog: Item -> {price, stock, unit}
catalog = {
    "101": {"name": "Milk (1L)",     "price": 60.0,  "stock": 25},
    "102": {"name": "Brown Bread",   "price": 45.0,  "stock": 15},
    "103": {"name": "Eggs (Dozen)",  "price": 84.0,  "stock": 40},
    "104": {"name": "Butter (500g)", "price": 275.0, "stock": 10},
    "105": {"name": "Coffee (200g)", "price": 320.0, "stock": 8}
}

# Customer shopping cart: {item_id: quantity_purchased}
cart = {"101": 2, "103": 1, "105": 2}

# Supermarket Invoice Calculation:
subtotal = 0.0
tax_rate = 0.05
line_items = []

for item_id, qty in cart.items():
    if item_id in catalog:
        product = catalog[item_id]
        if qty <= product["stock"]:
            # Deduct inventory stock:
            product["stock"] -= qty
            total_price = qty * product["price"]
            subtotal += total_price
            line_items.append({
                "name": product["name"],
                "qty": qty,
                "unit_price": product["price"],
                "total": total_price
            })

tax = subtotal * tax_rate
grand_total = subtotal + tax

invoice = {
    "items": line_items,
    "subtotal": subtotal,
    "tax": tax,
    "grand_total": grand_total
}

print("=" * 48)
print(f"{'SUPERMARKET TAX INVOICE':^48}")
print("=" * 48)
print(f"{'Item':<18} {'Qty':<6} {'Unit ($)':<10} {'Total ($)':<10}")
print("-" * 48)
for item in invoice["items"]:
    print(f"{item['name']:<18} {item['qty']:<6} {item['unit_price']:<10.2f} {item['total']:<10.2f}")
print("-" * 48)
print(f"{'Subtotal:':<36} ${invoice['subtotal']:.2f}")
print(f"{'Tax (5%):':<36} ${invoice['tax']:.2f}")
print(f"{'Grand Total:':<36} ${invoice['grand_total']:.2f}")
print("=" * 48)

C. Common questions

L1 L2

L1 Fundamental

C.1. Since what Python version are dictionaries ordered, and how is it implemented? ▾ Answer

Dictionaries became ordered by implementation in Python 3.6 (CPython optimization), and became an official language specification guarantee in Python 3.7.

This is implemented via a compact hash table featuring two separate arrays: a dense entries array storing keys, values, and hash codes in chronological insertion order, and a sparse indices array mapping hash codes to indices in the entries array.

C.2. What is the difference between d['key'] and d.get('key')? ▾ Answer
  • d['key']: Direct access. Raises a KeyError if the key is missing from the dictionary.
  • d.get('key', default=None): Safe access. Returns None (or the provided fallback default) when the key does not exist, avoiding exceptions.
C.3. What makes an object eligible to be a dictionary key? ▾ Answer

An object can be a dictionary key if and only if it is hashable:

  1. It implements __hash__() and its hash value remains constant throughout its lifecycle.
  2. It implements __eq__() to allow equality comparison with other keys.

Immutable types (integers, floats, strings, tuples of immutable items, frozensets) are hashable. Mutable types (lists, dicts, sets) are unhashable and raise TypeError: unhashable type.

C.4. How does setdefault() differ from dict.get()? ▾ Answer
  • d.get(k, default): Purely reads from the dictionary. If k is missing, it returns default but does not modify the dictionary.
  • d.setdefault(k, default): Reads and conditionally writes. If k is missing, it inserts d[k] = default in-place and returns that default.

L2 Intermediate

C.5. How does the | union operator in Python 3.9 handle duplicate keys? ▾ Answer

When merging dictionaries using c = a | b, if a key is present in both a and b, the value from the right-hand dictionary (b) takes precedence and overwrites the value from the left-hand dictionary (a).

C.6. Why is iterating over a dictionary and mutating its keys forbidden? ▾ Answer

Adding or removing keys during iteration alters the size of the underlying hash table. This invalidates the dictionary iterator's internal state, raising a RuntimeError: dictionary changed size during iteration.

Safe Solution: Iterate over a snapshot list of the keys using for key in list(d.keys()):.

C.7. What is the difference between collections.defaultdict and standard dict? ▾ Answer

collections.defaultdict is a subclass of dict that accepts a default_factory callable (e.g. int, list, set). When accessing a missing key via d[missing_key], it automatically invokes the factory to initialize the value, eliminating the need for if key not in d: or setdefault() checks.

C.8. Why are dictionary view objects (keys, values, items) advantageous? ▾ Answer

In Python 2, d.keys() constructed and returned a full list in memory ($O(N)$ space). In Python 3, view objects consume $O(1)$ memory by providing a read-through window directly into the dictionary's internal hash table. They dynamically reflect updates without requiring new list allocations and support set-like operations (d1.keys() & d2.keys()).

P.3. Challenge

  1. Challenge 1: Recursive Nested Dictionary Key Flattener — Flatten a deeply nested dictionary into dot-notated keys. ▾ Solution 
    nested = {
    "server": {
        "host": "localhost",
        "port": 8080,
        "auth": {"enabled": True, "token": "secret"}
    },
    "version": 2
}

# Flattening nested dictionary into dot-notated keys using a stack loop:
flattened = {}
stack = [("", nested)]

while stack:
    parent_key, current_dict = stack.pop()
    for k, v in current_dict.items():
        new_key = f"{parent_key}.{k}" if parent_key else k
        if isinstance(v, dict):
            stack.append((new_key, v))
        else:
            flattened[new_key] = v

print("Flattened Dict:", flattened)
# {'version': 2, 'server.host': 'localhost', 'server.port': 8080, ...}
  2. Challenge 2: In-Memory Key-Value Store with TTL (Time-to-Live) — Store and expire keys using dictionary timestamp metadata. ▾ Solution 
    import time

# Implementing TTL (Time-to-Live) expiration using a standard dictionary:
# Key -> (value, expires_at_timestamp)
cache = {}

# Storing a key with 0.1s TTL:
cache["session_123"] = ("user_active", time.time() + 0.1)

# Immediate retrieval:
key = "session_123"
if key in cache:
    val, exp = cache[key]
    if time.time() <= exp:
        print("Immediate get: ", val)  # 'user_active'
    else:
        del cache[key]

time.sleep(0.15)

# Retrieval after expiration:
if key in cache:
    val, exp = cache[key]
    if time.time() <= exp:
        print("After 150ms get:", val)
    else:
        del cache[key]
        print("After 150ms get: None (key expired and evicted!)")
else:
    print("After 150ms get: None (key does not exist)")
