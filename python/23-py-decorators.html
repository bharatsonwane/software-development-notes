1. Introduction

L1

L1 Fundamental

1.1. Overview

In Python, functions are first-class citizens (also known as first-class objects). This means functions can be treated just like integers, strings, or lists: they can be assigned to variables, passed as arguments to other functions, defined inside another function, and returned as values from functions.

A decorator is a design pattern and language feature that allows developers to dynamically modify or extend the behavior of a function, method, or class without directly altering its source code. Decorators represent a cornerstone of idiomatic, clean Python code, widely employed in web frameworks (e.g., Flask routing @app.route, Django authentication @login_required), logging, caching, and rate limiting.

Key Mental Model: A decorator is a callable that takes a function as input, wraps it with additional pre-processing or post-processing logic, and returns the modified wrapper function (or an entirely replacement callable).

1.2. First-Class Functions in Action

To truly understand decorators, you must understand three core properties of first-class functions:

  • Assignment: A function can be assigned to another variable (function aliasing).
  • Higher-Order Functions: A function can accept another function as an argument.
  • Function Returning: A function can create and return another function.
from collections.abc import Callable

# Demonstrating functions as first-class objects
def shout(text: str) -> str:
    return text.upper()

def whisper(text: str) -> str:
    return text.lower()

# 1. Assigned to a variable:
loud_speaker: Callable[[str], str] = shout
print(loud_speaker("hello world"))  # HELLO WORLD

# 2. Passed as an argument to another function:
def greet(func: Callable[[str], str], message: str) -> str:
    # 'func' is executed dynamically
    return func(message)

print(greet(shout, "good morning"))    # GOOD MORNING
print(greet(whisper, "SECRET MESSAGE"))  # secret message

# 3. Returned from another function:
def get_speaker(volume: int) -> Callable[[str], str]:
    if volume > 5:
        return shout
    return whisper

speaker: Callable[[str], str] = get_speaker(8)
print(speaker("testing microphone"))   # TESTING MICROPHONE

1.3. Typing Decorators (ParamSpec & TypeVar, PEP 612)

PEP 612: Parameter Specification Variables (ParamSpec)

Typing a decorator without losing parameter types or return types requires ParamSpec and TypeVar from typing:

from collections.abc import Callable
from typing import ParamSpec, TypeVar
import functools

P = ParamSpec("P")
R = TypeVar("R")

def typed_decorator(func: Callable[P, R]) -> Callable[P, R]:
    @functools.wraps(func)
    def wrapper(*args: P.args, **kwargs: P.kwargs) -> R:
        print("[TRACE] Before calling wrapped function")
        result: R = func(*args, **kwargs)
        print("[TRACE] After calling wrapped function")
        return result
    return wrapper

@typed_decorator
def greet_person(name: str, count: int = 1) -> str:
    return f"Hello, {name}!" * count

print(greet_person("Bharat", count=2))

2. Function aliasing and nested functions

L1 L2

L1 Fundamental

2.1. Function Aliasing

When you define a function in Python using def func(): ..., Python creates a function object in memory and binds the identifier func to that object. Assigning that function identifier to another variable name creates an alias. Both names now reference the exact same underlying function object in memory (sharing the same id()).

from collections.abc import Callable

def calculate_tax(income: float) -> float:
    return income * 0.18

# Aliasing calculate_tax to compute_tax
compute_tax: Callable[[float], float] = calculate_tax

print(id(calculate_tax))  # e.g., 4324785440
print(id(compute_tax))    # 4324785440 (identical memory address)

print(compute_tax(100000.0))      # 18000.0
print(calculate_tax(100000.0))    # 18000.0

# If we delete the original variable name:
del calculate_tax

# The function object is NOT garbage collected because compute_tax still references it!
print(compute_tax(100000.0))      # 18000.0

# Calling calculate_tax now fails because the name was unbound:
# calculate_tax(100000.0)  # NameError: name 'calculate_tax' is not defined
print("'calculate_tax' in globals():", "calculate_tax" in globals())  # False

L2 Intermediate

2.2. Nested (Inner) Functions

A nested function is a function defined inside the body of another enclosing function. Inner functions are not accessible directly from outside the enclosing function unless explicitly returned.

def outer_function(message: str) -> None:
    print("Outer function starting...")

    def inner_function() -> None:
        # Inner function has access to the enclosing scope variable 'message'
        print(f"Inner function received: {message}")

    # Calling inner function locally inside outer
    inner_function()
    print("Outer function finished.")

outer_function("Hello from enclosing scope!")

# Attempting to access inner_function directly from outside fails:
# inner_function()  # NameError: name 'inner_function' is not defined
print("'inner_function' in globals():", "inner_function" in globals())  # False

2.3. Closures: The Heart of Decorators

A closure is a nested function that remembers and retains access to variables in its enclosing lexical scope even after the outer function has finished executing and its stack frame has been dismantled.

For a closure to exist, three conditions must be met:

  1. There must be a nested function (a function inside another function).
  2. The nested function must refer to a variable defined in the enclosing function scope.
  3. The enclosing function must return the nested function object.
from collections.abc import Callable

def make_multiplier(factor: int) -> Callable[[int], int]:
    # 'factor' lives in the outer function's local scope
    def multiply(number: int) -> int:
        # 'multiply' captures 'factor' from its enclosing environment
        return number * factor

    return multiply  # Return the inner function object without calling it

# Create closures with different captured state:
double: Callable[[int], int] = make_multiplier(2)
triple: Callable[[int], int] = make_multiplier(3)

print(double(10))  # 20
print(double(25))  # 50

print(triple(10))  # 30
print(triple(25))  # 75

# Inspecting closure cells:
print("double.__closure__:", double.__closure__)
if double.__closure__:
    print("Captured cell value:", double.__closure__[0].cell_contents)  # 2
if triple.__closure__:
    print("triple captured value:", triple.__closure__[0].cell_contents)  # 3

3. Introduction to decorators

L1 L2

L1 Fundamental

3.1. Decorator Anatomy and Syntax

A decorator is a function that takes another function as an argument, defines a wrapper function that adds behavior before and/or after calling the original function, and returns that wrapper function.

Python provides the @decorator_name syntax sugar, introduced in PEP 318. Writing @my_dec right above a function definition is syntactically equivalent to func = my_dec(func).

from collections.abc import Callable

# 1. Defining the decorator
def announce(func: Callable[[], None]) -> Callable[[], None]:
    def wrapper() -> None:
        print("--- Before executing the function ---")
        func()
        print("--- After executing the function ---")
    return wrapper

# 2. Applying using the @ syntax
@announce
def say_hello() -> None:
    print("Hello, Python Developers!")

say_hello()

# Equivalent manual assignment without the @ symbol:
def say_bye() -> None:
    print("Goodbye everyone!")

say_bye = announce(say_bye)
say_bye()

L2 Intermediate

3.2. Supporting Arbitrary Arguments with *args and **kwargs

In real-world applications, functions accept various numbers of positional and keyword arguments, and return values. If the wrapper function does not accept *args, **kwargs or forgets to return the result of func(*args, **kwargs), the decorated function will either crash with a TypeError or return None.

from collections.abc import Callable
from typing import Any

def debug_decorator(func: Callable[..., Any]) -> Callable[..., Any]:
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        print(f"[DEBUG] Executing {func.__name__} with args={args}, kwargs={kwargs}")
        # Always capture and return the original function's result!
        result: Any = func(*args, **kwargs)
        print(f"[DEBUG] Finished {func.__name__}, returned: {result}")
        return result
    return wrapper

@debug_decorator
def multiply_and_offset(x: int, y: int, offset: int = 0) -> int:
    return (x * y) + offset

output: int = multiply_and_offset(5, 4, offset=10)
print("Final result:", output)  # 30

3.3. Preserving Metadata with functools.wraps

When a function is wrapped by a decorator, its identity (like __name__, __doc__, and function signature) is replaced by the wrapper's identity. This can break debugging tools, linters, documentation generators, and introspective frameworks.

The standard library provides @functools.wraps to automatically copy the original function's metadata to the wrapper function.

import functools
from collections.abc import Callable
from typing import Any

# WRONG WAY: Without functools.wraps
def flawed_decorator(func: Callable[..., Any]) -> Callable[..., Any]:
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        """This is the wrapper docstring."""
        return func(*args, **kwargs)
    return wrapper

@flawed_decorator
def calculate_area(radius: float) -> float:
    """Calculates the area of a circle given its radius."""
    import math
    return math.pi * radius * radius

print("Without @wraps:")
print("Function name:", calculate_area.__name__)  # 'wrapper' (LOST!)
print("Docstring:    ", calculate_area.__doc__)   # 'This is the wrapper docstring.' (LOST!)

# RIGHT WAY: With functools.wraps
def proper_decorator(func: Callable[..., Any]) -> Callable[..., Any]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        return func(*args, **kwargs)
    return wrapper

@proper_decorator
def calculate_perimeter(radius: float) -> float:
    """Calculates the perimeter of a circle given its radius."""
    import math
    return 2 * math.pi * radius

print("\nWith @wraps:")
print("Function name:", calculate_perimeter.__name__)  # 'calculate_perimeter' (PRESERVED)
print("Docstring:    ", calculate_perimeter.__doc__)   # 'Calculates the perimeter...' (PRESERVED)
print("Original func:", calculate_perimeter.__wrapped__) # Access original un-wrapped function

L1 L2

L1 Fundamental

4.1. Pattern 1: Performance Execution Timing

Measuring the runtime of critical operations without polluting the business logic is one of the most common applications of decorators.

import time
import functools
from collections.abc import Callable
from typing import Any

def timer(func: Callable[..., Any]) -> Callable[..., Any]:
    """Decorator to measure and log execution duration."""
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        start_time: float = time.perf_counter()
        result: Any = func(*args, **kwargs)
        end_time: float = time.perf_counter()
        run_duration: float = end_time - start_time
        print(f"[TIMER] '{func.__name__}' completed in {run_duration:.6f} seconds")
        return result
    return wrapper

@timer
def heavy_computation(iterations: int) -> int:
    return sum(i * i for i in range(iterations))

val: int = heavy_computation(1_000_000)

L2 Intermediate

4.2. Pattern 2: Access Control and Authentication

Verifying permissions or active session states before permitting function execution.

import functools
from collections.abc import Callable
from typing import Any

CURRENT_USER: dict[str, str] = {"username": "alice", "role": "admin"}

def require_admin(func: Callable[..., Any]) -> Callable[..., Any]:
    """Restricts access to users with the 'admin' role."""
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        if CURRENT_USER.get("role") != "admin":
            raise PermissionError(f"User {CURRENT_USER.get('username')} lacks admin privileges!")
        print(f"[AUTH] Access granted for {CURRENT_USER.get('username')}")
        return func(*args, **kwargs)
    return wrapper

@require_admin
def delete_database() -> str:
    return "Database purged successfully."

print(delete_database())

# Simulating unauthorized user:
CURRENT_USER["role"] = "guest"
try:
    delete_database()
except PermissionError as err:
    print("[AUTH FAILED]:", err)

4.3. Pattern 3: Automatic Retry Mechanism with Exception Handling

In network calls or database operations, transient errors occur. A retry decorator gracefully retries failed operations before giving up. (Note: As mastered in Module 22: Exception Handling, handling specific exception hierarchies ensures robust failure recovery).

import time
import functools
from collections.abc import Callable
from typing import Any

def retry_on_exception(max_retries: int = 3, delay_seconds: float = 0.1) -> Callable[[Callable[..., Any]], Callable[..., Any]]:
    def decorator(func: Callable[..., Any]) -> Callable[..., Any]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            attempts: int = 0
            while attempts < max_retries:
                try:
                    return func(*args, **kwargs)
                except Exception as exc:
                    attempts += 1
                    print(f"[RETRY] Attempt {attempts}/{max_retries} failed ({exc}). Retrying...")
                    if attempts >= max_retries:
                        raise
                    time.sleep(delay_seconds)
        return wrapper
    return decorator

# Simulating an unreliable external network service
call_count: int = 0

@retry_on_exception(max_retries=4, delay_seconds=0.05)
def fetch_cloud_metrics() -> dict[str, Any]:
    global call_count
    call_count += 1
    if call_count < 3:
        raise ConnectionResetError("Server connection reset by peer")
    return {"status": 200, "cpu_load": "42%"}

print("Result:", fetch_cloud_metrics())

4.4. Pattern 4: Memoization / In-Memory Caching

Caching expensive function results based on immutable argument tuples to eliminate redundant calculations.

import functools
from collections.abc import Callable
from typing import Any

def memoize(func: Callable[..., Any]) -> Any:
    cache: dict[tuple[Any, ...], Any] = {}
    @functools.wraps(func)
    def wrapper(*args: Any) -> Any:
        if args in cache:
            return cache[args]
        result: Any = func(*args)
        cache[args] = result
        return result
    wrapper.cache = cache  # type: ignore[attr-defined]
    return wrapper

@memoize
def fibonacci(n: int) -> int:
    if n <= 1:
        return n
    return fibonacci(n - 1) + fibonacci(n - 2)

print("fib(35) computed instantly:", fibonacci(35))
print("Total cache entries:", len(fibonacci.cache))

The standard library provides optimized C-level memoization decorators in the functools module:

from functools import lru_cache, cache

# Python 3.9+ @cache (unbounded memoization)
@cache
def ackermann(m: int, n: int) -> int:
    if m == 0:
        return n + 1
    elif m > 0 and n == 0:
        return ackermann(m - 1, 1)
    else:
        return ackermann(m - 1, ackermann(m, n - 1))

# @lru_cache with capacity limit and LRU eviction
@lru_cache(maxsize=128)
def fib_lru(n: int) -> int:
    if n <= 1:
        return n
    return fib_lru(n - 1) + fib_lru(n - 2)

print("Ackermann(3, 4):", ackermann(3, 4))
print("fib_lru(50):    ", fib_lru(50))
print("Cache info:     ", fib_lru.cache_info())

L1 L2

L1 Fundamental

5.1. Calling With vs Without Decorator

The @decorator syntax is applied at function definition time. However, in certain testing or dynamic scenarios, you may want to apply a decorator conditionally or call the underlying function without its decorator.

import functools
from collections.abc import Callable
from typing import Any

def double_output(func: Callable[..., int]) -> Callable[..., int]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> int:
        return func(*args, **kwargs) * 2
    return wrapper

def base_calculation(x: int, y: int) -> int:
    return x + y

# 1. Normal un-decorated call:
print("Direct call:", base_calculation(10, 5))  # 15

# 2. Dynamic manual decoration on demand:
decorated_calc: Callable[..., int] = double_output(base_calculation)
print("Manually decorated call:", decorated_calc(10, 5))  # 30

# 3. Accessing the un-decorated function using __wrapped__:
@double_output
def compute_total(a: int, b: int) -> int:
    return a + b

print("Decorated total:", compute_total(10, 5))            # 30
print("Unwrapped bypass total:", compute_total.__wrapped__(10, 5))  # 15

L2 Intermediate

5.2. Decorator Chaining (Stacking)

Multiple decorators can be applied to a single function by stacking them one above the other. The decorators are applied bottom-to-top (from the closest to the function outward), but the resulting wrappers execute from top-to-bottom.

import functools
from collections.abc import Callable
from typing import Any

def make_bold(func: Callable[..., str]) -> Callable[..., str]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> str:
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper

def make_italic(func: Callable[..., str]) -> Callable[..., str]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> str:
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper

def make_underlined(func: Callable[..., str]) -> Callable[..., str]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> str:
        return f"<u>{func(*args, **kwargs)}</u>"
    return wrapper

# Stacking decorators:
@make_bold
@make_italic
@make_underlined
def render_heading(title: str) -> str:
    return title

print(render_heading("Decorator Chaining"))
# Output: <b><i><u>Decorator Chaining</u></i></b>

# The above is 100% equivalent to:
# render_heading = make_bold(make_italic(make_underlined(render_heading)))
Chain Evaluation Order:
  • Wrapping order (Definition time): Bottom-up: make_underlined wraps first, then make_italic, then make_bold.
  • Execution order (Call time): Top-down: make_bold wrapper runs first, calling make_italic wrapper, which calls make_underlined wrapper, which calls render_heading.

5.3. Decorators with Arguments (3-Layer Closures)

When a decorator accepts configuration arguments (e.g., @repeat(num_times=3)), an additional outer enclosing function is required to accept those arguments and return the actual decorator.

import functools
from collections.abc import Callable
from typing import Any

# Layer 1: Takes arguments for the decorator
def repeat(num_times: int) -> Callable[[Callable[..., Any]], Callable[..., Any]]:
    # Layer 2: Takes the function to decorate
    def actual_decorator(func: Callable[..., Any]) -> Callable[..., Any]:
        # Layer 3: The wrapper that runs when func is invoked
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            last_result: Any = None
            for i in range(num_times):
                print(f"[Run {i + 1}/{num_times}]")
                last_result = func(*args, **kwargs)
            return last_result
        return wrapper
    return actual_decorator

@repeat(num_times=3)
def send_ping(host: str) -> str:
    print(f"Ping sent to {host}")
    return "ACK"

status: str = send_ping("192.168.1.1")

5.4. Class-Based Decorators (via __call__)

Decorators can also be implemented using Python classes. A class becomes a decorator when it implements __init__ (to receive the function) and __call__ (to act as the callable wrapper). Class-based decorators are ideal for maintaining state across calls.

import functools
from collections.abc import Callable
from typing import Any

class CallCounter:
    """Class-based decorator to track execution count across calls."""
    def __init__(self, func: Callable[..., Any]) -> None:
        self.func: Callable[..., Any] = func
        self.count: int = 0
        functools.update_wrapper(self, func)

    def __call__(self, *args: Any, **kwargs: Any) -> Any:
        self.count += 1
        print(f"[STAT] '{self.func.__name__}' has been called {self.count} time(s).")
        return self.func(*args, **kwargs)

@CallCounter
def process_payment(amount: float) -> str:
    return f"Payment of ${amount:.2f} processed."

print(process_payment(100.0))
print(process_payment(250.0))
print(process_payment(500.0))
print("Total recorded calls:", process_payment.count)  # 3

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a decorator in Python, and how does the @ syntax work under the hood? ▾ Answer

A decorator is a callable (function or class) that takes another function as input, extends or alters its behavior without modifying its source code, and returns the modified wrapper function.

The @my_decorator syntax is syntactic sugar. The statement:

@my_decorator
def target_func():
    pass

is directly executed by Python at definition time as:

def target_func():
    pass
target_func = my_decorator(target_func)
C.2. What is function aliasing vs calling a function? ▾ Answer

Calling a function means executing its body by appending parentheses () and optional arguments: result = func(). It evaluates the function and returns its output.

Function aliasing means assigning the function object itself (without parentheses) to a new variable name: alias_name = func. Both identifiers now reference the exact same function object in memory (id(alias_name) == id(func)). Deleting the original name via del func does not delete the function object as long as the alias reference remains.

C.3. What is a closure and why is it fundamental to decorators? ▾ Answer

A closure is an inner function that retains access to variables from its enclosing lexical scope even after the outer function has completed execution and exited the call stack.

Decorators rely entirely on closures: the decorator function takes func as an argument and defines an inner wrapper function that invokes func. When the decorator returns wrapper, wrapper retains access to func inside its __closure__ cell object, enabling it to execute func whenever called.

C.4. Why is @functools.wraps crucial when creating custom decorators? ▾ Answer

When a function is decorated, the original function is replaced by the decorator's internal wrapper function. Without @functools.wraps(func):

  • The function's __name__ becomes 'wrapper'.
  • The function's __doc__ docstring is overwritten with the wrapper's docstring (or None).
  • Signature inspection (via inspect.signature) and help utilities (like help()) display the wrapper's signature instead of the original function's parameters.

Applying @functools.wraps(func) to the wrapper copies over __module__, __name__, __qualname__, __doc__, and __annotations__, and adds a __wrapped__ attribute pointing directly to the original function.

L2 Intermediate

C.5. In what order do chained (stacked) decorators execute? ▾ Answer

Given the following code:

@dec1
@dec2
def my_func():
    pass
  • Definition / Wrapping Order: Bottom-to-top. dec2 wraps my_func first, and then dec1 wraps the result of dec2(my_func). Evaluated as: my_func = dec1(dec2(my_func)).
  • Execution / Runtime Order: Top-to-bottom. When my_func() is called, dec1's wrapper executes first. When dec1 invokes the wrapped function, dec2's wrapper executes, which finally calls the original my_func.
C.6. How do you pass arguments to a decorator itself? ▾ Answer

A decorator with arguments requires a 3-layer nested structure:

  1. The outermost function receives the decorator arguments (e.g., def repeat(n):).
  2. The middle function receives the target function to decorate (e.g., def decorator(func):).
  3. The innermost wrapper function receives *args, **kwargs passed to the decorated function at runtime.
import functools
from collections.abc import Callable
from typing import Any

def repeat(times: int) -> Callable[[Callable[..., Any]], Callable[..., Any]]:
    def decorator(func: Callable[..., Any]) -> Callable[..., Any]:
        @functools.wraps(func)
        def wrapper(*args: Any, **kwargs: Any) -> Any:
            res: Any = None
            for _ in range(times):
                res = func(*args, **kwargs)
            return res
        return wrapper
    return decorator
C.7. How do class-based decorators work in Python? ▾ Answer

A class-based decorator leverages the dunder methods __init__ and __call__:

  • __init__(self, func): Receives the target function when the decorator is applied at definition time and stores it as an instance attribute.
  • __call__(self, *args, **kwargs): Executed whenever the decorated function is called. It can execute pre/post logic and invoke self.func(*args, **kwargs).

Class-based decorators are especially suited for maintaining state across calls (such as hit counters, rate limiters, or history logs).

C.8. How do you decorate instance methods inside a class? ▾ Answer

Instance methods pass self as their first positional argument. When writing a decorator that may be used on methods, always ensure the inner wrapper function accepts *args, **kwargs and passes them through to func(*args, **kwargs). The self reference will naturally be passed as args[0].

import functools
from collections.abc import Callable
from typing import Any

def log_method(func: Callable[..., Any]) -> Callable[..., Any]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        # args[0] is the instance (self)
        instance: Any = args[0] if args else None
        print(f"[METHOD LOG] Invoking {func.__name__} on {instance}")
        return func(*args, **kwargs)
    return wrapper

class Account:
    def __init__(self, balance: float) -> None:
        self.balance: float = balance

    @log_method
    def deposit(self, amount: float) -> float:
        self.balance += amount
        return self.balance

import time
import functools
from collections.abc import Callable
from typing import Any

def measure_time(func: Callable[..., Any]) -> Callable[..., Any]:
    @functools.wraps(func)
    def wrapper(*args: Any, **kwargs: Any) -> Any:
        start: float = time.perf_counter()
        result: Any = func(*args, **kwargs)
        elapsed: float = time.perf_counter() - start
        print(f"[TIME] {func.__name__} executed in {elapsed:.6f}s")
        return result
    return wrapper

def compute_squares(n: int) -> int:
    return sum(i * i for i in range(n))

    # Mini Project: Stateful Memoization Decorator with Cache Stats
import functools
from collections.abc import Callable
from typing import Any

def smart_cache(func: Callable[..., Any]) -> Any:
    cache: dict[tuple[Any, ...], Any] = {}
    stats: dict[str, int] = {"hits": 0, "misses": 0}

    @functools.wraps(func)
    def wrapper(*args: Any, bypass_cache: bool = False, **kwargs: Any) -> Any:
        key: tuple[Any, ...] = args + tuple(sorted(kwargs.items()))
        if not bypass_cache and key in cache:
            stats["hits"] += 1
            return cache[key]
        
        stats["misses"] += 1
        result: Any = func(*args, **kwargs)
        cache[key] = result
        return result

    def get_stats() -> dict[str, int]:
        return stats.copy()

    def clear_cache() -> None:
        cache.clear()
        stats["hits"] = 0
        stats["misses"] = 0

    wrapper.stats = get_stats  # type: ignore[attr-defined]
    wrapper.clear = clear_cache  # type: ignore[attr-defined]
    return wrapper

@smart_cache
def fib(n: int) -> int:
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)

print("fib(20):", fib(20))
print("Stats after computation:", fib.stats())
print("fib(20) cached call:   ", fib(20))
print("Stats after cache hit:  ", fib.stats())
