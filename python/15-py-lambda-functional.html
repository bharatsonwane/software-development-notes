1. Introduction

L1

L1 Fundamental

1.1. Functional Programming in Python

  • Although Python is primarily an object-oriented and imperative language, it borrows powerful concepts from Functional Programming (FP):
    1. Higher-Order Functions: Functions that take other functions as arguments or return functions.
    2. Pure Functions: Functions with no side-effects that always return the same output for identical inputs.
    3. Anonymous (Lambda) Functions: Quick inline callables defined without explicit names.
    4. Stream Processing Primitives: map(), filter(), and reduce() for transforming collections.

1.2. Callable & Functional Type Annotations

Type Hints in Functional Programming:
  • The Callable Type: Import from collections.abc import Callable. Syntax: Callable[[Arg1Type, Arg2Type], ReturnType].
  • Typing Lambdas: When storing a lambda or passing a callable parameter: square: Callable[[int], int] = lambda x: x ** 2.
  • Typing Lazy Streams: map and filter return generator-like iterators typed via from collections.abc import Iterator (e.g., Iterator[int]).

2. Anonymous / lambda functions

L1 L2

L1 Fundamental

2.1. Syntax & Single-Expression Limitation

An anonymous function is a function defined without a name using the lambda keyword:

lambda arguments: expression
  • Implicit Return: The single expression is automatically evaluated and returned. You cannot use the return keyword inside a lambda.
  • No Statements Allowed: A lambda cannot contain assignments (=), loops (for, while), control flow statements (pass, break, continue), docstrings, or annotations.
  • Short Lifespan: Typically used as throwaway inline arguments to higher-order functions.
from collections.abc import Callable

# Standard def function:
def square(x: int) -> int:
    return x ** 2

# Equivalent lambda with Callable type annotation:
square_lambda: Callable[[int], int] = lambda x: x ** 2

print(square(5))         # 25
print(square_lambda(5))  # 25

# Multiple parameters:
add: Callable[[int, int, int], int] = lambda a, b, c: a + b + c
print("Sum:", add(10, 20, 30))  # 60

L2 Intermediate

2.2. Conditional Expressions in Lambdas

While if-elif-else statements are forbidden, single-line ternary conditional expressions are fully supported:

from collections.abc import Callable

# lambda param: val_if_true if condition else val_if_false
even_odd: Callable[[int], str] = lambda n: "Even" if n % 2 == 0 else "Odd"
print(even_odd(8))   # Even
print(even_odd(15))  # Odd

# Nested conditional:
classify: Callable[[int], str] = lambda score: "A" if score >= 90 else ("B" if score >= 80 else "C")
print("Grade:", classify(85))  # B

2.3. Lambdas as Custom Sorting Keys

The most ubiquitous and idiomatic use case for lambdas is the key= argument in sort(), sorted(), min(), and max():

# Sorting records by multiple criteria:
employees: list[dict[str, str | int]] = [
    {"name": "Alice", "salary": 90000, "age": 30},
    {"name": "Bob", "salary": 65000, "age": 24},
    {"name": "Charlie", "salary": 90000, "age": 28},
    {"name": "Diana", "salary": 110000, "age": 35}
]

# Sort primarily by salary descending, secondarily by age ascending:
employees.sort(key=lambda e: (-int(e["salary"]), int(e["age"])))
print("Sorted employees:")
for emp in employees:
    salary: int = int(emp["salary"])
    age: int = int(emp["age"])
    print(f"  {str(emp['name']):<8} Salary: ${salary:,}, Age: {age}")
# Diana    Salary: $110,000, Age: 35
# Charlie  Salary: $90,000, Age: 28
# Alice    Salary: $90,000, Age: 30
# Bob      Salary: $65,000, Age: 24

3. filter() with lambda

L1 L2

L1 Fundamental

3.1. Mechanics & Lazy Evaluation

filter(function, iterable) constructs an iterator from elements of iterable for which function(item) returns True:

from collections.abc import Iterator

nums: list[int] = [12, 5, 8, 19, 24, 7, 30]

# Filter even numbers:
evens_iter: Iterator[int] = filter(lambda x: x % 2 == 0, nums)
print(type(evens_iter))  # <class 'filter'> (Lazy generator-like iterator)

# Consume iterator into a list:
evens: list[int] = list(evens_iter)
print("Evens:", evens)   # [12, 8, 24, 30]

L2 Intermediate

3.2. Truthiness Filtering with filter(None, iterable)

If function is None, Python's identity truth-testing is used; all falsy elements (0, "", None, False, []) are stripped away:

raw_data: list[object] = ["active", "", None, "pending", 0, False, "archived", []]
cleaned: list[object] = list(filter(None, raw_data))
print("Truthy values only:", cleaned)
# ['active', 'pending', 'archived']

4. map() with lambda

L1 L2

L1 Fundamental

4.1. Mechanics & Single-Iterable Transformation

map(function, iterable) applies function to every item of iterable and yields the results lazily:

# Transform strings: strip whitespace and capitalize
users: list[str] = ["  alice ", "BOB", "  charlie  "]
cleaned: list[str] = list(map(lambda s: s.strip().title(), users))
print("Cleaned users:", cleaned)  # ['Alice', 'Bob', 'Charlie']

# Convert temperatures Celsius to Fahrenheit:
celsius: list[int] = [0, 20, 37, 100]
fahrenheit: list[float] = list(map(lambda c: round((c * 9/5) + 32, 1), celsius))
print("Fahrenheit:", fahrenheit)  # [32.0, 68.0, 98.6, 212.0]

L2 Intermediate

4.2. Multi-Iterable Mapping in Parallel

map() accepts multiple iterables. The function must accept as many parameters as there are iterables. Iteration stops when the shortest iterable is exhausted:

# Vector addition across parallel lists:
v1: list[int] = [10, 20, 30]
v2: list[int] = [1, 2, 3]
v3: list[int] = [100, 200, 300]

sums: list[int] = list(map(lambda x, y, z: x + y + z, v1, v2, v3))
print("Parallel sum:", sums)  # [111, 222, 333]

5. reduce() (functools)

L1 L2

L1 Fundamental

5.1. Rolling Accumulator Mechanics

Unlike map and filter which are built-ins, reduce() resides in the functools module. It applies a two-argument function cumulatively to the sequence elements to boil them down to a single scalar value:

from functools import reduce

# Calculating cumulative product (Factorial of 5):
nums: list[int] = [1, 2, 3, 4, 5]
product: int = reduce(lambda acc, x: acc * x, nums)
print("Product (5!):", product)  # 120

# Execution flow:
# Step 1: acc=1, x=2 -> 1*2 = 2
# Step 2: acc=2, x=3 -> 2*3 = 6
# Step 3: acc=6, x=4 -> 6*4 = 24
# Step 4: acc=24, x=5 -> 24*5 = 120

L2 Intermediate

5.2. The Initializer Argument & Safety

Safety Best Practice: If an iterable is empty and no initializer is provided, reduce() raises TypeError: reduce() of empty iterable with no initial value. Always pass an initializer as the 3rd argument to serve as a safe default fallback. 
from functools import reduce

# Finding maximum element using reduce:
nums: list[int] = [45, 12, 89, 34, 78, 23]
max_num: int = reduce(lambda a, b: a if a > b else b, nums)
print("Maximum:", max_num)  # 89

# Using initializer for safe sum:
empty_list: list[int] = []
safe_sum: int = reduce(lambda a, b: a + b, empty_list, 0)
print("Safe sum:", safe_sum)  # 0 (No TypeError)

5.3. When to Use Comprehensions Instead of map/filter

In modern Python, list and generator comprehensions are almost universally preferred over map and filter with lambdas for readability and performance:

# map + filter with lambda:
res1: list[int] = list(map(lambda x: x**2, filter(lambda x: x % 2 == 0, range(10))))

# Equivalent List Comprehension (Far more readable and faster in Python):
res2: list[int] = [x**2 for x in range(10) if x % 2 == 0]
print(res1 == res2)  # True

C. Common questions

L1 L2

L1 Fundamental

C.1. Why can't a lambda contain statements like return, pass, or assignments? ▾ Answer

In Python's formal grammar, a lambda is classified strictly as an expression (which evaluates to a value), not a statement. Statements (such as return, try/except, for, pass, and variable assignments) perform actions but do not evaluate directly to a single object.

This design constraint was intentionally imposed by Guido van Rossum to keep lambdas strictly one-line and simple, preventing developers from nesting unreadable multi-line logic inside expressions.

C.2. Why was reduce() moved from built-ins to functools in Python 3? ▾ Answer

Guido van Rossum moved reduce() out of built-ins into functools because 99% of its common uses were either:

  • Better served by dedicated built-ins like sum(), any(), all(), max(), or math.prod().
  • Far more readable when written as an explicit for loop with a clear accumulator variable.
C.3. How do map() and filter() differ in Python 2 vs Python 3? ▾ Answer
  • Python 2: Returned concrete list objects directly, allocating full memory for all results immediately.
  • Python 3: Return lazy iterator objects (map and filter objects) that compute elements one-by-one on demand via next(). This enables processing arbitrarily massive or infinite streams in $O(1)$ memory.
C.4. What happens when multiple iterables of unequal length are passed to map()? ▾ Answer

In Python 3, map() terminates immediately when the shortest iterable is exhausted, discarding remaining elements in longer iterables without raising errors.

L2 Intermediate

C.5. Why is [lambda: i for i in range(3)] a classic late-binding trap? ▾ Answer

This is the famous late-binding closure trap:

from collections.abc import Callable

funcs: list[Callable[[], int]] = [lambda: i for i in range(3)]
print([f() for f in funcs])  # Outputs [2, 2, 2], NOT [0, 1, 2]!

Cause: The variable i is not evaluated when the lambda is created; it is looked up when the lambda is called. By that time, the loop has completed and i is 2.

The Fix: Bind i immediately as a default parameter: funcs = [lambda i=i: i for i in range(3)].

C.6. Should you assign a lambda to a variable (f = lambda x: x)? What does PEP 8 advise? ▾ Answer

PEP 8 strongly discourages named lambdas:

Instead of f = lambda x: 2 * x, you should always write def f(x): return 2 * x.

Reason: A function created via def has a meaningful __name__ property (f.__name__ == 'f'), which renders accurate, readable tracebacks during debugging. A named lambda has __name__ == '<lambda>', obscuring error logs.

C.7. How does operator module optimize functional pipelines? ▾ Answer

The standard library operator module provides C-level implementations of standard arithmetic and item-getter operations:

  • reduce(operator.mul, nums) runs much faster than reduce(lambda a, b: a * b, nums) because it avoids Python bytecode evaluation overhead for each step.
  • operator.itemgetter(1) and operator.attrgetter('name') are faster alternatives to lambdas for sorting keys.
C.8. Why are list comprehensions faster than map() with lambdas? ▾ Answer

When using map(lambda x: x*2, nums), Python must create a new Python stack frame and execute function call overhead for every single item in the sequence.

In contrast, a list comprehension [x * 2 for x in nums] inlines the multiplication operation directly into the bytecode loop, avoiding thousands of function call frame creations and disposals.

P.3. Challenge

  1. Challenge 1: Functional Map-Filter-Reduce Pipeline — Process sales transactions into category totals. ▾ Solution 
    from functools import reduce
from collections.abc import Iterator

transactions: list[dict[str, str | float]] = [
    {"category": "Electronics", "amount": 120.0, "status": "completed"},
    {"category": "Groceries",   "amount": 45.0,  "status": "completed"},
    {"category": "Electronics", "amount": 250.0, "status": "refunded"},
    {"category": "Electronics", "amount": 80.0,  "status": "completed"},
    {"category": "Groceries",   "amount": 65.0,  "status": "completed"}
]

# 1. Filter completed transactions
completed: Iterator[dict[str, str | float]] = filter(lambda t: t["status"] == "completed", transactions)

# 2. Reduce to aggregate amounts per category
def aggregate(acc: dict[str, float], t: dict[str, str | float]) -> dict[str, float]:
    cat: str = str(t["category"])
    amt: float = float(t["amount"])
    acc[cat] = acc.get(cat, 0.0) + amt
    return acc

totals: dict[str, float] = reduce(aggregate, completed, {})
print("Category Totals:", totals)
# {'Electronics': 200.0, 'Groceries': 110.0}
  2. Challenge 2: Multi-Criteria Dynamic Object Sorter — Build a reusable sorting helper using lambdas and operator module. ▾ Solution 
    from typing import Any

def dynamic_sort(dataset: list[dict[str, Any]], *sort_keys: tuple[str, bool]) -> list[dict[str, Any]]:
    """Sort list of dicts by arbitrary keys with ascending/descending indicators."""
    def sort_extractor(item: dict[str, Any]) -> tuple[Any, ...]:
        key_tuple: list[Any] = []
        for k, descending in sort_keys:
            val: Any = item[k]
            key_tuple.append(-val if descending and isinstance(val, (int, float)) else val)
        return tuple(key_tuple)

    return sorted(dataset, key=sort_extractor)

items: list[dict[str, Any]] = [
    {"dept": "Sales", "salary": 50000},
    {"dept": "Engineering", "salary": 90000},
    {"dept": "Engineering", "salary": 110000},
    {"dept": "Sales", "salary": 70000}
]

# Sort by dept ascending, salary descending:
sorted_items: list[dict[str, Any]] = dynamic_sort(items, ("dept", False), ("salary", True))
for it in sorted_items:
    print(it)
