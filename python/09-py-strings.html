1. Introduction

L1

L1 Fundamental

1.1. Overview

  • In Python, a string is represented by the built-in str class. It is an immutable sequence of Unicode characters (code points).
  • Every character in a Python string is stored as a Unicode point. Unlike languages such as C or Java, Python does not have a distinct single-character char data type; a single character is simply a str of length 1.
  • Because strings are sequences, they support common sequence operations: forward and backward indexing, slicing, concatenation (+), repetition (*), membership testing (in, not in), and iteration via loops.

1.2. PEP 393 — Flexible String Representation

Under the Hood (Python 3.3+): Python optimizes string memory footprint dynamically using PEP 393. Instead of always allocating 4 bytes per character, the CPython interpreter chooses the smallest possible character size depending on the highest Unicode code point in the string:
  • Latin-1 (1 byte per char): Characters within ASCII / Latin-1 range (code points $\le 255$).
  • UCS-2 (2 bytes per char): Characters within the Basic Multilingual Plane (code points $\le 65535$).
  • UCS-4 (4 bytes per char): Characters outside the BMP, such as emojis and rare mathematical symbols (code points $\le 1114111$).

L2 Intermediate

2.3. String Immutability & Memory Interning

  • Immutability Guarantee: Once created, the contents of a str object cannot be modified in place. Any string manipulation method (such as upper(), replace(), or slicing) constructs and returns a brand new string object in memory.
  • Attempting item assignment or item deletion directly raises a TypeError.
s = "Python"
# Attempting in-place modification:
# s[0] = "J"   # Raises: TypeError: 'str' object does not support item assignment
# del s[0]     # Raises: TypeError: 'str' object doesn't support item deletion

# Correct modification: construct a new string
s = "J" + s[1:]
print(s)  # 'Jython'
Why Immutability?
  1. Hashability & Dictionary Keys: Because strings cannot change, their hash value computed via hash(s) remains constant throughout program execution. This allows strings to safely serve as dictionary keys and set members.
  2. Thread Safety: Multiple threads can read immutable strings concurrently without locks or race conditions.
  3. Memory Optimization (String Interning): Python automatically interns small strings, string literals that look like Python identifiers, and compile-time constants. Interned strings share the exact same memory address (a is b == True), accelerating comparison from $O(N)$ string character scans to $O(1)$ pointer comparison. You can explicitly intern strings using sys.intern(s).

  • Negative Indexing (Right-to-Left): Begins at index -1 for the last character and moves backwards to -len(s).

3. Slice operator

L1 L2

L1 Fundamental

3.1. Syntax & Step Mechanics

The slice operator allows extracting a contiguous or patterned substring from a string without mutating the original object:

substring = s[begin : end : step]
  • begin: Starting index (inclusive). Defaults to 0 if step > 0, or -1 if step < 0.
  • end: Stopping index (exclusive). Defaults to len(s) if step > 0, or before the beginning of the string if step < 0.
  • step: Increment value (direction and stride). Defaults to +1. Can be positive (forward traversal) or negative (reverse traversal). Must never be 0 (raises ValueError: slice step cannot be zero).

3.2. Slicing with Positive Step (step > 0)

When the step is positive, extraction proceeds strictly from left to right. If begin >= end, an empty string "" is returned.

s = "ABCDEFGHIJ"
# Indices:  0123456789

print(s[2:7])      # 'CDEFG' (From index 2 up to 6)
print(s[:5])       # 'ABCDE' (From start up to index 4)
print(s[5:])       # 'FGHIJ' (From index 5 to end)
print(s[:])        # 'ABCDEFGHIJ' (Full shallow copy)
print(s[1:8:2])    # 'BDFH'  (Indices 1, 3, 5, 7)
print(s[::3])      # 'ADGJ'  (Indices 0, 3, 6, 9)
print(s[6:2])      # ''      (Empty string because begin > end with positive step)

L2 Intermediate

3.3. Slicing with Negative Step (step < 0)

When the step is negative, extraction proceeds from right to left. The default begin is -1 (end of string), and default end goes all the way back to the start.

s = "ABCDEFGHIJ"

# String reversal:
print(s[::-1])     # 'JIHGFEDCBA'

# Stepping backwards from index 7 down to 3:
print(s[7:2:-1])   # 'HGFED' (Indices 7, 6, 5, 4, 3)

# Negative indices with negative step:
print(s[-2:-7:-1]) # 'IHGFE' (From index -2 down to -6)

# Negative step with begin < end produces empty string:
print(s[2:7:-1])   # '' (Cannot step backwards from index 2 towards index 7)

3.4. Boundary Clamping (No IndexError in Slicing)

Key Difference: Indexing vs Slicing: Direct character access s[i] raises IndexError if index is out of bounds. In contrast, slicing never raises an IndexError. Python automatically clamps out-of-bounds slice endpoints to the string boundaries. 
s = "Python"  # length 6

# Out-of-bounds indexing:
# print(s[100])    # Raises IndexError: string index out of range

# Out-of-bounds slicing (Clamped gracefully):
print(s[2:100])    # 'thon' (Clamped to len(s))
print(s[-100:4])   # 'Pyth' (Clamped to index 0)
print(s[10:20])    # ''     (Empty string, no error)

3.5. The Built-in slice Object

Python provides a first-class slice type. You can create named, reusable slice definitions instead of hardcoding colon syntax, which is particularly valuable when parsing fixed-width records, logs, and tabular data.

# Fixed-width record format: ID (0-4), Name (5-15), Salary (16-24)
ID_SLICE = slice(0, 4)
NAME_SLICE = slice(5, 15)
SALARY_SLICE = slice(16, 24)

record = "1001 Rahul_Sharma  00095000"
emp_id = record[ID_SLICE].strip()
name = record[NAME_SLICE].strip()
salary = int(record[SALARY_SLICE])

print(f"ID: {emp_id}, Name: {name}, Salary: ${salary:,}")
# Output: ID: 1001, Name: Rahul_Sharma, Salary: $95,000

4.2. Character Classification & Validation Predicates

Boolean testing methods return True or False:

4.4. Stripping, Trimming & Python 3.9+ Prefix Removal

  • s.strip([chars]): Removes leading and trailing characters (defaults to whitespace).
  • s.lstrip([chars]) / s.rstrip([chars]): Removes characters from left-only or right-only.
  • removeprefix(prefix) & removesuffix(suffix): Introduced in Python 3.9 (PEP 616). Removes exact substring once, avoiding the classic bug where strip() strips a character set greedily.
# Classic strip() traps (strips individual characters, NOT substring):
url = "www.python.org"
print(url.strip("w.org"))  # 'python' (stripped 'w', '.', 'o', 'r', 'g' from edges!)

test = "Arthur: three!"
print(test.lstrip("Arthur: ")) # 'three!'
test2 = "Order: 123"
print(test2.lstrip("Order: ")) # '123'
test3 = "Error: 500"
print(test3.lstrip("Error: ")) # '500' but also strips 'E', 'r', 'o', etc.!

# Safe Python 3.9+ methods (Exact substring removal):
filename = "draft_invoice_2026.pdf"
clean = filename.removeprefix("draft_").removesuffix(".pdf")
print(clean)  # 'invoice_2026'

4.5. Splitting, Joining & Partitioning

  • s.split(sep=None, maxsplit=-1): Splits string by delimiter into a list. When sep=None, runs of consecutive whitespace characters are collapsed together and leading/trailing whitespace is ignored.
  • delimiter.join(iterable): Concatenates elements of an iterable into a single string using delimiter. Crucial performance idiom: "".join(list) runs in $O(N)$ linear time, whereas repeated string concatenation in loops with += runs in $O(N^2)$ quadratic time due to reallocations.
  • s.partition(sep): Splits string at the first occurrence of separator and returns a 3-tuple: (before, sep, after). If not found, returns (s, "", "").
# split vs split(' '):
text = "apple   banana  orange"
print(text.split())       # ['apple', 'banana', 'orange'] (Collapses consecutive spaces)
print(text.split(" "))   # ['apple', '', '', 'banana', '', 'orange'] (Exact space match)

# Efficient joining:
words = ["Python", "is", "fast", "and", "clean"]
sentence = " ".join(words)
print(sentence)  # 'Python is fast and clean'

# Partitioning URLs and emails:
email = "developer@domain.com"
user, at_sym, domain = email.partition("@")
print(f"User: {user}, Domain: {domain}")  # User: developer, Domain: domain.com

5.1. Program 1: String Reversal (3 Approaches)

Comparison of slice reversal, built-in sequence inversion, and two-pointer manual traversal:

# Approach 1: Slicing (Fastest, C-level implementation)
def reverse_slice(s: str) -> str:
    return s[::-1]

# Approach 2: reversed() generator joined
def reverse_builtin(s: str) -> str:
    return "".join(reversed(s))

# Approach 3: Two-pointer in-place on list representation (Classic algorithm)
def reverse_twopointer(s: str) -> str:
    chars = list(s)
    left, right = 0, len(chars) - 1
    while left < right:
        chars[left], chars[right] = chars[right], chars[left]
        left += 1
        right -= 1
    return "".join(chars)

sample = "PythonMastery"
print("Slice:      ", reverse_slice(sample))
print("Builtin:    ", reverse_builtin(sample))
print("Two-pointer:", reverse_twopointer(sample))

5.2. Program 2: Advanced Palindrome Verification

Checks whether a sentence reads identically forwards and backwards, ignoring casing, punctuation, and whitespaces:

def is_palindrome(text: str) -> bool:
    # Filter only alphanumeric characters and normalize to lowercase
    filtered = [c.lower() for c in text if c.isalnum()]
    return filtered == filtered[::-1]

print(is_palindrome("A man, a plan, a canal: Panama"))  # True
print(is_palindrome("race a car"))                      # False
print(is_palindrome("Was it a car or a cat I saw?"))    # True

5.3. Program 3: Anagram Detection

Two strings are anagrams if they contain identical character frequencies:

def are_anagrams_sort(s1: str, s2: str) -> bool:
    # O(N log N) approach using sorted()
    return sorted(s1.replace(" ", "").lower()) == sorted(s2.replace(" ", "").lower())

def are_anagrams_count(s1: str, s2: str) -> bool:
    # O(N) linear time approach using dictionary frequency map
    clean1 = [c.lower() for c in s1 if c.isalnum()]
    clean2 = [c.lower() for c in s2 if c.isalnum()]
    if len(clean1) != len(clean2):
        return False
    freq = {}
    for c in clean1:
        freq[c] = freq.get(c, 0) + 1
    for c in clean2:
        if c not in freq or freq[c] == 0:
            return False
        freq[c] -= 1
    return True

print(are_anagrams_count("listen", "silent"))          # True
print(are_anagrams_count("Astronomer", "Moon starer")) # True
print(are_anagrams_count("hello", "world"))            # False

5.4. Program 4: Run-Length String Compression

Compresses consecutive repeated characters into character + count (e.g. "a4b3c2"):

def compress_string(s: str) -> str:
    if not s:
        return ""
    result = []
    current_char = s[0]
    count = 1
    for i in range(1, len(s)):
        if s[i] == current_char:
            count += 1
        else:
            result.append(f"{current_char}{count}")
            current_char = s[i]
            count = 1
    result.append(f"{current_char}{count}")
    compressed = "".join(result)
    return compressed if len(compressed) < len(s) else s

print(compress_string("aaaabbbcc"))      # 'a4b3c2'
print(compress_string("aabcccccaaa"))    # 'a2b1c5a3'
print(compress_string("abcdef"))         # 'abcdef' (Returns original if no compression gained)

5.5. Program 5: Character Classifier & Segregation

Separates a mixed string into distinct alphabet, digit, and special symbol components:

def segregate_characters(s: str) -> dict:
    alphas = []
    digits = []
    specials = []
    for char in s:
        if char.isalpha():
            alphas.append(char)
        elif char.isdigit():
            digits.append(char)
        else:
            specials.append(char)
    return {
        "alphabets": "".join(alphas),
        "digits": "".join(digits),
        "specials": "".join(specials)
    }

raw_data = "PY10@thon_2026!#Code"
classified = segregate_characters(raw_data)
print("Alphabets:", classified["alphabets"])  # PYthonCode
print("Digits:   ", classified["digits"])     # 102026
print("Specials: ", classified["specials"])   # @!#

C. Common questions

L1 L2

L1 Fundamental

C.1. Why are Python strings immutable? What architectural benefits does this provide? ▾ Answer

Python strings are immutable for three major reasons:

  1. Hashability & Dictionary Keys: A dictionary key or set item must be hashable, meaning its hash value must never change over its lifetime. Because strings cannot be altered, their hash value is calculated once and cached, ensuring robust and fast lookup tables.
  2. Thread Safety: Multiple execution threads can access string objects concurrently without requiring synchronization locks, because read-only memory cannot produce race conditions.
  3. Memory Optimization (Interning): Because strings cannot be mutated, Python can safely share identical string literal instances across different variables without risk of unexpected side effects.
C.2. What is Python String Interning, and when does CPython automatically intern strings? ▾ Answer

String Interning is a memory optimization where CPython maintains a central lookup table of unique string objects. When an interned string is referenced, Python reuses the existing memory address rather than creating a new instance.

  • Automatic Interning: CPython automatically interns string constants that look like valid Python identifiers (letters, numbers, underscores), strings of length 0 or 1, and compile-time constants.
  • Performance Advantage: Comparing two interned strings for equality (a is b or a == b) collapses from an $O(N)$ character-by-character scan into a single $O(1)$ memory pointer address comparison.
  • Manual Interning: Dynamic or runtime strings can be explicitly interned using the sys.intern() function: 
    import sys
s1 = sys.intern("long_dynamic_identifier_" + str(10))
s2 = sys.intern("long_dynamic_identifier_" + str(10))
print(s1 is s2)  # True
C.3. What is the difference between str.find() and str.index()? ▾ Answer

Both methods search for the first occurrence of a substring from left to right, but handle missing elements differently:

  • s.find(sub): Returns the lowest index if found; returns -1 if the substring does not exist. Ideal for conditional branching (if s.find(sub) != -1:).
  • s.index(sub): Returns the lowest index if found; raises ValueError: substring not found if absent. Requires a try...except ValueError: block when the presence of the substring is uncertain.
C.4. Why does str.strip("abc") behave differently than str.removeprefix("abc")? ▾ Answer

This is one of the most common beginner traps in Python:

  • s.strip(chars): Treats the argument as a set of individual characters to peel away from both edges until a character not in the set is reached. For example: 
    "banana".strip("ab")  # Returns '' because all edge chars 'b' and 'a' match the set
  • s.removeprefix(prefix) (Python 3.9+): Treats the argument as an exact atomic substring. If the string starts with that exact prefix, it is removed once; otherwise, the original string is returned unchanged: 
    "banana".removeprefix("ba")  # Returns 'nana'
"banana".removeprefix("ab")  # Returns 'banana' (Prefix does not match)

L2 Intermediate

C.5. Why is string concatenation using += in a loop an anti-pattern? What should you use instead? ▾ Answer

Because strings are immutable, executing s += item inside an $N$-iteration loop cannot append to the existing buffer. In the worst case, Python must allocate a new string buffer of size $(K + \text{item\_len})$, copy all existing bytes into it, and discard the old buffer. This results in $O(N^2)$ quadratic time complexity.

The Idiomatic Solution: Collect strings in a list and assemble them once using str.join(), which computes total memory required upfront and copies characters in a single $O(N)$ linear pass:

# Bad: O(N^2)
res = ""
for word in words:
    res += word + " "

# Good: O(N)
res = " ".join(words)
C.6. How does Python 3 store strings in memory under PEP 393? ▾ Answer

Prior to Python 3.3, Python was compiled with either "narrow" 2-byte builds or "wide" 4-byte builds, which wasted significant RAM on pure ASCII data.

PEP 393 (Flexible String Representation) dynamically selects the character representation based on the maximum Unicode code point ($U$):

  • $U \le 255$: 1 byte per character (Latin-1/ASCII encoding). Pure ASCII text consumes only 1 byte per char plus object header.
  • $256 \le U \le 65535$: 2 bytes per character (UCS-2).
  • $U > 65535$: 4 bytes per character (UCS-4, required for emojis like 🐍 and special scripts).

This provides constant-time $O(1)$ random index access (s[i]) while maintaining optimal memory utilization.

C.7. How does str.split() without arguments differ from str.split(" ")? ▾ Answer

The distinction lies in whitespace normalization:

  • s.split() (delimiter=None): Strips leading and trailing whitespace first, and collapses any run of contiguous whitespace (spaces, tabs, newlines) into a single split point. It will never produce empty strings in the resulting list.
  • s.split(" ") (explicit delimiter): Treats every individual space character literally. Two consecutive spaces will result in an empty string "" between them: 
    line = "  alpha   beta  "
print(line.split())      # ['alpha', 'beta']
print(line.split(" "))   # ['', '', 'alpha', '', '', 'beta', '', '']
C.8. How does casefold() differ from lower()? ▾ Answer

lower() converts ASCII and simple Unicode characters to lowercase. However, certain languages contain special casing rules defined in the Unicode Standard:

  • For instance, the German lowercase sharp s ('ß') is already lowercase, so 'ß'.lower() remains 'ß'.
  • However, in German capitalization, 'ß' corresponds to 'SS'.
  • casefold() performs full Unicode case folding. 'ß'.casefold() converts to 'ss', allowing accurate, language-agnostic caseless equality comparisons: 
    s1 = "der Fluß"
s2 = "der Fluss"
print(s1.lower() == s2.lower())       # False
print(s1.casefold() == s2.casefold()) # True

  4. Task 4: Substring Counter without count() — Implement a function that returns all overlapping occurrences of a pattern. ▾ Solution 
    def count_overlapping(text: str, pattern: str) -> int:
    if not pattern:
        return 0
    count = 0
    start = 0
    while True:
        idx = text.find(pattern, start)
        if idx == -1:
            break
        count += 1
        start = idx + 1  # Advance by 1 for overlapping matches
    return count

  2. Challenge 2: Robust IPv4 Address Validator — Validate an IPv4 address string without using ipaddress module or regex. ▾ Solution 
    def is_valid_ipv4(ip: str) -> bool:
    octets = ip.split(".")
    if len(octets) != 4:
        return False
    for octet in octets:
        if not octet.isdigit():
            return False
        # Leading zero check: "01" is invalid, but "0" is valid
        if len(octet) > 1 and octet[0] == "0":
            return False
        val = int(octet)
        if not (0 <= val <= 255):
            return False
    return True

    print(f"{ip:18} -> Valid: {is_valid_ipv4(ip)}")
