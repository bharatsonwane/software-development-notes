1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Python has five core fundamental (scalar/primitive) data types: int, float, complex, bool, and NoneType.
  • Every value in Python is an object. Even simple integer literals like 42 or boolean literals like True are complete heap-allocated objects with methods, attributes, and internal descriptors.
  • Universal Immutability: All five fundamental types are strictly immutable. Once constructed in memory, their internal value can never change. Reassigning a variable simply rebinds the identifier to a different object.

2. int (Integer Data Type) & Number Systems

L1 L2

L1 Fundamental

2.1. Arbitrary Precision & Python 3 Unification

  • Arbitrary Precision: In Python 3, int values have unlimited magnitude (arbitrary precision). Unlike C, C++, or Java (which cap integers at 32-bit or 64-bit limits like 2^63 - 1), a Python 3 integer can grow to fill all available host RAM.
  • Elimination of long: In Python 2, two separate integer types existed: fixed-width int (32/64 bit) and arbitrary-precision long (written with an L suffix, e.g. 100L). In Python 3, long was completely eliminated; the standard int handles both small and arbitrarily large numbers transparently.
  • PEP 515 Underscores in Numeric Literals: For visual readability in code, digits can be grouped using underscores (_). The PVM completely ignores these underscores during parsing:
    salary = 1_000_000, bin_mask = 0b_1111_0000, hex_addr = 0x_CAFE_BABE. 
# Python 3: Unlimited integer magnitude
big_num = 10 ** 50
print("10 ** 50 =", big_num)
print("Type:    ", type(big_num))  # <class 'int'> (no overflow!)

# PEP 515: Underscores in numeric literals for readability
million = 1_000_000
mask = 0b_1111_0000
addr = 0x_DEAD_BEEF
print("million:", million)  # 1000000
print("mask:   ", mask)     # 240
print("addr:   ", addr)     # 3735928559

2.2. Types of Representation for int Literal Values (Number Systems)

In Python, programmers can represent integer values in 4 different number systems (bases). The prefix indicators and hexadecimal characters are completely case-insensitive (0b or 0B, 0o or 0O, 0x or 0X):

Form / Number System Base Allowed Digits Required Prefix Valid Examples SyntaxError Pitfall
1. Decimal Form Base 10 0 to 9 None (Default) a = 10, count = 789 Cannot start with leading zero (e.g. 0123 is invalid in Python 3; causes SyntaxError: leading zeros in decimal integer literals are not permitted)
2. Binary Form Base 2 0, 1 0b or 0B a = 0b1111 (15), b = 0B11 (3) c = 0B112 (2 is not allowed in binary)
3. Octal Form Base 8 0 to 7 0o or 0O a = 0o123 (83), b = 0O567 (375) c = 0O786 (8 is not allowed in octal)
4. Hexadecimal Form Base 16 0 to 9 & a to f / A to F 0x or 0X a = 0xface (64206), b = 0XBee5 (48869) c = 0xBeer ('r' is not in hex range a-f)
Key Rule on PVM Output: As a programmer, you can declare integer literals in decimal, binary, octal, or hexadecimal forms. However, the Python Virtual Machine (PVM) will always print and return numbers in decimal (base-10) form by default! 
# --- 1. Decimal Form (Base-10, Default) ---
a = 10
print("Decimal:", a)  # 10
# invalid = 0777      # SyntaxError: leading zeros in decimal integer literals are not permitted

# --- 2. Binary Form (Base-2, Prefix 0b / 0B) ---
a = 0b1111
b = 0B11
print("0b1111 ->", a)  # 15 (PVM output is decimal)
print("0B11   ->", b)  # 3
# c = 0B112            # SyntaxError: invalid digit '2' in binary literal

# --- 3. Octal Form (Base-8, Prefix 0o / 0O) ---
a = 0o123
b = 0O567
print("0o123  ->", a)  # 83
print("0O567  ->", b)  # 375
# c = 0O786            # SyntaxError: invalid digit '8' in octal literal

# --- 4. Hexadecimal Form (Base-16, Prefix 0x / 0X) ---
a = 0xface
b = 0XBee5
print("0xface ->", a)  # 64206
print("0XBee5 ->", b)  # 48869
# c = 0xBeer           # SyntaxError: invalid hexadecimal literal ('r' is invalid)

2.3. Base Conversion Functions: bin(), oct(), hex()

Python provides built-in conversion functions to convert an integer value from any base (decimal, binary, octal, or hexadecimal) into its corresponding binary, octal, or hexadecimal string representation.

Conversion Function Target Base Description Prefix in Output String
bin(x) Base 2 (Binary) Converts any integer (decimal, octal, hex) into a binary string representation. '0b'
oct(x) Base 8 (Octal) Converts any integer (decimal, binary, hex) into an octal string representation. '0o'
hex(x) Base 16 (Hexadecimal) Converts any integer (decimal, binary, octal) into a hexadecimal string representation. '0x' 
# ==========================================================
# 1. bin() - Convert from ANY base to Binary
# ==========================================================
# From Decimal:
print(bin(15))       # '0b1111'

# From Octal:
print(bin(0o11))     # '0b1001' (0o11 is 9 in decimal -> 0b1001)

# From Hexadecimal:
print(bin(0X10))     # '0b10000' (0x10 is 16 in decimal -> 0b10000)

# ==========================================================
# 2. oct() - Convert from ANY base to Octal
# ==========================================================
# From Decimal:
print(oct(10))       # '0o12'

# From Binary:
print(oct(0B1111))   # '0o17' (0b1111 is 15 in decimal -> 0o17)

# From Hexadecimal:
print(oct(0X123))    # '0o443' (0x123 is 291 in decimal -> 0o443)

# ==========================================================
# 3. hex() - Convert from ANY base to Hexadecimal
# ==========================================================
# From Decimal:
print(hex(100))      # '0x64'

# From Binary:
print(hex(0B111111)) # '0x3f' (0b111111 is 63 in decimal -> 0x3f)

# From Octal:
print(hex(0o12345))  # '0x14e5' (0o12345 is 5349 in decimal -> 0x14e5)

# ==========================================================
# 4. int(string, base) - Convert strings back to Decimal
# ==========================================================
print(int("0b1111", 2))   # 15
print(int("0o123", 8))    # 83
print(int("0xface", 16))  # 64206

3. float (Floating-Point Numbers)

L1 L2

L1 Fundamental

3.1. Representation & Exponential Notation

  • The float type in Python represents IEEE 754 double-precision floating-point numbers (64-bit float in C).
  • Decimal Only Rule: Unlike integers, floating-point literals can only be specified in decimal (base-10) form. Python does not allow binary, octal, or hexadecimal float literals (e.g. 0b10.101 causes SyntaxError: invalid decimal literal).
  • You can write floating-point numbers in fractional form or exponential (scientific) form using e or E (e.g., 1.2e3 = 1.2 * 10^3 = 1200.0).
pi = 3.14159
rate = -0.0025

# Exponential / Scientific notation:
big_val = 1.2e3     # 1.2 * 10^3 = 1200.0
tiny_val = 2.5E-4   # 2.5 * 10^-4 = 0.00025
print(big_val, tiny_val)

# Base restriction pitfall:
# invalid_float = 0b101.11  # SyntaxError: invalid decimal literal

L2 Intermediate

3.2. Precision Quirks, IEEE Limits, & Comparisons

  • Finite Float Magnitude (Unlike int): While Python 3 integers have arbitrary precision, float is bound by IEEE 754 64-bit limits. The maximum representable float is approximately 1.7976931348623157e+308 (sys.float_info.max). Values exceeding this overflow directly to inf.
  • Computers store floats as binary fractions. Some decimal fractions (like 0.1) cannot be represented exactly in binary, leading to tiny rounding discrepancies.
  • Never compare floats using exact equality (==). Use math.isclose() instead.
import math
import sys

# Float boundary & overflow:
print("Max float:", sys.float_info.max)  # ~1.7976931348623157e+308
overflow = 1.8e308
print("Overflow:", overflow)              # inf (Infinity)

# Float precision quirk:
print(0.1 + 0.2)             # 0.30000000000000004
print(0.1 + 0.2 == 0.3)      # False (classic float quirk!)

# Correct way to compare floating-point numbers:
print(math.isclose(0.1 + 0.2, 0.3))  # True

# Special float values:
pos_inf = float("inf")
neg_inf = float("-inf")
not_a_num = float("nan")

print(pos_inf > 10**100)     # True
print(math.isnan(not_a_num)) # True

4. complex (Complex Numbers)

L1 L2

L1 Fundamental

4.1. Syntax & Literal Rules

  • Python has built-in support for complex numbers in the form a + bj, where a is the real part, b is the imaginary part, and j (or J) represents $\sqrt{-1}$.
  • Real vs Imaginary Base Rule:
    • The real part a can be specified in any number system (decimal, binary 0b, octal 0o, or hex 0x).
    • The imaginary part b MUST be specified strictly in decimal form! Writing non-decimal bases for the imaginary part triggers a SyntaxError.
  • Internal Representation: Both the real and imaginary components are stored internally as 64-bit float values, accessible via .real and .imag.
# Real part can be any base; Imaginary part MUST be decimal:
c1 = 0x10 + 20.5j    # Valid! 0x10 (16) + 20.5j
c2 = 0b1111 + 5j     # Valid! 0b1111 (15) + 5j
print("c1:", c1)     # (16+20.5j)
print("c2:", c2)     # (15+5j)

# Pitfall: Imaginary part in non-decimal is INVALID:
# c3 = 10 + 0x10j    # SyntaxError: invalid hexadecimal literal

# Component attributes always return float:
z = 3 + 4j
print("Real part (float):     ", z.real, type(z.real))  # 3.0 <class 'float'>
print("Imaginary part (float):", z.imag, type(z.imag))  # 4.0 <class 'float'>
print("Conjugate:             ", z.conjugate())         # (3-4j)

L2 Intermediate

4.2. Complex Arithmetic

  • Complex numbers support addition, subtraction, multiplication, and true division.
  • Complex numbers do not support relational order comparisons like <, <=, >, >= (raises TypeError: '<' not supported between instances of 'complex' and 'complex') because mathematically the complex plane has no natural ordering.
z1 = 3 + 4j
z2 = 1 - 2j

print("Addition:      ", z1 + z2)       # (4+2j)
print("Subtraction:   ", z1 - z2)       # (2+6j)
print("Multiplication:", z1 * z2)       # (11-2j)
print("Division:      ", z1 / z2)       # (-1+2j)
# print(z1 > z2)  # TypeError: '>' not supported between instances of 'complex' and 'complex'

5. bool (Boolean Values & Truthiness)

L1 L2

L1 Fundamental

5.1. Overview & Subclassing int

  • bool has exactly two literal values: True and False. Both are permanent singletons.
  • In Python, bool is an explicit subclass of int:
    True == 1 and False == 0.
  • Boolean Arithmetic: Because booleans inherit from integers, they participate directly in mathematical arithmetic:
    True + True == 2, True - False == 1, True * 10 == 10, True / 2 == 0.5.
  • Identity vs Equality: While True == 1 is True (value equality), True is 1 is False (they are separate objects at distinct memory addresses).
# Boolean arithmetic:
print(True + True)            # 2
print(True - False)           # 1
print(True * 5)               # 5
print(True / 2)               # 0.5

# Subclass relationship:
print(isinstance(True, int))  # True
print(issubclass(bool, int))  # True

# Equality vs Identity:
print(True == 1)              # True (same numeric value)
print(True is 1)              # False (different object identities!)

L2 Intermediate

5.2. Truthy and Falsy Values in Python

In Python, every object can be tested for truth value (evaluated in an if condition or passed to bool()).

Category Falsy Values (Evaluate to False) Truthy Values (Evaluate to True)
Constants False, None True
Numbers Zero: 0, 0.0, 0j Any non-zero number (1, -5, 3.14)
Strings Empty string: "", '' Non-empty strings ("hello", " ", "0", "False")
Collections / Sequences Empty collections: [], (), {}, set(), range(0) Non-empty collections ([0], {"a": 1}, (None,))
Pitfall Alert: String "False" and string "0" are Truthy because they are non-empty strings! Only the truly empty string "" is falsy. 
# Falsy examples:
print(bool(0))        # False
print(bool(0.0))      # False
print(bool(None))     # False
print(bool(""))       # False
print(bool([]))       # False
print(bool({}))       # False
print(bool(set()))    # False

# Truthy examples:
print(bool("hello"))  # True
print(bool("False"))  # True  (non-empty string!)
print(bool("0"))      # True  (non-empty string!)
print(bool([0]))      # True  (non-empty list!)
print(bool(-10))      # True  (non-zero number!)

6. NoneType (None)

L1

L1 Fundamental

6.1. The None Singleton

  • None is an object that represents the absence of a value or null state.
  • It is an instance of NoneType. There is only ever one instance of None in Python's memory (singleton).
  • Functions without an explicit return statement implicitly return None.

6.2. Identity Comparison: is None vs == None

  • Always use the identity operator is None or is not None rather than equality == None.
  • is compares memory pointer addresses and cannot be overridden by user classes; == calls __eq__, which can be modified or slow.
# NoneType represents the intentional absence of a value:
x = None
print("Value:", x)
print("Type: ", type(x))  # 

# Best Practice checking for None (always use 'is'):
if x is None:
    print("x has no value (unassigned/empty)")

# In Python, operations or functions that produce side effects (like print()) return None:
result = print("Displaying a message...")
print("print() return value:", result)          # None
print("Is result None?      ", result is None)  # True

C. Common questions

L1 L2

L1 Fundamental

C.1. How large can an integer be in Python 3? ▾ Answer

In Python 3, integers have arbitrary precision (no fixed 32-bit or 64-bit limit). They can expand to fill any amount of available RAM on the host machine.

C.2. Why does print(0b1111) output 15 instead of 0b1111? ▾ Answer

Python allows declaring integers in 4 bases (decimal, binary, octal, hex), but the Python Virtual Machine (PVM) always evaluates and displays integers in base-10 decimal by default. To display as binary, explicitly use bin(x).

L2 Intermediate

C.3. Why is bool("False") True? ▾ Answer

Python determines the truthiness of strings strictly by length. Any non-empty string has length > 0 and is truthy. The string "False" contains 5 characters, so bool("False") evaluates to True. Only the empty string "" is falsy.

C.4. Why should I use is None instead of == None? ▾ Answer

is checks exact object identity in memory (pointer check). Since None is guaranteed to be a singleton, x is None is faster and immune to custom classes that might override the __eq__ method to return unusual values.

C.5. Why does 0.1 + 0.2 != 0.3? ▾ Answer

Computers represent floating-point numbers in base 2 (IEEE 754). Numbers like 0.1 and 0.2 are repeating infinite fractions in binary, causing tiny precision inaccuracies during addition (0.30000000000000004). Use math.isclose() for float equality comparisons.

C.6. Can floating-point literals be specified in binary, octal, or hexadecimal form? ▾ Answer

No. Unlike integers, floating-point literals can only be specified in decimal (base-10) fractional form or exponential notation. Writing 0b11.01 or 0x12.3 raises a SyntaxError: invalid decimal literal or SyntaxError: invalid syntax.

C.7. In a complex number a + bj, can the imaginary part be written in hexadecimal or binary? ▾ Answer

No. The real part a can be written in any number system (0x10 + 5j evaluates to 16 + 5j), but the imaginary part b must strictly be base-10 decimal. Attempting 10 + 0x5j or 10 + 0b10j raises a SyntaxError.

C.8. Why does True == 1 evaluate to True, but True is 1 evaluates to False? ▾ Answer

== checks value equality. Since bool inherits from int and True has numerical value 1, their values compare equal. However, is checks object identity (heap memory address). True is an instance of bool, whereas 1 is an instance of int; they reside at distinct memory locations.
