  1. Task 1: Introduction and default exception handling — Write a small working demo (10–20 lines) covering the idea; print outputs. ▾ Solution 
    # Task 1: Introduction and default exception handling
# Demonstrating graceful error interception:
def divide_safe(a, b):
    try:
        return a / b
    except ZeroDivisionError:
        print("[Error] Cannot divide by zero. Returning fallback 0.0.")
        return 0.0

print("divide_safe(10, 2):", divide_safe(10, 2))
print("divide_safe(10, 0):", divide_safe(10, 0))
  2. Task 2: Exception hierarchy; try/except — Write a small working demo (10–20 lines) covering the idea; print outputs. ▾ Solution 
    # Task 2: Exception hierarchy; multiple except blocks
def process_data(val):
    try:
        num = int(val)
        return 100 / num
    except ValueError:
        print(f"ValueError: '{val}' is not a valid integer")
    except ZeroDivisionError:
        print("ZeroDivisionError: denominator cannot be zero")
    except Exception as general_err:
        print(f"Unexpected error: {type(general_err).__name__}")

process_data("abc")
process_data(0)
print("Valid:", process_data(5))
  3. Task 3: else and finally blocks — Write a small working demo (10–20 lines) covering the idea; print outputs. ▾ Solution 
    # Task 3: else and finally blocks
def open_and_process(data):
    try:
        print("[try] Attempting calculation")
        res = 50 / data
    except ZeroDivisionError:
        print("[except] Handled zero division")
    else:
        print(f"[else] Succeeded! Result: {res}")
    finally:
        print("[finally] Cleanup always executes (guaranteed)")

open_and_process(10)
print("-" * 30)
open_and_process(0)

P.3. Challenge

  1. Mini project — Combine two topics from this file into one short script related to Exception Handling. ▾ Solution 
    # Mini Project: Custom Exception Hierarchy for Banking API
class BankingError(Exception):
    """Base exception for all banking errors."""
    pass

class InsufficientFundsError(BankingError):
    def __init__(self, balance, amount):
        super().__init__(f"Cannot withdraw ${amount:.2f}; balance is only ${balance:.2f}")
        self.balance = balance
        self.amount = amount

class AccountLockedError(BankingError):
    pass

def withdraw_money(balance, amount, is_locked=False):
    if is_locked:
        raise AccountLockedError("Account is locked due to security policy.")
    if amount > balance:
        raise InsufficientFundsError(balance, amount)
    return balance - amount

try:
    withdraw_money(100.0, 250.0)
except InsufficientFundsError as err:
    print(f"Handled error: {err}")
  2. Edge cases — List 3 edge cases or mistakes beginners make; demonstrate at least one safely. ▾ Solution 
    # Exception Handling Pitfalls & Edge Cases:
# 1. Bare except: 'except:' catches KeyboardInterrupt and SystemExit!
# Always use 'except Exception:' instead of bare 'except:'.

# 2. Catching general Exception BEFORE specific subclasses shadows them:
# try: ... except Exception: ... except ValueError: (ValueError will NEVER run!)

# 3. Using exceptions for regular control flow is anti-pattern (slower than checking).
