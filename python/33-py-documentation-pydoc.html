Documenting code with pydoc, PEP 257 docstring conventions, Google/Sphinx styles, and HTML doc generation.

1. Introduction

L1

L1 Fundamental

1.1. Why Documentation Matters

In professional software engineering, code is read far more often than it is written. High-quality code documentation:

  • Defines API Contracts: Clarifies parameter types, return values, preconditions, and potential exceptions without requiring readers to decipher implementation internals.
  • Accelerates Team Onboarding: Enables new developers, API consumers, and external clients to integrate modules rapidly.
  • Powers IDE Introspection: Modern code editors (VS Code, PyCharm, Antigravity) use docstrings to display inline tooltips, autocompletion hints, and parameter signatures.
  • Enables Automated Site Generation: Automated build systems (Sphinx, MkDocs) extract docstrings directly from Python code into searchable HTML documentation sites.

2. Pydoc overview and usage

L1 L2

L1 Fundamental

2.1. What is pydoc?

pydoc is Python's standard built-in documentation generator and help tool. It reads the docstrings and structural declarations of modules, classes, and functions to generate formatted text or HTML documentation automatically.

Python's interactive help() function runs pydoc under the hood.

L2 Intermediate

2.2. Command-Line Usage of pydoc

Command Action / Output
python -m pydoc <name> Displays text documentation for a module, class, or function in the terminal (e.g. python -m pydoc math).
python -m pydoc -k <keyword> Searches across synopsis lines of all available modules for a keyword.
python -m pydoc -w <module> Writes out formatted HTML documentation to a local file (e.g. my_module.html).
python -m pydoc -p <port> Launches an internal HTTP documentation server on the specified port (e.g. http://localhost:8080/).
python -m pydoc -b Launches the documentation server on an arbitrary port and automatically opens it in your default web browser. 
# Viewing documentation from Python code:
import math

# Using built-in help() function:
# help(math.sqrt)

# Inspecting docstring programmatically:
print("math.sqrt docstring:")
print(math.sqrt.__doc__)  # Return the square root of x.

3. Docstrings and generating docs

L1 L2

L1 Fundamental

3.1. PEP 257 Docstring Conventions

A docstring is a string literal that occurs as the very first statement in a module, function, class, or method definition. Python stores this string in the object's __doc__ attribute.

Rules from PEP 257:

  • Always use triple double quotes: """...""".
  • One-line docstrings: For simple functions. Keep quotes on the same line, end with a period, and use imperative mood ("Return the square root" not "Returns the square root"):
    """Return the absolute path of the target file."""
  • Multi-line docstrings: Begin with a summary line, followed by a blank line, followed by detailed descriptions, argument explanations, return types, and exceptions raised.

L2 Intermediate

3.2. Standard Docstring Styles (Google vs Sphinx)

# Style 1: Google Docstring Style (Most readable in source code)
def calculate_compound_interest(principal: float, rate: float, time_years: int) -> float:
    """Calculate the total compound interest over a specified duration.

    Applies the standard compound interest formula: A = P * (1 + r)^t.

    Args:
        principal (float): The initial investment amount (must be positive).
        rate (float): The annual interest rate as a decimal (e.g. 0.05 for 5%).
        time_years (int): Number of years the amount is invested.

    Returns:
        float: Total accumulated balance including interest.

    Raises:
        ValueError: If principal or rate is negative.

    Example:
        >>> calculate_compound_interest(1000.0, 0.05, 2)
        1102.5
    """
    if principal < 0 or rate < 0:
        raise ValueError("Principal and rate must be non-negative")
    return principal * ((1 + rate) ** time_years)


# Style 2: Sphinx / reStructuredText (reST) Style (Default for Sphinx doc generator)
def format_user_label(username: str, user_id: int) -> str:
    """Format a human-readable display label for a user account.

    :param username: The alphanumeric username.
    :type username: str
    :param user_id: The unique primary key identifier.
    :type user_id: int
    :return: Formatted label string.
    :rtype: str
    """
    return f"{username} (ID: #{user_id})"

3.3. Programmatic Inspection with inspect

While obj.__doc__ gives raw text, the standard library inspect module provides inspect.getdoc(obj), which automatically strips leading indentation and cleans up multiline formatting.

import inspect

raw_doc = calculate_compound_interest.__doc__
clean_doc = inspect.getdoc(calculate_compound_interest)

print("Function name:   ", calculate_compound_interest.__name__)
print("Clean docstring:\n", clean_doc)

C. Common questions

L1 L2

L1 Fundamental

C.1. What is Pydoc and how does it relate to the help() function? ▾ Answer

pydoc is Python's standard library module for generating documentation from source code docstrings. When you call help(obj) in the Python interactive shell, Python invokes pydoc.help(obj) internally to format and display the documentation via a pager.

C.2. What is PEP 257 and what are its key conventions? ▾ Answer

PEP 257 establishes guidelines for Python docstrings:

  • Always enclose docstrings in triple double quotes ("""...""").
  • Use imperative mood in the summary line ("Calculate X" rather than "Calculates X").
  • For multiline docstrings, separate the summary line from the description body with a blank line.
  • Document arguments, return types, and exceptions raised.
C.3. What is the difference between a code comment (#) and a docstring? ▾ Answer

Comments (#): Are completely discarded by the Python bytecode compiler. They cannot be inspected at runtime and do not show up in help() or documentation generators.

Docstrings ("""..."""): Are retained by the compiler and bound to the object's __doc__ attribute at runtime. They are accessible programmatically and parsed by IDEs and documentation tools.

C.4. How do you launch a local web documentation server with Pydoc? ▾ Answer

Run python -m pydoc -p 8080 from your terminal to launch a local HTTP server on port 8080, or run python -m pydoc -b to start the server and automatically launch it in your default web browser.

L2 Intermediate

C.5. What are the differences between Google, NumPy, and Sphinx docstring styles? ▾ Answer
  • Google Style: Uses indented sections with clear titles (Args:, Returns:, Raises:). Highly readable in raw code.
  • NumPy / SciPy Style: Uses underlined sections with dashes (Parameters\n----------). Popular in data science and scientific computing.
  • Sphinx (reST) Style: Uses inline directives (:param name:, :returns:). Standard for Sphinx, but more verbose to read directly in source code.
C.6. What happens to docstrings when Python runs with the -OO flag? ▾ Answer

When Python is executed with python -OO, the compiler strips all assert statements AND strips all docstrings completely to minimize compiled .pyc file sizes and memory usage. As a result, __doc__ evaluates to None for all functions and classes!

C.7. How does inspect.getdoc() differ from accessing __doc__ directly? ▾ Answer

Accessing obj.__doc__ returns the raw string, including leading whitespace and tabs from source code indentation. inspect.getdoc(obj) automatically strips common leading indentation using cleandoc(), providing clean, formatted text ready for display.

C.8. What modern tools exist beyond Pydoc for documentation generation? ▾ Answer
  • Sphinx: The industry gold standard for large Python libraries (powers ReadTheDocs).
  • MkDocs with mkdocstrings: Markdown-based static site generator that automatically renders Python docstrings into modern responsive sites.
  • pdoc: Minimalist, zero-config modern alternative to Pydoc that auto-generates clean HTML5 documentation.

P.3. Challenge

  1. Mini project — Build a Self-Documenting SDK Class that inspects its own methods and prints a clean API manual. ▾ Solution 
    # Mini Project: Self-Documenting API Service
import inspect

class PaymentService:
    """Service handling multi-currency payment operations."""

    def authorize(self, card_token: str, amount: float) -> str:
        """Authorize a charge on a payment token."""
        return "AUTH_OK"

    def refund(self, transaction_id: str, amount: float) -> bool:
        """Refund a previously captured transaction."""
        return True

    @classmethod
    def generate_api_manual(cls):
        print(f"=== API Manual for {cls.__name__} ===")
        print(f"Description: {inspect.getdoc(cls)}\n")
        print("Methods:")
        for name, func in inspect.getmembers(cls, predicate=inspect.isfunction):
            if not name.startswith("_") and name != "generate_api_manual":
                sig = inspect.signature(func)
                doc = inspect.getdoc(func) or "No documentation provided."
                print(f"  - {name}{sig}: {doc}")

PaymentService.generate_api_manual()
