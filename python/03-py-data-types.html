3.1. int (Integer Data Type)

  • Arbitrary precision: In Python 3, int values have unlimited precision (no fixed 32-bit or 64-bit overflow limit; constrained only by available system RAM).

❖ Types of Representation for int Literal Values (Number Systems)

In Python, programmers can represent integer values in 4 different number systems (bases):

Form / Number System Base Allowed Digits Required Prefix Valid Examples SyntaxError Pitfall
1. Decimal Form Base 10 0 to 9 None (Default) a = 10, count = 789 Cannot start with leading zero (e.g. 0123 is invalid in Python 3)
2. Binary Form Base 2 0, 1 0b or 0B a = 0b1111 (15), b = 0B11 (3) c = 0B112 (2 is not allowed in binary)
3. Octal Form Base 8 0 to 7 0o or 0O a = 0o123 (83), b = 0O567 (375) c = 0O786 (8 is not allowed in octal)
4. Hexadecimal Form Base 16 0 to 9 & a to f / A to F 0x or 0X a = 0xface (64206), b = 0XBee5 (48869) c = 0xBeer ('r' is not in hex range a-f)
Key Rule on PVM Output: As a programmer, you can declare integer literals in decimal, binary, octal, or hexadecimal forms. However, the Python Virtual Machine (PVM) will always print and return numbers in decimal (base-10) form by default! 
# --- 1. Decimal Form (Base-10, Default) ---
a = 10
print("Decimal:", a)  # 10

# --- 2. Binary Form (Base-2, Prefix 0b / 0B) ---
a = 0b1111
b = 0B11
print("0b1111 ->", a)  # 15 (PVM output is decimal)
print("0B11   ->", b)  # 3
# c = 0B112            # SyntaxError: invalid digit '2' in binary literal

# --- 3. Octal Form (Base-8, Prefix 0o / 0O) ---
a = 0o123
b = 0O567
print("0o123  ->", a)  # 83
print("0O567  ->", b)  # 375
# c = 0O786            # SyntaxError: invalid digit '8' in octal literal

# --- 4. Hexadecimal Form (Base-16, Prefix 0x / 0X) ---
a = 0xface
b = 0XBee5
print("0xface ->", a)  # 64206
print("0XBee5 ->", b)  # 48869
# c = 0xBeer           # SyntaxError: invalid hexadecimal literal ('r' is invalid)

❖ Base Conversion Functions: bin(), oct(), hex()

Python provides built-in conversion functions to convert an integer value from any base (decimal, binary, octal, or hexadecimal) into its corresponding binary, octal, or hexadecimal string representation.

Conversion Function Target Base Description Prefix in Output String
bin(x) Base 2 (Binary) Converts any integer (decimal, octal, hex) into a binary string representation. '0b'
oct(x) Base 8 (Octal) Converts any integer (decimal, binary, hex) into an octal string representation. '0o'
hex(x) Base 16 (Hexadecimal) Converts any integer (decimal, binary, octal) into a hexadecimal string representation. '0x' 
# ==========================================================
# 1. bin() - Convert from ANY base to Binary
# ==========================================================
# From Decimal:
print(bin(15))       # '0b1111'

# From Octal:
print(bin(0o11))     # '0b1001' (0o11 is 9 in decimal -> 0b1001)

# From Hexadecimal:
print(bin(0X10))     # '0b10000' (0x10 is 16 in decimal -> 0b10000)

# ==========================================================
# 2. oct() - Convert from ANY base to Octal
# ==========================================================
# From Decimal:
print(oct(10))       # '0o12'

# From Binary:
print(oct(0B1111))   # '0o17' (0b1111 is 15 in decimal -> 0o17)

# From Hexadecimal:
print(oct(0X123))    # '0o443' (0x123 is 291 in decimal -> 0o443)

# ==========================================================
# 3. hex() - Convert from ANY base to Hexadecimal
# ==========================================================
# From Decimal:
print(hex(100))      # '0x64'

# From Binary:
print(hex(0B111111)) # '0x3f' (0b111111 is 63 in decimal -> 0x3f)

# From Octal:
print(hex(0o12345))  # '0x14e5' (0o12345 is 5349 in decimal -> 0x14e5)

# ==========================================================
# 4. Bonus: int(string, base) - Convert strings back to Decimal
# ==========================================================
print(int("0b1111", 2))   # 15
print(int("0o123", 8))    # 83
print(int("0xface", 16))  # 64206

4. Immutability concepts and the id() function

L1 L2

L1 Fundamental

4.1. What is the id() function?

  • id(object) is a built-in Python function that returns the unique identity of an object as an integer.
  • Unique & Constant: An object's ID is guaranteed to be unique and remain completely constant for that object throughout its entire lifetime in memory.
  • CPython Implementation (Memory Address): In standard CPython, id(x) is the actual virtual memory address (PyObject* pointer) where the object is stored in RAM.
  • You can format the ID with hex(id(x)) to see standard hexadecimal memory pointer addresses (e.g., 0x104b2c890).
name = "Bharat"
num = 42

print("Decimal ID:    ", id(name))        # e.g., 4376483504
print("Hex Memory Addr:", hex(id(name)))  # e.g., 0x104dd2eb0
print("Number ID:      ", hex(id(num)))   # e.g., 0x104b50d50

4.2. Relationship between id(), the 'is' operator, and '=='

Understanding id() is essential for grasping the difference between equality and identity:

Operator / Check What it tests How Python evaluates it Example (a = [1, 2]; b = [1, 2])
Equality: a == b Value equality: Do both objects contain identical data? Calls a.__eq__(b) True (both contain 1 and 2)
Identity: a is b Memory identity: Do both variable names point to the exact same object in RAM? Fundamentally evaluates id(a) == id(b) False (two distinct heap objects) 
list1 = [1, 2, 3]
list2 = [1, 2, 3]
list3 = list1  # Aliasing: list3 points to the same object as list1

print("list1 == list2:", list1 == list2)  # True  (same contents)
print("list1 is list2:", list1 is list2)  # False (different memory addresses)
print("id(list1) == id(list2):", id(list1) == id(list2))  # False

print("list1 is list3:", list1 is list3)  # True  (same object)
print("id(list1) == id(list3):", id(list1) == id(list3))  # True

4.3. Proving Mutability vs. Immutability with id()

  • Immutable Types (int, float, bool, str, tuple, frozenset, bytes): Any operation that appears to "modify" the value actually constructs a brand new object in memory with a new id().
  • Mutable Types (list, dict, set, bytearray): In-place modification alters the object contents directly, preserving the exact same id(). 
# --- Immutable Example: int ---
x = 100
print("Initial x ID:", hex(id(x)))
x = x + 1  # Creates a new int(101) object and rebinds name x
print("After + 1 ID: ", hex(id(x)))  # DIFFERENT memory address!

# --- Immutable Example: str ---
s = "hello"
print("Initial s ID:", hex(id(s)))
s = s + " world"  # Allocates a new concatenated string
print("After concat ID:", hex(id(s)))  # DIFFERENT memory address!

# --- Mutable Example: list ---
nums = [1, 2]
print("Initial nums ID:", hex(id(nums)))
nums.append(3)  # Mutates the existing list in-place
print("After append ID:  ", hex(id(nums)))  # EXACT SAME memory address!

L2 Intermediate

4.4. CPython Memory Optimization: Interning & Singletons

Because creating millions of tiny immutable objects would be slow and waste RAM, CPython employs memory interning and pre-allocated singleton pools:

  • Small Integer Caching (-5 to 256): CPython pre-allocates an array of integer objects for values between -5 and 256 at startup. Any variable holding a value in this range shares the exact same object and ID.
  • String Interning: Short strings that look like Python identifiers (alphanumeric and underscores) are automatically interned.
  • Singletons: None, True, and False are guaranteed singletons; their memory address is permanent across the process. Always compare them using is None rather than == None.
# Small integers share IDs (interned):
a = 250
b = 250
print("250: a is b ->", a is b)              # True (same id)
print("id(a) == id(b):", id(a) == id(b))      # True

# Large integers outside [-5, 256] may have different IDs:
c = 1000500
d = 1000500
print("1000500: c is d ->", c is d)          # Often False in REPL / scripts
print("id(c) == id(d):", id(c) == id(d))      # False (distinct heap objects)
print("c == d (values equal):", c == d)      # True

# None is a singleton:
val = None
print("val is None:", val is None)            # True (checks id(val) == id(None))

4.5. The ID Recycling Gotcha (Temporary Objects)

Crucial Pitfall — Lifetime and ID Reuse: An object's ID is only guaranteed unique while the object is alive. Once an object has no remaining references, Python's garbage collector deallocates it. The memory allocator can then immediately reuse that same memory address for a new object! 
# Pitfall: Comparing IDs of temporary objects that don't exist simultaneously
# The first list [1, 2] is created and immediately garbage-collected!
# The second list [3, 4] can be allocated in the EXACT SAME freed memory slot:
print(id([1, 2]) == id([3, 4]))  # May evaluate to True!

# To safely compare identities, both objects MUST be held by variables simultaneously:
obj_a = [1, 2]  # Kept alive by obj_a
obj_b = [3, 4]  # Kept alive by obj_b
print(id(obj_a) == id(obj_b))    # Always False!
print(obj_a is obj_b)            # Always False!

5. range and sequence forms

L1 L2

L1 Fundamental

  • range is an immutable sequence of integers — lazy (does not build a full list).
range(5)          # 0..4
range(1, 5)       # 1..4
range(1, 10, 2)   # 1, 3, 5, 7, 9
list(range(3))    # [0, 1, 2]

L2 Intermediate

  • Forms: range(stop), range(start, stop), range(start, stop, step). stop is exclusive. Negative step allowed.
list(range(5, 0, -1))  # [5, 4, 3, 2, 1]
len(range(1_000_000))  # cheap — no million-element list

6. Bytes / bytearray (intro)

L1 L2

L1 Fundamental

  • bytes — immutable sequence of bytes (0–255). bytearray — mutable version.
b = b"hi"
ba = bytearray(b"hi")
ba[0] = ord("H")
print(ba)          # bytearray(b'Hi')

L2 Intermediate

C. Common questions

L1 L2

L1 Fundamental

C.1. How do I check a type? ▾ Answer

Prefer isinstance(x, int) over type(x) == int (handles subclasses). For exact type, type(x) is int.

C.2. Why is bool a subclass of int? ▾ Answer

Historical design — booleans participate in arithmetic. Prefer clear boolean logic over relying on that.

L2 Intermediate

C.3. Does a = a + 1 mutate the int? ▾ Answer

No. Integers are immutable. A new int is created and the name is rebound.

P.3. Challenge

  1. Explain with code why small ints may share ids (interning) but large ones may not. ▾ Solution 
    # Small integer interning in CPython [-5 to 256]:
a = 250
b = 250
print("a is b (250, interned):", a is b)  # True (same memory reference)

c = 1000001
d = 1000001
print("c is d (large int outside intern range):", c is d)  # Often False in REPL / scripts
print("c == d (equality check):", c == d)  # Always True
  2. Write a function describe(x) that returns type name and whether the value is mutable (for the types you know). ▾ Solution 
    def describe(x):
    """Return type name and whether the value is mutable."""
    type_name = type(x).__name__
    mutable_types = (list, dict, set, bytearray)
    is_mutable = isinstance(x, mutable_types)
    return {"type": type_name, "mutable": is_mutable}

print(describe(42))            # {'type': 'int', 'mutable': False}
print(describe("hello"))       # {'type': 'str', 'mutable': False}
print(describe([1, 2, 3]))     # {'type': 'list', 'mutable': True}
print(describe({"a": 1}))      # {'type': 'dict', 'mutable': True}
print(describe((1, 2)))        # {'type': 'tuple', 'mutable': False}
