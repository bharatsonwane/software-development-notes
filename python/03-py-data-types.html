3. Immutability concepts and the id() function

L1 L2

L1 Fundamental

3.1. What is the id() function?

  • id(object) is a built-in Python function that returns the unique identity of an object as an integer.
  • Unique & Constant: An object's ID is guaranteed to be unique and remain completely constant for that object throughout its entire lifetime in memory.
  • CPython Implementation (Memory Address): In standard CPython, id(x) is the actual virtual memory address (PyObject* pointer) where the object is stored in RAM.
  • You can format the ID with hex(id(x)) to see standard hexadecimal memory pointer addresses (e.g., 0x104b2c890).
name = "Bharat"
num = 42

print("Decimal ID:    ", id(name))        # e.g., 4376483504
print("Hex Memory Addr:", hex(id(name)))  # e.g., 0x104dd2eb0
print("Number ID:      ", hex(id(num)))   # e.g., 0x104b50d50

3.2. Relationship between id(), the 'is' operator, and '=='

Understanding id() is essential for grasping the difference between equality and identity:

Operator / Check What it tests How Python evaluates it Example (a = [1, 2]; b = [1, 2])
Equality: a == b Value equality: Do both objects contain identical data? Calls a.__eq__(b) True (both contain 1 and 2)
Identity: a is b Memory identity: Do both variable names point to the exact same object in RAM? Fundamentally evaluates id(a) == id(b) False (two distinct heap objects) 
list1 = [1, 2, 3]
list2 = [1, 2, 3]
list3 = list1  # Aliasing: list3 points to the same object as list1

print("list1 == list2:", list1 == list2)  # True  (same contents)
print("list1 is list2:", list1 is list2)  # False (different memory addresses)
print("id(list1) == id(list2):", id(list1) == id(list2))  # False

print("list1 is list3:", list1 is list3)  # True  (same object)
print("id(list1) == id(list3):", id(list1) == id(list3))  # True

3.3. Proving Mutability vs. Immutability with id()

  • Immutable Types (int, float, bool, str, tuple, frozenset, bytes): Any operation that appears to "modify" the value actually constructs a brand new object in memory with a new id().
  • Mutable Types (list, dict, set, bytearray): In-place modification alters the object contents directly, preserving the exact same id(). 
# --- Immutable Example: int ---
x = 100
print("Initial x ID:", hex(id(x)))
x = x + 1  # Creates a new int(101) object and rebinds name x
print("After + 1 ID: ", hex(id(x)))  # DIFFERENT memory address!

# --- Immutable Example: str ---
s = "hello"
print("Initial s ID:", hex(id(s)))
s = s + " world"  # Allocates a new concatenated string
print("After concat ID:", hex(id(s)))  # DIFFERENT memory address!

# --- Mutable Example: list ---
nums = [1, 2]
print("Initial nums ID:", hex(id(nums)))
nums.append(3)  # Mutates the existing list in-place
print("After append ID:  ", hex(id(nums)))  # EXACT SAME memory address!

L2 Intermediate

3.4. CPython Memory Optimization: Interning & Singletons

Because creating millions of tiny immutable objects would be slow and waste RAM, CPython employs memory interning and pre-allocated singleton pools:

  • Small Integer Caching (-5 to 256): CPython pre-allocates an array of integer objects for values between -5 and 256 at startup. Any variable holding a value in this range shares the exact same object and ID.
  • String Interning: Short strings that look like Python identifiers (alphanumeric and underscores) are automatically interned.
  • Singletons: None, True, and False are guaranteed singletons; their memory address is permanent across the process. Always compare them using is None rather than == None.
# Small integers share IDs (interned):
a = 250
b = 250
print("250: a is b ->", a is b)              # True (same id)
print("id(a) == id(b):", id(a) == id(b))      # True

# Large integers outside [-5, 256] may have different IDs:
c = 1000500
d = 1000500
print("1000500: c is d ->", c is d)          # Often False in REPL / scripts
print("id(c) == id(d):", id(c) == id(d))      # False (distinct heap objects)
print("c == d (values equal):", c == d)      # True

# None is a singleton:
val = None
print("val is None:", val is None)            # True (checks id(val) == id(None))

3.5. The ID Recycling Gotcha (Temporary Objects)

Crucial Pitfall — Lifetime and ID Reuse: An object's ID is only guaranteed unique while the object is alive. Once an object has no remaining references, Python's garbage collector deallocates it. The memory allocator can then immediately reuse that same memory address for a new object! 
# Pitfall: Comparing IDs of temporary objects that don't exist simultaneously
# The first list [1, 2] is created and immediately garbage-collected!
# The second list [3, 4] can be allocated in the EXACT SAME freed memory slot:
print(id([1, 2]) == id([3, 4]))  # May evaluate to True!

# To safely compare identities, both objects MUST be held by variables simultaneously:
obj_a = [1, 2]  # Kept alive by obj_a
obj_b = [3, 4]  # Kept alive by obj_b
print(id(obj_a) == id(obj_b))    # Always False!
print(obj_a is obj_b)            # Always False!

4. range and sequence forms

L1 L2

L1 Fundamental

range represents an immutable, lazy sequence of numbers. Unlike in Python 2 (where range built a full list eagerly), Python 3's range creates a sequence object that calculates integers on demand.

Constructor FormSyntaxDefault ValuesValues Generated
1-Argument Form range(stop) start = 0, step = 1 0, 1, 2, ..., stop - 1
2-Argument Form range(start, stop) step = 1 start, start + 1, ..., stop - 1
3-Argument Form range(start, stop, step) None start, start + step, ... until boundary reached 
# Basic range forms:
r1 = range(5)             # 0, 1, 2, 3, 4
r2 = range(10, 15)        # 10, 11, 12, 13, 14
r3 = range(0, 20, 5)      # 0, 5, 10, 15

# Converting to collection to visualize elements:
print(list(r1))           # [0, 1, 2, 3, 4]
print(list(r3))           # [0, 5, 10, 15]

L2 Intermediate

4.1. Rules, Negative Steps & $O(1)$ Performance Characteristics

  • Integral Type Enforcement: All three arguments must be strictly integers (int). Passing floats (e.g. range(1.5, 10.5)) immediately raises TypeError: 'float' object cannot be interpreted as an integer.
  • Zero Step Prohibition: step can never be 0. Passing step=0 raises ValueError: range() arg 3 must not be zero.
  • Negative Step Direction: When step < 0, progression moves downward, requiring start > stop (e.g. range(10, 0, -2) yields 10, 8, 6, 4, 2). If start <= stop with a negative step, an empty range is produced without errors.
  • $O(1)$ Constant Memory: A range object stores only three integers in memory: start, stop, and step. A range representing 1 billion numbers (range(1_000_000_000)) consumes the exact same 48 bytes of memory as range(5)!
  • $O(1)$ Membership Testing: In Python 3, checking membership (x in range(...)) does not perform a linear scan. The interpreter uses an arithmetic boundary formula ($O(1)$ time complexity):
    start <= x < stop and (x - start) % step == 0
import sys

# Constant memory proof:
small_range = range(10)
huge_range = range(10_000_000_000)
print("Memory of range(10):            ", sys.getsizeof(small_range), "bytes")  # 48 bytes
print("Memory of range(10,000,000,000):", sys.getsizeof(huge_range), "bytes")   # 48 bytes

# Negative step countdown:
print(list(range(5, 0, -1)))  # [5, 4, 3, 2, 1]

# Fast O(1) membership check:
print(999_999_999 in huge_range)  # True (computed instantly in nanoseconds!)

# Indexing and slicing on range objects:
print("First element:", huge_range[0])     # 0
print("Slice of range:", huge_range[2:6])  # range(2, 6)

5. Bytes / bytearray (intro)

L1 L2

L1 Fundamental

Python provides two primary built-in data types for manipulating raw 8-bit binary data (such as network packets, images, audio streams, and encrypted payloads):

Binary TypeMutabilityAllowed Element Value RangeModification In-Place?
bytes Immutable Integers from 0 to 255 ($2^8 - 1$) No. Attempting item assignment raises TypeError: 'bytes' object does not support item assignment.
bytearray Mutable Integers from 0 to 255 ($2^8 - 1$) Yes. Elements can be updated, appended, popped, or sliced in-place without reallocating the container. 
# 1. bytes: immutable binary sequence
b1 = b"Hello"
print("b1:", b1, "type:", type(b1))  # b'Hello', 
print("First byte integer value:", b1[0])  # 72 (ASCII for 'H')

# 2. Creating bytes from integer iterable:
b2 = bytes([65, 66, 67, 68])
print("b2:", b2)  # b'ABCD'

# 3. bytearray: mutable binary sequence
ba = bytearray(b"Hello")
ba[0] = 74  # 74 is ASCII for 'J'
print("Modified bytearray:", ba)  # bytearray(b'Jello')

L2 Intermediate

5.1. Value Bounds & String Encoding/Decoding

  • Out-of-Bounds Error: Every byte slot must fit in a single 8-bit byte. Providing an integer outside the range $0 \le x \le 255$ raises ValueError: bytes must be in range(0, 256) or byte must be in range(0, 256).
  • Encoding Text to Bytes: Calling str.encode(encoding="utf-8") converts Unicode characters into raw bytes.
  • Decoding Bytes to Text: Calling bytes.decode(encoding="utf-8") parses raw binary data back into a Unicode str.
  • Indexing vs Slicing Nuance:
    • Indexing a byte object (b[0]) returns an int (the byte's numeric value, e.g. 65).
    • Slicing a byte object (b[0:1]) returns a bytes sequence (e.g. b'A').
# Out of bounds value demonstration:
# Attempting to pass values >= 256 raises ValueError (bytes only hold 0..255):
# bad_bytes = bytes([100, 200, 256])  # ValueError: bytes must be in range(0, 256)
valid_bytes = bytes([100, 200, 255])  # Valid 8-bit bytes (0 to 255)
print("Valid bytes created:", valid_bytes)

# Encoding and Decoding:
text = "Python 🐍"
encoded = text.encode("utf-8")
print("Encoded bytes:", encoded)         # b'Python \xf0\x9f\x90\x8d'
print("Byte length:  ", len(encoded))    # 11 bytes (the emoji takes 4 bytes!)

decoded = encoded.decode("utf-8")
print("Decoded text: ", decoded)         # Python 🐍

C. Common questions

L1 L2

L1 Fundamental

C.1. How should you check an object's type in production code? ▾ Answer

Always prefer isinstance(x, ExpectedType) over type(x) == ExpectedType.

  • isinstance correctly recognizes subclasses (e.g., isinstance(True, int) is True, adhering to the Liskov Substitution Principle).
  • Use type(x) is ExpectedType only when you specifically want to reject subclasses and verify the exact concrete class identity.
C.2. Why does modifying an immutable variable (e.g., x = x + 1) work without raising an error? ▾ Answer

Because the existing integer object in memory is never modified. Instead, Python computes the result, allocates a brand-new integer object in heap memory, and rebinds the variable name x to point to the new memory address.

You can verify this by checking id(x) before and after the operation—the memory address changes!

C.3. Why is bool implemented as a subclass of int? ▾ Answer

In early Python versions (pre-2.3), there was no dedicated bool type; integers 1 and 0 were used directly. When bool was formally introduced (PEP 285), it was created as a subclass of int for backward compatibility with existing code that expected numerical return values.

As a result, True == 1, False == 0, and mathematical expressions like True + True evaluate to 2.

L2 Intermediate

C.4. Why does range(1_000_000) consume negligible memory, and how does x in range(...) run in $O(1)$ time? ▾ Answer

In Python 3, a range object does not store integers in an array. It is a lightweight descriptor storing only three numbers: start, stop, and step (fixed 48 bytes).

When testing membership (x in r), Python performs an arithmetic calculation in constant time ($O(1)$):
1. Checks if start <= x < stop (or reverse for negative step).
2. Checks if (x - start) % step == 0.
It never iterates through numbers linearly!

C.5. What is the fundamental difference between bytes and bytearray? ▾ Answer

bytes is an immutable sequence of bytes, whereas bytearray is a mutable sequence.

  • bytes is hashable and can be used as dictionary keys or set elements.
  • bytearray can be mutated in-place (e.g. ba[0] = 65 or ba.append(255)), making it ideal for high-performance network buffer processing without repeated memory reallocations.
C.6. Can an immutable container (like a tuple) have its contents changed if it contains a mutable object? ▾ Answer

Yes. Immutability in Python means that the container's bindings (memory references) cannot be changed once created. In t = (1, [10, 20]), the tuple will always point to integer 1 and the list object at that specific memory address.

However, the internals of the referenced list can be mutated in-place: t[1].append(30) succeeds, resulting in (1, [10, 20, 30]). Because its content can change, such a tuple is unhashable and cannot be used as a dictionary key!
