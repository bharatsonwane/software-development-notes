4. Limitations of Python

L1

L1 Fundamental

  • Slower than C/C++/Rust for CPU-heavy loops (often mitigated with NumPy / C extensions).
  • GIL (CPython) limits true parallel CPU threads in one process — File 25.
  • Mobile / browser not primary targets (unlike JS on the web).
  • Runtime errors for type mistakes unless you add type checkers (mypy) — File 32.
  • Design choices (indentation, dynamic typing) can frustrate some teams — not “bugs,” but trade-offs.

6. Install, REPL, and first program

L1

L1 Fundamental

6.1. Install

  • Download from python.org, or use OS package managers / pyenv. On macOS/Linux use python3; Windows often installs py launcher.

6.2. REPL (interactive shell)

$ python3
>>> 2 + 3
5
>>> print("hi")
hi
>>> exit()
  • REPL is great for experiments. Exit with exit() or Ctrl-D (Unix) / Ctrl-Z Enter (Windows).

6.3. Creating and running a Python file

A Python script is a plain text file saved with the .py extension. You can run it in several ways:

# hello.py
print("Hello, Python")
  • 1. Standard terminal execution: Open your terminal, navigate to the folder where the file is saved, and run:
# macOS / Linux
python3 hello.py

# Windows (using py launcher or python)
py hello.py
# or: python hello.py

# Output:
# Hello, Python
  • 2. Running with relative or absolute paths: If your terminal is in the project root, provide the relative path to the script:
python3 python/01-practice.py
  • 3. Inside an active virtual environment: Once your .venv is activated (prompt displays (.venv)), the alias python points directly to the environment runtime:
python hello.py
  • 4. Running as a module (-m flag): Executes the file as a module within Python's import path (leave off the .py):
python3 -m hello
  • 5. From your code editor / IDE: In VS Code or Antigravity IDE, click the ▷ (Run Python File) play button in the top-right corner of the editor, or right-click in the file and select "Run Python File in Terminal".

6.4. Virtual environments (preview)

  • A virtual environment (venv) provides an isolated Python runtime so project dependencies do not conflict with system packages (full details in File 17):
# 1. Create a virtual environment named .venv
python3 -m venv .venv

# 2. Activate it (prompt will change to show (.venv))
source .venv/bin/activate          # macOS / Linux
# .venv\Scripts\activate          # Windows PowerShell / CMD

# 3. Confirm which Python interpreter is active (points inside .venv)
which python                       # macOS / Linux (Windows: where python)
# Output: /path/to/project/.venv/bin/python

# 4. Deactivate when finished
deactivate

C. Common questions

L1 L2

L1 Fundamental

C.1. Is Python compiled or interpreted? ▾ Answer

Python source code (.py) is compiled into platform-independent bytecode (.pyc files inside __pycache__), which is then executed by the Python Virtual Machine (PVM) (the CPython runtime). Because compilation happens automatically on the fly without producing a standalone machine binary, Python is classified as an interpreted, bytecode-executed language.

C.2. Why prefer Python 3? ▾ Answer
  • Python 2 is EOL: Python 2 reached official End-of-Life on Jan 1, 2020 and receives no security updates.
  • Native Unicode: Python 3 uses UTF-8 strings by default (str is Unicode text, bytes is raw binary).
  • Cleaner syntax: True float division (5 / 2 = 2.5), print() as a function, f-strings, keyword-only args, and type hints.
  • Modern libraries: All modern frameworks (FastAPI, Django, NumPy, PyTorch) exclusively support Python 3.

L2 Intermediate

C.3. What is CPython? ▾ Answer

CPython is the default reference implementation of Python written in C. It compiles Python code to bytecode and executes it on the CPython VM. Alternatives include:

  • PyPy: Uses a Just-In-Time (JIT) compiler for significantly faster execution in CPU-bound programs.
  • Jython: Runs on the JVM with seamless Java interoperability.
  • IronPython: Targets the .NET framework / CLR.
  • MicroPython: Optimized to run directly on microcontrollers and embedded devices.

L2 Intermediate

P.3. Challenge

  1. Research one alternative implementation (PyPy or Jython) and write a 5-line comment comparing it to CPython. ▾ Solution 
    # Comparison: PyPy vs CPython
# 1. CPython is the standard reference implementation written in C; it interprets bytecode with a PVM.
# 2. PyPy is an alternative implementation written in RPython with a built-in JIT (Just-In-Time) compiler.
# 3. PyPy often executes pure CPU-bound Python code significantly faster (often 4x-7x) than CPython.
# 4. PyPy has higher memory overhead and may have compatibility issues with some C-extensions.
# 5. CPython remains the default because of universal C-extension library compatibility (NumPy, SciPy).
  2. List three domains where Python is common and one where another language is often preferred — with reasons. ▾ Solution 
    # --- 3 Domains where Python is common ---
# 1. AI & Machine Learning: Unmatched ecosystem (PyTorch, TensorFlow, Scikit-learn, HuggingFace).
# 2. Web Development & APIs: Rapid turnaround with modern frameworks (FastAPI, Django, Flask).
# 3. Data Analysis & Automation: Intuitive data wrangling (Pandas, Polars, BeautifulSoup).

# --- 1 Domain where another language is preferred ---
# Game Engines / Low-Latency Trading / OS Kernels:
# C, C++, or Rust are preferred because they compile directly to machine code, offer direct memory
# control, deterministic execution latency, and zero garbage-collection pauses.
