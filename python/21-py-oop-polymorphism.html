1. Introduction

L1 Fundamental

1.1. Overview

  • Polymorphism (Greek for "many forms") is the OOP ability to treat different underlying types through a uniform interface. In Python, this is manifested through operator overloading, method overriding, and duck typing.
  • Encapsulation bundles data (attributes) and methods that operate on that data into a single unit while restricting direct outside access to internal representation (data hiding).

2. Operator overloading and __str__ / __repr__

L1 L2

L1 Fundamental

2.1. Magic (Dunder) Methods for Operators

In Python, operators are syntactic sugar for special double-underscore ("dunder") methods:

OperatorExpressionUnderlying Dunder Method
Addition (+) a + b a.__add__(b)
Subtraction (-) a - b a.__sub__(b)
Multiplication (*) a * b a.__mul__(b)
Equality (==) a == b a.__eq__(b)
Less Than (<) a < b a.__lt__(b) 
class Vector2D:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __add__(self, other):
        if isinstance(other, Vector2D):
            return Vector2D(self.x + other.x, self.y + other.y)
        return NotImplemented

    def __eq__(self, other):
        if isinstance(other, Vector2D):
            return self.x == other.x and self.y == other.y
        return False

    def __repr__(self):
        return f"Vector2D({self.x}, {self.y})"

v1 = Vector2D(2, 4)
v2 = Vector2D(3, 1)
v3 = v1 + v2
print("v1 + v2 =", v3)          # Vector2D(5, 5)
print("v1 == Vector2D(2, 4):", v1 == Vector2D(2, 4))  # True

L2 Intermediate

2.2. __str__ vs __repr__

  • __repr__(self): For developers and debugging. Should be unambiguous and, if possible, look like valid Python code to recreate the object (eval(repr(obj)) == obj). Fallback for __str__ if __str__ is not defined.
  • __str__(self): For end users. Should be readable and user-friendly. Called by print(obj) and str(obj).

3. Method and constructor overloading patterns

L1 L2

L1 Fundamental

3.1. Why Python Does Not Support Method Overloading

In Java/C++, you can define multiple methods with the same name and different parameter types. In Python, defining two methods with identical names causes the second definition to overwrite the first in the class dictionary.

L2 Intermediate

3.2. Pythonic Overloading Patterns

# Pattern 1: Default arguments and type inspection:
class Calculator:
    def add(self, a, b=0, c=0):
        return a + b + c

calc = Calculator()
print(calc.add(10))        # 10
print(calc.add(10, 20))    # 30
print(calc.add(10, 20, 30))# 60

# Pattern 2: singledispatchmethod from functools (Python 3.8+):
from functools import singledispatchmethod

class Formatter:
    @singledispatchmethod
    def format(self, val):
        return f"Unknown: {val}"

    @format.register(int)
    def _(self, val):
        return f"Integer: {val:,}"

    @format.register(list)
    def _(self, val):
        return f"List of {len(val)} items"

4. Method and constructor overriding

L1 L2

L1 Fundamental

4.1. Overriding Parent Methods

When a subclass provides its own definition of a method already declared in its superclass, it overrides the parent's behavior:

class NotificationService:
    def send(self, recipient, message):
        print(f"Generic notification to {recipient}: {message}")

class EmailNotification(NotificationService):
    def send(self, recipient, message):
        # Override to send email
        print(f"Sending SMTP email to {recipient}: {message}")

class SMSNotification(NotificationService):
    def send(self, recipient, message):
        # Override to send SMS
        print(f"Dispatching SMS to {recipient}: {message}")

def notify_user(service: NotificationService, user, text):
    service.send(user, text)  # Polymorphic dispatch

notify_user(EmailNotification(), "sonwane@example.com", "Welcome!")
notify_user(SMSNotification(), "+1-555-0199", "Code: 4920")

5. Abstract methods and abstract classes

L1 L2

L1 Fundamental

5.1. The abc Module & Strict Contracts

  • An Abstract Base Class (ABC) is a class that defines an interface contract that subclasses must implement.
  • Inherits from abc.ABC and decorates abstract methods with @abstractmethod.
  • Cannot be instantiated directly: Attempting to instantiate an ABC with unimplemented abstract methods raises a TypeError at runtime.
from abc import ABC, abstractmethod

class PaymentGateway(ABC):
    @abstractmethod
    def process_payment(self, amount: float) -> bool:
        """Must be implemented by concrete gateways."""
        pass

# Attempting direct instantiation:
# p = PaymentGateway()  # TypeError: Can't instantiate abstract class PaymentGateway with abstract method process_payment

class StripeGateway(PaymentGateway):
    def process_payment(self, amount: float) -> bool:
        print(f"Charging ${amount} via Stripe.")
        return True

s = StripeGateway()
s.process_payment(99.0)

6. Duck typing & Protocols

L1 L2

L1 Fundamental

6.1. Duck Typing Philosophy

"If it walks like a duck and quacks like a duck, it's a duck."
In Python, polymorphism does not require inheriting from a common base class. A function only cares that an object has the necessary method or attribute at runtime: 
class PDFRenderer:
    def render(self, content):
        return f"Rendering PDF: {content}"

class HTMLRenderer:
    def render(self, content):
        return f"<html><body>{content}</body></html>"

def publish_document(renderer, text):
    # Works for any object having a .render() method
    print(renderer.render(text))

publish_document(PDFRenderer(), "Financial Report")
publish_document(HTMLRenderer(), "Financial Report")

7. Public, protected, private & mangling

L1 L2

L1 Fundamental

7.1. Access Conventions in Python

Access LevelSyntax ConventionVisibility IntentEnforcement Mechanism
Public self.name Accessible from anywhere. None (unrestricted).
Protected self._name Internal to class and subclasses. Convention only (PEP 8 gentle reminder).
Private self.__name Strictly private to the defining class. Name Mangling (_Class__name).

L2 Intermediate

7.2. Name Mangling in Detail

When an attribute begins with at least two underscores and at most one trailing underscore, Python internally renames it to prevent accidental overrides in subclasses:

class Vault:
    def __init__(self, passcode):
        self.__passcode = passcode  # Mangled to _Vault__passcode

v = Vault("SecretPass123")

# Direct access raises AttributeError:
# print(v.__passcode)  # AttributeError: 'Vault' object has no attribute '__passcode'

# Can still be accessed via mangled name (Python trusts consenting adults):
print("Mangled access:", v._Vault__passcode)  # SecretPass123

8. @property getters & setters

L1 L2

L1 Fundamental

8.1. Managed Attributes via @property

In Python, you don't write Java-style get_age() and set_age() methods. You expose attributes cleanly and use the @property decorator when validation or computation is needed:

class BankAccount:
    def __init__(self, initial_balance: float):
        self._balance = initial_balance

    @property
    def balance(self) -> float:
        """Getter for balance."""
        return self._balance

    @balance.setter
    def balance(self, new_balance: float):
        """Setter with validation."""
        if new_balance < 0:
            raise ValueError("Balance cannot be negative!")
        self._balance = new_balance

acc = BankAccount(100.0)
print("Balance:", acc.balance)  # 100.0 (Accessed like an attribute)
acc.balance = 250.0             # Uses setter
# acc.balance = -50.0           # Raises ValueError: Balance cannot be negative!

9. Bank account mini project

L1 L2

L1 Fundamental

9.1. Complete Encapsulated Banking Application

class SecureAccount:
    def __init__(self, account_number: str, holder_name: str, pin: str, initial_deposit: float = 0.0):
        self.account_number = account_number
        self.holder_name = holder_name
        self.__pin = pin
        self.__balance = initial_deposit
        self.__statement = []
        self.__record_transaction("Account opened", initial_deposit)

    def __record_transaction(self, action: str, amount: float):
        self.__statement.append(f"{action}: ${amount:.2f} | Balance: ${self.__balance:.2f}")

    def verify_pin(self, pin: str) -> bool:
        return self.__pin == pin

    def deposit(self, amount: float):
        if amount <= 0:
            raise ValueError("Deposit amount must be positive.")
        self.__balance += amount
        self.__record_transaction("Deposit", amount)

    def withdraw(self, amount: float, pin: str) -> float:
        if not self.verify_pin(pin):
            raise PermissionError("Incorrect PIN.")
        if amount <= 0:
            raise ValueError("Withdrawal amount must be positive.")
        if amount > self.__balance:
            raise ValueError("Insufficient funds.")
        self.__balance -= amount
        self.__record_transaction("Withdrawal", -amount)
        return amount

    @property
    def balance(self):
        return self.__balance

    def print_statement(self, pin: str):
        if not self.verify_pin(pin):
            raise PermissionError("Invalid PIN.")
        print(f"Statement for {self.holder_name} ({self.account_number}):")
        for entry in self.__statement:
            print("  ", entry)

# Demo:
user_acc = SecureAccount("ACC-1002", "Bharat Sonwane", "4920", 500.0)
user_acc.deposit(200.0)
user_acc.withdraw(150.0, "4920")
user_acc.print_statement("4920")

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between __str__ and __repr__? ▾ Answer
  • __str__: Designed for end users. Returns an informal, readable string representation. Used by print().
  • __repr__: Designed for developers and debugging. Should return an unambiguous representation that looks like valid Python code to reconstruct the instance. Fallback for __str__.
C.2. Does Python have true private variables? What is Name Mangling? ▾ Answer

No. Python operates on the philosophy: "We are all consenting adults here."

Variables prefixed with two underscores (__var) undergo Name Mangling: the compiler renames them to _ClassName__var to avoid accidental name collisions in subclasses. It is not a security sandbox, and the attribute can still be accessed via its mangled name.

C.3. Why does Python not support compile-time method overloading? ▾ Answer

Python is a dynamically typed language where function signatures do not include static types at compile time. Method lookups occur in the class dictionary (__dict__) by name alone. If two methods share the same name, the second definition overwrites the first.

C.4. What is the difference between an Abstract Class and an Interface in Python? ▾ Answer

Python does not have a separate interface keyword. An interface is simply an Abstract Base Class (abc.ABC) whose methods are all abstract with no concrete implementations. In Python 3.8+, static structural interfaces can also be defined using typing.Protocol (PEP 544).

L2 Intermediate

C.5. How does @property improve over traditional get/set methods? ▾ Answer

@property adheres to the Uniform Access Principle. Callers access attributes naturally using dot notation (person.age = 30) instead of method calls (person.set_age(30)). If validation logic is required later in development, you can convert a public attribute into a managed property without breaking existing consumer code.

C.6. What happens if a subclass does not implement all abstract methods of an ABC? ▾ Answer

The subclass remains an abstract class itself. If code attempts to instantiate the subclass, Python raises a TypeError: Can't instantiate abstract class SubClass with abstract method ... at instantiation time.

C.7. What is NotImplemented and when should a dunder method return it? ▾ Answer

NotImplemented is a special singleton. When an operator dunder method (like __add__) does not support the type of the second operand, returning NotImplemented tells Python to try the reflected method on the other operand (other.__radd__(self)) before finally raising a TypeError.

C.8. How does duck typing differ from nominal subtyping? ▾ Answer

Nominal Subtyping: Type compatibility is determined strictly by explicit inheritance hierarchies (class Dog(Animal)).

Duck Typing: Type compatibility is determined solely by the presence of methods and attributes at runtime, regardless of class inheritance trees.

  1. Task 1: Complex Number Operator Overloading — Implement __add__, __sub__, and __eq__ for ComplexNum. ▾ Solution 
    class ComplexNum:
    def __init__(self, real: float, imag: float):
        self.real = real
        self.imag = imag

    def __add__(self, other):
        return ComplexNum(self.real + other.real, self.imag + other.imag)

    def __sub__(self, other):
        return ComplexNum(self.real - other.real, self.imag - other.imag)

    def __eq__(self, other):
        return self.real == other.real and self.imag == other.imag

    def __repr__(self):
        return f"{self.real} + {self.imag}i"

c1 = ComplexNum(3, 4)

  2. Task 2: Abstract Shape Hierarchy — Define Shape ABC with Circle and Rectangle concrete subclasses. ▾ Solution 
    from abc import ABC, abstractmethod
import math

class Shape(ABC):
    @abstractmethod
    def area(self) -> float:
        pass

class Circle(Shape):
    def __init__(self, radius: float):
        self.radius = radius

    def area(self) -> float:
        return math.pi * self.radius ** 2

class Rectangle(Shape):
    def __init__(self, width: float, height: float):
        self.width = width
        self.height = height

    def area(self) -> float:
        return self.width * self.height

shapes = [Circle(5), Rectangle(4, 6)]
for s in shapes:
    print(f"Area: {s.area():.2f}")

  1. Challenge 1: Complete Money Value Object — Implement a Money class with currency validation and arithmetic operators. ▾ Solution 
    class Money:
    def __init__(self, amount: float, currency: str = "USD"):
        self.amount = round(amount, 2)
        self.currency = currency.upper()

    def __add__(self, other):
        if not isinstance(other, Money) or self.currency != other.currency:
            raise ValueError("Cannot add Money of different currencies!")
        return Money(self.amount + other.amount, self.currency)

    def __mul__(self, factor: float):
        return Money(self.amount * factor, self.currency)

    def __repr__(self):
        return f"{self.currency} {self.amount:,.2f}"

m1 = Money(150.50, "USD")
m2 = Money(49.50, "USD")
print("Total:", m1 + m2)     # USD 200.00
print("Tripled:", m1 * 3)    # USD 451.50
  2. Challenge 2: Custom Validation Property Descriptor — Create a reusable validator descriptor ensuring positive numbers. ▾ Solution 
    class PositiveNumber:
    def __set_name__(self, owner, name):
        self.name = name

    def __get__(self, instance, owner):
        if instance is None:
            return self
        return instance.__dict__.get(self.name, 0)

    def __set__(self, instance, value):
        if value <= 0:
            raise ValueError(f"{self.name} must be positive!")
        instance.__dict__[self.name] = value

class Product:
    price = PositiveNumber()
    stock = PositiveNumber()

    def __init__(self, price, stock):
        self.price = price
        self.stock = stock

p = Product(19.99, 50)
print(f"Product: ${p.price}, Stock: {p.stock}")
