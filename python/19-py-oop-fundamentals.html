1. Introduction

1.1. Overview

  • Object-Oriented Programming (OOP) is a design paradigm based on modeling software around real-world entities ("objects") containing state (attributes/data) and behavior (methods/functions).
  • In Python, everything is an object: integers, strings, functions, modules, and user-defined classes are all first-class instances inheriting from the root object base class.

2. Class, object, and reference variable

L1 L2

L1 Fundamental

2.1. The Blueprint & Instance Paradigm

  • Class: A blueprint or template defining the structure and behavior for future objects. Consumes memory only to store its class namespace dictionary (Class.__dict__).
  • Object (Instance): A physical realization instantiated from the class blueprint allocated on the heap.
  • Reference Variable: A variable holding the memory address reference pointing to the heap-allocated object instance.
class Student:
    """Blueprint representing a student."""
    pass

# Creating two distinct object instances on heap:
s1 = Student()  # s1 is a reference variable
s2 = Student()

print("s1 id:", id(s1))
print("s2 id:", id(s2))
print("Are they the same object?", s1 is s2)  # False

3. self variable (complete story)

L1 L2

L1 Fundamental

3.1. What is self?

Under the Hood: self is a reference variable that always points to the current object instance executing the method. Unlike Java/C++ this which is an implicit language keyword, self in Python is an explicit first parameter in instance method definitions, though calling obj.method() passes it implicitly behind the scenes. 
class Account:
    def deposit(self, amount):
        print("Self pointer address:", id(self))

acc = Account()
print("acc object address:  ", id(acc))

# Invoking via instance (Python automatically passes acc as self):
acc.deposit(100)

# Equivalent invocation via Class:
Account.deposit(acc, 100)

4. Constructors (__init__)

L1 L2

L1 Fundamental

4.1. The Role of __init__

  • __init__ is the special initialization method invoked automatically right after a new object instance is created.
  • Its sole responsibility is to attach and initialize instance variables on self.
  • It must never return anything other than None; attempting return value raises a TypeError.
class Employee:
    def __init__(self, emp_id: int, name: str, salary: float):
        self.emp_id = emp_id
        self.name = name
        self.salary = salary
        print(f"Initialized Employee: {self.name}")

e = Employee(101, "Bharat Sonwane", 95000.0)

5. Instance variables and methods

L1 L2

L1 Fundamental

5.1. Where Can Instance Variables Be Created?

  • Inside __init__: Using self.var = val (Standard practice).
  • Inside an instance method: Using self.var = val.
  • Outside the class: Using the reference variable obj.var = val.
class Laptop:
    def __init__(self, brand):
        self.brand = brand          # Created in constructor

    def set_ram(self, ram_gb):
        self.ram = ram_gb           # Created in instance method

l = Laptop("Apple")
l.set_ram(16)
l.color = "Space Grey"              # Created outside class via reference

print("Instance namespace dictionary:")
print(l.__dict__)
# {'brand': 'Apple', 'ram': 16, 'color': 'Space Grey'}

6. Static / class variables

L1 L2

L1 Fundamental

6.1. Class Variables vs Instance Variables

  • Class Variables (Static): Declared directly within the class body outside any method. Shared by all instances of that class. Modifying it via ClassName.var = new_val affects every instance.
  • The Shadowing Gotcha: Assigning via an instance (obj.var = new_val) does NOT modify the class variable; it silently creates a new instance variable on obj that shadows the class variable!
class BankAccount:
    bank_name = "Global National Bank"  # Class / static variable

    def __init__(self, account_holder, balance):
        self.holder = account_holder    # Instance variable
        self.balance = balance

b1 = BankAccount("Alice", 5000)
b2 = BankAccount("Bob", 8000)

print(b1.bank_name)  # Global National Bank
print(b2.bank_name)  # Global National Bank

# Modifying class variable via ClassName (Affects all):
BankAccount.bank_name = "Apex Universal Bank"
print(b1.bank_name)  # Apex Universal Bank
print(b2.bank_name)  # Apex Universal Bank

# Shadowing trap:
b1.bank_name = "Alice's Private Bank"  # Creates instance variable on b1!
print(b1.bank_name)          # Alice's Private Bank (Shadowed)
print(b2.bank_name)          # Apex Universal Bank (Unchanged)
print(BankAccount.bank_name) # Apex Universal Bank (Class level unchanged)

7. Instance vs class vs static methods

L1 L2

L1 Fundamental

7.1. Method Classification Table

Method TypeDecoratorFirst ParameterAccess CapabilitiesPrimary Use Case
Instance Method None self Instance variables and Class variables. Operating on specific object state.
Class Method @classmethod cls Class variables only (no access to self). Alternative constructors (factory methods).
Static Method @staticmethod None General utility logic (no self, no cls). Isolated helper functions scoped to class.

L2 Intermediate

class Date:
    def __init__(self, year, month, day):
        self.year = year
        self.month = month
        self.day = day

    # Instance method:
    def format_iso(self):
        return f"{self.year:04d}-{self.month:02d}-{self.day:02d}"

    # Class method as alternative constructor (Factory):
    @classmethod
    def from_string(cls, date_str: str):
        # Parses "YYYY-MM-DD"
        y, m, d = map(int, date_str.split("-"))
        return cls(y, m, d)

    # Static method: General validator independent of state
    @staticmethod
    def is_valid_month(month: int) -> bool:
        return 1 <= month <= 12

# Using standard constructor:
d1 = Date(2026, 9, 14)
print(d1.format_iso())  # 2026-09-14

# Using class method factory:
d2 = Date.from_string("2026-12-31")
print(d2.format_iso())  # 2026-12-31

# Using static method:
print("Is month 13 valid:", Date.is_valid_month(13))  # False

8. Accessing members across classes

L1 L2

L1 Fundamental

8.1. Passing Object References Between Classes

One class can interact with another by receiving an instance reference as a parameter:

class Engine:
    def start(self):
        print("V8 engine roaring to life...")

class Car:
    def __init__(self, model, engine: Engine):
        self.model = model
        self.engine = engine

    def drive(self):
        print(f"Driving {self.model}:")
        self.engine.start()

eng = Engine()
car = Car("Ford Mustang", eng)
car.drive()

9. Inner / nested classes and nested methods

L1 L2

L1 Fundamental

9.1. Inner Classes

When an object cannot exist independently of another object (e.g. a Head without a Human, an Address without an Employee), define it as an Inner Class:

class University:
    def __init__(self, name):
        self.name = name
        self.cs_department = self.Department("Computer Science")

    class Department:
        def __init__(self, dept_name):
            self.dept_name = dept_name

        def display(self):
            print(f"Department: {self.dept_name}")

uni = University("Stanford")
uni.cs_department.display()  # Department: Computer Science

10. Garbage collection and destructor

L1 L2

L1 Fundamental

10.1. CPython's Dual Garbage Collection Mechanism

  • 1. Reference Counting (Primary): Every Python object has an internal ob_refcnt field tracking how many references point to it. As soon as ob_refcnt == 0, memory is deallocated immediately.
  • 2. Generational Cyclic GC (Secondary): Detects and reclaims isolated reference cycles (Object A references B, and B references A, but neither is reachable from the root). Python classifies objects into 3 generations (Gen 0, 1, 2).

10.2. The Destructor (__del__)

__del__ is called just before the object is destroyed by garbage collection:

import gc

class Resource:
    def __init__(self, name):
        self.name = name
        print(f"Acquired: {self.name}")

    def __del__(self):
        print(f"Destructor invoked: Releasing {self.name}")

# Reference count drop triggers destructor:
r1 = Resource("DatabaseSocket")
del r1  # Prints: Destructor invoked: Releasing DatabaseSocket

10.3. Controlling Cyclic GC and Tracking References

CPython provides the gc and sys modules to programmatically inspect and control garbage collection:

import gc
import sys

# 1. Inspect and control cyclic GC status
print("GC enabled?", gc.isenabled())  # True
gc.disable()                           # Temporarily turn off cyclic GC sweeps
print("GC enabled after disable?", gc.isenabled())  # False
gc.enable()                            # Re-enable cyclic sweeps

# 2. Force manual collection sweep across generations
collected = gc.collect()
print(f"Unreachable objects cleared: {collected}")

# 3. Inspect Reference Counts with sys.getrefcount()
class Sample:
    pass

s1 = Sample()
# Note: sys.getrefcount() temporarily increments reference count by 1 during execution
print(sys.getrefcount(s1))  # Output: 2 (s1 variable + getrefcount parameter)

s2 = s1
print(sys.getrefcount(s1))  # Output: 3

del s2
print(sys.getrefcount(s1))  # Output: 2

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between __new__ and __init__? ▾ Answer
  • __new__(cls): The actual creator method. It is a static method that allocates memory and returns a brand new instance of cls. Used in Singletons and subclassing immutable types (tuple, int).
  • __init__(self): The initializer method. It receives the already-created instance as self and attaches attributes. Returns None.
C.2. Why does self need to be explicitly written in Python method definitions? ▾ Answer

Explicit self adheres to Python's core zen: "Explicit is better than implicit." It avoids ambiguity between local variables and instance variables without requiring an extra keyword like this, simplifies method inspection, and enables dynamic method binding onto classes at runtime.

C.3. What is the difference between @classmethod and @staticmethod? ▾ Answer
  • @classmethod: Receives the class (cls) as its first implicit argument. Can access and modify class-level state. Primary use case: Factory methods / alternative constructors.
  • @staticmethod: Receives neither self nor cls. Behaves like a plain function that happens to live inside a class's namespace. Primary use case: Utility functions.
C.4. How does assigning to a class variable via an instance (obj.var = 10) create a bug? ▾ Answer

In Python, reading obj.var searches the instance namespace first, then falls back to the class namespace.

However, writing obj.var = 10 always adds an entry to obj.__dict__. It creates a new instance variable on obj that shadows the class variable, leaving the class variable unchanged for all other instances.

Fix: Always mutate class variables through the class name: ClassName.var = 10.

L2 Intermediate

C.5. How does CPython resolve cyclic reference memory leaks? ▾ Answer

Reference counting cannot free circular structures (e.g. Node A references Node B, and Node B references Node A). When both external references are lost, their reference counts remain 1.

CPython includes a Generational Cyclic Garbage Collector (gc module). It periodically runs graph cycle-detection algorithms across objects in Generation 0, 1, and 2, detects isolated reference islands with no roots reachable from global namespaces or call stacks, and reclaims them.

C.6. Why shouldn't you rely on __del__ for critical resource cleanup? ▾ Answer

The exact timing of __del__ execution is non-deterministic:

  • If objects form circular references, __del__ might not be called until program termination, or may be deferred indefinitely.
  • Exceptions occurring inside __del__ are ignored and printed to sys.stderr.

Solution: Always use Context Managers (with statement) or explicit close() methods inside try...finally blocks for sockets, files, and database connections.

C.7. What does __dict__ contain in a class and instance? ▾ Answer
  • instance.__dict__: A dictionary mapping instance attribute names to their current values.
  • Class.__dict__: A mappingproxy containing the class's methods, static attributes, docstrings, and descriptors.
C.8. What is the purpose of __slots__? ▾ Answer

By default, every Python instance stores attributes in a dynamic __dict__ dictionary, which consumes significant RAM. Declaring __slots__ = ['x', 'y'] instructs Python to allocate a fixed-size array of pointers instead of a dictionary, reducing memory footprint by 40–50% when creating millions of small objects.

class Person:
    def __init__(self, name: str, age: int):
        self.name = name
        self.age = age

    @classmethod
    def from_birth_year(cls, name: str, birth_year: int):

  1. Challenge 1: Singleton Pattern Implementation via __new__ — Ensure only one instance of DatabasePool can exist. ▾ Solution 
    class DatabasePool:
    _instance = None

    def __new__(cls, *args, **kwargs):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
            cls._instance.connection_string = "postgresql://localhost:5432/prod"
        return cls._instance

  2. Challenge 2: Memory Optimization with __slots__ — Benchmark memory consumption of 100,000 instances with and without __slots__. ▾ Solution 
    import sys

class StandardPoint:
    def __init__(self, x, y):
        self.x = x
        self.y = y

class SlottedPoint:
    __slots__ = ["x", "y"]
    def __init__(self, x, y):
        self.x = x
        self.y = y

p_std = StandardPoint(10, 20)
p_slot = SlottedPoint(10, 20)

# Standard has __dict__, slotted does not:

print("Slotted size (bytes): ", sys.getsizeof(p_slot))
