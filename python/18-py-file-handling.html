1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Data stored in variables, lists, or dictionaries is volatile and lives only in RAM; it disappears when the Python process exits. File Handling allows programs to persist data permanently on non-volatile storage (SSD/HDD).
  • In Python, file interactions are handled via file stream objects created by the built-in open() function.
  • Python provides robust support for text files, binary assets (images, PDFs), structured formats (CSV, JSON), archives (ZIP, TAR), and filesystem navigation.

1.2. File Stream Typing (TextIO, BinaryIO, PathLike)

PEP 484 & PEP 519: Typing File Streams & Paths

When writing functions that accept open file descriptors or filesystem paths, use standard type annotations from typing and os:

from typing import TextIO, BinaryIO
import os
from pathlib import Path

# Functions accepting open file stream handles:
def process_text_stream(stream: TextIO) -> list[str]:
    return [line.strip() for line in stream]

def process_binary_stream(stream: BinaryIO, chunk_size: int = 4096) -> bytes:
    return stream.read(chunk_size)

# Functions accepting file paths (str or PathLike):
def read_configuration(file_path: str | os.PathLike[str] | Path) -> str:
    with open(file_path, "r", encoding="utf-8") as f:
        return f.read()

2. File types, open/close, modes, properties

L1 L2

L1 Fundamental

2.1. Text Files vs Binary Files

  • Text Files (t): Store human-readable characters encoded with a character set (default UTF-8). Automatically translates newline characters (\n on Linux/macOS vs \r\n on Windows).
  • Binary Files (b): Store raw byte sequences without character encoding or newline translation (images, audio, video, compiled bytecode, executable binaries).

3. Write and read operations

L1 L2

L1 Fundamental

3.1. Writing Data to Files

  • f.write(string): Writes string to file. Returns total characters written. Does not append a newline automatically!
  • f.writelines(list_of_strings): Writes an iterable of strings. Does not add newlines between elements.
with open("log.txt", "w", encoding="utf-8") as f:
    f.write("Line 1: System initiated.\n")
    f.write("Line 2: Service listening on port 8080.\n")
    
    lines: list[str] = ["Line 3: Database connected.\n", "Line 4: All checks passed.\n"]
    f.writelines(lines)

L2 Intermediate

3.2. Reading Data from Files

MethodBehaviorReturn TypeMemory Impact
f.read([size]) Reads entire file (or up to size characters/bytes). str (or bytes) High if file is large.
f.readline() Reads a single line up to and including \n. Returns "" at EOF. str $O(1)$ low memory per line.
f.readlines() Reads all lines into a Python list of strings. list[str] High (loads entire file into memory).
for line in f: Streaming line-by-line iterator (Idiomatic!). Yields str Optimal $O(1)$ constant memory. 
# Idiomatic line-by-line processing for massive log files:
with open("log.txt", "r", encoding="utf-8") as f:
    for line_num, line in enumerate(f, start=1):
        clean_line: str = line.rstrip("\n")
        print(f"[{line_num}] {clean_line}")

4. with statement; seek() and tell()

L1 L2

L1 Fundamental

4.1. The with Statement (Context Manager)

Why Always Use with? Opening a file via f = open(...) requires an explicit f.close(). If an exception occurs before reaching f.close(), the operating system file descriptor remains leaked. The with statement binds the file to a Context Manager (__enter__ and __exit__), guaranteeing that the file is automatically closed when execution leaves the block, even if an unhandled exception or crash occurs.

L2 Intermediate

4.2. File Pointer Navigation: tell() and seek()

  • f.tell(): Returns the current byte offset position of the read/write cursor from the start of the file.
  • f.seek(offset, whence=0): Moves the cursor to a specific byte location:
    • whence=0 (default): Relative to file beginning.
    • whence=1: Relative to current cursor (binary files only).
    • whence=2: Relative to file end (binary files only).
with open("seek_demo.txt", "w+", encoding="utf-8") as f:
    f.write("ABCDEFGHIJ")
    print("Cursor after write:", f.tell())  # 10
    
    # Rewind cursor back to beginning:
    f.seek(0)
    print("Cursor after seek(0):", f.tell())# 0
    print("Read first 4 chars:  ", f.read(4))# 'ABCD'
    
    # Jump to index 6:
    f.seek(6)
    print("Read from index 6:   ", f.read()) # 'GHIJ'

5. Binary, CSV, and ZIP files

L1 L2

L1 Fundamental

5.1. Handling Binary Files ('rb', 'wb')

Binary mode reads and writes raw bytes objects, ideal for copying media files:

# Binary file copy chunk-by-chunk (Memory-safe for 10GB files):
def copy_binary_file(source_path: str, dest_path: str, chunk_size: int = 65536) -> None:
    with open(source_path, "rb") as src, open(dest_path, "wb") as dst:
        while chunk := src.read(chunk_size):
            dst.write(chunk)

6.3. Classic Program: Count Lines, Words, and Characters in a File

A classic interview and system automation program to analyze file statistics using streaming iteration:

import os

def analyze_file_content(filepath: str) -> None:
    """Counts total lines, words, and characters in a file."""
    if not os.path.isfile(filepath):
        print(f"Error: File '{filepath}' does not exist.")
        return

    line_count: int = 0
    word_count: int = 0
    char_count: int = 0

    with open(filepath, "r", encoding="utf-8") as f:
        for line in f:
            line_count += 1
            char_count += len(line)
            words: list[str] = line.split()
            word_count += len(words)

    print(f"--- File Statistics: {os.path.basename(filepath)} ---")
    print(f"Total Lines:      {line_count:,}")
    print(f"Total Words:      {word_count:,}")
    print(f"Total Characters: {char_count:,}")

# Example invocation:
analyze_file_content("log.txt")

7.1. Modern Subprocess Execution: subprocess.run()

Avoid legacy os.system() due to security vulnerabilities (shell injection). Use the modern subprocess module:

import subprocess

# Run a CLI command safely without shell=True:
result: subprocess.CompletedProcess[str] = subprocess.run(
    ["echo", "Hello from Python subprocess!"],
    capture_output=True,
    text=True,
    check=True
)

print("Exit code:", result.returncode)  # 0
print("Output:   ", result.stdout.strip())

C. Common questions

L1 L2

L1 Fundamental

C.1. Why should you always use with open(...) as f instead of open() and f.close()? ▾ Answer

Using with open(...) employs Python's Context Manager protocol (__enter__ and __exit__). Even if an unexpected exception occurs inside the block or the program exits prematurely via a return statement, Python guarantees that the file descriptor is immediately flushed and closed.

Relying on manual f.close() frequently causes file descriptor leaks when exceptions interrupt execution before the close line is reached.

C.2. What is the difference between mode 'w', 'w+', 'r+', and 'a'? ▾ Answer
  • 'w': Write-only. Overwrites/truncates existing file immediately to 0 bytes.
  • 'r+': Read and Write. Does not truncate. Raises FileNotFoundError if file does not exist. Cursor starts at byte 0.
  • 'w+': Write and Read. Truncates existing file to 0 bytes upon opening.
  • 'a': Append-only. Cursor always moves to the end of the file for writing, preserving old contents.
C.3. Why does open() require newline='' when writing CSV files on Windows? ▾ Answer

The csv.writer module terminates rows with RFC 4180 standard CRLF (\r\n) by default. On Windows, Python's default text mode automatically translates every \n into \r\n, resulting in double carriage returns (\r\r\n) and blank lines between rows.

Specifying newline="" disables automatic platform newline translation in the file stream.

C.4. How does Python stream 10GB files without running out of RAM? ▾ Answer

Using for line in f: treats the file object as a lazy generator iterator that buffers only a small chunk (typically 8KB) in memory at any given moment. It yields one line at a time, consuming constant $O(1)$ memory regardless of whether the file is 10 MB or 100 GB.

In contrast, f.read() or f.readlines() loads the entire file into RAM, causing an OutOfMemoryError.

L2 Intermediate

C.5. What is the difference between seek() and tell()? ▾ Answer
  • tell(): Returns current integer byte offset position in the file.
  • seek(offset, whence): Repositions the file cursor to a target byte offset. In text files, seeking relative to current or end (whence=1 or 2) is generally unsupported; it is only permitted in binary mode ('rb').
C.6. Why should you avoid os.system() and use subprocess.run()? ▾ Answer

os.system() spawns a full underlying shell and executes strings directly, leaving the system vulnerable to Command Injection attacks if user input is concatenated. It also does not capture stdout/stderr easily.

subprocess.run(["cmd", "arg1", "arg2"]) executes the binary directly without a subshell by default, passing arguments as a safe array that prevents injection.

C.7. What does mode 'x' do in open()? ▾ Answer

'x' enables Exclusive Creation Mode. If the target file already exists, opening in 'x' mode raises a FileExistsError immediately. This prevents accidental overwriting of critical configuration files or logs.

C.8. How does pathlib.Path modernise file interactions? ▾ Answer

pathlib.Path replaces clumsy string path manipulations (os.path.join, os.path.splitext) with object-oriented syntax (p / "sub" / "file.txt"), provides cross-platform path resolution, and includes built-in convenience methods like Path.read_text() and Path.write_text().

    import time

def tail_file(filepath: str, max_iterations: int = 5) -> None:
    with open(filepath, "r", encoding="utf-8") as f:
        # Move cursor to the end of the file:
        f.seek(0, 2)
        iterations: int = 0
        while iterations < max_iterations:
            line: str = f.readline()
            if line:
                print("New appended line:", line.strip())
            else:
                time.sleep(0.5)
            iterations += 1
  2. Challenge 2: In-Memory File Integrity Checksum (SHA-256) — Compute cryptographic hash of a file using hashlib. ▾ Solution 
    import hashlib

def calculate_sha256(filepath: str, chunk_size: int = 65536) -> str:
    sha = hashlib.sha256()
    with open(filepath, "rb") as f:
        while chunk := f.read(chunk_size):
            sha.update(chunk)
    return sha.hexdigest()
