1. Introduction

1.1. Overview

  • Operators are special symbols or keywords in Python used to perform computations, manipulate variables, evaluate logical conditions, and compare data structures.
  • Python classifies operators into clear, dedicated categories: Arithmetic, Relational (Comparison), Logical, Bitwise, Assignment, Identity, Membership, Ternary, and Precedence hierarchies.

1.2. Default rules and how to study this file

Default Best Practices: Use == for value equality and is strictly for singletons like None. Always prefer and, or, not for boolean logic over bitwise operators. When writing complex expressions, use parentheses to ensure clear intent regardless of operator precedence.

Critical Arithmetic Nuances:

# 1. True division (/) always yields float:
print(10 / 2)       # 5.0 (always float, never int)
print(7 / 2)        # 3.5

# 2. Floor division (//) rounds toward negative infinity (floor):
print(5 // 2)       # 2   (2.5 floored to 2)
print(-5 // 2)      # -3  (floor(-2.5) is -3, NOT -2!)
print(10.0 // 3)    # 3.0 (returns float if any operand is float)

# 3. Modulo (%) remainder formula: r = x - (x // y) * y:
print(5 % 2)        # 1   (5 - (2) * 2 = 1)
print(-5 % 2)       # 1   (-5 - (-3) * 2 = -5 - (-6) = 1)
print(5 % -2)       # -1  (5 - (-3) * (-2) = 5 - 6 = -1)

# 4. Exponentiation (**) is right-to-left associative:
print(2 ** 3 ** 2)  # 512 (evaluates as 2 ** (3 ** 2) = 2 ** 9 = 512, NOT (2**3)**2 = 64)

# 5. Sequence replication and concatenation:
print("Py" * 3)     # "PyPyPy"
print([1, 2] + [3]) # [1, 2, 3]
print([0] * 4)      # [0, 0, 0, 0]

Chained Comparisons & Lexicographical Ordering:

  • Chained Comparisons: Python natively allows mathematical range chaining such as 10 < x < 20. This is evaluated as (10 < x) and (x < 20), evaluating x only once.
  • Lexicographical String Ordering: Strings are compared character by character according to their Unicode code points (ord()).

# Mixed-type comparisons:
print(10 == 10.0)         # True  (mathematical value equality)
# print(10 < "20")        # TypeError: '<' not supported between 'int' and 'str'

4. Logical operators

L1 L2

L1 Fundamental

Python provides three logical operators: and, or, and not. Using symbol equivalents (&&, ||, !) causes a SyntaxError.

4.1. Truth Value Testing (Truthiness)

  • Logical operators test the truth value of any Python object, not just booleans.
  • Falsy values: False, None, numeric zero (0, 0.0, 0j), empty sequences/collections ("", (), [], {}, set(), range(0)).
  • Truthy values: All other objects (non-zero numbers, non-empty collections, valid objects).

4.2. Return Value Rules (Operand Evaluation)

Key Rule to Remember: In Python, and and or do not necessarily return a boolean! They return the actual operand that determined the outcome of the expression. Only not is guaranteed to always return a pure bool (True or False).
OperatorSyntaxEvaluation RuleReturn Value Rule
and x and y Evaluates x. If x is falsy, stops immediately. Otherwise, evaluates y. Returns the first falsy operand, or the last operand if all are truthy.
or x or y Evaluates x. If x is truthy, stops immediately. Otherwise, evaluates y. Returns the first truthy operand, or the last operand if all are falsy.
not not x Evaluates truth value of x and inverts it. Always returns bool: False if x is truthy; True if x is falsy. 
# --- 1. 'and': returns first falsy OR last truthy ---
print(True and False)       # False
print(10 and 20)            # 20 (both truthy -> returns last operand)
print(0 and 20)             # 0  (0 is falsy -> stops and returns 0)
print("" and "Python")      # "" (empty string is falsy -> returns "")
print("Python" and "Rocks") # "Rocks" (both truthy -> returns last operand)
print(1 and 2 and 3 and 4)  # 4  (all truthy -> returns last operand)
print(1 and 0 and 3 and 4)  # 0  (stops at first falsy: 0)

# --- 2. 'or': returns first truthy OR last falsy ---
print(True or False)        # True
print(10 or 20)             # 10 (10 is truthy -> stops and returns 10)
print(0 or 5)               # 5  (0 is falsy -> evaluates and returns 5)
print(0 or "")              # "" (both falsy -> returns last operand)
print([] or {} or "found")  # "found" (returns first truthy)
print([] or 0 or None)      # None (all falsy -> returns last operand)

# Idiomatic default fallback:
user_input = ""
display_name = user_input or "Guest"
print("Welcome,", display_name)  # "Welcome, Guest"

# --- 3. 'not': always returns a pure boolean ---
print(not True)             # False
print(not False)            # True
print(not 0)                # True
print(not 100)              # False
print(not "hello")          # False
print(not [])               # True
print(not not "hello")      # True (double negation bool conversion: bool("hello"))

L2 Intermediate

4.3. Short-Circuit Evaluation (Lazy Evaluation)

  • Python executes boolean expressions strictly from left to right and terminates as soon as the final result is certain.
  • False and <expr>: <expr> is never evaluated.
  • True or <expr>: <expr> is never evaluated.
# Short-circuiting proof using division-by-zero:
# If Python evaluated both sides, (100 / 0) would crash with ZeroDivisionError!

denominator = 0

# Test 1: 'and' short-circuits on False:
# The left operand is False, so Python NEVER evaluates the right operand:
result1 = (denominator != 0) and (100 / denominator > 10)
print("Result 1 (False and ...):", result1)  # Prints: False (Safe! No ZeroDivisionError)

# Test 2: 'or' short-circuits on True:
# The left operand is True, so Python NEVER evaluates the right operand:
result2 = (denominator == 0) or (100 / denominator > 10)
print("Result 2 (True or ...):  ", result2)  # Prints: True (Safe! No ZeroDivisionError)

# Practical defensive guards using short-circuiting:
# 1. Null / None guard:
user = None
if user is not None and user.is_active:
    print("User is active")  # Safe: user.is_active never executed if user is None

# 2. Zero-division guard:
count = 0
total = 150
if count != 0 and (total / count) > 50:
    print("Threshold reached")  # Safe: division never attempted if count == 0

# 3. Collection bounds guard:
data = []
if len(data) > 0 and data[0] == "admin":
    print("Welcome Admin")  # Safe: IndexError prevented

# DANGEROUS BUG: Using '&' for condition checking:
x = 5
# WRONG:
# if x > 0 & x < 10:  # Syntax error or unexpected result!
# Because '&' binds tighter than '>' and '<', this parses as:
# x > (0 & x) < 10  ->  x > 0 < 10 (chained comparison, completely different!)

    print("x is in range (0, 10)")

# Multi-value equality trap:
# WRONG: if x == 1 or 2 or 3:  (2 is truthy, so always True!)

Augmented Assignment on Mutable vs Immutable Objects:

Crucial Distinction: On mutable objects (like lists), augmented assignment (+=) invokes __iadd__ and modifies the object in-place. In contrast, standard addition (lst = lst + [...]) creates a brand new list object in memory! 
# Immutable objects (integers): re-binds variable to a new object:
x = 10
print(id(x))
x += 1
print(id(x))  # Different memory address!

# Mutable objects (lists):
list1 = [1, 2, 3]
list2 = list1
list1 += [4]         # Calls __iadd__; mutates list1 in-place!
print(list1)         # [1, 2, 3, 4]
print(list2)         # [1, 2, 3, 4] (list2 sees the change!)
print(list1 is list2)# True

# Contrast with lst = lst + [...]:
list3 = [1, 2, 3]
list4 = list3
list3 = list3 + [4]  # Creates a NEW list object and rebinds list3
print(list3 is list4)# False (list4 remains [1, 2, 3])

7. Identity operators

L1 L2

L1 Fundamental

Identity operators test whether two variables point to the exact same object in memory (same memory address returned by id()).

OperatorMeaningEvaluates As
isReturns True if both variables point to the same objectid(a) == id(b)
is notReturns True if both variables point to different objectsid(a) != id(b)
 
# Value equality (==) vs Object identity (is):
a = [1, 2, 3]
b = [1, 2, 3]
c = a

print(a == b)      # True  (contents/values are identical)
print(a is b)      # False (separate objects in heap memory)
print(a is c)      # True  (both refer to the exact same object)

# Idiomatic check for None:
result = None
if result is None:      # Correct singleton identity check
    print("No result found")

L2 Intermediate

The Small Integer Caching & String Interning Trap:

  • CPython pre-allocates and caches small integers in the range -5 to 256. Any integer created in this range points to the shared cached singleton.
  • Integers outside this range (> 256 or < -5) might not share the same address, especially across interactive REPL lines.
  • Golden Rule: Never use is to compare numeric or string values! Always use ==. Reserve is for singletons like None, True, and False.
x = 256
y = 256
print(x is y)  # True (small integer cached by CPython)

x = 257
y = 257
print(x is y)  # False (in REPL; separate heap allocations!)
print(x == y)  # True (values are equal! Always use ==)

L2 Intermediate

Dictionary Membership & Performance ($O(1)$ vs $O(n)$):

  • Dictionary Key Checking: Applying in to a dictionary checks whether the item exists as a key, not a value. To check values, you must query dict.values() explicitly.
  • Lookup Performance: Checking membership in a set or dict runs in $O(1)$ average time (via hash table lookup), whereas checking a list or tuple requires $O(n)$ linear scan.
user = {"id": 101, "name": "Bharat", "role": "admin"}

# Checks keys by default:
print("name" in user)          # True
print("Bharat" in user)        # False (does NOT check values!)

# Checking values explicitly:
print("Bharat" in user.values())  # True

# Performance tip:
allowed_ids = {101, 102, 103}  # Use set for O(1) membership test
if 101 in allowed_ids:
    print("Access granted")

9. Ternary operator

L1 L2

L1 Fundamental

Python provides a concise ternary operator known as a conditional expression (introduced in Python 2.5 via PEP 308). Unlike C/C++/Java's punctuation-heavy syntax (condition ? val1 : val2), Python employs an expressive, readable English syntax.

Standard Syntax: value_if_true if condition else value_if_false
  • Evaluation Semantics: Python tests the condition first.
  • If the condition is truthy, value_if_true is evaluated and returned.
  • If the condition is falsy, value_if_false is evaluated and returned.
  • Short-Circuit Execution: Only the matching branch expression is evaluated. The non-selected branch is completely bypassed (preventing errors and unnecessary function calls).
# Basic conditional assignment:
age = 20
status = "Adult" if age >= 18 else "Minor"
print("Status:", status)  # Status: Adult

# Finding minimum and maximum of two numbers:
a, b = 45, 80
min_val = a if a < b else b
max_val = a if a > b else b
print(f"Min: {min_val}, Max: {max_val}")  # Min: 45, Max: 80

# Dynamic user input:
num = 17
result = "Even" if num % 2 == 0 else "Odd"
print(f"{num} is {result}")  # 17 is Odd

Nesting of Ternary Operators (Multi-Condition Chaining):

In Python, you can nest (or chain) multiple ternary expressions to evaluate sequential conditions in a single statement, acting as a concise one-line alternative to an if-elif-else ladder.

Nested Syntax:
val1 if cond1 else val2 if cond2 else val3 if cond3 else default_val 
# 1. Minimum of three numbers using nested ternary:
a = int(input("Enter First Number: "))   # e.g., 30
b = int(input("Enter Second Number: "))  # e.g., 10
c = int(input("Enter Third Number: "))   # e.g., 20

min_val = a if a < b and a < c else b if b < c else c
print("Minimum Value:", min_val)  # Minimum Value: 10

# 2. Maximum of three numbers:
max_val = a if a > b and a > c else b if b > c else c
print("Maximum Value:", max_val)  # Maximum Value: 30

# 3. Three-way comparison (equality vs greater vs smaller):
n1, n2 = 25, 25
msg = "Both numbers are equal" if n1 == n2 else "First is greater" if n1 > n2 else "Second is greater"
print(msg)  # Both numbers are equal

# 4. Number sign classification (Positive, Negative, or Zero):
val = -15
sign = "Positive" if val > 0 else "Negative" if val < 0 else "Zero"
print(f"{val} is {sign}")  # -15 is Negative

L2 Intermediate

Right-to-Left Associativity & Evaluation Flow:

  • Associativity (Right-to-Left): Python evaluates chained conditional expressions with right-to-left associativity. An unparenthesized expression a if c1 else b if c2 else c is parsed by the compiler as a if c1 else (b if c2 else c).
  • Parentheses for Clarity: While parentheses are completely optional, adding them can make complex chains much easier to read and maintain.
  • Sequential Short-Circuiting: Conditions are evaluated strictly from left to right. The first condition that evaluates to True immediately produces its corresponding branch value and terminates further evaluation.

Complex Chaining Examples:

# Maximum of four numbers:
w, x, y, z = 12, 45, 28, 9
max_4 = w if (w > x and w > y and w > z) else x if (x > y and x > z) else y if (y > z) else z
print("Max of 4:", max_4)  # Max of 4: 45

# Academic grading scale:
score = 85
grade = "A" if score >= 90 else "B" if score >= 80 else "C" if score >= 70 else "D" if score >= 60 else "F"
print("Grade:", grade)  # Grade: B

Alternative Ways to Emulate Ternary in Python (Classroom & Interview Gotchas):

Before PEP 308 introduced native x if cond else y in Python 2.5, programmers used several idiom tricks to simulate ternary logic. Understanding their critical differences and pitfalls is a popular interview topic:

TechniqueSyntax PatternShort-Circuits?Major Pitfalls / Gotchas
Native Ternary (Recommended) true_val if cond else false_val Yes None. Clear, Pythonic, and safely short-circuits.
Tuple Indexing (false_val, true_val)[bool(cond)] No Eager evaluation: Both expressions are computed upfront! E.g. (1/0, 10)[True] crashes with ZeroDivisionError!
Dictionary Lookup {False: false_val, True: true_val}[cond] No Eagerly evaluates both values before selection; incurs hash lookup overhead.
Logical and-or Trick cond and true_val or false_val Partial Critical Bug with Falsy Values: If true_val is falsy (0, "", [], None), it falls through to false_val! E.g. True and 0 or 100 yields 100! 
# Pitfalls of older ternary emulation tricks:

# 1. Tuple indexing evaluates BOTH branches (raises ZeroDivisionError even if condition is False):
denom = 0
# The following raises ZeroDivisionError because (100 / denom) is evaluated immediately:
# ans = ("Safe", 100 / denom)[False]  # ZeroDivisionError: division by zero!

# In contrast, native ternary short-circuits and never evaluates the unselected branch:
ans = "Safe" if denom == 0 else (100 / denom)
print("Native ternary safe result:", ans)  # "Safe" (No crash!)

# 2. Logical and-or bug when true_val is falsy (0, empty string, None):
is_logged_in = True
unread_count = 0  # 0 is falsy!
display_badge = is_logged_in and unread_count or 99
print("Display badge (and-or):", display_badge)  # 99 (BUG! Should be 0!)

# Native ternary handles falsy values cleanly:
display_badge_correct = unread_count if is_logged_in else 99
print("Display badge (native):", display_badge_correct)  # 0 (Correct!)

10. Operator precedence

L1 L2

L1 Fundamental

Operator precedence determines the grouping and evaluation order in compound expressions. Operators with higher precedence are evaluated before operators with lower precedence.

# Default precedence: multiplication (*) binds tighter than addition (+):
print(2 + 3 * 4)    # 14 (3 * 4 = 12; 2 + 12 = 14)

# Overriding precedence with parentheses ():
print((2 + 3) * 4)  # 20 (5 * 4 = 20)

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between / (True Division) and // (Floor Division)? ▾ Answer
  • True Division (/): Always returns a float in Python 3, even if the division is exact (10 / 2 → 5.0).
  • Floor Division (//): Returns the largest integer less than or equal to the quotient (rounds toward $-\infty$). If both operands are integers, it returns an int (5 // 2 → 2); if either operand is a float, it returns a floored float (5.0 // 2 → 2.0).
C.2. What is the difference between == and is? ▾ Answer
  • == (Value Equality): Compares whether the contents or values of two objects are equal by calling __eq__().
  • is (Object Identity): Compares whether two variables reference the exact same memory address (id(a) == id(b)).
  • Best Practice: Always use is None or is not None for singletons; use == for comparing data values (strings, lists, numbers).
C.3. What do and and or return, and how does short-circuit evaluation work? ▾ Answer

They do not always return a boolean (True / False). Instead, they return the last evaluated operand that determined the outcome:

  • x and y: Returns x if x is falsy; otherwise evaluates and returns y (first falsy or last truthy).
  • x or y: Returns x if x is truthy; otherwise evaluates and returns y (first truthy or last falsy).

Short-circuiting means Python evaluates strictly from left to right and stops the instant the final boolean outcome is certain, skipping execution of remaining operands (avoiding unnecessary computation, exceptions, or database queries).

C.4. Why does if x == 1 or 2 or 3: always evaluate to True? ▾ Answer

Because Python groups the condition as (x == 1) or (2) or (3). The sub-expression 2 is a non-zero integer, which evaluates to truthy. Therefore, regardless of what x is, the or 2 branch causes the whole condition to evaluate to truthy (2). The correct idiom is if x in (1, 2, 3):.

C.5. How does the in operator work on dictionaries? ▾ Answer

By default, x in dict checks whether x exists among the dictionary's keys in $O(1)$ average time. It does not check values. To check values, you must explicitly write x in dict.values() (which runs in $O(n)$ linear scan time).

C.6. What is the difference between logical (and, or, not) and bitwise (&, |, ~) operators? ▾ Answer
  • Logical operators work with truth values of arbitrary Python objects, support short-circuit evaluation, and have lower precedence than comparisons.
  • Bitwise operators work on integer bits (or set intersections/unions), never short-circuit (both operands are always evaluated), and have higher precedence than comparisons.

L2 Intermediate

C.7. Why is -5 // 2 equal to -3 and -5 % 2 equal to 1? ▾ Answer
  • True quotient is $-2.5$. Floor division rounds down toward $-\infty$, and the greatest integer $\le -2.5$ is $-3$.
  • Modulo uses Python's universal identity: r = x - (x // y) * y.
    Substituting values: -5 - (-3 * 2) = -5 - (-6) = 1.
    In Python, the sign of the remainder always matches the sign of the divisor (y).
C.8. What is the difference between lst += [4] and lst = lst + [4]? What happens in t = (1, [2]); t[1] += [3]? ▾ Answer
  • lst += [4] invokes __iadd__(), which extends the existing list in-place without changing its memory address.
  • lst = lst + [4] creates a brand-new list in memory and rebinds the variable lst to it.
  • The Tuple Quiz: In t = (1, [2]); t[1] += [3], the list inside the tuple is modified in-place to [2, 3], but Python immediately raises a TypeError: 'tuple' object does not support item assignment because the augmented assignment attempts to assign the result back to t[1]!
C.9. Why does 2 ** 3 ** 2 evaluate to 512 instead of 64? ▾ Answer

Because the exponentiation operator (**) in Python has right-to-left associativity. Python evaluates 3 ** 2 first (which is 9), followed by 2 ** 9 = 512. To force left-to-right evaluation, use explicit parentheses: (2 ** 3) ** 2 = 64.

C.10. Why is 256 is 256 True, but 257 is 257 can be False? ▾ Answer

CPython maintains an internal cache of small integer objects in the range -5 to 256 at startup. Whenever an integer in this range is created, Python reuses the existing singleton object in memory. Numbers outside this range (257, 1000) are allocated separately on the heap when evaluated across different statements in the REPL. Never rely on is for numeric comparisons; always use ==.

C.11. Why is if x > 0 & x < 10: a dangerous bug? ▾ Answer

Because the bitwise AND operator (&) has a higher precedence than comparison operators (> and <). Python parses this line as:
x > (0 & x) < 10 $\implies$ x > 0 < 10.
This becomes a chained comparison testing whether x > 0 AND 0 < 10, which is completely different from verifying whether x is between 0 and 10! The correct expression is if x > 0 and x < 10: or if 0 < x < 10:.

C.12. Why does ~5 evaluate to -6 and ~0 evaluate to -1? ▾ Answer

Python integers are represented using two's complement binary format. The bitwise NOT operator (~) inverts all bits of a number. Mathematically, for any integer x, two's complement inversion satisfies the identity:
~x = -(x + 1).
Therefore, ~5 = -(5 + 1) = -6, and ~0 = -(0 + 1) = -1.

C.13. How do chained comparisons like 10 < x < 20 evaluate, and is x evaluated twice? ▾ Answer

In Python, a < b < c is logically equivalent to (a < b) and (b < c), with one crucial performance and safety feature: the middle operand b is evaluated exactly once. If b is an expensive computation or a function call with side effects (e.g. 10 < compute() < 20), compute() will only run once.

C.14. Why does a = [[]] * 3 cause bugs when modifying an inner list? ▾ Answer

Sequence multiplication (*) creates shallow copies of the object reference, not deep copies. In a = [[]] * 3, all three elements reference the exact same list object in memory. Modifying one (a[0].append(1)) reflects in all three ([[1], [1], [1]]).
Correct idiom: Allocate distinct objects explicitly: a = [[], [], []] (or via a list comprehension in Module 10: [[] for _ in range(3)]).

C.15. What is the Walrus Operator (:=) in Python 3.8+, and when should you use it? ▾ Answer

The Walrus Operator (:=), officially called an assignment expression, assigns a value to a variable inside an expression, avoiding redundant function calls or temporary variables.
Common examples:
1. In while loops: while (chunk := file.read(1024)): ...
2. In if conditions: if (n := len(data)) > 10: print(f"Too long: {n}")
Because its precedence is very low, it generally requires parentheses when combined with comparisons.

C.16. Can you compare numbers and strings with < or > in Python 3? ▾ Answer

No. In Python 3, comparing incompatible types (like 5 < "10") raises a TypeError: '<' not supported between instances of 'int' and 'str'.
(Note: Python 2 historically allowed ordering between arbitrary types based on alphabetical type names, but this was removed in Python 3 to prevent subtle bugs. Value equality 5 == "5" is allowed and safely returns False).

C.17. What are De Morgan's Laws, and how do they simplify conditional logic? ▾ Answer

De Morgan's Laws are fundamental transformation rules in boolean logic:

  • not (A and B) is equivalent to (not A) or (not B)
  • not (A or B) is equivalent to (not A) and (not B)
They are frequently used in code reviews to refactor clunky negative conditions (e.g. if not (is_valid and has_permission): into if not is_valid or not has_permission:).

C.18. How does Python implement operator overloading behind the scenes? ▾ Answer

Every Python operator delegates its implementation to a special dunder (double underscore) method on the class:

  • a + b $\implies$ a.__add__(b)
  • a == b $\implies$ a.__eq__(b)
  • a < b $\implies$ a.__lt__(b)
  • a in b $\implies$ b.__contains__(a)
  • a += b $\implies$ a.__iadd__(b) (in-place)
Custom classes can define or override these methods to provide native mathematical, comparison, or container syntax.

C.19. How does Python evaluate nested ternary expressions, what is its associativity, and why is the older a and b or c trick dangerous? ▾ Answer
  • Associativity: The ternary operator has right-to-left associativity. An expression such as a if c1 else b if c2 else c is parsed as a if c1 else (b if c2 else c).
  • Short-Circuit Evaluation: Python evaluates conditions from left to right. As soon as a condition evaluates to truthy, its corresponding expression is evaluated and returned; all subsequent conditions and branches are skipped.
  • The and-or Trick Danger: In older Python code, programmers simulated ternary logic with condition and val_true or val_false. However, if val_true evaluates to any falsy value (0, "", [], None), the and expression produces that falsy value and Python mistakenly falls through to evaluate and return val_false! Native val_true if condition else val_false avoids this bug completely.
