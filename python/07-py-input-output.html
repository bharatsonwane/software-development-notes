1. Introduction

L1

L1 Fundamental

1.1. Overview

  • Every interactive program requires communication with the outside world: reading data from users or external processes (Input) and rendering results back to terminals, logs, or streams (Output).
  • In Python, standard I/O revolves around three standard streams in the operating system:
    • sys.stdin — standard input stream (read via input()).
    • sys.stdout — standard output stream (written to via print()).
    • sys.stderr — standard error stream (for diagnostic error logs).
  • This chapter covers the full mechanics of terminal input, single-line multiple value parsing, dynamic evaluation via eval(), command-line parameter passing with sys.argv, and professional output formatting using modern f-strings.

1.2. Default Rules and How to Study This File

Default Best Practices:
  1. Always remember: input() and sys.argv always produce strings (str). Always cast explicitly when numbers are expected.
  2. Prefer f-strings: Use formatted string literals (f"...") for all string interpolation. They are cleaner, faster, and less error-prone than % or .format().
  3. Security First: Never pass untrusted user input directly into eval() due to arbitrary code execution risks.

2. input() and reading values

L1 L2

L1 Fundamental

2.1. The input() Function

  • Syntax: variable = input([prompt])
  • When called, Python pauses script execution and displays the optional prompt message in the terminal. It waits until the user types input and presses the Enter key.
  • Universal String Rule: Whatever the user enters is captured and returned strictly as a str. Even if the user enters digits like 45, Python treats it as "45".
  • Python 2 vs. Python 3 Note: In Python 2, raw_input() returned strings and input() automatically evaluated code. In Python 3, raw_input() was removed and input() always returns a string.
Classic Beginner Pitfall (String Concatenation): Because input() returns strings, using + on two inputs performs string concatenation rather than numerical addition:
input("Num 1: ") + input("Num 2: ") with entries 10 and 20 yields "1020", not 30! 
# Basic input usage:
name = input("Enter your name: ")
print("Hello,", name)
print("Type of name:", type(name))  # Always <class 'str'>

# The string addition pitfall:
num1 = input("Enter first number: ")   # User types 10 -> "10"
num2 = input("Enter second number: ")  # User types 20 -> "20"
print("num1 + num2 =", num1 + num2)   # "1020" (String concatenation!)

2.2. Typecasting User Input

To perform mathematical operations or type-sensitive comparisons, you must explicitly cast the string returned by input() using type constructor functions:

Target Type Casting Syntax Valid User Entry Failure Pitfall
int int(input()) 25, -10 Entering decimal 25.5 or words raises ValueError
float float(input()) 3.14, 10, 1e3 Entering letters raises ValueError
bool Custom logic (see warning) True, False bool(input()) is True for any non-empty string!
The bool(input()) Trap: In Python, any non-empty string is truthy. If the user enters the text "False", bool("False") evaluates to True! To properly read boolean flags from users, check against explicit matching values. 
# Correct numeric casting:
age = int(input("Enter your age: "))
height = float(input("Enter height in meters: "))
print(f"Next year you will be {age + 1} years old.")

# Safe boolean parsing pattern:
raw_flag = input("Enable notifications? (yes/no): ").strip().lower()
is_enabled = raw_flag in ("yes", "y", "true", "1")
print("Notifications active:", is_enabled)

L2 Intermediate

2.3. Reading Multiple Values on a Single Line

Often, users or competitive programming platforms provide multiple inputs on a single line separated by spaces or commas. We can parse them using the string .split() method combined with unpacking, list comprehensions, or map().

Method Syntax Use Case
Unpacking with split() a, b = input().split() When the exact count of strings is known in advance
map() + Unpacking a, b = map(int, input().split()) Fixed count of numbers to separate variables
list(map()) Conversion list(map(int, input().split())) Arbitrary count of numbers into a single list
Custom Delimiter input().split(",") Comma-separated values (CSV style) 
# 1. Unpacking two strings:
first_name, last_name = input("Enter first and last name: ").split()
print(f"Initials: {first_name[0]}.{last_name[0]}.")

# 2. Reading multiple integers into separate variables:
a, b = map(int, input("Enter two integers separated by space: ").split())
print(f"{a} + {b} = {a + b}")

# 3. Reading arbitrary number of integers into a list:
numbers = list(map(int, input("Enter space-separated integers: ").split()))
print("Count:", len(numbers), "| Sum:", sum(numbers), "| Max:", max(numbers))

# Note: In Module 10 (Lists), we will also learn List Comprehensions:
# [int(x) for x in input().split()] as a powerful alternative syntax!

2.4. Dynamic Evaluation: eval()

  • The built-in eval(expression) function parses a Python expression string, evaluates it dynamically as executable Python code, and returns the result with its natural type.
  • Automatic Type Deduction: eval() automatically converts string representations of numbers, floats, booleans, lists, tuples, and dictionaries into their respective types without manual casting.
# Automatic type deduction:
x = eval(input("Enter any Python value: "))
print("Value:", x, "| Type:", type(x))
# If user inputs: 10          -> <class 'int'>
# If user inputs: 10.5        -> <class 'float'>
# If user inputs: [1, 2, 3]   -> <class 'list'>
# If user inputs: True        -> <class 'bool'>
# If user inputs: (10, 20)    -> <class 'tuple'>

# Evaluating mathematical expressions:
result = eval("10 + 20 * 3")
print("Math result:", result)  # 70
Security Warning on eval(): eval() executes arbitrary Python code. If malicious users pass system commands like __import__('os').system('rm -rf /'), eval() will execute them with full script privileges! In production environments, use ast.literal_eval() for safely parsing literals.

3. Command-line arguments (sys.argv)

L1 L2

L1 Fundamental

3.1. What are Command-Line Arguments?

  • Command-line arguments are parameters passed to a Python script at invocation time from the terminal/shell:
    python3 app.py arg1 arg2 arg3
  • They allow scripts to run in headless automation pipelines, scheduled cron jobs, and background workers without prompting the user interactively.
  • To read command-line arguments, Python provides the argv list inside the built-in sys module.

3.2. Anatomy of sys.argv

sys.argv is a standard Python list where elements are indexed based on terminal input order:

Index Content Example (python script.py 10 20)
sys.argv[0] Script file name (or relative/absolute path used to invoke it) "script.py"
sys.argv[1] First command-line argument passed by the user "10"
sys.argv[2] Second command-line argument passed by the user "20"
sys.argv[1:] Slice containing all user-supplied arguments (excluding script name) ["10", "20"]
len(sys.argv) Total number of arguments + 1 (includes the script name) 3 
import sys

# Displaying all command-line arguments:
print("Script name:       ", sys.argv[0])
print("Total elements:    ", len(sys.argv))
print("User arguments list:", sys.argv[1:])

# Iterating over arguments:
for i, arg in enumerate(sys.argv):
    print(f"sys.argv[{i}] = {arg}")

L2 Intermediate

3.3. Crucial Rules & Pitfalls of sys.argv

  1. Always Strings: Every item inside sys.argv is strictly of type str. Even if numbers are passed on the terminal, they must be converted explicitly using int() or float() before arithmetic.
  2. Space Separator Rule: Terminal shells split arguments by spaces. If an argument contains spaces (e.g. a full name or address), it must be wrapped in quotation marks:
    python3 user.py "John Doe" 28
    Here, sys.argv[1] is "John Doe". Without quotes, "John" and "Doe" become two distinct arguments.
  3. The IndexError Trap: Accessing an index that wasn't supplied (e.g. sys.argv[1] when the user simply ran python3 app.py) crashes the program with IndexError: list index out of range. Always inspect len(sys.argv) before indexing. 
import sys

# Safe command-line argument processing pattern:
if len(sys.argv) < 3:
    print(f"Usage: python3 {sys.argv[0]} <num1> <num2>")
    sys.exit(1)

num1 = float(sys.argv[1])
num2 = float(sys.argv[2])
print(f"Result: {num1} + {num2} = {num1 + num2}")
# Note: In Module 24 (Exception Handling), we will learn how to catch
# ValueError if the user enters non-numeric text!

3.4. Calculating the Sum of Arbitrary Command-Line Arguments

A classic interview and practical scripting pattern is computing aggregations over an unknown number of command-line inputs:

import sys

# Slice off the script name and convert all remaining arguments:
raw_args = sys.argv[1:]

if not raw_args:
    print("No numbers provided! Pass numbers like: python3 sum_args.py 10 20 30")
else:
    numbers = [float(arg) for arg in raw_args]
    print(f"Processed {len(numbers)} numbers.")
    print(f"Sum: {sum(numbers):.2f} | Average: {sum(numbers)/len(numbers):.2f}")

4. print and output formatting

L1 L2

L1 Fundamental

4.1. The Complete print() Signature

In Python 3, print() is a versatile built-in function with four optional keyword parameters:

print(*objects, sep=' ', end='\n', file=sys.stdout, flush=False)
Parameter Default Value Description & Use Cases
*objects None Zero or more objects to be printed. Values are converted to strings via str().
sep ' ' (single space) String inserted between multiple objects. Can be custom delimiters like "-", ",", or "".
end '\n' (newline) String appended after the last object. Setting end=" " or end="" prints on the same line.
file sys.stdout The stream or file-like object receiving output. Can redirect to sys.stderr or an opened file.
flush False If True, forces the output buffer to immediately flush to the screen without buffering. 
# 1. Custom Separator (sep):
print("2026", "09", "14", sep="-")          # 2026-09-14
print("user", "domain.com", sep="@")        # user@domain.com
print("192", "168", "1", "1", sep=".")      # 192.168.1.1
print("A", "B", "C", sep="")                # ABC (no space)

# 2. Custom Line Ending (end):
print("Loading", end="...")
print("Complete!")                          # Loading...Complete! (on same line)

# Printing items in a loop horizontally:
for i in range(1, 6):
    print(i, end=" ")                       # 1 2 3 4 5 
print()  # Newline flush

# 3. Output Redirection & Flushing:
import sys
print("Standard info message", file=sys.stdout)
print("Critical Error Alert!", file=sys.stderr)

# Note: Python can also redirect print() output directly into disk files:
# print("Writing into log file...", file=open("log.txt", "w"))
# (Physical file I/O is covered comprehensively in Module 18 File Handling).

# Demonstrating flush=True for immediate buffer emission:
print("Processing data...", end=" ", flush=True)
print("Done!")

4.2. Escape Characters in String Literals and Output Formatting

  • In Python string literals, we can use escape characters (prefixed with a backslash \) to associate a special non-printable meaning, such as line breaks, tabs, or quotes within strings.
Character Feature / Meaning Example Code Console Output
\n New line (line feed) print("Hello\nWorld") Hello
World
\t Horizontal tab (indent spacing) print("Name:\tBharat") Name:    Bharat
\v Vertical tab print("Row1\vRow2") Moves down vertically (terminal-dependent)
\r Carriage return (returns cursor to line start) print("Processing...\rDone! ") Done! (overwrites "Processing...")
\b Back space (erases previous character) print("Hellx\bo") Hello (erases 'x')
\f Form feed (page break on printers/terminals) print("Page1\fPage2") Page break / terminal feed
\' Single quote inside single-quoted string print('It\'s Python') It's Python
\" Double quote inside double-quoted string print("He said \"Hello\"") He said "Hello"
\\ Back slash (literal backslash character) print("C:\\users\\notes") C:\users\notes 
# --- Escape Characters in Action ---
# 1. New line (\n) and Tab (\t):
print("ID\tName\tScore\n101\tBharat\t98\n102\tSonwane\t95")

# 2. Quotes without conflicts:
print('Python\'s syntax is "clean"')
print("She said: \"Keep learning!\"")

# 3. Backslash escaping vs Raw strings:
print("Path: C:\\new_folder\\test.txt")      # Escapes each backslash
print(r"Path: C:\new_folder\test.txt")     # Raw string (r"...") treats backslashes literally!

# 4. Carriage return (\r) for in-place progress update:
import time
for percent in (25, 50, 75, 100):
    print(f"\rDownloading... {percent}%", end="", flush=True)
print("\nDownload complete!")

L2 Intermediate

4.3. Modern Formatting: f-strings (Formatted String Literals)

  • Introduced in Python 3.6 (PEP 498), f-strings are prefixed with f or F.
  • Replacement fields enclosed in curly braces {expression} are evaluated at runtime and formatted directly into the string.
  • They are evaluated faster than % or .format() because they are parsed directly into bytecode instructions.

❖ Advanced f-string Format Specifiers

Specifier Meaning Example Code Formatted Result
:.2f Float with fixed 2 decimal places f"{3.14159:.2f}" '3.14'
:, Thousands comma separator f"{1000000:,}" '1,000,000'
:.1% Percentage with 1 decimal place f"{0.856:.1%}" '85.6%'
:>10 Right align within 10 spaces f"{'data':>10}" ' data'
:<10 Left align within 10 spaces f"{'data':<10}" 'data '
:^10 Center align within 10 spaces f"{'data':^10}" ' data '
:*^10 Center align with custom fill character f"{'hi':*^10}" '****hi****'
:04d Zero-padded integer (4 digits) f"{7:04d}" '0007'
:b / :x Binary / Hexadecimal formatting f"{15:b}, {15:x}" '1111, f' 
# Practical Tabular formatting with f-strings:
print(f"{'Item':<15} | {'Qty':^6} | {'Price':>10}")
print("-" * 35)
print(f"{'Keyboard':<15} | {1:^6} | ${89.99:>9.2f}")
print(f"{'Ultra Monitor':<15} | {2:^6} | ${349.50:>9.2f}")

# Escaping literal braces:
print(f"Use {{name}} for variable injection.")  # Use {name} for variable injection.

# Python 3.8+ Debug feature:
num = 42
print(f"{num=}, {num*2=}")  # num=42, num*2=84

4.4. Comparison: %-Formatting vs. str.format() vs. f-Strings

Python has evolved through three primary formatting paradigms:

Method Example Syntax Pros Cons / Recommendation
1. %-Formatting (Legacy / C-style) "Hi %s, age %d" % (name, age) Familiar to C/C++ developers Prone to tuple unpacking errors; rigid; obsolete.
2. str.format() (Python 2.7 / 3.0+) "Hi {}, age {}".format(name, age) Supports reordered indices & reusable template strings More verbose than f-strings; slower execution.
3. f-Strings (Python 3.6+) f"Hi {name}, age {age}" Extremely readable, fastest performance, full Python expressions Recommended standard for all modern Python code. 
item = "Widget"
cost = 19.5

# 1. Legacy %-formatting:
print("Item: %s, Cost: $%.2f" % (item, cost))

# 2. str.format() method:
print("Item: {0}, Cost: ${1:.2f}".format(item, cost))
print("Item: {name}, Cost: ${price:.2f}".format(name=item, price=cost))

# 3. Modern f-string (Preferred):
print(f"Item: {item}, Cost: ${cost:.2f}")

C. Common questions

L1 L2

L1 Fundamental

C.1. Why does int(input()) raise a ValueError when the user enters "10.5"? ▾ Answer

The int() constructor can directly convert float objects (e.g. int(10.5) -> 10), but when parsing a string literal, it strictly expects base-10 digits only. The dot . character in "10.5" is an invalid integer character. To handle decimal user input, convert to float first: int(float(input())).

C.2. Why does bool(input("Enter True/False: ")) always return True? ▾ Answer

input() returns a string. In Python, all non-empty strings are truthy. Even if the user enters the word "False", the string has length 5 and evaluates to True. Only pressing Enter with zero text yields the empty string "", which evaluates to False. To parse booleans safely, compare against explicit strings: input().strip().lower() == "true".

C.3. What is the difference between sep and end in print()? ▾ Answer

sep dictates the delimiter inserted between items passed into a single print statement (default is a single space ' '). end specifies the character placed at the end after all items are displayed (default is a newline '\n').

L2 Intermediate

C.4. Why is eval(input()) dangerous, and what should be used instead? ▾ Answer

eval() executes any valid Python code passed into it. An attacker can supply code to delete files, inspect environment variables, or spawn a reverse shell. For safe evaluation of Python literals (numbers, lists, dicts, tuples), use ast.literal_eval() from the standard ast library.

C.5. Why does sys.argv[0] store the script name instead of the first argument? ▾ Answer

This follows the UNIX C standard where argv[0] always contains the invocation command or executable path. This allows programs to inspect how they were invoked, output proper usage messages (e.g. f"Usage: python {sys.argv[0]} [options]"), or act differently depending on binary symlinks.

C.6. How do you redirect print() output directly to a file on disk? ▾ Answer

Use the file parameter in print() with an opened file object in write or append mode:
with open("app.log", "a") as f: print("User logged in", file=f). This avoids needing manual f.write("...\n") string conversions and appends a newline automatically.

C.7. How can we read multiple space-separated integers in a single line without manual loops? ▾ Answer

Use map(int, input().split()) or a list comprehension:
• Fixed variables: a, b, c = map(int, input().split())
• Into a list: numbers = list(map(int, input().split())) or [int(x) for x in input().split()].
