1. Introduction

L1

L1 Fundamental

1.1. Overview

  • A Function is a reusable, named block of organized code designed to perform a single, coherent task.
  • Functions eliminate redundancy (the DRY principle — Don't Repeat Yourself), enhance modularity, and make programs testable, maintainable, and debuggable.
  • In Python, functions are First-Class Citizens (First-Class Objects). This means functions can be assigned to variables, passed as arguments into other functions, returned from functions, and stored inside data structures.

1.2. Function Type Annotations (PEP 484 & PEP 3107)

Type Hinting Signatures: Python function definitions support explicit type hints on parameters and return values:
  • Parameters & Return: def add(a: int, b: int) -> int:
  • Procedures returning None: def log_event(msg: str) -> None:
  • Variable-Length Args: Type hints on *args and **kwargs specify the type of each individual element, not the container: def process(*items: str, **meta: Any) -> None:
  • Higher-Order Callables: from collections.abc import Callable; def execute(fn: Callable[[int, int], int], x: int, y: int) -> int:
  • Runtime Introspection: Stored in the __annotations__ dictionary attribute.

2. Defining functions, parameters, return

L1 L2

L1 Fundamental

2.1. Anatomy of a Python Function

def function_name(param1: int, param2: str) -> bool:
    """Optional docstring explaining what the function accomplishes (PEP 257)."""
    # Function body / statements
    return True
  • def keyword: Tells Python to create a function object and bind it to the identifier name.
  • Parameters vs Arguments:
    • Parameters: The variable names listed in the function definition header.
    • Arguments: The concrete values or references passed into the function upon invocation.
  • Docstrings ("""..."""): Triple-quoted explanation placed on the first line inside the function. Accessible programmatically via function_name.__doc__ and interactive help().
def calculate_area(width: float, height: float) -> float:
    """Calculate the area of a rectangle given width and height."""
    return width * height

print(calculate_area(5.0, 3.0))      # 15.0
print(calculate_area.__doc__)        # Displays docstring

L2 Intermediate

2.2. The return Statement

  • Explicit Return: The return statement exits the function immediately and passes back a value to the caller.
  • Implicit Return: If a function finishes executing its body without hitting a return statement, or uses a bare return, it implicitly returns None.
  • Returning Multiple Values: When multiple comma-separated values are returned (return a, b, c), Python packs them into a single tuple, which the caller can unpack directly.
# Implicit return None:
def log_message(msg: str) -> None:
    print(f"[LOG] {msg}")

res: None = log_message("System boot")
print("Return value:", res)  # None

# Returning multiple values (Tuple packing & unpacking):
def min_max_sum(numbers: list[int]) -> tuple[int, int, int]:
    return min(numbers), max(numbers), sum(numbers)

low: int
high: int
total: int
low, high, total = min_max_sum([10, 20, 5, 40, 15])
print(f"Low: {low}, High: {high}, Total: {total}")
# Low: 5, High: 40, Total: 90

3. Positional, keyword, default, variable args

L1 L2

L1 Fundamental

3.1. Positional & Keyword Arguments

  • Positional Arguments: Bound to parameters strictly based on their order in the call.
  • Keyword Arguments: Bound by parameter name (param=value), allowing arguments to be passed in any order.
  • Rule: In any function call, positional arguments must always precede keyword arguments.
def greet(name: str, greeting: str = "Hello", punctuation: str = "!") -> str:
    return f"{greeting}, {name}{punctuation}"

# Positional:
print(greet("Bharat"))                     # Hello, Bharat!

# Keyword:
print(greet(punctuation=".", name="Rahul"))# Hello, Rahul.

# SyntaxError if positional follows keyword:
# greet(greeting="Hi", "Suresh")  # SyntaxError: positional argument follows keyword argument

L2 Intermediate

3.2. The Infamous Mutable Default Argument Trap

Critical Interview Trap: Default parameter expressions are evaluated once at function definition time, NOT every time the function is called! If you use a mutable object (like [] or {}) as a default value, that same instance is shared across all subsequent invocations. 
from typing import Any

# BAD: Mutable default argument shared across calls
def append_bad(item: Any, target_list: list[Any] = []) -> list[Any]:
    target_list.append(item)
    return target_list

print(append_bad("apple"))   # ['apple']
print(append_bad("banana"))  # ['apple', 'banana'] <-- Unintended shared state!

# GOOD: Use None as default sentinel and initialize in body
def append_good(item: Any, target_list: list[Any] | None = None) -> list[Any]:
    if target_list is None:
        target_list = []
    target_list.append(item)
    return target_list

print(append_good("apple"))   # ['apple']
print(append_good("banana"))  # ['banana'] (Clean instance each call)

3.3. Variable-Length Arguments: *args and **kwargs

  • *args: Gathers excess positional arguments into a tuple.
  • **kwargs: Gathers excess keyword arguments into a dictionary.
from typing import Any

def make_request(method: str, url: str, *headers: str, **options: Any) -> None:
    print(f"Method: {method} -> {url}")
    print(f"Headers tuple: {headers}")
    print(f"Options dict:  {options}")

make_request(
    "GET", "https://api.example.com",
    "Accept: application/json", "Authorization: Bearer xyz",
    timeout=30, retries=3, verify_ssl=True
)

3.4. Special Parameter Markers: Positional-Only (/) and Keyword-Only (*)

Python 3.8+ allows precise architectural control over how callers can pass arguments:

def full_signature(pos_only: int, /, standard: int, *, kw_only: int) -> None:
    print(pos_only, standard, kw_only)

# pos_only MUST be passed by position (no keyword)
# standard can be passed by position OR by keyword
# kw_only MUST be passed by keyword

full_signature(10, standard=20, kw_only=30)  # Valid
full_signature(10, 20, kw_only=30)           # Valid
# full_signature(pos_only=10, 20, kw_only=30) # TypeError: pos_only is positional-only
# full_signature(10, 20, 30)                  # TypeError: kw_only must be keyword

4. Local & global scope, global keyword

L1 L2

L1 Fundamental

4.1. The LEGB Scope Resolution Rule

When resolving variable names, Python searches four concentric scope namespaces in strict order:

  1. L — Local: Names assigned within the current function body.
  2. E — Enclosing: Names in the local scope of enclosing/outer functions (closures).
  3. G — Global: Names defined at the module top level or declared via global.
  4. B — Built-in: Pre-assigned built-in names (len, range, print, ValueError).

L2 Intermediate

4.2. The global and nonlocal Keywords

  • Reading a global variable from inside a function works freely without keywords.
  • However, assigning to a variable inside a function creates a new local variable by default. To reassign a module-level variable, declare it with global <var>.
  • To reassign a variable in an outer enclosing function from an inner closure, declare it with nonlocal <var>.
from collections.abc import Callable

counter: int = 0

def increment() -> None:
    global counter
    counter += 1

increment()
increment()
print("Global counter:", counter)  # 2

# nonlocal example (Closure state):
def make_accumulator(initial: int = 0) -> Callable[[int], int]:
    total: int = initial
    def add(amount: int) -> int:
        nonlocal total
        total += amount
        return total
    return add

acc: Callable[[int], int] = make_accumulator(100)
print(acc(25))  # 125
print(acc(50))  # 175

4.3. The Classic UnboundLocalError

Under the Hood: Python's compiler scans function bodies at compile-time. If a variable is assigned anywhere inside the function, Python marks it as local for the entire function. Accessing it before the assignment triggers an UnboundLocalError. 
x: int = 10

def broken_func() -> None:
    # print(x)  # Raises UnboundLocalError: cannot access local variable 'x' where it is not associated with a value
    x: int = 20    # Because 'x' is assigned here, the compiler treats 'x' as local throughout!

# broken_func()

4.4. Accessing Shadowed Global Variables via globals()

When a local variable inside a function shares the exact same name as a global variable, the local variable completely shadows the global variable. If you need to access or modify the global variable while simultaneously maintaining the local variable with that same name, use the built-in globals() dictionary:

# Classic Interview Question: Same name for global and local variable
score: int = 100  # Global variable

def update_scores() -> None:
    score: int = 20  # Local variable shadows global 'score'
    print("Local score: ", score)               # 20
    print("Global score:", globals()['score'])  # 100 (Accessing global via globals() dict)

    # Modifying the global variable directly through the dictionary:
    globals()['score'] = 999

update_scores()
print("Global score after function execution:", score)  # 999

5. Recursive functions

L1 L2

L1 Fundamental

5.1. Anatomy of Recursion

A recursive function is a function that calls itself directly or indirectly to solve smaller instances of the same problem. Every recursive function must contain two essential parts:

  1. Base Case: A terminating condition that stops recursion and returns a concrete value without making further recursive calls.
  2. Recursive Step: Moving toward the base case by calling itself with reduced input.
def factorial(n: int) -> int:
    # 1. Base case:
    if n <= 1:
        return 1
    # 2. Recursive step:
    return n * factorial(n - 1)

print("5! =", factorial(5))  # 120

L2 Intermediate

5.2. Recursion Limit & Lack of Tail Call Optimization (TCO)

  • In Python, each function call consumes a new stack frame. To prevent runaway recursion from causing C-level stack overflow crashes, Python imposes a default recursion depth limit (typically 1,000 frames).
  • Exceeding this raises a RecursionError: maximum recursion depth exceeded.
  • You can inspect and adjust the limit using sys.getrecursionlimit() and sys.setrecursionlimit().
  • No Tail Call Optimization: Python does not optimize tail-recursive calls into loops. Guido van Rossum deliberately rejected TCO to preserve complete stack traces for debugging.
import sys
print("Current recursion limit:", sys.getrecursionlimit())  # Typically 1000

# Memoization: Transforming O(2^N) exponential recursion into O(N) linear time
# using a dictionary cache (Dedicated decorator syntax @lru_cache is covered in Module 23):
fib_cache: dict[int, int] = {0: 0, 1: 1}

def fibonacci(n: int) -> int:
    if n not in fib_cache:
        fib_cache[n] = fibonacci(n - 1) + fibonacci(n - 2)
    return fib_cache[n]

print("Fibonacci(50):", fibonacci(50))  # 12586269025 (Instantaneous with cache!)

C. Common questions

L1 L2

L1 Fundamental

C.1. What does it mean that functions are "First-Class Citizens" in Python? ▾ Answer

It means functions are treated like any other object (integers, strings, lists):

  • Can be assigned to variables: f = print; f("hello").
  • Can be passed as arguments into other functions (Higher-Order Functions like map, filter, or decorators).
  • Can be returned from functions (Closures).
  • Can be stored inside collections (e.g. dispatch dictionaries {"add": add_func, "sub": sub_func}).
C.2. Why does def append_to(item, lst=[]) retain elements between separate calls? ▾ Answer

In Python, default parameter values are evaluated only once when the function is defined (at compile/module loading time), NOT when the function is called.

The empty list [] is bound to the function object's __defaults__ tuple. Each function call that relies on the default receives a reference to this exact same list. Mutating it modifies the persistent object in __defaults__.

Solution: Always use def f(item, lst=None): if lst is None: lst = [].

C.3. What is the difference between *args and **kwargs? ▾ Answer
  • *args: Variable-length positional arguments. Python collects all excess positional arguments into an immutable tuple.
  • **kwargs: Variable-length keyword arguments. Python collects all excess keyword arguments into a mutable dictionary.
C.4. What causes an UnboundLocalError and how do you resolve it? ▾ Answer

An UnboundLocalError occurs when a variable is referenced before it has been assigned inside the local scope of a function.

If Python sees an assignment statement anywhere in a function (x = 10), it classifies x as a local variable for the entire function body. If code attempts to read x before that assignment line executes, Python cannot fall back to the global scope and raises UnboundLocalError.

Fix: Declare global x at the top of the function if you intend to modify the global variable.

L2 Intermediate

C.5. What is the difference between the global and nonlocal keywords? ▾ Answer
  • global: Binds the variable name directly to the top-level module namespace.
  • nonlocal: Binds the variable name to the nearest enclosing function scope (excluding the global scope). Used in closures to maintain state across invocations.
C.6. What is the purpose of the / and * markers in function parameter lists? ▾ Answer
  • / (Positional-only marker, PEP 570): All parameters before / must be passed by position, never by keyword. Useful for library authors to rename parameters in future releases without breaking user keyword calls.
  • * (Keyword-only marker): All parameters after * must be passed as keyword arguments (arg=val). Prevents subtle bugs where callers pass boolean flags positionally.
C.7. Why does Python not support Tail Call Optimization (TCO)? ▾ Answer

Guido van Rossum deliberately decided against implementing TCO for two primary reasons:

  1. Preserving Debugging Stack Traces: TCO overwrites the current stack frame with the recursive call, which destroys the call history and makes post-mortem traceback debugging much harder.
  2. Pythonic Iteration: Python emphasizes explicit loops (for, while, comprehensions) over recursion as the idiomatic mechanism for repetition.
C.8. How are arguments passed in Python: by value or by reference? ▾ Answer

Python uses Call by Object Reference (or Call by Sharing):

  • The parameter receives a copy of the reference (pointer) to the object.
  • If you pass a mutable object (like a list) and mutate it in-place (lst.append(5)), the caller sees the change.
  • If you rebind the parameter name (lst = [1, 2]), it points to a new object, leaving the caller's reference unaffected.
  • If you pass an immutable object (int, string, tuple), it cannot be modified in-place, behaving effectively like call-by-value.
C.9. If a local variable and a global variable have the same name, how can you access both inside a function? ▾ Answer

Inside the function, the identifier binds to the local variable by default. Declaring global var would prevent having a distinct local variable with the same name. To access and modify the shadowed global variable without sacrificing the local variable, access Python's global namespace dictionary using globals()['var'].

        val: int = current
        current += step
        return val
    return counter

  4. Task 4: GCD (Greatest Common Divisor) via Euclidean Algorithm — Implement Euclidean recursion with a base case. ▾ Solution 
    def gcd(a: int, b: int) -> int:
    # Base case:
    if b == 0:
        return a
    # Recursive step: gcd(b, a % b)
    return gcd(b, a % b)

print("GCD(48, 18):", gcd(48, 18))    # 6
print("GCD(101, 10):", gcd(101, 10))  # 1

    from collections.abc import Callable

def make_memoized_fib() -> Callable[[int], int]:

        if n not in cache:
            cache[n] = fib(n - 1) + fib(n - 2)

    return fib

  2. Challenge 2: Pipeline Function Composer — Implement a compose(*functions) utility executing functions from left to right. ▾ Solution 
    from collections.abc import Callable
from typing import Any

def compose_pipeline(*functions: Callable[[Any], Any]) -> Callable[[Any], Any]:
    def execute(initial_value: Any) -> Any:
        res: Any = initial_value
        for f in functions:
            res = f(res)
        return res
    return execute

# Example pipeline: string sanitization
cleanse: Callable[[Any], Any] = compose_pipeline(
    str.strip,
    str.lower,
    lambda s: s.replace(" ", "-"),
    lambda s: f"https://example.com/tags/{s}"
)

print(cleanse("   Python Best Practices   "))
# https://example.com/tags/python-best-practices
  3. Challenge 3: Modular Decomposition (Number-to-Words Converter) — Decompose a complex numerical formatting problem into nested helper functions. ▾ Solution 
    def number_to_words(num: int) -> str:
    """Convert integer between 0 and 99,999 into English words using modular helper."""
    if num == 0:
        return "Zero"

    units: list[str] = [
        "", "One", "Two", "Three", "Four", "Five", "Six", "Seven", "Eight", "Nine",
        "Ten", "Eleven", "Twelve", "Thirteen", "Fourteen", "Fifteen", "Sixteen",
        "Seventeen", "Eighteen", "Nineteen"
    ]
    tens: list[str] = [
        "", "", "Twenty", "Thirty", "Forty", "Fifty", "Sixty", "Seventy", "Eighty", "Ninety"
    ]

    def convert_hundred(n: int) -> str:
        """Helper to convert 1 to 999."""
        words: list[str] = []
        if n >= 100:
            words.append(units[n // 100] + " Hundred")
            n %= 100
        if 1 <= n <= 19:
            words.append(units[n])
        elif n >= 20:
            ten_part: str = tens[n // 10]
            unit_part: str = units[n % 10]
            words.append(f"{ten_part} {unit_part}".strip())
        return " ".join(words)

    result: list[str] = []
    thousands_val: int = num // 1000
    if thousands_val > 0:
        result.append(convert_hundred(thousands_val) + " Thousand")
        num %= 1000

    if num > 0:
        result.append(convert_hundred(num))

    return " ".join(result)

print("4520  ->", number_to_words(4520))
print("99999 ->", number_to_words(99999))
