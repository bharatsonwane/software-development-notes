1.1. Overview

  • An identifier is a name you give to a variable, function, class, module, etc. Python has strict rules for what is legal, plus conventions for what is readable.

1.2. Default rules and how to study this file

Default rule today: use snake_case for variables/functions, PascalCase for classes, and never start names with a digit. Indent with 4 spaces.

2. Identifiers and naming rules

L1

L1 Fundamental

  • Allowed: letters (A–Z, a–z), digits (0–9), underscore _.
  • Must start with a letter or _ — not a digit.
  • Case-sensitive: age, Age, AGE are different.
  • No special characters like @, $, - in names.
name = "Bharat"     # OK
_total = 10         # OK — often means "internal"
user2 = 99          # OK
# 2user = "x"       # SyntaxError — starts with digit
# user-name = "x"   # SyntaxError — hyphen not allowed

3. Reserved words

L1

L1 Fundamental

  • Keywords are reserved — you cannot use them as identifiers.
import keyword
print(keyword.kwlist)
# False, None, True, and, as, assert, async, await, break, class, ...
# if = 10   # SyntaxError
  • True, False, None are keywords (capitalized).

4. Comments and indentation basics

L1 L2

L1 Fundamental

4.1. Comments

# Single-line comment

"""
Multi-line string — often used as a docstring
(not a special comment type).
"""

def greet(name):
    """Return a greeting. This is a docstring."""
    return f"Hello, {name}"

4.2. Indentation

  • Python uses indentation (not braces) to define blocks. Standard is 4 spaces. Mixing tabs and spaces causes errors.
x = 10
if x > 5:
    print("big")   # indented block
    print("still in if")
print("outside if")

L2 Intermediate

4.3. Statements and lines

  • One statement per line is normal. Use \ or parentheses for line continuation. Semicolons can join statements but are uncommon.
total = (1 + 2 + 3
         + 4 + 5)

a = 1; b = 2   # legal, rarely preferred

C. Common questions

L1 L2

L1 Fundamental

C.1. Can identifiers start with underscore? ▾ Answer

Yes. Leading _ is a convention for “internal” use. Double leading __ on class attributes triggers name mangling (File 20).

C.2. Why no braces for blocks? ▾ Answer

Design choice — indentation is mandatory and keeps structure consistent. Wrong indent raises IndentationError.

L2 Intermediate

C.3. Are Unicode letters allowed in identifiers? ▾ Answer

Yes in Python 3 (PEP 3131), but prefer ASCII names in most codebases for tooling and collaboration.

  1. Write a mini style guide (10 lines of comments) for naming in this course. ▾ Solution 
    # ==========================================================
# MINI STYLE GUIDE: NAMING CONVENTIONS IN PYTHON (PEP 8)
# ==========================================================
# 1. Variables & Functions: lowercase with words separated by underscores (snake_case)
#    e.g., user_account, calculate_total_tax()
# 2. Classes: CapWords / PascalCase convention
#    e.g., UserAccount, PaymentProcessor
# 3. Constants: ALL_CAPS with underscores
#    e.g., DEFAULT_TIMEOUT, MAX_RETRIES = 3
# 4. Protected instance attributes: single leading underscore (_internal_cache)
# 5. Private / mangled instance attributes: double leading underscore (__private_secret)
# 6. Avoid single-character names except for counters like i, j, k or coordinates x, y.
# 7. Never use 'l' (el), 'O' (oh), or 'I' (eye) as single-letter variable names.
# ==========================================================
print("Style guide loaded.")
  2. Demonstrate how mixing tabs/spaces can break code (describe or show). ▾ Solution 
    # Demonstrating how mixing tabs and spaces causes TabError in Python 3:
# In Python 3, mixing tabs and spaces in indentation is strictly prohibited.
# The following will fail if one line uses spaces and the other uses a tab:

def demonstrate_indent():
    # 4 spaces indentation
    status = "ready"
    if status == "ready":
        # TabError: inconsistent use of tabs and spaces in indentation
        # <TAB>print(status)  <-- Never mix tabs with spaces!
        print("Use 4 spaces per indentation level throughout.")
