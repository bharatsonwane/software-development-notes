02. Identifiers and Language Basics

File 02 — naming rules, reserved words, comments, indentation.

Identifiers Keywords Indentation

L1 Fundamental

  • An identifier is a name you give to a variable, function, class, module, etc. Python has strict rules for what is legal, plus conventions for what is readable.

L1 Fundamental

Default rule today: use snake_case for variables/functions, PascalCase for classes, and never start names with a digit. Indent with 4 spaces.

1. Identifiers and naming rules

L1

L1 Fundamental

  • Allowed: letters (A–Z, a–z), digits (0–9), underscore _.
  • Must start with a letter or _ — not a digit.
  • Case-sensitive: age, Age, AGE are different.
  • No special characters like @, $, - in names.
name = "Bharat"     # OK
_total = 10         # OK — often means "internal"
user2 = 99          # OK
# 2user = "x"       # SyntaxError — starts with digit
# user-name = "x"   # SyntaxError — hyphen not allowed

2. Reserved words

L1

L1 Fundamental

  • Keywords are reserved — you cannot use them as identifiers.
import keyword
print(keyword.kwlist)
# False, None, True, and, as, assert, async, await, break, class, ...
# if = 10   # SyntaxError
  • True, False, None are keywords (capitalized).

3. Comments and indentation basics

L1 L2

L1 Fundamental

3.1. Comments

# Single-line comment

"""
Multi-line string — often used as a docstring
(not a special comment type).
"""

def greet(name):
    """Return a greeting. This is a docstring."""
    return f"Hello, {name}"

3.2. Indentation

  • Python uses indentation (not braces) to define blocks. Standard is 4 spaces. Mixing tabs and spaces causes errors.
x = 10
if x > 5:
    print("big")   # indented block
    print("still in if")
print("outside if")

L2 Intermediate

3.3. Statements and lines

  • One statement per line is normal. Use \ or parentheses for line continuation. Semicolons can join statements but are uncommon.
total = (1 + 2 + 3
         + 4 + 5)

a = 1; b = 2   # legal, rarely preferred

4. Common questions

L1 L2

L1 Fundamental

4.1. Can identifiers start with underscore?

  • A: Yes. Leading _ is a convention for “internal” use. Double leading __ on class attributes triggers name mangling (File 20).

4.2. Why no braces for blocks?

  • A: Design choice — indentation is mandatory and keeps structure consistent. Wrong indent raises IndentationError.

L2 Intermediate

4.3. Are Unicode letters allowed in identifiers?

  • A: Yes in Python 3 (PEP 3131), but prefer ASCII names in most codebases for tooling and collaboration.
