2. What a branch is

L1

L1 Fundamental

In Git, a branch is not an expensive copy of all project files. It is merely a lightweight, movable pointer to a specific commit.

/*
Git Branch Architecture:

Commit A <─── Commit B <─── Commit C (main)
                             ▲
                             └── HEAD (points to current branch)
*/
  • Lightweight Storage: Each local branch is represented by a tiny 41-byte text file inside .git/refs/heads/<branch-name> containing a 40-character commit hash and a newline.
  • HEAD Pointer: HEAD is a special symbolic reference (stored in .git/HEAD) pointing to the branch currently checked out. When you make a commit, the active branch pointer automatically moves forward to the new commit.

3. Create, list, rename, delete branches

L1

L1 Fundamental

Branch management commands allow you to organize independent lines of development:

# List all local branches (* indicates currently checked out branch)
git branch

# List all local and remote tracking branches
git branch -a

# Create a new branch at the current commit (does not switch to it)
git branch feature/user-profile

# Rename current branch
git branch -m feature/user-profile-v2

# Delete a branch safely (prevents deletion if branch has unmerged work)
git branch -d feature/user-profile-v2

# Force delete a branch regardless of merge status
git branch -D feature/abandoned-experiment

4. git switch / checkout

L1

L1 Fundamental

To start working on another branch, you must switch your working tree and point HEAD to it.

# Modern dedicated command (Git 2.23+):
# Switch to an existing branch
git switch feature/login

# Create and switch to a new branch in a single step
git switch -c feature/payments

# Legacy multi-purpose command:
git checkout feature/login
git checkout -b feature/payments
Best Practice: Prefer git switch for branch navigation and git restore for discarding working tree modifications. git checkout remains supported for backwards compatibility.

5. Tracking branches and upstream

L2

L2 Intermediate

A tracking branch is a local branch that maintains a direct relationship with a remote reference.

Preview: Remote servers (origin) and remote collaboration workflows are fully explored in File 06 (Remote & Collaboration).
# Inspect tracking relationships and commit divergence
git branch -vv

# Set upstream for current branch (requires configured remote)
git branch -u origin/main

# Push and set upstream simultaneously
git push -u origin feature/auth
  • When an upstream is configured, running git status reports whether your local branch is ahead, behind, or diverged from the remote.

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a Git branch under the hood, and why is creating one instantaneous? ▾ Answer

Unlike older version control systems that copy every file in the project into a new directory, a Git branch is simply a 41-byte text file inside .git/refs/heads/ containing a 40-character hexadecimal commit hash. Creating a branch merely writes a commit SHA-1 into a tiny file, making branch creation an instantaneous $O(1)$ operation regardless of repository size.

C.2. Why was git switch introduced alongside git checkout? ▾ Answer

Historically, git checkout was overloaded with multiple unrelated responsibilities: switching branches, creating new branches, and discarding uncommitted file changes in the working directory. Git 2.23 introduced git switch (strictly for branch navigation) and git restore (strictly for discarding or un-staging file modifications), clarifying user intent and preventing accidental file overwrites.

L2 Intermediate

C.3. What is the difference between git branch -d and git branch -D? ▾ Answer

git branch -d (delete) is a safe guard: Git will refuse to delete the branch if it contains commits that have not been merged into your current branch or upstream. git branch -D is a shortcut for --delete --force: it deletes the branch pointer immediately regardless of whether its commits have been merged anywhere.

C.4. What information does git branch -vv provide? ▾ Answer

git branch -vv displays verbose details for all local branches: the latest commit hash, commit subject line, configured upstream tracking branch (e.g. [origin/main]), and whether the local branch is [ahead N], [behind N], or [gone].

P. Practical Assignment

L1 L2
Create throwaway branches; delete them when done.

L1 Fundamental

P.1. Warm-up

  1. Create and switch to feature/demo. ▾ Solution 
    # Create and switch to a new feature branch in one command
git switch -c feature/user-profile
# (Equivalent legacy command: git checkout -b feature/user-profile)
  2. List branches; rename one. ▾ Solution 
    # List local and remote branches
git branch -a

# Rename current branch
git branch -m feature/user-settings
  3. Make a commit on the feature branch. ▾ Solution 
    # Make commit on feature branch
echo "export const profile = {};" > profile.js
git add profile.js
git commit -m "feat(profile): scaffold profile schema"

P.2. Core tasks

  1. switch — Move between main and feature without losing work. ▾ Solution 
    # Move between branches cleanly
git switch main
# (Working tree updates to match main)

git switch feature/user-settings
# (Working tree updates to match feature)
  2. upstream — Set upstream when pushing (even to a local “remote” or document the flag). ▾ Solution 
    # Push branch and set upstream tracking branch
git push -u origin feature/user-settings
# (-u / --set-upstream links local branch to origin/feature/user-settings)
  3. delete — Delete a merged vs unmerged branch (safe flags). ▾ Solution 
    # Safe delete (fails if branch has unmerged changes)
git branch -d feature/merged-feature

# Force delete unmerged branch (use with caution)
git branch -D feature/abandoned-idea
  4. orphan sketch — Comment when orphan branches are used. ▾ Solution 
    /*
Orphan Branches in Git:
- An orphan branch (git checkout --orphan gh-pages) has completely disconnected history (root commit with 0 parents).
- Use cases:
  1. GitHub Pages (gh-pages) documentation hosting.
  2. Starting an entirely clean project branch in the same repo without historical baggage.
*/

L2 Intermediate

P.3. Challenge

  1. Simulate two features in parallel branches; switch and show log per branch. ▾ Solution 
    # Simulating parallel feature development:
git switch -c feature/feature-a
echo "Feature A" > a.txt && git add a.txt && git commit -m "feat: add A"

git switch main
git switch -c feature/feature-b
echo "Feature B" > b.txt && git add b.txt && git commit -m "feat: add B"

# Compare branch histories:
git log --oneline feature/feature-a
git log --oneline feature/feature-b
  2. Explain in comments what HEAD points to after each switch. ▾ Solution 
    /*
HEAD Mechanics:
- HEAD is a symbolic pointer referencing your current location in the commit graph.
- When on 'main', HEAD -> refs/heads/main -> commit SHA.
- When switching to 'feature/demo', HEAD updates to refs/heads/feature/demo.
- 'Detached HEAD' occurs when HEAD points directly to a raw commit SHA instead of a named branch pointer.
*/
