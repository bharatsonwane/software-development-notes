2. git stash (push, pop, apply, list)

L1 L2

L1 Fundamental

Stashing takes uncommitted changes in your working tree and staging area and saves them onto an internal stack (refs/stash), giving you a clean working directory without creating an unnecessary commit.

# Stash working changes with a descriptive message (include untracked files with -u)
git stash push -m "WIP: checkout logic before emergency fix" -u

# View all stashed changesets
git stash list
# stash@{0}: WIP: checkout logic before emergency fix
# stash@{1}: WIP on dev: 3a2c4e refactoring

# Apply the latest stash and REMOVE it from the stash stack
git stash pop

# Apply a specific stash while KEEPING it in the stash stack
git stash apply stash@{1}

# Inspect what changes a stash contains
git stash show -p stash@{0}

# Delete a specific stash or clear all stashes
git stash drop stash@{0}
git stash clear

3. git cherry-pick

L1 L2

L1 Fundamental

Cherry-picking applies the patch introduced by a specific commit from one branch directly onto your current branch, generating a brand-new commit SHA.

# Switch to target branch and cherry-pick a specific commit by SHA
git switch main
git cherry-pick 7b8c9d0

# Cherry-pick without immediately committing (leaves changes staged for tweaking)
git cherry-pick -n 7b8c9d0

# Resolving conflicts during a cherry-pick:
git status
# Resolve files, then:
git add <resolved-files>
git cherry-pick --continue

# Or abort and return to pre-cherry-pick state:
git cherry-pick --abort
Common Use Case: Backporting a hotfix from main to an older release branch, or extracting a single bugfix out of an unfinished feature branch.

4. reset vs restore vs revert

L1 L2

L1 Fundamental

Git offers three distinct commands to undo or modify changes. Understanding their scope prevents accidental data loss:

  • git restore (File-level undo): Introduced in Git 2.23 to replace ambiguous git checkout -- file. Unstages files or discards unstaged working tree edits without touching commit history.
  • git revert (Safe public undo): Creates a new inverse commit that negates previous changes. Ideal for shared or public branches because it preserves commit history.
  • git reset (History rewriting undo): Moves current branch HEAD backward. Rewrites commit history; dangerous on shared branches.
# 1. git restore: Safe working directory & staging area cleanup
git restore app.js             # Discard unstaged working tree changes
git restore --staged app.js    # Unstage app.js back to working tree

# 2. git revert: Safe inverse commit for shared branches
git revert a1b2c3d             # Generates new commit undoing a1b2c3d

# 3. git reset: Local history rewriting
git reset --soft HEAD~1        # Moves HEAD back; keeps changes staged
git reset --mixed HEAD~1       # Default: moves HEAD back; leaves changes unstaged in working tree
git reset --hard HEAD~1        # DESTRUCTIVE: moves HEAD back; DISCARDS changes from staging & working tree

5. reflog for recovery

L1 L2

L1 Fundamental

Reflog (Reference Log) tracks every update made to branch tips and HEAD in your local repository. Even if you run an accidental git reset --hard or delete a local branch, the commits remain recorded in the reflog until garbage collected (typically 30–90 days).

# View HEAD movement history
git reflog
# Output example:
# e4f5a6b HEAD@{0}: reset: moving to HEAD~1
# 1a2b3c4 HEAD@{1}: commit: add payment processor
# d9e8f7a HEAD@{2}: checkout: moving from dev to main

# Recover a lost commit by creating a new branch at its reflog SHA:
git branch recovery-branch 1a2b3c4

# Or restore current branch to its pre-reset state:
git reset --hard HEAD@{1}

C. Common questions

L1 L2

L1 Fundamental

C.1. What is the difference between git stash pop and git stash apply? ▾ Answer

git stash apply restores the stashed modifications into your working tree while keeping the entry in the stash list. git stash pop applies the modifications and immediately deletes (drops) the entry from the stash stack if the merge succeeds without conflict.

C.2. When should you use git revert instead of git reset? ▾ Answer

Use git revert whenever the commit you want to undo has already been pushed to a remote shared branch. Revert records a brand-new commit that inverses the changes, preserving history without forcing team members to re-sync or force-pull. Use git reset only for private, local commits that have not been shared.

L2 Intermediate

C.3. Explain the differences between git reset --soft, --mixed, and --hard. ▾ Answer

All three move the current branch ref and HEAD backward to the specified commit:

  • --soft: Only moves HEAD. Staging area (Index) and working tree remain untouched. Changes from reset commits stay staged.
  • --mixed (default): Moves HEAD and resets the Index (staging area) to match. Working tree is preserved unstaged.
  • --hard: Moves HEAD, resets the Index, and overwrites the working tree. Any uncommitted local work is permanently discarded.
C.4. How does git reflog help recover from an accidental git reset --hard? ▾ Answer

Git does not immediately delete commits when HEAD is reset backward. Local commit references are recorded in git reflog under HEAD@{n}. By inspecting git reflog, finding the SHA right before the reset, and running git branch <recovery-branch> <SHA> or git reset --hard HEAD@{1}, you can restore all committed changes intact.

P. Practical Assignment

L1 L2
Practice recovery commands on disposable commits.

L1 Fundamental

P.1. Warm-up

  1. Stash uncommitted work; pop it back. ▾ Solution 
    # Stash uncommitted changes in working tree and staging
git stash -u # (-u includes untracked files)

# Switch branches or pull changes cleanly
git switch main && git pull

# Pop stashed changes back into working tree
git switch -
git stash pop
  2. Cherry-pick one commit onto another branch. ▾ Solution 
    # Cherry-pick a specific commit by SHA onto current branch
git switch main
git cherry-pick 7b8c9d0
# Applies exact commit changes to current branch with new commit SHA
  3. Reset --soft and --mixed on an unpushed commit (compare). ▾ Solution 
    # git reset comparison:
# 1. --soft: Moves HEAD back, leaves all changes in Staging Area
git reset --soft HEAD~1

# 2. --mixed (default): Moves HEAD back, unstages changes to Working Tree
git reset --mixed HEAD~1

P.2. Core tasks

  1. stash list — Multiple stashes; apply a specific one. ▾ Solution 
    # List all stashed changesets
git stash list
# stash@{0}: WIP on main: 7a8b9c feature
# stash@{1}: WIP on dev: 1d2e3f quick fix

# Apply specific stash without dropping it from the stash stack
git stash apply stash@{1}
  2. revert — Revert a published commit (new undo commit). ▾ Solution 
    # Safely undo a published commit by generating a new inverse commit:
git revert 4d5e6f -m "revert: rollback broken authentication patch"
git push origin main
  3. restore — Discard file changes vs restore from HEAD. ▾ Solution 
    # Discard uncommitted changes in working tree (Git 2.23+):
git restore broken-file.js

# Unstage a file from staging back to working tree:
git restore --staged config.json
  4. reflog — Find a “lost” commit SHA and recover. ▾ Solution 
    # Find "lost" commits after bad reset using Reflog:
git reflog
# 1a2b3c4 HEAD@{0}: reset: moving to HEAD~1
# 5d6e7f8 HEAD@{1}: commit: important work was here!

# Recover the lost commit by branching from its SHA:
git branch recovered-work 5d6e7f8

L2 Intermediate

P.3. Challenge

  1. Create detached HEAD on purpose; create a branch to save work. ▾ Solution 
    # Enter detached HEAD (checkout raw commit SHA instead of branch)
git checkout 5d6e7f8
# Make test changes and commit:
git commit -am "test: experimental trial"

# Save work before switching away by creating a real branch:
git switch -c feature/experimental-saved
  2. Document reset --hard danger and a safer alternative. ▾ Solution 
    /*
git reset --hard Dangers & Safe Alternatives:
- DANGER: git reset --hard permanently erases all uncommitted changes in your working tree with NO way to recover them!
- SAFE ALTERNATIVES:
  1. Stash first: git stash -u before running any reset.
  2. Use git restore to discard only specific files.
  3. Create backup branch: git branch backup-before-reset
*/

  • I know reset/restore/revert differences.
