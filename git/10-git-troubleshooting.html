2. Detached HEAD

L1 L2

L1 Fundamental

A detached HEAD occurs when HEAD points directly to a specific commit SHA or tag rather than to a named branch reference.

  • How it happens: Running git checkout <commit-hash> or checking out a tag/remote branch directly.
  • The risk: New commits created in this state do not belong to any branch. If you switch branches without saving them, Git considers them unreachable, and they will eventually be pruned by garbage collection.
  • How to resolve: Simply create a branch at your current commit to preserve your work.
# Inspect current state (Git will explicitly warn you of detached HEAD)
git status
# "HEAD detached at a1b2c3d"

# Save commits made in detached HEAD to a new branch:
git switch -c feature/saved-work

# Or return back to your main branch discarding test experiments:
git switch main

3. Accidental commits on the wrong branch

L1 L2

L1 Fundamental

A common mistake is committing changes directly to main instead of creating a feature branch first.

Scenario A — Commits NOT pushed yet:

# 1. Create a new feature branch pointing to current commit (keeps all new commits)
git branch feature/new-work

# 2. Reset main back to where it should be (e.g. back 2 commits)
git reset --hard HEAD~2

# 3. Switch to the feature branch to continue working
git switch feature/new-work

Scenario B — Commits already pushed to remote: Never force-reset public branches. Instead, checkout your feature branch, cherry-pick the commits, and run git revert on the shared branch.

4. Recovering with reflog

L1 L2

L1 Fundamental

git reflog is Git's safety net. It records every time HEAD or branch pointers move locally (commits, checkouts, merges, resets, rebases).

# Display local history of HEAD movements with relative timestamps
git reflog --date=relative
# Example output:
# 3c4d5e6 HEAD@{10 minutes ago}: reset: moving to HEAD~1
# a1b2c3d HEAD@{25 minutes ago}: commit: complete payment gateway

# Recover by checking out a new branch pointing directly to the lost commit:
git branch recovered-feature a1b2c3d

# Or restore current branch pointer immediately:
git reset --hard HEAD@{1}
Garbage Collection Note: Reflog entries expire after 30 days (for unreachable commits) or 90 days (for reachable commits) by default.

5. Common error messages and fixes

L1 L2

L1 Fundamental

Quick reference for recurring errors encountered in day-to-day Git operations:

  • "fatal: refusing to merge unrelated histories": Occurs when merging two repositories with no common root ancestor. 
    git pull origin main --allow-unrelated-histories
  • "error: failed to push some refs (non-fast-forward)": Remote contains commits your local branch lacks. 
    git pull --rebase origin <branch>
git push origin <branch>
  • "Permission denied (publickey)": SSH key is missing, not added to ssh-agent, or not registered in GitHub. 
    ssh-add -l || ssh-add ~/.ssh/id_ed25519
ssh -Tv git@github.com
  • "fatal: index file corrupt": Git's staging index binary was damaged. 
    rm .git/index
git reset

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a "Detached HEAD" state and how do you safely keep work done in it? ▾ Answer

A detached HEAD occurs when HEAD points directly to an individual commit SHA instead of a named branch ref. Any commits created are not attached to a branch. To safely keep them, create a new branch at your current location using git switch -c <new-branch-name> before switching away.

C.2. What causes "fatal: refusing to merge unrelated histories" and how is it resolved? ▾ Answer

This error occurs when attempting to pull or merge two repositories that were initialized independently (for example, a newly created remote repository with a README merged into an existing local repository) having no shared root commit. It is resolved by explicitly appending the --allow-unrelated-histories flag during git pull or git merge.

L2 Intermediate

C.3. You accidentally committed changes to local main instead of a feature branch. How do you fix it without losing work? ▾ Answer

If the commits have not been pushed to remote:

  1. Create a new feature branch at current commit: git branch feature/my-work.
  2. Switch back to main and reset it back to before the accidental commits: git reset --hard HEAD~N (or git reset --hard origin/main).
  3. Switch to your feature branch: git switch feature/my-work. All work is preserved on the feature branch while main is restored clean.
C.4. How do you recover a branch or commit accidentally deleted via git branch -D or git reset --hard? ▾ Answer

Commits in Git are not erased immediately upon deletion. Run git reflog to find the commit SHA where the deleted branch tip or previous state resided. Once identified (e.g. c3d4e5f), create a new branch from that commit: git branch recovered-branch c3d4e5f. Git will recreate the branch pointing to that commit snapshot with all history intact.

P. Practical Assignment

L1 L2
Break and fix in a playground repo — do not practice --hard on real work without a backup branch.

L1 Fundamental

P.1. Warm-up

  1. Enter detached HEAD; create a branch to keep the commit. ▾ Solution 
    # Rescuing commits made in detached HEAD state:
git checkout 7a8b9c0
git commit -am "work done in detached HEAD"

# Secure commits into a named branch:
git switch -c feature/rescued-branch
  2. Commit on wrong branch; move the commit with cherry-pick or reset. ▾ Solution 
    # Moving a commit accidentally made on 'main' to a new feature branch:
# 1. Create feature branch at current commit
git branch feature/my-feature

# 2. Reset local main back one commit
git reset --hard HEAD~1

# 3. Switch to feature branch
git switch feature/my-feature
  3. Use reflog to find yesterday’s tip. ▾ Solution 
    # Using reflog to restore yesterday's state:
git reflog --date=relative
# Find entry: HEAD@{yesterday}: commit: Stable work
git reset --hard HEAD@{yesterday}

P.2. Core tasks

  1. error catalog — Reproduce “refusing to merge unrelated histories” or document the fix. ▾ Solution 
    # Error: "fatal: refusing to merge unrelated histories"
# Cause: Two repositories initialized independently with no common ancestor.
# Fix:
git pull origin main --allow-unrelated-histories
  2. corrupt index — Comment recovery: git reset / remove index cautiously. ▾ Solution 
    # Recovering from corrupted git index:
# Symptom: "fatal: index file corrupt"
# Fix: Remove corrupt index and reset from HEAD
rm .git/index
git reset
  3. permission denied (publickey) — Checklist for SSH failures. ▾ Solution 
    /*
SSH "Permission denied (publickey)" Troubleshooting Checklist:
1. Verify ssh-agent is running: eval "$(ssh-agent -s)"
2. Confirm key is loaded: ssh-add -l
3. Test GitHub connection: ssh -Tv git@github.com
4. Ensure public key (.pub) is uploaded to GitHub Settings -> SSH Keys.
5. Check ~/.ssh/config permissions (chmod 600 ~/.ssh/config).
*/
  4. large file — What to do if you committed a huge binary. ▾ Solution 
    # Removing large accidental binary file from git history:
# 1. Remove from index and track in gitignore:
git rm --cached heavy-data.zip
echo "heavy-data.zip" >> .gitignore

# 2. For committed files across history, use git-filter-repo:
# git filter-repo --path heavy-data.zip --invert-paths

L2 Intermediate

P.3. Challenge

  1. Write a personal runbook: 8 recovery commands with one-line purpose. ▾ Solution 
    /*
8 Essential Git Recovery Runbook Commands:
1. git restore <file>                    -> Discard unstaged working tree edits.
2. git restore --staged <file>           -> Unstage file back to working tree.
3. git commit --amend                    -> Fix message or stage forgotten files for last commit.
4. git reset --soft HEAD~1               -> Undo last commit, keep changes staged.
5. git reset --mixed HEAD~1              -> Undo last commit, unstage changes to working tree.
6. git revert <commit-sha>               -> Safely undo a published commit with inverse commit.
7. git reflog                            -> View chronological log of every HEAD movement to recover lost work.
8. git clean -fd                         -> Remove untracked files and directories.
*/
  2. Practice: undo last commit keeping changes, then redo cleanly. ▾ Solution 
    # Practice: Undo last commit keeping changes, then redo cleanly:
git commit -m "wip: bad commit message"
git reset --soft HEAD~1
git commit -m "feat(api): proper descriptive commit message"
