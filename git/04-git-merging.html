2. Fast-forward vs merge commit

L1

L1 Fundamental

When integrating two branches, Git determines the merge strategy based on commit history:

/*
1. Fast-Forward Merge:
Before:  C1 <─── C2 (main)
                  └─── C3 <─── C4 (feature)
After:   C1 <─── C2 <─── C3 <─── C4 (main, feature)

2. 3-Way Merge (True Merge Commit):
Before:  C1 <─── C2 <─── C3 (main)
                  └─── C4 <─── C5 (feature)
After:   C1 <─── C2 <─── C3 <─── M (main: two parents C3 and C5)
                  └─── C4 <─── C5 ┘
*/
  • Fast-Forward (--ff): If the destination branch has no new commits since the feature branched off, Git simply advances the branch pointer to the latest feature commit. No merge commit is created.
  • 3-Way Merge (--no-ff): If both branches have diverged, Git finds their common ancestor and generates a special merge commit with two parent hashes.

3. Merging a feature branch

L1

L1 Fundamental

Standard merge workflows bring feature work into the main codebase:

# Step 1: Switch to receiving branch
git switch main

# Step 2: Merge the feature branch
git merge feature/search

# Force a merge commit even if fast-forward is possible
git merge --no-ff feature/search

# Squash merge: compress entire feature history into a single staged commit
git merge --squash feature/search
git commit -m "feat: complete search filter functionality"

4. Resolving merge conflicts

L2

L2 Intermediate

A merge conflict occurs when both branches modify the same line of a file differently, or when one branch deletes a file that another modified.

<<<<<<< HEAD (current branch)
const API_URL = "https://api.production.com";
=======
const API_URL = "https://api.staging.com";
>>>>>>> feature/staging-config (incoming branch)
  1. Open the conflicted file and locate conflict markers (<<<<<<<, =======, >>>>>>>).
  2. Edit the code to keep the intended changes and delete all conflict markers.
  3. Stage the resolved file: git add filename.
  4. Finalize the merge: git commit.

5. Aborting and undoing a merge

L2

L2 Intermediate

If conflicts are complicated or a merge was started by mistake, you can abort safely:

# Abort an in-progress conflicted merge (returns working tree to pre-merge state)
git merge --abort

# Check if repository is currently in the middle of a merge
git status

C. Common questions

L1 L2

L1 Fundamental

C.1. What is a fast-forward merge and when does Git use it? ▾ Answer

A fast-forward merge occurs when there is a linear path from the target branch to the feature branch (the target branch has no new commits since the feature branched off). In this scenario, Git simply moves the branch pointer forward without creating a new merge commit.

C.2. What is the difference between git merge --no-ff and git merge --squash? ▾ Answer

git merge --no-ff forces Git to create a merge commit with two parents, preserving all individual feature commits and explicitly documenting that a branch existed. git merge --squash takes all modifications from the feature branch, combines them into a single staged change, but creates no merge commit or parent pointer, resulting in a single clean commit on the target branch.

L2 Intermediate

C.3. What do the conflict markers (<<<<<<<, =======, >>>>>>>) signify? ▾ Answer

<<<<<<< HEAD denotes the beginning of the conflicting section on the branch you currently have checked out. The ======= line separates your branch's version from the incoming version. >>>>>>> branch-name marks the end of the conflicting changes from the branch being merged.

C.4. How can you safely cancel a merge that resulted in messy conflicts? ▾ Answer

Run git merge --abort. This command cancels the merge operation, rolls back the staging area, and cleanly restores all files in your working directory to the exact commit state they were in before git merge was invoked.

P. Practical Assignment

L1 L2
Practice merges in a local-only repo first.

L1 Fundamental

P.1. Warm-up

  1. Branch, commit on both sides, merge feature into main. ▾ Solution 
    # Merge feature branch into main
git switch main
git merge feature/user-profile
  2. Create a conflict on purpose; resolve it. ▾ Solution 
    # Creating and resolving a merge conflict:
# 1. When Git encounters conflicting changes on the same lines, it pauses:
# "CONFLICT (content): Merge conflict in config.js"

# 2. Open file, manually remove conflict markers (<<<<<<<, =======, >>>>>>>)
# 3. Stage resolved file and complete merge:
git add config.js
git commit -m "merge: resolve conflict in config.js"
  3. Abort a merge mid-conflict once for practice. ▾ Solution 
    # Aborting a conflicted merge and returning working directory to pre-merge state:
git merge --abort

P.2. Core tasks

  1. fast-forward — Show a FF merge. ▾ Solution 
    # Fast-Forward Merge:
# Occurs when main has no new commits since the branch was created.
# Git simply moves the 'main' pointer forward without creating a merge commit.
git switch main
git merge feature/linear-task
# Output: "Updating 3a4b5c..6d7e8f Fast-forward"
  2. no-ff — Force a merge commit and compare history. ▾ Solution 
    # Forcing a merge commit (--no-ff) to preserve branch topology:
git switch main
git merge --no-ff feature/linear-task -m "merge: merge feature/linear-task into main"
  3. conflict markers — Resolve keeping both changes intentionally. ▾ Solution 
    /*
Conflict Marker Anatomy & Resolution:
<<<<<<< HEAD (Current branch: main)
const API_URL = "https://api.prod.com";
=======
const API_URL = "https://api.staging.com";
const TIMEOUT = 5000;
>>>>>>> feature/api-update

Resolved combination:
const API_URL = "https://api.prod.com";
const TIMEOUT = 5000;
*/
  4. merge tool — Note your preferred conflict editor. ▾ Solution 
    # Setting default merge conflict resolution tool (e.g. VS Code):
git config --global merge.tool code
git config --global mergetool.code.cmd 'code --wait "$MERGED"'

# Launch tool during conflict:
git mergetool

P.3. Challenge

  1. Document the difference between merge commit and FF with two ASCII graphs. ▾ Solution 
    /*
Fast-Forward vs Merge Commit (--no-ff):

Fast-Forward (Linear History):
A --- B --- C (main, feature)

Merge Commit (--no-ff):

  2. Undo a merge with git revert -m 1 (after merge commit) or explain reset if unpushed. ▾ Solution 
    # Undoing an already pushed merge commit:
# -m 1 specifies that parent 1 (mainline branch) is kept as the baseline
