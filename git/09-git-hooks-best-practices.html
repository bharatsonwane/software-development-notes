P. Practical Assignment

L1 L2
Use a sample repo; hooks are local unless shared via a framework.

L1 Fundamental

P.1. Warm-up

  1. List hooks in .git/hooks. ▾ Solution 
    # Inspect available sample git hooks
ls -la .git/hooks
# pre-commit.sample, pre-push.sample, commit-msg.sample, etc.
  2. Enable a sample pre-commit that rejects WIP in the message. ▾ Solution 
    # Create simple pre-commit hook that blocks "WIP" in staged files:
cat << 'EOF' > .git/hooks/pre-commit
#!/bin/sh
if git diff --cached | grep -q "TODO: NOCOMMIT"; then
  echo "ERROR: Attempting to commit code containing 'TODO: NOCOMMIT'!"
  exit 1
fi
EOF

chmod +x .git/hooks/pre-commit
  3. Write a conventional commit example set. ▾ Solution 
    /*
Conventional Commit Examples:
feat(auth): implement Google OAuth2 login flow
fix(cart): prevent negative item quantity calculation
docs(readme): update local setup instructions
test(order): add unit tests for discount coupon validation
refactor(api): simplify database query builder
chore(deps): bump vite from 5.1 to 5.4
*/

P.2. Core tasks

  1. commit-msg — Enforce subject length or prefix. ▾ Solution 
    # Enforce commit message format in .git/hooks/commit-msg:
cat << 'EOF' > .git/hooks/commit-msg
#!/bin/sh
msg=$(head -n 1 "$1")
regex="^(feat|fix|docs|style|refactor|perf|test|chore)(\(.+\))?: .+"

if ! echo "$msg" | grep -Eq "$regex"; then
  echo "ERROR: Invalid commit message format. Expected conventional commit."
  exit 1
fi
EOF

chmod +x .git/hooks/commit-msg
  2. secrets — Checklist of files that must never be committed. ▾ Solution 
    /*
Files That Must NEVER Be Committed Checklist:
- .env, .env.local, .env.production (secret environment keys)
- *.pem, *.key, id_rsa, id_ed25519 (private cryptographic keys)
- credentials.json, service-account.json (cloud provider credentials)
- database backups (*.sql, *.dump)
- node_modules/, vendor/, target/, dist/
*/
  3. pre-commit framework — Note or install pre-commit.com style config (optional). ▾ Solution 
    # pre-commit framework (.pre-commit-config.yaml):
# Install: pip install pre-commit && pre-commit install

#     hooks:
#       - id: trailing-whitespace
#       - id: end-of-file-fixer
#       - id: check-yaml
  4. signed commits — Comment when GPG/SSH signing helps. ▾ Solution 
    /*
Signed Commits (GPG / SSH):
- Proves cryptographic authenticity that a commit was created by the keyholder, preventing author impersonation.
- GitHub displays a "Verified" badge next to signed commits.
- Enable: git config --global commit.gpgsign true
*/

L2 Intermediate

P.3. Challenge

  1. Design a minimal team hook policy (what runs locally vs CI). ▾ Solution 
    /*
Team Hook Architecture Strategy:
- Local Hooks (Husky / pre-commit):
  - Fast linting (ESLint on staged files via lint-staged).
  - Secret scanning (detect-secrets / git-secrets).
  - Must execute in < 2 seconds so developer workflow is not hindered.
- CI/CD Server (GitHub Actions):
  - Full test suite, integration tests, security audits, build validation.
  - Acts as the final non-bypassable gate.
*/
  2. Show how to bypass a hook and why you usually should not. ▾ Solution 
    # Bypassing hooks:
git commit --no-verify -m "urgent hotfix"

# DANGER:
# Bypassing hooks skips linters and secret detectors. Never use in regular workflows!
