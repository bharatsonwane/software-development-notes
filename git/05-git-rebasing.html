P. Practical Assignment

L1 L2
Only rebase commits you have not shared (or coordinate carefully).

L1 Fundamental

P.1. Warm-up

  1. Rebase a feature branch onto updated main (local). ▾ Solution 
    # Rebase feature branch onto updated main
git switch feature/login
git fetch origin
git rebase origin/main
# Re-applies feature commits one by one on top of origin/main
  2. Compare merge vs rebase histories visually. ▾ Solution 
    # Merge vs Rebase history visualization:
# Merge creates a non-linear diamond history with a merge commit.
# Rebase rewrites commit history linearly as if work began today.
git log --graph --oneline --decorate -n 10
  3. Run rebase -i and squash two commits. ▾ Solution 
    # Interactive rebase: squash last 2 commits into one
git rebase -i HEAD~2

# In the editor, change the second line from 'pick' to 'squash' (or 's'):
# pick 1a2b3c feat: initial login button
# squash 4d5e6f fix: adjust button padding

P.2. Core tasks

  1. onto — Rebase onto a different base. ▾ Solution 
    # Rebase --onto: move commits from one branch base to another
# git rebase --onto <new-base> <old-base> <branch>
git rebase --onto main feature/legacy-base feature/my-feature
  2. conflict during rebase — Resolve and --continue. ▾ Solution 
    # Resolving conflict during rebase:
# 1. Fix conflicting files
# 2. Stage resolved files
git add auth.js

# 3. Continue rebase (DO NOT use git commit)
git rebase --continue
  3. abort — Abort a rebase once. ▾ Solution 
    # Abort rebase mid-way and restore original branch state:
git rebase --abort
  4. golden rule — Write when not to rebase. ▾ Solution 
    /*
The Golden Rule of Rebasing:
NEVER rebase commits that exist outside your local repository and that other people might have based work on.
Rebasing changes commit SHAs; rebasing shared branches causes merge chaos for teammates.
Only rebase local, unpushed feature branches.
*/

L2 Intermediate

P.3. Challenge

  1. Interactive rebase: reword + drop one commit in a 4-commit branch. ▾ Solution 
    # Interactive rebase reword and drop:
git rebase -i HEAD~4

# In editor:
# r 1111111 feat: reword this commit message
# pick 2222222 feat: keep this commit
# d 3333333 test: drop this unwanted commit
# pick 4444444 feat: final commit
  2. Explain force-push need after rebase of a published branch — and safer alternatives. ▾ Solution 
    /*
Force-pushing after Rebase:
- Because rebase recalculates commit hashes, git push will be rejected with (non-fast-forward).
- DANGEROUS: git push --force (overwrites remote even if teammates pushed new commits).
- SAFE ALTERNATIVE: git push --force-with-lease
  Ensures no one else pushed new work to the remote branch before overwriting.
*/
